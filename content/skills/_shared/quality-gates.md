# 품질 관문

모든 스킬이 단계를 끝내기 전에 확인하는 기준이다. 워크플로우 agent 가 먼저 확인하고 워크플로우를 실행한 agent 가 결과를 받아 다시 확인한다. 관문 하나라도 통과하지 못하면 그 단계를 끝내지 않는다.

## 공통

| 관문 | 통과 조건 | 확인 방법 |
|---|---|---|
| 형식 | `engine/bin/cresvoid validate <트랙>` 이 통과한다 | 실행 |
| 흐름 | `kotlin engine/e2e.main.kts` 가 통과한다 | 실행 |
| 템플릿 | `kotlin content/templates/sync.main.kts --check` 가 통과한다 | 실행 |
| 근거 | refs 와 quote 가 정답이나 테스트의 근거 문장을 가리킨다 | 문항과 테스트마다 근거 문단을 읽는다 |
| 정답 하나 | 문서만으로 정답이 하나로 정해진다 | 블라인드 풀이와 재풀이 |
| 주장 확인 | 계산, 코드 동작, 사실 서술을 실행이나 1차 자료로 확인했다 | 워크플로우 결과의 확인 기록 |
| 난도 | 대충 읽으면 틀리는 지점이 단계마다 있다 | 블라인드 풀이의 확신도와 `too_easy` |
| 문장 | 한국어 문서가 해라체 평서형이고 글쓰기 기준을 한 번 적용했다 | 문서를 읽는다 |
| 기록 | 결정마다 이유가 `docs/log/` 에 있다 | 기록을 읽는다 |

## 종류별

### reading

- 지문 글자 수와 문단 수가 카드 형식 범위 안에 있다.
- 지문의 사실 서술은 출처와 함께 확인 기록에 있다.
- 오답 선지는 상식만으로 지울 수 없다.
- 재풀이에서 정답과 다르게 푼 문항이 없다.

### build

- 참조 풀이, 테스트, 문항을 서로 독립적으로 만들었고 교차 검증 결과가 `clean` 이다.
- 모호성 검토의 must 지적이 남지 않았다.
- 대규모 테스트에서 참조 풀이 실행 시간이 제한 시간의 1/5 이하다.
- 앞 단계 참조 풀이가 새 단계 테스트에서 실패한다. validate 가 확인한다.
- 테스트 이름에 숨은 케이스의 조건이나 답이 드러나지 않는다. 엔진은 통과하거나 실패한 테스트 이름을 보여 준다(FORMAT.md 11.2 절).

### code

- short 문항 정답은 `code/` 실행 결과와 같다. validate 가 확인한다.
- 재풀이에서 실행 뒤 낸 최종 답이 모두 정답과 같다.
- 실행 전 첫 풀이에서 모든 문항을 확신하며 맞혔으면 난도를 다시 검토한다.
- antislop Delivery Gate 가 모두 PASS 다.

### fix

- 시작 코드는 그 단계 테스트 하나 이상에서 실패하고 참조 풀이는 모두 통과한다. validate 가 확인한다.
- 시작 코드와 참조 풀이의 차이는 버그를 고치는 줄뿐이다.
- 블라인드 수정본이 숨은 테스트를 통과한다.
- 테스트 이름에 숨은 케이스의 조건이나 답이 드러나지 않는다. 엔진은 통과하거나 실패한 테스트 이름을 보여 준다(FORMAT.md 11.2 절).
- 버그 신고에 원인과 위치가 드러나지 않는다.
- antislop Delivery Gate 가 모두 PASS 다.

## antislop 적용

code·fix 트랙 코드와 모든 참조 풀이는 FORMAT.md 11.8 절을 따른다. 기준 원문은 `antislop-code` 스킬과 `antislop` 스킬의 C-1~C-5, R-31, R-35, R-36, R-38, Delivery Gate 다. 워크플로우 agent 는 Delivery Gate 를 PASS/FAIL 과 증거로 돌려준다.
