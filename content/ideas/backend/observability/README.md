# 관측성

지표, 백분위수, SLO 경보, 분산 추적을 익힌다. 대시보드의 숫자가 무엇을 숨기는지, 경보가 너무 늦거나 너무 잦은 이유를 설명하는 힘을 기른다.

## 1. 개념 지도

- 지표 종류: 카운터(늘기만 하고 재시작 때 0 으로 돌아감), 게이지, 히스토그램, 요약.
- 요약이 계산한 분위수는 인스턴스 여럿에 걸쳐 합칠 수 없다. 히스토그램은 버킷 수를 더해 합칠 수 있다.
- Prometheus 의 `histogram_quantile` 은 버킷 안에서 선형 보간으로 분위수를 추정한다. 요청이 220ms 에 몰려 있어도 버킷이 200~300ms 면 95번째 백분위수를 295ms 로 추정한다. 관심 있는 값(SLO 경계) 근처에 버킷 경계를 두면 정확해진다. 네이티브 히스토그램은 지수 버킷을 동적으로 쓴다.
- 소진율은 SLO 에 비해 오류 예산을 얼마나 빨리 쓰는지다. 99.9% SLO 의 권장 시작값은 긴 창 1시간·짧은 창 5분·소진율 14.4(예산 2%)와 6시간·30분·6(5%)에 호출 경보, 3일·6시간·1(10%)에 티켓이다. 긴 창과 짧은 창이 함께 넘을 때만 경보해 오류가 멈추면 빨리 꺼진다.
- 백분위수의 평균은 전체 백분위수가 아니다. 평균은 꼬리 지연을 숨긴다. 닫힌 부하 모델은 서버가 느려질 때 요청을 덜 보내 꼬리 지연을 가린다(조정된 누락, [../load/README.md](../load/README.md) 의 '부하와 회복력' 절).
- 리틀의 법칙: 시스템 안의 평균 요청 수 = 도착률 × 평균 머무는 시간.
- 분산 추적: W3C `traceparent` 는 버전-트레이스 ID(16진수 32자)-부모 스팬 ID(16진수 16자)-플래그 꼴이다. 표본 추출은 처음에 정하는 방식과 끝난 뒤 정하는 방식이 있다.
- 레이블 값이 많은 지표는 시계열 수가 폭증한다.

## 2. 학습 경로

1. R-observability-10 기술 지문으로 백분위수, 히스토그램, 소진율을 익힌다.
2. B-observability-20 `metrics` 트랙에서 지표 저장과 분위수 추정, 소진율 경보를 만든다.
