# R-incidents-10 정규식 하나가 멈춘 전 세계 프록시

- 분야: 기술(장애 보고서)
- 목표: 역추적 정규식이 CPU 를 소진한 원리와 그 변경이 몇 초 만에 전 세계로 퍼진 절차를 서로 다른 고리로 구별하고 재발 방지책과 짝짓는다.
- 사건: 2019-07-02 13:42 UTC 부터 27분 동안 장애가 이어졌다. 웹 방화벽 관리 규칙에 새로 들어간 정규식의 `.*(?:.*=.*)` 부분이 과도한 역추적을 일으켜 HTTP 를 처리하는 CPU 코어를 모두 소진했다. 방화벽 규칙은 새 위협에 빨리 대응해야 해서 몇 초 만에 전 세계에 퍼지는 분산 키-값 저장소(Quicksilver)로 배포됐다. 사용자는 502 오류를 받았고 트래픽의 80% 를 잃었다. 14:09 무렵 트래픽과 CPU 가 정상으로 돌아왔다.
- 다룰 내용: 역추적 정규식 엔진이 최악 입력에서 시간이 폭증하는 원리, 몇 주 전 리팩터링에서 실수로 빠진 CPU 사용 보호, 성능 회귀를 찾지 못한 시험, 비상이 아닌 변경도 전역 배포가 가능했던 절차, 자사 접근 제어 서비스가 함께 멈춰 내부 관리 화면에 로그인하지 못했고 우회 절차가 충분히 훈련되지 않아 늦어진 대응.
- 재발 방지책: CPU 보호 복구, 방화벽 관리 규칙 3,868개 점검, 시험에 규칙별 성능 측정 추가, 실행 시간을 보장하는 정규식 엔진(re2, Rust regex)으로 교체, 비상 전역 배포는 남기고 평소 규칙은 단계 배포.
- 난도: LEET 언어이해 수준.
- 형식: 2,600~3,000자, 6~7문단, 6문항. `<보기>` 는 역추적 엔진과 선형 시간 엔진에 같은 패턴과 입력을 줄 때 단계 수가 어떻게 늘어나는지 단순화한 표를 준다.
- 함정과 엣지 케이스: 정규식이 틀린 결과를 냈다고 본 선지(결과가 아니라 시간이 문제), 단계 배포만 있었으면 원인이 사라진다고 본 선지(영향 범위가 줄어든다), 재발 방지책과 원인 사슬의 고리를 엇갈려 짝지은 선지.
- 검증: 수치와 시각은 보고서로 확인한다. `<보기>` 의 단계 수는 Kotlin 스크립트로 계산한다.
- 이어지는 카드: B-regex-10(선형 시간 정규식 엔진 구현).
- 출처: Cloudflare 사후 보고서(이 도메인 README 의 '출처' 절).
- 피할 것: 보고서에 없는 원인 추측, 사람을 탓하는 서술, 지문에서 수치를 찾기만 하면 풀리는 문항.
