# R-incidents-50 필드 하나가 모자랐던 콘텐츠 갱신

- 분야: 기술(장애 보고서)
- 목표: 정의와 실제 입력의 불일치가 여러 겹의 시험을 빠져나간 경로를 따라가고 각 방지책이 어느 겹을 메우는지 판단한다.
- 사건: IPC 템플릿 유형의 정의는 입력 필드 21개를 요구했지만 센서 코드는 값 20개만 넘겼다. 시험과 앞서 배포된 인스턴스들은 21번째 필드에 와일드카드 조건을 써서 불일치가 드러나지 않았다. 2024-07-19 배포된 인스턴스 하나가 21번째 필드에 처음으로 와일드카드가 아닌 조건을 넣었다. 콘텐츠 검증기는 입력이 21개라고 전제하고 평가해 이 인스턴스를 통과시켰다. 채널 파일 291 을 받은 센서에서 콘텐츠 해석기가 21번째 값을 읽으려다 입력 배열 범위 밖을 읽었고 시스템이 멈췄다.
- 다룰 내용: 코드 배포 없이 데이터(콘텐츠, 설정) 갱신만으로 장애가 나는 경로, 정의와 실제 입력의 불일치, 와일드카드 조건이 오래 문제를 가린 이유, 여러 겹의 시험을 모두 빠져나간 경로, 단계 배포 없이 퍼진 콘텐츠.
- 재발 방지책: 센서 빌드 때 필드 수 검증, 실행 시 배열 범위 검사, 모든 필드를 와일드카드가 아닌 조건으로 시험, 검증기 검사 추가, 새 인스턴스마다 해석기 안에서 시험, 카나리와 단계 배포, 고객이 배포 위치와 시점을 고르는 기능, 외부 보안 업체 두 곳의 독립 검토.
- 난도: LEET 언어이해 수준.
- 형식: 2,600~3,000자, 6~7문단, 6문항. `<보기>` 는 다른 서비스의 설정 스키마와 설정 묶음을 주고 같은 유형의 불일치가 숨어 있는지 판단하게 한다.
- 함정과 엣지 케이스: 시험을 통과했으니 안전했다고 본 선지, 와일드카드 조건이 버그를 만들었다고 본 선지(가렸을 뿐이다), 검증기가 아무 검사도 하지 않았다고 본 선지(21개를 전제로 검사했다), 콘텐츠는 코드가 아니어서 검증이 덜 필요하다고 본 선지.
- 검증: 사실은 근본 원인 분석 보고서로 확인한다. 보고서에 없는 피해 규모는 쓰지 않는다.
- 출처: CrowdStrike 근본 원인 분석 보고서.
- 피할 것: 보고서에 없는 원인 추측, 사람을 탓하는 서술, 지문에서 수치를 찾기만 하면 풀리는 문항.
