# B-hdfs-20 네임노드 시뮬레이터 만들기

- 목표: 네임노드가 하는 일인 이름 공간 관리, 블록 분할, 복제본 배치, 장애 감지, 재복제, 안전 모드를 시각이 입력 명령으로 움직이는 시뮬레이터로 만든다.
- 입출력 모양: 데이터노드 등록(이름, 랙, 용량), 파일 만들기(경로, 크기, 복제 수, 쓰는 노드), 디렉터리와 이름 바꾸기와 지우기, 할당량 설정, `TICK <초>`, 하트비트와 블록 보고, 노드 중지, 상태 조회 명령이다.
- 1단계 `01-namespace`: 디렉터리 트리, 파일 만들기와 지우기와 이름 바꾸기, 블록 분할(마지막 블록은 남은 크기), 이름 할당량과 공간 할당량. 공간 할당량은 복제본마다 세고 블록 하나를 끝까지 쓸 공간이 없으면 실패한다. 이름 바꾸기가 할당량을 넘기면 실패한다.
- 2단계 `02-placement`: 기본 배치 규칙으로 복제본 위치를 정한다. 같은 조건의 후보 가운데 고르는 규칙(예: 남은 용량이 큰 노드, 이름 순서)을 명세로 고정해 출력이 결정적이게 한다. 랙이 하나뿐일 때, 노드 수가 복제 수보다 적을 때를 다룬다.
- 3단계 `03-recovery`: 하트비트가 끊긴 노드를 stale 과 죽음으로 판정하는 시각, 복제가 모자란 블록을 남은 복제본이 적은 순서로 다시 복제하는 계획, 노드가 돌아왔을 때 넘치는 복제본 지우기, 시작할 때의 안전 모드(블록 보고 비율과 연장 시간)를 다룬다.
- 난도: 단계마다 숙련 개발자 2시간 안팎. 대규모 테스트는 파일 수십만 개와 노드 수백 개다. 블록을 찾을 때 전체를 훑으면 제한 시간을 넘게 만든다.
- 함정: 할당량 계산에 복제 수를 빠뜨리는 것, 마지막 블록 크기, 같은 랙 두 복제본 규칙, 죽은 노드의 블록을 두 번 세는 것, 안전 모드 동안의 쓰기 거절, 노드가 돌아온 뒤 복제본이 넘치는 블록.
- 검증: build 스킬의 교차 검증. 배치 규칙은 HDFS Architecture 문서와 대조한다.
- 출처: HDFS Architecture, hdfs-default.xml, HDFS Quotas Guide.
- 피할 것: 실제 HDFS 의 RPC 나 파일 형식을 흉내 내는 것. 판정 시각 계산식은 명세가 직접 정의한다.
