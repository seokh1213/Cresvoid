# L-load-50 캐시와 원천의 불일치

- 모드: implement
- 난도: 어려움.
- 목표: 읽기와 쓰기가 겹칠 때 오래된 값이 캐시에 남지 않게 한다.
- 서비스: `GET /products/{id}` 와 `PUT /products/{id}/price`. 읽기 경로의 원천 조회와 캐시 쓰기 사이에 지연이 있다.
- 비울 핵심: 쓰기 경로와 읽기 경로의 일관성 전략. 버전을 붙인 조건부 캐시 쓰기(Lua), 지연 재삭제, TTL 안전망 가운데 고르거나 조합한다.
- 시나리오: 같은 상품들을 동시에 읽고 고친다. 부하가 끝난 뒤 2초 안에 모든 키의 캐시가 원천과 같거나 비어야 한다.
- 불변식: 수렴 시간 안의 캐시-원천 일치, 응답 본문 버전이 직전에 확인된 버전보다 오래된 비율 ≤ 1%.
- 문항이 노릴 것: 삭제 후 쓰기와 쓰기 후 삭제의 경합 차이, 캐시를 먼저 고칠 때의 위험, 리스로 오래된 값 기록을 막는 원리, 읽기 복제본 지연.
