# B-pipeline-70 실험 종료 뒤 운영 상태로 복구하는 도구 만들기

- 목표: 실험이 종료된 뒤, 정상 병합의 일부가 빠진 대상도 운영 원천과 다시 맞춘다. 정상 경로가 이미 복원했을 것이라는 가정에 기대지 않는다.
- 입출력 모양: 앞 카드의 명령과 출력을 유지하고 실험 비활성화, 복구 계획 생성, 계획 적용, 복구 상태 조회 명령을 더한다. 계획은 생성 당시의 두 원천 버전과 대상 키 목록을 고정한다.
- 4단계 `04-reconcile`: 실험이 한 번이라도 관리한 키 전체를 대상으로 운영 최신 상태를 적용한다. 삭제 표식이 된 실험 키도 포함한다. 운영에 살아 있으면 복원하고 없거나 삭제되어 있으면 대상에서도 삭제한다. 실험과 무관한 키는 건드리지 않는다.
- 실행 규칙: 실험이 활성화되어 있으면 계획 생성·적용을 거절한다. 적용 전 원천 버전이 달라졌으면 계획을 버리고 다시 만든다. 같은 계획의 재적용은 멱등이며, 일부 적용 뒤 중단해도 남은 키를 이어 처리할 수 있어야 한다.
- 난도: 1~3시간. 같은 트랙의 후속 단계다. 앞 단계와 달리 정상 실행 때의 증거가 빠진 상태를 고정 입력으로 제공한다.
- 함정: 삭제 표식의 키를 대상 목록에서 빼는 것, 실험 전용 키의 잔존, 대상의 옛 문서, 중간 실패, 계획 이후의 원천 변경, 무관한 키의 삭제.
- 검증: 운영 원천·실험 이력에서 직접 유도한 결과와 대조한다. 반복 적용과 모든 정해진 중단 위치에서 복구 후 결과가 같은지 확인한다. 건수뿐 아니라 키와 내용을 비교한다.
- 출처: [Event Sourcing pattern](https://learn.microsoft.com/en-us/azure/architecture/patterns/event-sourcing)의 원천을 통한 상태 재생성을 배경으로 쓴다. 실험 비활성화·계획 버전·복구 대상 규칙은 이 과제의 계약이다.
- 피할 것: 실제 운영 색인에 접근하는 복구 도구를 만드는 것. 원천과 대상은 모두 모형이며 실제 파일·데이터를 지우지 않는다.
