# B-pipeline-30 실행 증거로 연결하는 배치 단계 만들기

- 목표: 단계가 끝났다는 증거를 남기고 중간 실패에서 재개하는 작은 배치 실행기를 만든다. 입력·실행 세대·조각이 다른 완료 표식을 재사용하지 않는다.
- 입출력 모양: 실행 등록, 고정 단계 실행, 실패 주입, 재개, 전체 완료 판정 명령을 처리한다. 입력에는 세대와 입력 식별자, 예상 조각 목록을 준다. 결과물과 완료 표식은 별도 가짜 저장소에 둔다.
- 1단계 `01-markers`: 추출→변환→적재의 고정 단계를 연결한다. 결과물 기록이 끝난 뒤에만 해당 입력·세대·조각의 완료 표식을 만들고, 필요한 앞 단계 표식이 없으면 실행을 거절한다. 빈 결과도 명시적인 성공 증거를 남긴다.
- 2단계 `02-resume`: 결과물 저장 전·후와 표식 저장 전·후의 정해진 위치에 실패를 주입한다. 완료되지 않은 단계만 다시 실행하며 쓰기는 동일 실행 키로 멱등하게 한다. 입력 식별자가 바뀐 재실행은 이전 표식을 쓰지 않는다.
- 3단계 `03-seal`: 등록된 모든 조각의 필수 표식과 결과물을 확인한 뒤 세대를 닫는다. 빠진 조각과 0건 성공 조각을 구분한다. 닫힌 세대의 입력·결과 변경을 거절하고 같은 완료 판정은 반복해도 같다.
- 난도: 단계마다 1~3시간. 단계 수는 세 개로 고정하고 스케줄러나 범용 DAG 엔진은 만들지 않는다.
- 함정: 존재하는 파일만 순회한 전체 성공, 과거 세대의 표식, 동일 이름의 다른 입력, 결과물만 남은 실패, 표식만 있는 손상, 빈 조각과 누락 조각.
- 검증: 고정된 실패 위치마다 재개 후 결과가 무실패 실행과 같은지 검사한다. 결과물과 표식의 저장은 원자적이지 않다는 모형을 공개 스펙에 적는다. 숨은 실패 위치로 계약 밖의 장애를 추가하지 않는다.
- 출처: [Flink Fault Tolerance](https://nightlies.apache.org/flink/flink-docs-stable/docs/learn-flink/fault_tolerance/)의 일관된 복구 상태, [Step Functions Distributed Map](https://docs.aws.amazon.com/step-functions/latest/dg/state-map-distributed.html)의 조각별 실행과 결과 추적. 완료 표식·세대 닫기는 이 과제의 규칙이다.
- 피할 것: 실제 작업 프로세스나 클라우드 오케스트레이터 실행, 외부 부수효과의 정확히 한 번 처리를 일반적으로 보장한다고 설명하는 것.
