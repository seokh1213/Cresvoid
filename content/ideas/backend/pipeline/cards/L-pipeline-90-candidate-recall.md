# L-pipeline-90 비교 비용과 놓친 중복쌍 측정

- 모드: 시작 코드를 관찰한 뒤 구현한다.
- 실행 방식: JDK HTTP 서비스가 토큰 레코드 묶음의 중복쌍을 반환한다. Kotlin 실험기가 고정된 자료와 시드로 요청을 보내 결과·비교 횟수·응답 시간을 모은다. 외부 브로커나 Spark를 실행하지 않는다.
- 목표: 빠른 후보 분할이 없앤 비교와 놓친 중복을 함께 관찰하고, 판정 결과를 보존하는 후보 제외로 고친다. 입력 자료와 유사도·빈 집합 규칙은 B-pipeline-80과 같게 고정한다.
- 시나리오: 정확 일치가 많은 자료, 큰 범주 하나에 유사 항목이 몰린 자료, 길이 구간의 경계 양쪽에 정답 쌍이 놓인 자료를 사용한다. 같은 시드의 무작위 분할, 길이 구간, 최근 N건 제한은 비교용 실패 변형으로 두고 판정 함수는 같게 유지한다.
- 예측 문항: 비교 횟수가 줄어도 재현율이 보존되지 않는 이유, 다른 구간 사이에서 사라지는 쌍, 직접 중복쌍과 대표 그룹 수의 차이를 묻는다.
- 불변식: 작은 자료의 전수 비교를 독립 기준으로 삼아 직접 중복쌍 재현율 1과 오탐 0을 요구한다. 기준 정답 쌍이 0개인 경우의 지표는 분모 0으로 표시하고 별도 판정한다. 비교 횟수 상한은 자료별로 독립 계산하며 제작 스펙에 정확히 적는다. 모든 요청은 정상 완료해야 한다.
- 관측: p95 응답 시간과 실제 비교 횟수를 함께 표시하되 기기별 시간 배수를 합격 기준으로 쓰지 않는다. 정확 일치 처리의 생략 비용과 직접 판정 호출 횟수의 정의를 공개한다.
- 검증: 참조 풀이가 각 시나리오를 세 번 통과하고 근사 분할 변형이 정합성 불변식에서 세 번 실패하는지 확인한다. 시작 코드의 실패는 프로그램 오류나 시간 초과가 아닌 누락된 쌍으로 재현한다. 공개 스펙과 시작 코드만 본 별도 구현도 통과해야 한다.
- 출처: [Python Record Linkage Toolkit Indexing](https://recordlinkage.readthedocs.io/en/latest/ref-index.html)의 전수쌍·blocking·sorted neighbourhood. 합격에 요구하는 무손실 조건과 자료별 비교 예산은 이 실험이 정한다.
- 피할 것: 근사 손실을 허용하면서 완전한 중복 제거라고 부르는 것, 원문의 처리량 배수를 합격 기준으로 옮기는 것, 실제 운영 데이터를 쓰는 것.
