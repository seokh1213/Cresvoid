# B-pipeline-50 운영과 실험의 변경을 합치는 병합기 만들기

- 목표: 운영 원천과 실험 원천의 변경을 한 결과로 합친다. 어느 원천이 값을 제공하는지와 삭제·복원의 의미를 규칙으로 정한다.
- 입출력 모양: 원천별 키·회차·순번·내용·삭제 표식을 등록한다. 1단계의 `RESOLVE`는 두 원천의 기초 병합 후보를 조회하고, 2단계에 더하는 회차 처리 명령과 `INDEX`는 회차 우선순위를 적용한 대상 색인을 조회한다. 가짜 색인에는 키당 문서 하나 또는 삭제 표식 하나만 둔다.
- 1단계 `01-current-state`: 각 원천에서 키별 최신 상태를 고른다. 살아 있는 실험 문서가 있으면 기초 병합 후보로 사용한다. 실험이 그 키를 삭제하면 살아 있는 운영 문서로 돌아가고 운영에도 없으면 삭제 후보가 된다. `RESOLVE`는 회차별 산출이나 최종 색인 상태를 뜻하지 않는다. 동점 순번은 입력 오류로 거절한다.
- 2단계 `02-round-merge`: 별도 회차 처리 명령으로 이번 변경만 출력하고 색인에 적용한다. 같은 회차의 운영 삭제는 실험 갱신보다 우선한다. 이후 회차에서 실험이 다시 갱신한 경우의 재노출은 허용한다. 같은 키의 문서와 삭제를 같은 회차에 함께 내지 않는다. 앞 단계의 `RESOLVE` 출력은 유지한다. 이 정책은 과제가 정한 것이며 모든 실험 시스템의 기본 규칙이 아니다.
- 3단계 `03-replay`: 회차를 다시 실행해도 그 뒤 회차에서 바뀐 키는 되돌리지 않는다. 같은 회차 재적용은 결과가 같고, 오래된 출력이 뒤늦게 대상에 도착할 때도 키별 적용 회차·순번을 확인한다. 삭제의 버전 정보도 모형 안에서 유지한다.
- 난도: 단계마다 1~3시간. 작은 입력의 모든 원천 상태 조합을 직접 검사하고, 큰 입력에서는 회차마다 전체 원천을 다시 합치는 방식과 구분한다. 제한은 제작 때 정한다.
- 함정: 실험의 부재와 삭제, 운영 삭제와 실험 갱신의 충돌, 실험 전용 키의 삭제, 중복 산출, 옛 회차 재실행, 삭제 뒤의 늦은 갱신.
- 검증: 우선순위 표에서 독립 기대값을 만들고 회차 재실행·적용 순서 뒤섞기를 확인한다. 2단계 이후 대상 색인의 기준값은 초기 상태에서 같은 회차 우선순위를 적용하며 모든 회차를 순서대로 재생해 구한다. 최신 원천의 `RESOLVE` 결과를 대상 색인의 기준값으로 대신하지 않는다.
- 출처: [Elasticsearch Index API](https://www.elastic.co/docs/api/doc/elasticsearch/operation/operation-index)의 외부 버전 검사, [Event Sourcing pattern](https://learn.microsoft.com/en-us/azure/architecture/patterns/event-sourcing)의 상태 재생성. 원천 간 우선순위와 삭제 표식 보관은 이 모형의 별도 계약이다.
- 피할 것: 실제 Elasticsearch·Iceberg나 조직 고유 스키마를 요구하는 것. 기존 주문 이벤트 처리와 달리 두 원천의 충돌·복원을 중심으로 둔다.
