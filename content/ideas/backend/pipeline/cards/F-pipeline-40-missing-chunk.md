# F-pipeline-40 빠진 조각을 못 찾는 완료 판정

- 맥락: 분할 배치는 실행 전에 예상 조각 목록을 등록한다. 조각마다 성공·실패·0건 성공 상태를 남긴다. 전체 완료는 등록된 모든 조각의 같은 세대·입력에 대한 성공 증거가 있을 때만 허용한다.
- 버그 후보: 저장소에 존재하는 결과만 찾아 모두 성공인지 검사하고, 예상 목록에서 빠진 조각이 있는지 확인하지 않는 원인 하나를 심는다. 세대·입력 확인은 올바르게 둔다.
- 버그 신고: 작업자 하나가 결과를 남기기 전에 종료됐는데도 배치 전체가 성공으로 표시됐다. 결과가 0건이었던 다른 조각은 정상 완료로 인정되어야 한다.
- 형식: 150~260줄, 파일 2~4개. 실행 계획·조각 결과·완료 판정기를 분리한다. 수정은 전체 완료 조건을 고치는 몇 줄로 끝나게 한다.
- 검증: 고정 테스트 6~10개로 정상 전체 완료, 누락 조각, 실패 조각, 0건 성공, 예상 밖 조각과 빈 계획을 다룬다. 빈 계획의 성공 여부는 스펙에 정하고 표식 파일 개수만 맞추는 수정은 통과하지 못하게 한다.
- 출처: [Step Functions Distributed Map](https://docs.aws.amazon.com/step-functions/latest/dg/state-map-distributed.html)의 입력 항목과 개별 실행 추적. 과제는 실패 허용 없이 예상 목록 전체의 성공을 요구하는 별도 규칙을 쓴다.
- 피할 것: 오래된 표식의 재사용이나 실패를 성공으로 저장하는 버그를 함께 심는 것.
