# F-pipeline-20 다시 적재하지 않은 키까지 지우는 정리 작업

- 맥락: 변경 이력을 정리하는 작업이 이번 창에 바뀐 키의 전체 상태를 새 기준으로 적재했다. 바뀌지 않은 키는 이전 기준 상태만 가지고 있으므로 그 이력을 유지해야 한다. 저장소와 적재 결과는 제공한다.
- 버그 후보: 삭제할 키 집합에 확인된 재적재 키 대신 전체 저장소 키를 넘기는 원인 하나를 심는다. 기준 시각과 적재 확인 로직은 올바르게 둔다.
- 버그 신고: 정리 작업은 성공했고 최근에 바뀐 항목은 정상이지만 오래 바뀌지 않은 항목이 조회되지 않는다. 공개 재현은 바뀐 키와 바뀌지 않은 키를 포함한 작은 저장소를 보여 준다.
- 형식: 180~300줄, 파일 3~4개. 정리 계획·버전 저장소·실행기를 나누고 수정은 대상 집합을 선택하는 몇 줄로 끝나게 한다.
- 검증: 고정 테스트 6~10개로 보존 대상 키, 적재 확인이 끝난 키, 빈 변경 집합, 삭제된 필드와 반복 실행을 검사한다. 삭제 호출의 횟수보다 최종 상태와 남겨야 할 이력으로 판정한다.
- 출처: [Kafka Log Compaction](https://kafka.apache.org/42/design/design/)의 최종 상태 보존을 배경으로 쓴다. 재적재 키와 삭제 범위의 관계는 B-pipeline-10이 정한 보관 계약이다.
- 피할 것: 잘못된 기준 시각이나 일부 필드만 적재하는 버그를 함께 심는 것. 전체 상태 적재는 시작 코드에서 올바르게 제공한다.
