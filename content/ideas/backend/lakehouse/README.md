# 레이크하우스: 파일 포맷과 테이블 포맷

분산 저장소 위에서 분석용 데이터를 담는 열 지향 파일 포맷(Parquet)과 그 파일들을 테이블로 묶는 테이블 포맷(Iceberg)을 익힌다. 질의가 읽지 않아도 되는 데이터를 어떻게 건너뛰는지, 여러 작업이 같은 테이블에 동시에 쓸 때 무엇이 보장되는지 설명하는 힘을 기른다.

## 1. 개념 지도

### 1.1 Parquet

- 파일은 행 그룹으로 나뉘고 행 그룹은 열마다 열 조각을, 열 조각은 페이지를 가진다.
- 문서는 큰 행 그룹(512MB~1GB)과 8KB 페이지를 권한다. 큰 행 그룹은 큰 열 조각과 순차 입출력을 주고 작은 페이지는 행 하나를 찾을 때처럼 잘게 읽기 좋다. 구현의 기본값은 문서 권장값과 다를 수 있으므로 카드를 만들 때 쓰는 라이브러리의 기본값을 확인한다.
- 행 그룹마다 열의 최솟값과 최댓값 통계가 있다. 술어 푸시다운은 이 통계로 읽을 필요 없는 행 그룹을 건너뛴다.
- 페이지 인덱스(ColumnIndex, OffsetIndex)는 페이지마다 최솟값과 최댓값, 페이지 위치를 푸터 근처에 따로 둔다. 페이지 머리를 모두 읽지 않고 맞는 페이지로 바로 간다. 정렬된 열이면 이진 탐색으로 찾고 행 하나를 찾을 때 열마다 페이지 하나만 읽는다.
- 사전 부호화, 런 길이 부호화와 비트 패킹 혼합, 델타 부호화로 열 값을 줄인다. 정렬과 클러스터링은 압축률과 건너뛰기 효과를 함께 높인다.
- 중첩 데이터는 Dremel 의 반복 수준과 정의 수준으로 평평한 열에 담는다.

### 1.2 Iceberg

- 테이블 상태는 메타데이터 파일에 있다. 메타데이터 파일은 스키마, 파티션 설정, 속성, 스냅숏 목록을 가진다. 스냅숏은 매니페스트 목록을, 매니페스트 목록은 매니페스트를, 매니페스트는 데이터 파일과 파티션 값과 통계를 가리킨다.
- 바뀐 내용은 새 메타데이터 파일로 만들고 메타데이터 파일 하나를 다른 하나로 원자적으로 바꿔 커밋한다. 이 교체가 직렬화 격리의 바탕이다. 읽는 쪽은 테이블을 불러온 때의 스냅숏을 쓰고 새로 고칠 때까지 바뀐 내용을 보지 않는다.
- 쓰는 쪽은 낙관적으로 새 메타데이터를 만든다. 기준 스냅숏이 이미 현재가 아니면 새 현재 버전을 기준으로 다시 시도한다.
- 파티션 변환은 identity, bucket[N], truncate[W], year, month, day, hour 다. 질의는 파티션 값이 아니라 데이터 값의 술어로 계획하고(숨은 파티셔닝) 파티션 방식은 나중에 바꿀 수 있다(파티션 진화).
- 데이터 파일의 열은 이름이 아니라 필드 ID 로 고른다. 그래서 열 이름과 순서를 바꿔도 옛 파일을 바르게 읽는다.
- 판 2는 행 단위 삭제를 더했다. 위치 삭제는 데이터 파일 경로와 행 위치로, 동등 삭제는 열 값(예: id = 5)으로 행을 지운다. 판 3은 위치 삭제를 이진 삭제 벡터로 담고 새 자료형을 더했다. 판 4는 개발 중이고 새 동등 삭제를 쓰지 못하게 한다.
- 작은 파일 압축, 스냅숏 만료, 고아 파일 지우기 같은 유지 작업이 필요하다.

### 1.3 디렉터리 테이블과의 비교

- 디렉터리 경로로 파티션을 나타내는 테이블은 파일 목록을 얻으려고 디렉터리를 훑어야 하고 여러 파티션에 걸친 쓰기를 한 번에 커밋하지 못한다. 카드를 만들 때 이 비교는 Iceberg 문서의 설명으로 확인한다.

## 2. 학습 경로

1. R-lakehouse-10 기술 지문으로 테이블 포맷의 메타데이터 계층과 커밋 규칙을 익힌다.
2. B-lakehouse-20 `columnar` 트랙에서 열 지향 파일의 부호화와 통계 기반 건너뛰기를 구현한다.
3. B-lakehouse-30 `table-format` 트랙에서 스냅숏, 낙관적 커밋, 행 단위 삭제를 구현한다.

## 3. 환경

모든 카드가 추가 도구 없이 표준 라이브러리로 만든다. 실제 Parquet 이나 Iceberg 라이브러리는 쓰지 않고 명세가 정한 단순한 형식을 쓴다.

## 4. 아이디어

| 아이디어 | 종류 | 메모 |
|---|---|---|
| ORC 와 Parquet 비교 | reading | 스트라이프, 인덱스 간격, 블룸 필터 |
| Z-order 와 클러스터링 | build 단계 | 두 열 술어에서 건너뛰는 행 그룹 수 |
| 블룸 필터 | build 단계 | 같음 술어의 건너뛰기, 거짓 양성률 |
| 스키마 진화의 함정 | code | 이름으로 열을 고르는 포맷과 ID 로 고르는 포맷의 차이 |
