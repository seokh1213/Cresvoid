# B-lakehouse-30 테이블 포맷 만들기

- 목표: 스냅숏과 매니페스트로 테이블을 관리하고 낙관적 커밋과 행 단위 삭제를 구현한다.
- 입출력 모양: 테이블 만들기, 데이터 파일 더하기(파티션 값, 행 수, 통계), 커밋 시작과 커밋, 스냅숏 지정 조회(시간 여행), 삭제, 압축, 스냅숏 만료 명령이다. 저장소는 메모리 안의 가짜 객체 저장소이고 메타데이터 위치 교체만 원자적이다.
- 1단계 `01-snapshots`: 메타데이터 파일, 스냅숏, 매니페스트 목록, 매니페스트를 만들고 현재 스냅숏과 과거 스냅숏을 조회한다. 숨은 파티셔닝(day, bucket[N])으로 술어에 맞는 파일만 고른다.
- 2단계 `02-commits`: 두 작업이 같은 기준에서 시작한 뒤 커밋할 때의 충돌 판정과 재시도. 덧붙이기끼리는 다시 적용으로 성공하고 같은 파일을 지우고 바꾸는 작업끼리는 실패하는 규칙을 명세로 정한다. 스냅숏 만료 뒤 남는 파일과 고아 파일.
- 3단계 `03-deletes`: 위치 삭제와 동등 삭제를 읽을 때 적용하는 순서(순번 규칙), 압축으로 삭제를 데이터 파일에 반영하기.
- 난도: 단계마다 2~3시간.
- 함정: 시간 여행 조회가 만료된 스냅숏을 가리킬 때, 같은 순번의 동등 삭제가 같은 커밋의 데이터에 적용되는지, 재시도할 때 기준 스냅숏을 바꾸지 않는 실수.
- 검증: build 스킬의 교차 검증. 커밋 규칙은 Iceberg Table Spec 과 대조하되 명세가 단순화한 부분을 스펙에 밝힌다.
- 출처: Iceberg Table Spec.
- 피할 것: Iceberg 의 실제 JSON·Avro 메타데이터 형식을 요구하는 것.
