# B-system-design-20 처리율 제한기 만들기

- 목표: 처리율 제한 알고리즘을 가상 시계 위에서 구현하고 정확도와 메모리, 분산 환경의 경합을 비교한다.
- 1단계 `01-buckets`: 토큰 버킷(용량, 채우는 속도, 순간 폭주 허용)과 새는 버킷(대기열 길이, 내보내는 속도). 요청마다 허용·거절과 남은 토큰을 출력한다.
- 2단계 `02-windows`: 고정 창(경계에서 두 배 폭주), 요청 시각 기록 방식(정확하지만 메모리가 큼), 미끄러지는 창 근사(Cloudflare 공식: 이전 창 개수 × 남은 비율 + 현재 창 개수). 같은 요청열을 세 방식으로 판정한 결과와 정확한 방식과의 차이를 출력한다.
- 3단계 `03-distributed`: 게이트웨이 여러 대가 지연이 있는 공유 저장소의 카운터를 쓴다. 읽고 쓰는 사이의 경합, 원자적 증가, 로컬 사본과 동기화 주기, 저장소 장애 때 허용(fail open), 요청 등급별로 먼저 버리는 순서(Stripe 의 부하 차단).
- 난도: 단계마다 2시간 안팎. 대규모 테스트는 사용자 수십만 명이다. 사용자마다 시각 목록을 들고 있으면 메모리 한도를 넘게 만든다.
- 함정: 토큰 계산의 소수점 처리, 창 경계 시각의 포함 여부, 시계가 뒤로 가는 입력, 근사 공식의 반올림.
- 검증: build 스킬의 교차 검증. 2단계는 정확한 방식의 결과와 비교해 근사 오차를 확인한다.
- 출처: 이 도메인 README 의 '빅테크 공개 사례' 절의 Stripe, Cloudflare 글.
- 피할 것: Redis 같은 실제 저장소를 요구하는 것. 실제 Redis 실험은 load L-load-90 에서 한다.
