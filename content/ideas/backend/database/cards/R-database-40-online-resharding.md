# R-database-40 서비스를 멈추지 않는 데이터 이전과 샤딩

- 분야: 기술(데이터베이스)
- 목표: 운영 중인 서비스의 데이터를 새 테이블이나 새 샤드로 옮길 때 단계의 순서와 단계마다 둔 확인 장치가 왜 필요한지 설명하고 새 이전 계획의 빈틈을 찾는다.
- 다룰 내용: 이중 쓰기, 읽기 경로 전환, 쓰기 경로 전환, 옛 데이터 제거의 순서, 과거 데이터 채우기, 두 경로의 결과 비교, 변경 기록을 따라잡는 방식, 논리 샤드와 물리 샤드를 나누는 이유, 같은 샤드 키를 쓰는 테이블 묶음, 질의를 샤드로 보내는 프록시, 짧은 전환 시간.
- 난도: LEET 언어이해 수준.
- 형식: 2,900~3,300자, 7~8문단, 6문항. `<보기>` 는 다른 서비스의 이전 계획 하나를 단계별로 주고 데이터를 잃거나 어긋나게 하는 단계를 고르게 한다.
- 함정과 엣지 케이스: 읽기 경로보다 쓰기 경로를 먼저 바꾸면 생기는 일, 이중 쓰기에서 한쪽만 실패하는 경우, 채우기와 새 쓰기가 같은 행에서 겹치는 경우, 논리 샤드 수를 물리 서버 수와 같게 두면 나중에 생기는 일.
- 검증: 사실은 각 회사 글로 확인한다. 단계 순서 문항은 작은 시뮬레이션 표로 확인한다.

- 피할 것: 회사별 도구 이름을 외워야 풀리는 문항.
