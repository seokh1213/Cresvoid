# B-design-patterns-80 되돌리기를 지원하는 문서 편집기 만들기

- 목표: 편집 요청을 커맨드 객체로 만들어 되돌리기와 다시 실행, 묶음 실행(컴포지트), 저장 지점(메멘토)을 차례로 구현하며 각 패턴이 푸는 문제를 직접 겪는다.
- 입출력 모양: 표준 입력의 명령(`INSERT pos text`, `DELETE pos len`, `UNDO`, `REDO`, `BEGIN`, `END`, `SAVE name`, `RESTORE name`, `PRINT from len`)을 한 줄씩 처리하고 결과나 오류를 출력한다. 위치는 유니코드 코드 포인트 단위로 센다. 범위를 벗어난 편집은 문서를 바꾸지 않고 오류를 출력한다.
- 1단계 `01-edit`: 삽입, 삭제, 구간 출력과 범위 오류. 긴 문서에서 많은 편집을 처리해도 제한 시간 안에 끝나야 한다.
- 2단계 `02-undo`: 모든 편집을 커맨드로 만들고 되돌리기와 다시 실행을 지원한다. 새 편집은 다시 실행 기록을 버린다. 기록이 상한 N을 넘으면 가장 오래된 기록부터 버린다. 실패한 편집은 기록에 남기지 않는다.
- 3단계 `03-macro`: `BEGIN`과 `END` 사이의 편집을 묶음 하나로 실행하고 되돌린다. 묶음은 중첩할 수 있다(컴포지트). 묶음 안에서 편집이 실패하면 그 묶음에서 이미 한 편집을 모두 되돌린다. 기록 상한은 바깥 묶음 하나를 기록 하나로 센다.
- 4단계 `04-snapshot`: `SAVE`로 저장 지점을 만들고 `RESTORE`로 돌아간다. `RESTORE`도 되돌릴 수 있는 편집이다. 저장 지점마다 문서 전체를 복사하면 메모리 한도를 넘게 만든다.
- 난도: 단계마다 1~2시간.
- 함정: 되돌린 뒤의 새 편집, 묶음 안 실패의 원자성, 빈 묶음과 닫히지 않은 묶음, 기록 상한에서 묶음을 세는 단위, `RESTORE` 뒤의 `UNDO`, 코드 포인트와 `Char` 위치의 차이.
- 검증: build 스킬의 교차 검증. 명령마다 문서 전체를 복사해 기록하는 단순 구현과 작은 입력에서 출력을 비교한다. 대규모 테스트는 문서 길이 10^6, 명령 10^5개로 전체 복사 방식이 시간이나 메모리 한도를 넘게 만든다.
- 출처: GoF(Command, Composite, Memento). 이 도메인 README의 '출처' 절.
- 피할 것: 파일 저장, 커서와 선택 영역 같은 화면 개념, 여러 사용자의 동시 편집(CRDT는 distributed 도메인이 다룬다).
