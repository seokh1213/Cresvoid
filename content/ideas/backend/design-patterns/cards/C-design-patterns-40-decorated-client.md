# C-design-patterns-40 겹겹이 감싼 상품 조회 클라이언트

- 도메인: 상품 정보를 외부 저장소에서 읽는 클라이언트. 인터페이스 하나를 캐시, 호출 기록, 실패 재시도 데코레이터가 겹겹이 감싼다. 일부 데코레이터는 클래스 위임(`by`)으로 만든다. 조회 요청은 입력 명령으로 주고 각 계층의 호출 횟수와 결과를 출력한다. 가짜 저장소는 입력 명령으로 실패와 `null` 결과를 흉내 낸다. 인터페이스, 데코레이터, 조립, 명령 처리를 파일로 나눈다.
- 겨냥: 데코레이터를 쌓는 순서에 따라 바뀌는 원본 호출 횟수(캐시가 재시도의 안쪽이냐 바깥쪽이냐), 클래스 위임에서 대상 내부의 자기 호출(`getMany`가 안에서 `get`을 부르면 캐시 데코레이터를 거치지 않는다), 위임 클래스가 일부 메서드만 재정의했을 때 나머지 메서드의 경로, `getOrPut`은 저장된 값이 `null`이면 없는 것으로 보고 다시 계산한다, 실패한 결과를 캐시하지 않는 조건.
- 형식: 220~320줄, 파일 3~4개, 5문항(실행 결과 예측 short 2, choice 3), 목표 25분.
- 난도: 세 계층의 호출 순서를 머릿속에서 펼쳐야 하는 문항이 둘 이상이다.
- 검증: 실행으로 확인한다. `getOrPut`과 클래스 위임의 동작은 짧은 스크립트로 따로 확인한다.
- 출처: [Kotlin 문서: Delegation](https://kotlinlang.org/docs/delegation.html), Kotlin 표준 라이브러리 문서의 `getOrPut`. 이 도메인 README의 '출처' 절.
- 피할 것: 실제 네트워크와 시간 대기, C-kotlin-50의 백오프 계산(여기서는 재시도 횟수만 센다), C-kotlin-40의 LRU 축출 규칙.
