# C-design-patterns-50 주문 상태 객체와 구독자 알림

- 도메인: 주문 상태(생성, 결제, 배송, 취소)를 상태 객체로 나누고 상태가 바뀔 때마다 구독자에게 알린다. 다음 상태는 상태 객체가 정한다. 구독자 가운데 하나는 알림을 받으면 다른 상태 전이를 요청하고(재진입), 다른 하나는 첫 알림 뒤 스스로 구독을 해제한다. 전이 요청은 입력 명령으로 주고 알림 기록을 출력한다. 상태, 구독 관리, 조립, 명령 처리를 파일로 나눈다.
- 겨냥: 알림 도중의 재진입 전이가 만드는 알림 순서(바깥 알림이 모든 구독자에게 가기 전에 안쪽 알림이 먼저 나간다), 알림 중 구독 해제에 대비해 목록 사본을 순회하면 해제한 구독자도 이번 알림은 받는다는 점, `LinkedHashSet`에 담은 구독자의 순서와 같은 구독자를 두 번 등록했을 때, 상태 객체를 `object`로 만들어 상태별 데이터를 담지 못하는 설계와 그 결과, 허용되지 않은 전이를 무시할지 예외로 볼지에 따른 출력 차이.
- 형식: 250~350줄, 파일 3~5개, 5문항(실행 결과 예측 short 2, choice 3), 목표 25분.
- 난도: 재진입으로 겹친 알림의 순서를 끝까지 추적해야 한다.
- 검증: 실행으로 확인한다.
- 출처: GoF(State, Observer). 이 도메인 README의 '출처' 절.
- 피할 것: C-kotlin-30이 다루는 sealed 상태 전이 규칙, 이벤트 중복 제거, `Sequence`의 지연 평가. 스레드 동시성.
