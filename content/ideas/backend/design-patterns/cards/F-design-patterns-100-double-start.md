# F-design-patterns-100 두 번 시작되는 정산 작업

- 맥락: 하루 한 번 실행하는 정산 작업을 스케줄러 여러 대가 같은 시각에 시작하라고 요청한다. 작업 객체는 이미 실행 중이면 요청을 거부(balking)해야 한다. 실행 상태는 상태 저장소 인터페이스 뒤에 있다.
- 버그 후보: 실행 중인지 읽는 것과 실행 중으로 표시하는 것이 원자적이지 않아 두 요청이 모두 통과한다(먼저 고른다). 상태 필드에 `@Volatile`만 붙여 막으려 한 코드.
- 버그 신고: "정산 결과가 가끔 두 번 반영된다. 스케줄러 두 대가 같은 시각에 깨어난 날과 겹친다."
- 형식: 180~260줄, 파일 3~4개.
- 난도: `@Volatile`은 가시성만 보장하고 검사와 갱신을 하나로 묶어 주지 않는다는 점을 알아야 한다.
- 검증: 숨은 테스트는 상태 저장소의 읽기 직후에 멈추는 시험용 지점을 써서 두 요청이 모두 검사를 통과한 뒤 갱신하는 순서를 결정적으로 만든다. 고친 코드가 그 지점을 거치지 않아도 테스트가 멈추지 않게 대기에 상한을 둔다. `compareAndSet`, 잠금, 저장소의 조건부 갱신으로 고친 수정이 모두 통과해야 한다.
- 출처: Goetz 외 "Java Concurrency in Practice" 2장(경쟁 조건, 검사 후 행동), Lea "Concurrent Programming in Java" 2판(balking).
- 피할 것: `sleep`으로 순서를 맞추는 테스트, 분산 잠금(distributed 도메인의 만료 잠금 카드가 다룬다).
