# F-search-70 대체 배치 경로의 노출 상한 누락

- 맥락: 결과 배치 서비스는 최적화기가 실패하면 간단한 탐욕 배치로 응답한다. 입력 명령이 최적화기의 성공·실패를 결정하므로 실제 시간 제한 없이 두 경로를 재현한다. 대체 경로는 최적 점수를 보장하지 않아도 되지만 노출 상한·순서·중복 금지 같은 필수 규칙은 지켜야 한다.
- 버그 후보: 대체 경로에서 추천 항목 수의 상한 검사를 빠뜨리는 원인 하나를 심는다. 최적화 경로와 나머지 제약 검사, 입력 검증은 올바르게 둔다.
- 버그 신고: "같은 후보와 노출 상한으로 요청했는데 최적화기가 실패한 응답에서만 추천 항목 수가 상한을 넘었다. 실패하지 않은 요청은 상한을 지켰다."
- 형식: Kotlin 180~300줄, 파일 3~4개. 수정은 몇 줄로 끝나고 스펙은 필수 규칙과 최적 점수 목표를 분리한다. 가능한 응답이 없을 때의 실패 동작도 공개한다.
- 난도: 대체 경로에서만 나타나는 증상을 추적한다. 상한 0·경계 일치·추천 후보 부족과 일반 후보 부족을 구분한다.
- 검증: 고정 테스트 6~10개로 정상 최적화 경로를 보존하면서 대체 경로의 필수 규칙을 확인한다. 대체 경로의 후보 순회·동점 규칙을 스펙에 정하고 그 규칙에서 기대 출력을 유도한다. 최적 점수는 요구하지 않으며 수정 코드의 구조나 자료구조를 제한하지 않는다.
- 출처: [Google OR-Tools의 배정 문제 예제](https://developers.google.com/optimization/assignment/assignment_example)의 목적값과 제약 구분. 대체 경로와 노출 정책은 과제의 제품 규칙이다.
- 피할 것: 대체 경로에 서로 다른 제약 버그를 여러 개 심는 것, 요청을 전부 실패시키면 통과하는 검사, 실제 벽시계 시간에 따라 최적화 실패 여부를 바꾸는 것.
