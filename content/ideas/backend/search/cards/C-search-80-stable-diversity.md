# C-search-80 재조회해도 유지되는 추천 다양성

- 도메인: 추천 결과의 품질 하한을 지키면서 세션과 페이지에 따라 후보를 섞는 모듈이다. 입력으로 세션 ID·페이지 번호·후보 ID와 정수 점수를 받고 선택된 ID 순서를 출력한다. 시드 생성, 후보 정렬과 필터, 추첨, 명령 처리로 나눈다.
- 겨냥: 난수 생성기를 요청마다 같은 시드로 새로 만드는지 공유하는지, 동일 시드라도 후보 순서와 난수 호출 횟수가 다르면 결과가 달라지는 이유, 필터와 추첨의 순서, 정수 품질 하한의 경계와 안정적인 동점 정렬. 시드 생성 규칙과 추첨 API는 안내 문서와 코드에 공개한다.
- 형식: Kotlin 200~320줄, 파일 3~4개, 5~6문항. short는 2개 이상이고 재조회와 후보 입력 순서 변경의 실제 출력을 예측하게 한다. 나머지는 시드 범위·필터 위치 변경의 영향을 묻는다. 목표 25~30분이다.
- 난도: 같은 세션·페이지·후보 집합의 재조회는 같은 결과를 내는 계약이다. 다른 세션이나 페이지가 반드시 다른 순서를 낸다고 가정하지 않는다. 후보 집합이 달라지면 같은 시드라도 결과가 바뀔 수 있다.
- 검증: code 스킬의 실행 전 블라인드 풀이와 실행 후 확인을 따른다. 모든 short 답과 품질 하한·재현성 주장을 실행으로 검증한다. 해시 순회 순서와 실제 시각을 결과의 근거로 쓰지 않는다.
- 출처: [Java SE 21 Random](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/Random.html)의 동일 시드와 동일 호출 순서. 이 카드는 `java.util.Random`을 사용하며 세션별 시드·품질 하한·추첨 방식은 과제에서 정한다.
- 피할 것: 무작위 출력의 통계 분포만으로 정답을 판정하는 문항, 난수 구현의 내부 비트 계산을 외워야 하는 문항, 단일 후보에서도 반드시 결과가 바뀐다는 주장. 동일 입력의 재현성을 보안용 난수의 안전성과 혼동하지 않는다.
