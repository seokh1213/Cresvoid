# R-search-10 거의 실시간 검색과 내구성

- 분야: 기술(검색 엔진)
- 목표: 색인한 문서가 검색에 보이는 시점과 장애 뒤에도 남는 시점이 왜 다른지 설명하고 사건 시간표에 적용한다.
- 다룰 내용: 역색인 세그먼트가 바뀌지 않는다는 성질, 메모리 버퍼와 refresh 로 새 세그먼트를 여는 과정, refresh 가 Lucene 커밋보다 가벼운 이유, 검색이 없던 샤드의 refresh 생략, 삭제가 표시로 남고 병합 때 사라지는 과정, translog 가 커밋 전 연산을 지키는 방식, 내구성 request 와 async 의 차이, flush 가 하는 일.
- 난도: 수능 기술 지문 최고난도.
- 형식: 2,800~3,200자, 7~8문단, 6문항. `<보기>` 하나는 색인, 삭제, refresh, 검색, 장애, 재시작이 섞인 시간표를 주고 시점마다 검색 결과와 재시작 뒤 남는 문서를 묻는다. 다른 하나는 내구성 설정이 다른 두 색인에서 같은 장애가 났을 때의 차이를 묻는다.
- 함정과 엣지 케이스: refresh 와 flush 를 같은 것으로 본 선지, 검색에 보이면 장애 뒤에도 남는다고 본 선지, 삭제 즉시 디스크 공간이 준다고 본 선지, 검색이 없던 샤드에서 1초가 지나도 안 보이는 경우.
- 검증: Elastic 문서의 Near real-time search, Translog settings 와 대조한다. `<보기>` 의 시간표는 Kotlin 스크립트로 시뮬레이션해 확인한다.
- 출처: 이 도메인 README 의 '거의 실시간 검색과 내구성' 절의 문서들.
- 피할 것: 버전마다 바뀌는 기본값을 정답 근거로 삼는 것. 필요한 값은 지문에서 준다.
