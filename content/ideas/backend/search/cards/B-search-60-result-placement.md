# B-search-60 제약을 만족하는 검색 결과 배치기 만들기

- 목표: 일반 결과와 추천 결과의 후보열을 페이지의 칸에 배치한다. 후보열의 순서와 앞부분 사용 규칙을 지키면서 칸별 점수 합이 최대인 결과를 구하고, 뒤 단계에서 노출 제약과 중복 제한을 더한다.
- 입출력 모양: 입력으로 후보의 ID·종류·정수 점수와 칸별 가중치, 배치 규칙을 받는다. `PLAN`은 배치와 총점을 출력하고 불가능하면 `NO_PLAN`을 낸다. 점수 동률은 종류·후보 ID·빈칸의 비교 순서를 명세해 하나의 결과로 정한다. 입력 크기와 곱셈·합계 범위도 스펙에서 정한다.
- 1단계 `01-ordered`: 각 후보열은 앞에서부터 사용하고 선택한 후보의 원래 순서를 지킨다. 비어 있는 칸의 허용 여부와 점수 계산을 정의한 작은 입력에서 최적 배치를 구현한다.
- 2단계 `02-constraints`: 별도 `PLAN_CONSTRAINED` 명령으로 추천 노출 상한, 추천 사이 최소 간격, 첫 추천의 최소 위치와 같은 ID의 중복 노출 금지를 더한다. 제약은 모두 필수이며 만족 가능한 배치가 없으면 실패를 명시한다. 앞 단계 명령의 규칙과 출력은 유지한다.
- 3단계 `03-exact-search`: `PLAN_LARGE`로 더 큰 입력 범위를 추가한다. 상태를 공유하거나 탐색을 줄여 정확한 최적 배치를 구하되, 작은 입력은 2단계와 같은 결과를 내야 한다. 입력 크기와 제한 시간을 별도로 정해 단순 전수 탐색만으로는 마지막 테스트를 통과하지 못하게 한다.
- 난도: 단계마다 1~3시간. 배경에 후보열의 상태와 제약을 설명하되 완성된 상태 전이식이나 자료구조 선택을 지시하지 않는다.
- 함정: 후보열 중간 항목만 고르기, 중복 ID가 다른 종류에 걸쳐 나타나는 경우, 추천 후보 부족, 제약 경계, 최적 점수와 동점 규칙의 불일치, 필수 제약을 암묵적으로 완화하는 경우.
- 검증: build 스킬의 교차 검증을 따른다. 단계마다 고정 10~14개와 생성 2~3개를 둔다. 작은 입력의 기대값은 독립 전수 열거로 계산하고, 큰 입력에는 최적 점수와 필수 제약을 함께 검사할 수 있는 사례를 둔다.
- 출처: [Google OR-Tools의 배정 문제 예제](https://developers.google.com/optimization/assignment/assignment_example). 비용과 제약을 구분하는 배경으로 쓰며 후보열의 prefix·간격·동점 규칙은 이 과제에서 따로 정한다.
- 피할 것: 외부 ILP·최적화 라이브러리 의존성, 실제 검색엔진 실행, 단순 점수 내림차순 정렬을 최적화 문제와 같다고 설명하는 것. 원문 사례의 성능 배수나 구현을 합격 기준으로 쓰지 않는다.
