# lab 종류와 확장 메모

현재 lab 계약은 [content/FORMAT.md](../../FORMAT.md)에 있다. `coroutine-lab/01-dispatcher-starvation`이 첫 단계다. 이 문서는 아직 만들지 않은 lab의 환경 후보만 남긴다.

## 현재 구현

- 단계마다 `spec.md`, `starter/`, `hidden/quiz.json`, `hidden/lab.json`, `hidden/experiment.main.kts`, `hidden/solution/`, 선택한 `hidden/variants/`를 둔다.
- 실험 스크립트가 서비스의 시작과 종료, 부하, 통계 판정을 맡는다. 엔진은 풀이를 빌드하고 스크립트를 제한 시간 안에 실행한 뒤 집계 지표만 표시한다.
- 검증은 참조 풀이가 3회 통과하고 시작 코드와 실패 변형이 각각 3회 모두 불변식에서 실패하는지 확인한다. 실험 실행 오류는 실패 변형의 성공적인 판별로 취급하지 않는다.
- 첫 코루틴 실험은 JDK HTTP 서버와 클라이언트만으로 개방형 도착률 부하를 만든다. 이미 승인된 kotlinx.coroutines jar 외에 새 의존성은 없다.

## 확장할 때 정할 것

Redis, 데이터베이스, Kafka, Elasticsearch 같은 외부 서비스가 필요한 lab은 의존 서비스의 시작·준비 확인·종료 계약을 별도로 정해야 한다. 현재 엔진의 `lab.json`에는 의존 서비스나 k6 스크립트 필드가 없다. 실험 스크립트 안에서 직접 다룰 수 없는 경우 FORMAT과 엔진을 함께 확장한다.

## 도메인 lab 의 의존 서비스

Spark는 `spark-sql`과 `spark-submit`을 실행할 환경을 먼저 정한다. 검색·메시징·데이터베이스 lab은 각 서비스의 버전, 준비 확인 방법, 정리 방법을 실험별로 정한다. 현재 엔진은 이 서비스들을 자동으로 띄우지 않는다.

k6가 필요한 실험은 도구 설치 승인을 받은 뒤 재현 가능한 버전과 실행 환경을 기록한다. 부하 모델은 서비스가 느려져도 요청 도착률이 함께 줄지 않는 개방형 모델을 우선 검토한다. 시간 임계값은 실습 기기에서 참조 풀이와 실패 변형을 반복 측정해 정한다. Redis나 Docker가 필요한 카드도 같은 방식으로 환경을 먼저 확정한다.
