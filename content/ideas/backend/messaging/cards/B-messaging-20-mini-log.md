# B-messaging-20 파티션 로그와 컨슈머 그룹 만들기

- 목표: 파티션 로그, 멱등 프로듀서, 컨슈머 그룹 재조정, 로그 압축을 시각이 입력으로 움직이는 시뮬레이터로 만든다.
- 1단계 `01-partitions`: 토픽과 파티션, 키 해시로 파티션 고르기(명세가 정한 해시), 키 없는 메시지의 배정 규칙, 오프셋, 읽기, 시간과 크기 기준 보관.
- 2단계 `02-idempotence`: 프로듀서 ID 와 파티션별 시퀀스 번호, 중복 재시도 거르기, 시퀀스가 건너뛴 요청 거절, 프로듀서 재시작 뒤의 새 ID.
- 3단계 `03-groups`: 컨슈머 그룹, 배정 전략 두 가지(범위, 순환)를 명세가 정한 대로, 가입·탈퇴·시간 초과에 따른 재조정, 커밋한 오프셋에서 다시 읽기, 처리 뒤 커밋과 처리 전 커밋의 차이가 출력으로 드러나는 장애 시나리오.
- 4단계 `04-compaction`: 키별 최신 값 남기기, 툼스톤 보관 시간, 더러운 비율 기준 압축 시점, 압축 중인 세그먼트와 활성 세그먼트의 구분.
- 난도: 단계마다 2시간 안팎. 대규모 테스트는 메시지 수백만 개다.
- 함정: 음수 해시, 파티션 수가 바뀐 뒤의 배정, 재조정 중의 커밋, 툼스톤과 보관 기간의 관계, 압축 뒤 오프셋이 비는 점.
- 검증: build 스킬의 교차 검증.
- 출처: Kafka 문서의 Design 장(로그, 복제, 압축)과 Consumer Configs.
- 피할 것: Kafka 의 실제 프로토콜이나 디스크 형식을 요구하는 것.
