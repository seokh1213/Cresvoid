# B-ai-agent-40 MCP 서버 만들기

- 목표: 표준 입출력으로 JSON-RPC 2.0 메시지를 주고받는 MCP 서버를 명세 원문을 읽고 만든다. 긴 기술 명세를 정확히 읽는 훈련을 겸한다.
- 입출력 모양: 테스트가 클라이언트 역할로 요청을 한 줄에 하나씩 보낸다. 서버는 응답을 한 줄에 하나씩 쓴다. 상품 조회 같은 가짜 도메인 도구와 리소스를 서버에 둔다.
- 판 고정: 스펙 작성 때 MCP 판을 하나 고정한다(카드 작성 시점 최신판은 2026-07-28). 그 판의 schema.ts 를 근거로 쓰고 스펙의 번호 문단에 필요한 규칙을 옮겨 쓴다.
- 1단계 `01-tools`: 요청과 응답과 알림의 구분, id 규칙, 요청마다 `_meta` 의 프로토콜 버전과 클라이언트 기능 확인, 도구 목록과 도구 호출, 도구 실행 오류와 프로토콜 오류의 구분.
- 2단계 `02-resources-prompts`: 리소스 목록과 읽기, 프롬프트 목록과 가져오기, 목록의 페이지 나누기.
- 3단계 `03-errors-and-versions`: 잘못된 JSON, 모르는 메서드, 빠진 필수 필드, 지원하지 않는 프로토콜 버전, 클라이언트가 밝히지 않은 기능이 필요한 요청의 오류 코드와 응답.
- 난도: 단계마다 2~3시간. JSON 을 직접 다뤄야 한다. 시작 코드에 JSON 읽기·쓰기를 넣을지 스펙 작성 때 정한다.
- 함정: 알림에 응답하는 실수, id 가 문자열인 요청, 결과의 resultType 누락, 도구 실패를 프로토콜 오류로 돌려주는 실수, 줄바꿈이 들어간 JSON 출력.
- 검증: build 스킬의 교차 검증. 오류 코드와 필드 이름은 고정한 판의 명세와 대조한다.
- 출처: MCP Specification(고정한 판)과 schema.ts, JSON-RPC 2.0 Specification.
- 피할 것: 판을 고정하지 않고 쓰는 것. 규약이 판마다 크게 바뀐다.
