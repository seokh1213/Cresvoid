# B-ai-agent-30 검색 증강 파이프라인 만들기

- 목표: 문서 청크 나누기, 낱말 검색과 벡터 검색, 결과 결합, 검색 품질 평가를 만든다. 임베딩은 입력으로 주어 모델 없이 결정적으로 채점한다.
- 입출력 모양: 문서 적재, 청크 설정, 청크 임베딩 적재(벡터), 질의(낱말, 질의 벡터, k), 정답 집합 적재, 평가 명령이다.
- 1단계 `01-chunking`: 글자 수 기준 청크와 겹침, 문장 경계를 지키는 규칙, 제목을 청크 앞에 붙이는 문맥 규칙. 청크 경계는 명세가 문장 부호와 공백 규칙으로 정한다.
- 2단계 `02-retrieval`: 청크 단위 BM25 와 코사인 유사도 검색, 동점 규칙, 0 벡터 처리.
- 3단계 `03-hybrid`: RRF(점수 = Σ 1/(k + 순위), k 는 인자이고 기본 60)로 두 결과 합치기, MMR 로 비슷한 청크를 덜어 다양성 맞추기, 같은 문서의 청크를 묶는 규칙.
- 4단계 `04-eval`: 질의별 recall@k, MRR, nDCG@k(이득과 할인 정의는 명세가 정함)와 전체 평균. 청크 설정을 바꿔 가며 지표를 비교하는 명령.
- 난도: 단계마다 2시간 안팎. 대규모 테스트는 청크 수만 개다. 질의마다 모든 청크와 거리를 재면 제한 시간을 넘게 만들지는 않는다. 정확도가 목표인 트랙이다.
- 함정: 겹침이 청크보다 클 때, 순위가 없는 결과의 RRF 기여, 동점 순위, 정답이 없는 질의의 지표, 부동소수 합의 순서.
- 검증: build 스킬의 교차 검증. 지표 계산은 작은 예를 손으로 계산해 대조한다.
- 출처: Cormack 외 SIGIR 2009, Introducing Contextual Retrieval, search-engine 트랙 02-ranking 스펙(BM25).
- 피할 것: 실제 임베딩 모델을 부르는 것. 벡터는 생성기가 만든다.
