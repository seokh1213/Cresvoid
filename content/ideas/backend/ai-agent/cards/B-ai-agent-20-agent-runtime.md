# B-ai-agent-20 에이전트 실행기 만들기

- 목표: 모델 호출, 도구 실행, 결과 전달을 되풀이하는 에이전트 실행기를 만든다. 모델은 테스트 입력에 든 각본이 대신하므로 출력이 결정적이다.
- 입출력 모양: 도구 정의, 도구의 가짜 동작(입력별 결과, 실패, 걸리는 시간), 모델 각본(차례마다 내놓을 텍스트와 도구 사용 블록), 사용자 요청 명령이다. 실행기는 매 차례 모델에 보낼 메시지 기록과 최종 응답, 이벤트 기록을 출력한다. 각본은 실행기가 보낸 기록이 기대와 다르면 규약 오류를 낸다.
- 입력 형식은 JSON 을 쓸지 줄 형식을 쓸지 스펙 작성 때 정한다. JSON 을 쓰면 파서 구현이 1단계의 절반을 차지하므로 시작 코드에 작은 JSON 읽기·쓰기 함수를 넣을지 함께 정한다.
- 1단계 `01-loop`: 도구 사용 요청과 결과의 짝(식별자), 결과 메시지 순서 규칙, 정지 이유별 처리(끝, 도구 사용, 길이 한도), 최대 차례 수.
- 2단계 `02-schema`: 입력 스키마의 부분집합(type, required, enum, minimum, maximum, items) 검증, 검증 실패와 도구 실패를 오류 결과로 돌려주기, 같은 오류가 정해진 횟수 되풀이되면 멈추기.
- 3단계 `03-parallel`: 한 차례의 여러 도구 사용을 동시에 실행하고(가상 시계) 결과를 요청 순서대로 한 메시지에 담기, 일부 실패와 시간 초과, 부수효과가 있는 도구의 재시도 금지.
- 4단계 `04-context`: 명세가 정한 토큰 계산법으로 컨텍스트 예산을 세고 한도에 가까우면 오래된 도구 결과를 지우거나 요약 자리표시로 바꾸는 정책.
- 5단계 `05-guard`: 도구마다 권한 등급(읽기, 쓰기, 되돌릴 수 없음)을 두고 되돌릴 수 없는 도구는 확인 명령이 있어야 실행한다. 도구 결과에서 온 텍스트가 권한을 올리지 못하게 한다. 감사 기록을 남긴다.
- 난도: 단계마다 2~3시간.
- 함정: 결과 순서, 오류 결과의 is_error 표시 누락, 병렬 결과를 끝난 순서로 담는 실수, 지운 도구 결과의 식별자가 남아 짝이 깨지는 경우, 확인 없는 쓰기 도구.
- 검증: build 스킬의 교차 검증. 규약 규칙은 Claude 도구 사용 문서와 대조하되 스펙은 특정 API 에 묶이지 않게 일반화한다.
- 출처: Claude 문서(Define tools, Handle tool calls), Building effective agents, Effective context engineering for AI agents.
- 피할 것: 실제 모델 API 를 호출하는 것. 판마다 바뀌는 API 필드 이름을 그대로 요구하는 것.
