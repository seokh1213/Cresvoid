# F-kotlin-30 일일 사용 한도

- 맥락: 사용자별 일일 사용 한도와 남은 한도를 관리한다. 하루는 한국 시각 자정에 시작한다. 시각은 입력 명령의 UTC 시각 문자열로 움직인다. 사용, 취소, 한도 조회 명령을 처리한다.
- 버그 후보: 날짜 경계를 UTC 로 계산해 한국 시각 오전 9시에 한도가 초기화된다(먼저 고른다), 지연 평가 시퀀스를 두 번 소비해 사용 기록 저장이 두 번 일어난다, 가변 객체를 해시 맵 키로 쓴 뒤 바꿔 기록을 찾지 못한다(F-kotlin-40 과 겹치므로 마지막에 고른다).
- 버그 신고: "한국 시각 밤 11시 30분에 한도를 다 쓴 사용자가 자정이 지나도 한도가 초기화되지 않는다." 재현 입력과 기대한 결과, 실제 결과를 적는다.
- 형식: 300~400줄, 파일 4~5개.
- 난도: 첫 세 단계 가운데 가장 어렵다. 시각 변환을 따라가야 원인에 닿는다.
- 검증: 숨은 테스트는 한국 시각 자정과 UTC 자정 전후를 모두 지나는 시나리오를 둔다. `ZoneId` 를 쓰든 오프셋을 직접 더하든 맞게 고치면 통과해야 한다.
- 출처: Java SE 21 API 문서의 `Instant`, `ZoneId`, `ZonedDateTime`, `LocalDate`.
- 피할 것: 서머타임이 있는 시간대. 한국 시각만 쓴다.
