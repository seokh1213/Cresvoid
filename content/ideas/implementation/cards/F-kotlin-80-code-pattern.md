# F-kotlin-80 상품 코드 검증

- 맥락: 판매자가 입력한 상품 코드를 검증하고 코드에서 분류와 일련번호를 추출한다. 코드 형식은 대문자 3자, 하이픈, 숫자 4자다(예: `TOP-0042`). 형식에 맞지 않으면 등록을 거절한다.
- 버그 후보: 검증에 `Regex.containsMatchIn` 이나 `find` 를 써서 `XTOP-00421` 처럼 앞뒤에 문자가 더 붙은 코드도 통과한다(먼저 고른다. `matches` 는 문자열 전체가 일치해야 한다), 추출 정규식의 `.*` 가 탐욕적으로 일치해 여러 코드가 든 문자열을 한 덩어리로 읽는다.
- 버그 신고: "형식이 틀린 상품 코드가 등록되어 정산에서 분류를 찾지 못한다."
- 형식: 150~220줄, 파일 2~3개.
- 난도: 정상 코드로는 증상이 나지 않아 틀린 입력을 스스로 만들어 봐야 한다.
- 검증: 숨은 테스트는 앞뒤에 문자가 붙은 코드, 소문자, 자릿수가 다른 코드를 둔다. `matches` 로 바꾸거나 `^` 와 `$` 앵커를 붙인 수정이 모두 통과해야 한다.
- 출처: Kotlin 표준 라이브러리 문서의 `Regex`(matches, containsMatchIn, find). Java SE 21 API 문서의 `Pattern`.
- 피할 것: 정규식 엔진 구현(B-regex-10 이 다룬다)이나 역추적 성능.
