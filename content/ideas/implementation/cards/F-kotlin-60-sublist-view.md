# F-kotlin-60 페이지 단위 일괄 처리

- 맥락: 처리할 주문 ID 목록을 페이지 크기만큼 잘라 차례로 처리하는 일괄 작업. 처리한 주문은 목록에서 지우고 실패한 주문은 다시 시도하려고 목록 끝에 붙인다.
- 버그 후보: `subList` 로 만든 뷰를 들고 있는 동안 원본 목록에 원소를 더하거나 지워 다음 접근에서 ConcurrentModificationException 이 나거나 엉뚱한 범위를 처리한다(먼저 고른다), 뷰에서 `clear()` 하면 원본에서도 지워진다는 점을 놓친 처리.
- 버그 신고: "실패한 주문이 하나라도 있으면 일괄 작업이 중간에 예외로 멈춘다."
- 형식: 180~260줄, 파일 3~4개.
- 난도: 스택 트레이스가 원인 위치가 아니라 뷰를 쓰는 곳을 가리켜 한 단계 거슬러 올라가야 한다.
- 검증: 숨은 테스트는 실패가 없는 입력과 있는 입력을 둔다. `toList()` 로 복사하거나 `chunked` 를 쓰는 수정이 모두 통과해야 한다.
- 출처: Java SE 21 API 문서의 `List.subList`(원본의 구조가 뷰 밖에서 바뀌면 뷰의 동작은 정의되지 않는다).
- 피할 것: 스레드 동시성 버그로 보이게 만드는 것. 단일 스레드다.
