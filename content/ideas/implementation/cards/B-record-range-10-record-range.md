# B-record-range-10 레코드 경계를 지키는 파일 분할기 만들기

- 목표: 큰 입력을 레코드가 끊기지 않는 바이트 구간으로 나누고 각 구간을 따로 읽어 원래 레코드를 복원한다.
- 입출력 모양: 파일 등록, 형식별 구간 생성, 구간 읽기 명령을 표준 입출력으로 받는다. 파일은 UTF-8 바이트와 변경되지 않는 버전 식별자를 가진 가짜 저장소에 둔다. 구간은 시작 포함·끝 제외로 통일하고 레코드 수와 함께 출력한다.
- 1단계 `01-lines`: LF·CRLF로 끝나는 줄 레코드를 정해진 건수로 묶는다. 마지막 줄의 개행 유무, 빈 줄, 빈 파일의 의미를 명시하고 한 번의 순차 읽기로 구간을 만든다.
- 2단계 `02-json-ranges`: 최상위 객체 배열을 레코드 경계에서 나눈다. 문자열 안의 괄호·이스케이프된 따옴표·중첩 객체와 배열을 구분한다. 입력은 스펙이 제한한 올바른 JSON으로 주고 미완성 문자열·닫히지 않은 구조의 오류만 추가한다. 범용 JSON 값 파서 구현은 요구하지 않는다.
- 3단계 `03-range-read`: 파일 버전과 구간으로 부분 읽기를 수행한다. 짧은 읽기는 이어 받고 구간보다 앞서 EOF가 오면 실패한다. JSON 구간은 배열로 감싸 파싱 가능한 바이트를 출력한다. 다른 버전의 파일에는 같은 구간을 적용하지 않는다.
- 난도: 단계마다 1~3시간. 대규모 입력은 작은 읽기 버퍼를 사용하게 하고, 구간마다 파일 처음부터 다시 훑거나 전체 파일을 객체로 파싱하는 방식과 구분한다. 실제 메모리·시간 제한은 제작 때 실측해 정한다.
- 함정: 문자 위치와 UTF-8 바이트 위치의 차이, 읽기 버퍼 사이에서 나뉜 CRLF와 이스케이프, 마지막 묶음, 중복·누락된 경계, 같은 경로의 다른 버전.
- 검증: 작은 입력은 직접 계산한 구간과 대조한다. 모든 구간을 순서대로 읽은 레코드가 원본과 정확히 같은지, 구간을 다른 순서로 읽어도 내용이 같은지 검사한다. 참조 풀이와 독립 테스트를 나눠 제작한다.
- 출처: [RFC 8259](https://www.rfc-editor.org/rfc/rfc8259)의 문자열·배열·인코딩 규칙, [Java SE 21 InputStream](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/io/InputStream.html)의 부분 읽기 계약. 구간 형식과 파일 버전 검사는 이 과제의 규칙이다.
- 피할 것: 외부 JSON 라이브러리와 실제 객체 저장소를 요구하는 것, UTF-8에서 유효한 모든 JSON 오류를 진단하는 파서를 만드는 것. C-kotlin-80의 CSV 문법과 문자열 API 함정을 반복하지 않는다.
