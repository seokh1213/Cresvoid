# F-kotlin-90 주문 상태 변경 기록

- 맥락: 주문 상태가 바뀔 때마다 변경 기록을 외부 이력 저장소에 남긴다. 저장소 호출은 가끔 시간이 초과되며 시간이 초과돼도 저장은 이미 끝났을 수 있다. 호출부는 시간 초과면 다시 시도한다. 저장소는 같은 멱등 키의 두 번째 요청을 무시한다. 가짜 저장소는 입력 명령으로 시간 초과를 흉내 낸다.
- 버그 후보: 멱등 키를 재시도마다 새로 만들어 시간 초과 뒤의 재시도가 기록을 하나 더 남긴다(먼저 고른다), 재시도 횟수 계산의 하나 차이로 한 번 더 시도한다.
- 버그 신고: "주문 이력에 같은 상태 변경이 두 번 찍힌 주문이 있다. 저장소 응답이 느렸던 시각과 겹친다."
- 형식: 200~300줄, 파일 3~4개.
- 난도: 시간 초과가 실패가 아니라 결과를 모르는 상태라는 점을 알아야 원인에 닿는다.
- 검증: 숨은 테스트는 시간 초과가 저장 전에 나는 경우와 저장 뒤에 나는 경우를 모두 둔다. 멱등 키를 재시도 밖에서 한 번만 만들도록 고친 수정이 통과해야 한다.
- 출처: Stripe, "Designing robust and predictable APIs with idempotency". load README 의 '부하와 회복력' 절.
- 피할 것: 실제 네트워크와 실제 시간. L-load-20(멱등 키 실험)와 같은 서비스 구조.
