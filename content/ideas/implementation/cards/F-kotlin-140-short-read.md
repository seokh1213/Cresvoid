# F-kotlin-140 한 번만 읽어 잘리는 전송 구간

- 맥락: 이미 계산된 구간의 바이트를 스트림에서 받아 임시 파일에 저장하는 처리기다. 구간 길이만큼 받아야 성공이며 앞서 EOF를 만나면 해당 구간은 실패한다. 구간 시작 위치 계산은 제공한다.
- 버그 후보: `read(buffer)` 한 번이 요청한 길이를 전부 채운다고 가정하는 원인 하나를 심는다. 짧은 반환값을 EOF로 취급하거나 남은 버퍼를 정상 데이터로 저장하는 증상은 같은 원인에서 나오게 한다.
- 버그 신고: 로컬 메모리 파일에서는 정상인데 조각 단위로 응답하는 전송원에서는 큰 구간의 뒤쪽이 빠진다. 공개 재현에서는 요청 크기보다 작은 값을 순서대로 반환하는 가짜 스트림을 사용한다.
- 형식: 150~240줄, 파일 2~4개. 가짜 스트림, 전송 처리기, 구간 저장소를 분리한다. 실제 소켓·시간 대기·저장소 장애는 넣지 않는다.
- 검증: 고정 테스트 6~10개로 한 번에 읽기, 여러 번의 짧은 읽기, 0길이 구간, 정확한 EOF, 조기 EOF와 정상 이웃 구간을 확인한다. 반복 읽기와 `readNBytes`를 사용한 수정 모두 성공·실패 계약을 만족하면 통과한다.
- 출처: [Java SE 21 InputStream](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/io/InputStream.html)의 `read(byte[], int, int)`와 `readNBytes` 계약. 양수 길이의 정상 읽기에서 0을 반환하는 비표준 가짜 스트림은 쓰지 않는다.
- 피할 것: 문자·바이트 위치 혼동이나 `skip`의 부분 이동을 함께 심는 것. F-kotlin-130과 분리한다.
