# B-search-engine-40 검색 결과 발췌

- 목표: 문서 원문에서 검색어가 가장 많이 모인 구간을 골라 검색어를 표시한 발췌문을 만든다.
- 입출력 모양: `SNIPPET <id> <낱말> …` 가 원문 구간을 그대로 옮기고 검색어 토큰을 표시 문자로 감싸 한 줄에 출력한다.
- 단계별 내용: 원문 보관과 토큰의 글자 위치, 토큰 수 상한이 있는 구간 안에서 서로 다른 검색어를 가장 많이 담는 구간 고르기(같으면 짧은 구간, 그다음 앞 구간), 검색어가 하나도 없을 때와 문서가 없을 때의 출력, ADD 로 대체한 문서와 DEL 로 지운 문서.
- 난도: 대규모 테스트는 긴 문서와 드문 검색어 조합으로 만든다. 질의마다 원문을 다시 토큰화하는 방법으로는 제한 시간을 넘게 한다. 미리 토큰화해 둔 배열을 질의마다 훑는 방법은 통과한다. 이 방법까지 막으려면 SNIPPET 을 6~7배로 늘려야 하는데 그러면 생성기 출력이 상한(64MB)을 넘는다. 문서는 한 줄 상한 때문에 더 길게 만들 수 없다. 3단계 위치 색인에서 검색어의 위치 목록만 모아 두 포인터로 구간을 찾는 방법을 배경 개념으로 설명한다.
- 함정: 대소문자를 바꾸기 전 원문 보존, `Kotlin은` 처럼 한 낱말 안에서 토큰이 둘로 나뉠 때의 표시 위치, 같은 검색어가 여러 번 나올 때, 구간 상한 경계, 표시 문자가 원문에 이미 있을 때.
- 검증: 참조 풀이와 독립 테스트의 교차 검증, 무작위 생성기로 단순 구현과 대조.
- 출처: Elastic 문서의 Highlighting(발췌 조각과 표시 태그의 동작).
- 피할 것: SEARCH 출력에 발췌를 붙이는 것(앞 단계 출력을 바꾼다), 여러 문서를 한 번에 발췌하는 명령.
