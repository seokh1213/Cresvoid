# 02. 레벨 압축과 증폭 지표

## 1. 개요

[1.1] 01-memtable의 저장소에 레벨 압축과 증폭 지표를 추가한다. 앞 단계의 입력·오류 규칙과 명령을 유지하고, 이 문서에 적힌 규칙만 더한다. 목표 풀이 시간은 2~3시간이다.

[1.2] 압축은 새 명령인 COMPACT를 실행할 때만 일어난다. 기존 PUT, DEL, FLUSH는 레벨 0 파일을 만드는 데서 끝난다. 따라서 COMPACT가 없는 이전 단계 입력의 출력은 그대로 유지된다. 압축 뒤에도 GET은 논리적으로 최신인 값 또는 삭제 상태를 반환한다.

## 2. 배경 개념

[2.1] 여러 정렬 파일을 압축(compaction)하면 같은 키의 오래된 버전을 없애고 파일 수와 중복 저장량을 줄일 수 있다. 여기서 압축은 바이트 인코딩의 압축이 아니라 정렬 파일의 병합을 뜻한다. 새 파일을 쓰는 비용이 추가되므로 쓰기 증폭이 생긴다.

[2.2] 레벨 압축은 파일을 여러 레벨에 배치하고, 한 레벨의 크기가 한도를 넘으면 일부 파일을 다음 레벨의 겹치는 파일과 합치는 방식이다. 레벨 0은 서로 겹치는 키 범위를 허용하지만 그 아래 레벨에서는 파일의 키 범위가 겹치지 않게 유지한다. 크기 계층 압축은 비슷한 크기의 묶음을 합치는 방식으로, 이 과제의 규칙과 다르다.

[2.3] 병합할 때 같은 키의 여러 버전 중 최신 버전을 골라야 한다. 최신 레코드가 툼스톤이어도 아래 레벨에 옛 값이 남아 있다면 삭제 사실을 보존해야 한다. 더는 옛 값이 남지 않는 위치에서만 툼스톤을 제거할 수 있다. 파일을 다시 만든 시각과 레코드를 갱신한 시각은 구별해야 한다.

[2.4] 쓰기 증폭은 사용자가 기록한 양에 비해 정렬 파일에 쓴 양이 얼마나 큰지를 나타낸다. 공간 증폭은 현재 유효한 데이터에 비해 실제 보관하는 양이 얼마나 큰지를 나타낸다. 단위와 측정 범위에 따라 수치가 달라지므로 이 과제는 레코드 개수로 계산한다. 배경은 [LevelDB의 Compactions 절](https://github.com/google/leveldb/blob/main/doc/impl.md)과 DDIA 초판 3장을 참고하며, 아래의 레벨 수·비율·선택 순서는 과제에서 정한 규칙이다.

## 3. 입출력 규칙

[3.1] 새 명령은 인자가 없는 `COMPACT`와 `METRICS`다. 성공한 COMPACT는 `OK` 한 줄을 출력한다. METRICS는 4.9~4.11에서 정한 지표 한 줄을 출력한다. 기존 LAYOUT은 동일한 형식으로 현재의 모든 레벨 파일을 출력한다.

[3.2] 레벨 번호는 0, 1, 2뿐이며 레벨 2가 마지막 레벨이다. 정렬 파일 하나의 레코드 수는 어느 레벨에서든 capacity 이하이다. 레벨 0 전체의 크기 한도는 `2 × capacity`, 레벨 1은 `4 × capacity`다. 크기는 해당 레벨에 현재 있는 모든 레코드의 합이며 툼스톤과 파일 간 중복 키도 각각 센다. 레벨 2는 크기 한도가 없다.

## 4. 명령 규칙

[4.1] COMPACT는 메모리 테이블을 flush하지 않는다. 레벨 0과 1 중 크기가 한도를 엄격히 초과하는 레벨이 없으면 상태를 바꾸지 않는다. 하나 이상 있으면 번호가 가장 작은 초과 레벨에서 병합 한 번을 수행하고, 바뀐 상태에서 초과 레벨을 다시 고른다. 모든 레벨이 한도 이하가 될 때까지 반복한 뒤 `OK`를 출력한다. 한도와 크기가 같으면 병합하지 않는다.

[4.2] 한 번의 병합에서 출발 레벨이 0이면 그 레벨에서 파일 번호가 가장 작은 파일 하나를 고른다. 출발 레벨이 1이면 최소 키가 가장 작은 파일 하나를 고른다. 최소 키가 같으면 파일 번호가 작은 파일을 고른다. 이 파일을 출발 파일, 바로 다음 레벨을 도착 레벨이라 부른다. 다른 출발 파일은 그 범위가 겹치더라도 함께 고르지 않는다.

[4.3] 파일의 범위는 최소 키와 최대 키를 모두 포함하는 닫힌 구간이다. 도착 레벨에서 출발 파일의 범위와 교집합이 있는 파일을 전부 고른다. 경계 키가 같은 경우도 겹친다. 파일 범위 안의 실제 키들이 서로 달라도 구간이 겹치면 선택한다. 선택 범위는 최초 출발 파일의 범위로 고정하고, 도착 파일의 범위를 따라 넓히지 않는다. 도착 파일을 하나도 고르지 않는 병합도 가능하다.

[4.4] 병합 입력은 출발 파일 전체와 선택한 도착 파일 전체다. 같은 키가 여러 번 나오면 갱신 번호가 가장 큰 레코드 하나를 남긴다. 병합으로 레코드의 갱신 번호를 바꾸지 않는다. 메모리 테이블과 선택하지 않은 파일은 병합 입력에 넣지 않으며, 거기에 최신 버전이 있어도 병합 입력의 레코드를 대신 제거하지 않는다.

[4.5] 도착 레벨이 1이면 최신 레코드가 툼스톤이어도 남긴다. 도착 레벨이 2이면 병합 입력에서 키별 최신 레코드를 고른 다음 그중 툼스톤을 전부 버린다. 먼저 툼스톤을 빼고 옛 값을 고르면 안 된다. 이 규칙은 레벨 0의 오래된 파일부터 이동시키고 레벨 1의 키 범위를 겹치지 않게 유지하는 선택 순서를 전제로 한다.

[4.6] 남은 레코드를 키 오름차순으로 나열하고 앞에서부터 capacity개씩 나눠 새 도착 파일들을 만든다. 마지막 파일만 capacity보다 작을 수 있다. 각 파일의 최소·최대 키는 실제 남은 레코드에서 다시 구한다. 새 파일 번호는 키가 작은 묶음부터 전역 증가 순서로 부여하며, 도착 파일과 겹치지 않는 단순 이동이라도 새 파일을 만들고 번호를 소비한다. 레코드가 하나도 남지 않으면 파일을 만들지 않고 번호도 소비하지 않는다.

[4.7] 병합에 사용한 기존 파일은 모두 제거하고, 새 파일들을 도착 레벨에 넣는다. 선택하지 않은 파일의 번호·내용·범위는 유지한다. 제거한 파일 번호는 재사용하지 않는다. 레벨 1과 2의 파일 범위는 각각 같은 레벨 안에서 서로 겹치지 않아야 한다. 레벨 0 파일끼리 또는 서로 다른 레벨 사이의 범위 겹침은 허용한다.

[4.8] 압축 이후 GET의 확인 순서는 메모리 테이블, 레벨 0의 파일 번호 내림차순, 레벨 1의 최소 키 오름차순, 레벨 2의 최소 키 오름차순이다. 각 파일에서는 요청 키가 있을 때만 발견한 것으로 처리한다. 처음 발견한 레코드가 값이면 VALUE, 툼스톤이면 NOT_FOUND를 반환하고 끝낸다. 압축 정책상 이 순서에서 처음 발견한 레코드가 해당 키의 최신 레코드다. 파일 번호가 크다는 이유로 아래 레벨을 먼저 확인하지 않는다.

[4.9] 누적 사용자 쓰기 수 U는 마지막 RESET 이후 성공한 PUT과 DEL의 합이다. 같은 키의 덮어쓰기, 같은 값의 재기록, 없는 키의 삭제도 각각 1이다. 누적 파일 쓰기 수 W는 flush와 모든 병합에서 새 파일에 기록한 레코드 수의 합이다. 병합으로 버린 옛 버전과 툼스톤은 그 병합의 W에 포함하지 않는다. 겹치는 파일 없는 이동도 출력 레코드 수만큼 W에 더한다. 메모리에만 기록한 레코드, 파일 읽기, 파일 제거, 필터와 메타데이터는 W에 더하지 않는다.

[4.10] 현재 보관량 P는 메모리 테이블의 레코드 수와 현재 모든 정렬 파일의 레코드 수를 더한 값이다. 툼스톤, 같은 키의 다른 파일 버전도 각각 1로 센다. 병합 중의 일시적인 중복 파일은 포함하지 않는다. 현재 유효 키 수 V는 저장소 전체에서 최신 레코드가 값인 서로 다른 키의 수다. 아직 flush하지 않은 값과 삭제도 V에 반영한다.

[4.11] METRICS는 `METRICS <U> <W> <P> <V> <쓰기 증폭> <공간 증폭>`을 출력한다. 쓰기 증폭은 `W/U`, 공간 증폭은 `P/V` 형식이며 정수를 대입한 분수를 약분하지 않고 출력한다. 분모가 0이면 해당 증폭만 `NA`로 출력한다. 예를 들어 W가 0이고 U가 3이면 `0/3`이다. U와 W는 누적값이며 METRICS가 초기화하지 않는다. 성공한 RESET은 U와 W를 모두 0으로 만든다. METRICS 자체는 어떤 상태도 바꾸지 않는다.

## 5. 오류 규칙

[5.1] COMPACT와 METRICS도 저장소가 없거나 인자가 붙으면 `ERROR`이며 어떤 상태도 바꾸지 않는다. 앞 단계의 ERROR 원자성은 파일 배치와 지표에도 적용한다. 이번 단계의 추가 명령은 COMPACT와 METRICS뿐이다.

## 6. 예시

[6.1] capacity가 1이면 레벨 0 한도는 2, 레벨 1 한도는 4다. 다음 예시의 첫 COMPACT에서는 파일 1~5가 차례로 레벨 1로 이동해 파일 8~12가 되고, 레벨 1이 초과하므로 `a`의 파일 8이 마지막 레벨로 이동해 파일 13이 된다. 두 번째 COMPACT에서는 `a`의 툼스톤이 레벨 1을 거쳐 레벨 2의 옛 값과 함께 사라진다.

입력:
```text
RESET 1
PUT a A
PUT b B
PUT c C
PUT d D
PUT e E
PUT f F
PUT g G
COMPACT
LAYOUT
METRICS
DEL a
PUT h H
PUT i I
COMPACT
GET a
LAYOUT
METRICS
```

출력:
```text
OK
OK
OK
OK
OK
OK
OK
OK
OK
MEM 0
FILE 6 0 1 f f
FILE 7 0 1 g g
FILE 9 1 1 b b
FILE 10 1 1 c c
FILE 11 1 1 d d
FILE 12 1 1 e e
FILE 13 2 1 a a
END
METRICS 7 13 7 7 13/7 7/7
OK
OK
OK
OK
NOT_FOUND
MEM 0
FILE 15 0 1 h h
FILE 16 0 1 i i
FILE 11 1 1 d d
FILE 12 1 1 e e
FILE 17 1 1 f f
FILE 18 1 1 g g
FILE 20 2 1 b b
FILE 21 2 1 c c
END
METRICS 10 21 8 8 21/10 8/8
```

[6.2] 다음 예시는 아직 파일로 내리지 않은 툼스톤도 보관량에 포함되며, 유효 키가 하나도 없으면 공간 증폭이 NA가 되는 경우다.

입력:
```text
RESET 2
METRICS
DEL ghost
METRICS
COMPACT

METRICS
```

```text

OK
OK

```

## 7. 검사 방식

[7.1] 실행·출력 비교 방식과 일반 검사 20초, 대규모 검사 60초의 제한 시간은 앞 단계와 같다. 이번 단계 참조 구현은 01-memtable의 모든 검사도 통과해야 한다. 고정 검사 10~14개와 생성 검사 2~3개를 사용하며 마지막 검사는 대규모 입력이다.

[7.2] 생성 입력의 단건 조회와 V는 독립적인 맵 모형과 대조한다. 병합 파일 선택, 번호 부여, 출력 분할, W와 P는 이 문서의 규칙에서 별도로 기대값을 유도한다. 레벨 한도와 같은 크기, 겹치는 구간의 경계, 같은 키의 여러 버전, 빈 병합 결과를 확인한다.

[7.3] 대규모 검사는 capacity 1,024에서 RESET 1줄, PUT·DEL 합계 100,000줄, COMPACT 10,000줄, GET 50,000줄, METRICS 1줄로 총 160,002줄이다. 명령은 섞어서 보내며 같은 키의 재기록과 여러 레벨의 버전을 포함한다. 매 단건 조회마다 모든 저장 레코드를 순회하는 구현을 구별하기 위한 규모다. 실제 파일 입출력과 벽시계 기반 증폭 수치는 검사하지 않는다.
