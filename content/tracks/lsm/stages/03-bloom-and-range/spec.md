# 03. 블룸 필터와 범위 조회

## 1. 개요

[1.1] 02-compaction의 저장소에 파일별 블룸 필터, 필터를 사용하는 단건 조회, 여러 레벨을 합치는 범위 조회를 추가한다. 앞 두 단계의 규칙을 유지하며 기존 명령의 출력은 바꾸지 않는다. 목표 풀이 시간은 2~3시간이다.

[1.2] 블룸 필터를 사용하는 새 조회 명령은 BGET이다. 기존 GET은 결과와 동작을 유지하며 새 읽기 지표를 바꾸지 않는다. 범위 조회도 새 읽기 지표에 포함하지 않는다. 따라서 앞 단계의 지표와 새 필터 효과를 각각 확인할 수 있다.

## 2. 배경 개념

[2.1] 블룸 필터는 여러 해시 위치의 비트를 켜서 집합의 원소를 요약한다. 조회 키의 해시 위치 중 꺼진 비트가 하나라도 있으면 그 집합에는 키가 없다. 모든 위치가 켜져 있어도 다른 키가 같은 비트들을 켰을 수 있으므로 실제로 존재한다는 보장은 없다. 이런 양성 판정 뒤 실제 파일에는 키가 없는 경우가 거짓 양성이다. 같은 해시 규칙으로 구성하고 조회한 필터는 들어 있는 키를 없다고 판정해서는 안 된다.

[2.2] 필터가 요약하는 집합은 저장소 전체의 유효 키가 아니라 개별 파일에 물리적으로 들어 있는 키다. 툼스톤도 파일의 키이므로 집합에 포함한다. 삭제된 키라는 이유로 필터에서 빼면 오래된 값으로 조회가 이어질 수 있다. 파일을 압축해 내용이 바뀌면 필터 역시 새 파일의 내용에 맞아야 한다.

[2.3] 범위 조회는 한 파일의 정렬 결과만 반환하는 것으로 끝나지 않는다. 범위 안의 같은 키가 여러 파일과 메모리에 있을 수 있으므로 최신 버전을 고르고, 최신 버전이 툼스톤인 키는 결과에서 제외해야 한다. 키가 하나의 범위 경계와 같은 경우, 결과 개수 제한에 도달하기 전에 삭제된 키가 끼는 경우도 판단해야 한다.

[2.4] 배경 자료는 [LevelDB의 Filters 절](https://github.com/google/leveldb/blob/main/doc/index.md#filters)과 DDIA 초판 3장이다. 다음 절의 해시 식, 비트 수, 측정 단위는 실행 결과를 재현하기 위해 이 과제에서 정한 규칙이다.

## 3. 입출력 규칙

[3.1] 추가 명령은 `BGET <key>`, `READS`, `RANGE <lower> <upper> <limit>`이다. key, lower, upper는 01-memtable에서 정한 키 형식을 따른다. limit는 01-memtable의 3.3에서 정한 정수 표기와 값 판정 규칙을 따르며 허용 범위는 0~1,000이다.

[3.2] BGET은 GET과 같은 `VALUE <value>` 또는 `NOT_FOUND`를 출력한다. READS는 `READS <검사 수> <음성 수> <파일 조회 수> <거짓 양성 수>` 한 줄이다. RANGE의 출력은 4.9에서 정한다. 성공한 RESET은 읽기 계수를 모두 0으로 초기화한다.

## 4. 명령 규칙

[4.1] 레코드 n개인 파일의 블룸 필터는 `m = 8 × n`개의 비트로 이뤄지며 비트 번호는 0부터 m−1까지다. 빈 파일은 만들지 않으므로 m은 항상 양수다. 새 파일을 만들 때 모든 비트를 0으로 시작하고, 그 파일에 남는 모든 키의 해시 위치를 1로 설정한다. 툼스톤의 키도 포함한다. 파일이 제거되면 해당 필터도 제거한다. 메모리 테이블에는 필터를 만들지 않는다.

[4.2] 키의 문자를 왼쪽부터 읽으며 두 해시 값 h1과 h2를 계산한다. 시작값은 각각 0과 7이며, 문자 ASCII 코드 c마다 `h1 = (31 × h1 + c) mod 2147483647`, `h2 = (131 × h2 + c) mod 2147483647`로 갱신한다. mod는 음이 아닌 나머지다. 각 곱셈과 덧셈은 수학적 정수 값으로 계산하며 32비트 오버플로를 적용하지 않는다. 키의 세 비트 위치는 i가 0, 1, 2일 때의 `(h1 + i × h2) mod m`이다. 위치가 같으면 같은 비트를 여러 번 설정하거나 검사한다. h2가 0이어도 다른 값으로 보정하지 않는다.

[4.3] 필터 생성은 flush와 압축의 새 출력 파일마다 따로 수행한다. 압축 입력의 필터를 합치거나 기존 비트 수를 이어 쓰지 않는다. 필터 생성·제거는 기존 METRICS의 U, W, P, V와 파일 번호에 영향을 주지 않는다.

[4.4] BGET은 메모리 테이블을 먼저 확인한다. 키가 있으면 값 또는 툼스톤에 따라 즉시 결과를 출력하며 읽기 계수를 올리지 않는다. 키가 없으면 02-compaction의 GET 순서대로 파일들을 방문한다. 파일의 닫힌 키 범위 밖에 있는 키이면 필터 검사와 파일 조회를 모두 생략하고 다음 파일로 넘어간다. 이 생략은 어떤 읽기 계수에도 더하지 않는다.

[4.5] 키가 파일 범위 안에 있으면 그 파일의 필터를 한 번 검사하고 검사 수를 1 올린다. 세 위치 중 0인 비트가 하나라도 있으면 음성 수를 1 올리고 파일 내용을 조회하지 않은 채 다음 파일로 넘어간다. 세 비트가 모두 1이면 파일 조회 수를 1 올리고 그 파일 안에서 키를 찾는다. 여기서 파일 조회 한 번은 파일 내 키 존재 여부를 확인하는 논리적인 작업 1회이며, 비교 횟수나 실제 입출력 횟수가 아니다.

[4.6] 양성 판정으로 조회한 파일에 키가 없으면 거짓 양성 수를 1 올리고 다음 파일로 넘어간다. 키가 있고 레코드가 툼스톤이면 거짓 양성에 포함하지 않고 NOT_FOUND로 종료한다. 키가 있고 값이면 VALUE로 종료한다. 방문할 파일이 더 없으면 NOT_FOUND다. 한 BGET이 여러 파일에서 거짓 양성을 만들 수 있으며, 결과가 NOT_FOUND라고 해서 반드시 거짓 양성이 있었던 것은 아니다.

[4.7] READS는 마지막 RESET 이후 성공한 BGET들의 계수 합을 출력하고 계수를 유지한다. 각 시점에서 검사 수는 음성 수와 파일 조회 수의 합이며, 거짓 양성 수는 파일 조회 수 이하이다. PUT, DEL, FLUSH, COMPACT, GET, LAYOUT, METRICS, READS, RANGE와 오류는 이 계수를 증가시키지 않는다.

[4.8] RANGE는 lower 이상 upper 이하의 닫힌 구간에 있는 모든 키를 대상으로, 메모리 테이블과 모든 레벨의 파일을 함께 해석한다. 키마다 갱신 번호가 가장 큰 레코드가 최신 버전이며, 최신 버전이 툼스톤인 키는 반환하지 않는다. 유효 키를 ASCII 사전순으로 정렬하고 앞에서부터 limit개까지만 반환한다. 오래된 버전과 삭제된 키는 limit를 소비하지 않는다. lower가 upper보다 크거나 limit가 0이면 빈 결과이며 오류가 아니다.

[4.9] RANGE는 첫 줄에 `ROWS <반환 개수>`를 출력하고, 이어서 반환하는 키마다 `ROW <key> <value>`를 한 줄씩 출력한 뒤 `END`를 출력한다. 빈 결과는 ROWS 0 행과 END 행만 있다. 결과가 잘렸더라도 전체 유효 키 수나 다음 커서는 출력하지 않는다. RANGE는 블룸 필터를 사용한 단건 조회로 정의하지 않으며, 필터 계수·파일 배치·메모리·갱신 번호·증폭 지표를 바꾸지 않는다.

## 5. 오류 규칙

[5.1] 저장소 생성 전의 새 명령, 인자 수가 틀린 명령, 형식이 잘못된 키나 범위를 벗어난 limit는 `ERROR`다. 잘못된 RANGE는 lower와 upper의 대소관계나 limit가 0인지보다 인자의 형식·범위를 먼저 검사한다. 모든 오류는 앞 단계처럼 상태와 모든 계수를 유지한다.

## 6. 예시

[6.1] 파일 1의 비트 수는 16이다. `a`가 켜는 비트는 1, 7, 13이고 `z`가 켜는 비트는 10, 9, 8이다. `q`는 `a`와 같은 세 위치를 검사하므로 거짓 양성이고, `b`는 꺼진 비트 2를 검사하므로 음성이다. 마지막 BGET a는 메모리의 툼스톤에서 끝난다.

입력:
```text
RESET 2
PUT a A
PUT z Z
BGET q
BGET b
BGET a
DEL a
BGET a
RANGE a z 10
READS
METRICS
```

출력:
```text
OK
OK
OK
NOT_FOUND
NOT_FOUND
VALUE A
OK
NOT_FOUND
ROWS 1
ROW z Z
END
READS 3 1 2 1
METRICS 3 2 3 1 2/3 3/1
```

[6.2] 다음 예시는 닫힌 구간의 양 끝, 키의 사전순, 삭제와 limit의 관계를 보여 준다. `a10`의 최신 버전이 툼스톤이므로 limit를 소비하지 않고 `a2`가 반환된다.

입력:
```text
RESET 3
PUT a2 TWO
PUT a10 TEN
PUT b B
DEL a10
PUT a2 NEW
FLUSH
RANGE a a2 1
RANGE a2 a2 2
RANGE z a 1
RANGE a z 0
READS
```

출력:
```text
OK
OK
OK
OK
OK
OK
OK
ROWS 1
ROW a2 NEW
END
ROWS 1
ROW a2 NEW
END
ROWS 0
END
ROWS 0
END
READS 0 0 0 0
```

## 7. 검사 방식

[7.1] 실행·출력 비교 방식과 일반 검사 20초, 대규모 검사 60초의 제한 시간은 앞 단계와 같다. 이번 단계 구현은 앞 두 단계의 모든 검사도 통과해야 한다. 고정 검사 10~14개와 생성 검사 2~3개를 사용하며 마지막 검사는 대규모 입력이다.

[7.2] BGET 결과와 RANGE 결과는 독립적인 맵 모형의 조회 결과와 대조한다. READS의 계수는 이 문서의 해시·파일 방문 규칙에서 계산하며, 논리적으로 삭제된 키라도 파일에 툼스톤이 있으면 참 양성으로 취급한다. 압축 뒤 재구성된 필터, 범위 양 끝의 포함, 같은 키의 여러 버전, 삭제된 키가 limit를 소비하지 않는 규칙을 함께 확인한다.

[7.3] 대규모 검사는 capacity 1,024에서 RESET 1줄, PUT·DEL 합계 90,000줄, COMPACT 1,000줄, BGET 20,000줄, RANGE 80,000줄, READS 1줄로 총 191,002줄이다. RANGE의 limit는 0~2이며 여러 레벨에 데이터가 남는 시점에도 조회한다. 매 범위 조회마다 저장된 모든 레코드를 다시 정렬하는 구현을 구별하기 위한 규모다. 파일 조회 수는 4.5의 논리 단위로 비교하며, 실제 파일 입출력 속도나 특정 거짓 양성 비율을 합격 기준으로 삼지 않는다.
