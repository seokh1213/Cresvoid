# 2단계: 부모와 자식의 수명

## 1. 개요

[1.1] 1단계 실행기에 `JOIN`, `SCOPE`, 지연 시작, 상태 조회와 문맥 상속을 더하라. 부모가 자식을 기다리는 기본 규칙과 기존 명령의 출력은 1단계 그대로다. 새 기능도 실제 중단 가능한 작업과 그 Job의 수명으로 구현하라.

## 2. 배경 개념

[2.1] Job은 코루틴의 실행 상태와 부모·자식 관계를 나타낸다. 본문이 끝난 시점과 자식까지 모두 끝나 Job이 완료된 시점은 다를 수 있다. `JOIN`은 본문만이 아니라 Job의 완료를 기다린다. 작업을 시작하기 전 상태도 Job에 포함된다.

[2.2] 코루틴 문맥은 작업과 함께 전달되는 값들의 모음이다. 자식은 부모 문맥을 물려받고, 같은 키의 값을 넘겨 받으면 그 키만 바꾼다. 이 과제의 `tag`와 `trace`는 문맥 상속을 확인하기 위한 두 개의 독립된 키다.

[2.3] 지연 시작 작업은 만들 때는 Job을 갖지만 아직 본문을 실행하지 않는다. 시작을 요청하거나 그 완료를 기다리는 순간 시작된다. 이 단계는 한 스레드에서만 실행하므로 상태 읽기와 시작 요청의 순서를 이벤트 루프가 정한다.

## 3. 입출력 규칙

[3.1] 1단계 [3.1]~[3.5]를 따른다. `ROOT <정의> <인스턴스> [tag=<값>] [trace=<값>]`에 문맥 값을 적을 수 있다. 생략한 키는 `-`이며 한 줄에서 같은 키를 두 번 적을 수 없다. 값은 1단계 [3.2]의 값 형식이다.

[3.2] `SPAWN <정의> <자식 이름> [LAZY] [tag=<값>] [trace=<값>]`을 허용한다. `LAZY`가 없으면 1단계처럼 곧바로 시작 대기열에 들어간다. 문맥 값은 키별로 부모 값을 물려받고, 명령에 적힌 키만 덮어쓴다. 선택 인자는 `LAZY`, `tag`, `trace` 순서로 적는다.

[3.3] 새 출력 사건은 `STATE <자식 이름> <상태>`와 `CONTEXT <키> <값>`이다. 상태는 `NEW`, `ACTIVE`, `COMPLETING`, `COMPLETED` 가운데 하나다. 사건의 시각과 경로는 1단계 [3.5]를 따른다.

## 4. 명령과 수명 규칙

[4.1] `STATE <자식 이름>`은 그 시점의 자식 Job 상태를 출력한다. `NEW`는 지연 시작 전, `ACTIVE`는 시작 요청 이후 본문이 아직 끝나지 않은 상태, `COMPLETING`은 본문은 끝났지만 자식이 남은 상태, `COMPLETED`는 `DONE` 사건을 낸 뒤의 상태다. 준비 큐에만 들어 있고 `START`를 아직 내지 않은 작업도 `ACTIVE`다.

[4.2] `START <자식 이름>`은 `NEW`인 자식의 시작 continuation을 준비 큐 끝에 넣고 곧바로 돌아온다. 이미 시작했거나 완료한 자식에게는 아무 일도 하지 않는다. 지연 시작 자식도 부모의 자식으로 등록되므로 부모 완료에는 포함된다. 모든 지연 시작 자식은 그 부모 본문의 끝에 도달하기 전에 `START`, `JOIN`, `AWAIT` 중 하나로 시작해야 한다.

[4.3] `JOIN <자식 이름>`은 `NEW` 자식을 먼저 시작하고 그 Job이 완료할 때까지 중단한다. 이미 완료했으면 중단 없이 돌아온다. `LAUNCH`와 `ASYNC` 자식 모두 기다릴 수 있고 성공 결과는 출력하지 않는다. 이 단계에는 실패와 취소가 없으므로 완료 뒤 항상 다음 명령을 실행한다.

[4.4] `SCOPE <정의> <자식 이름> [tag=<값>] [trace=<값>]`은 `LAUNCH` 정의를 자식으로 시작하고 그 Job이 완료할 때까지 현재 작업을 중단한다. `SPAWN` 후 즉시 `JOIN`한 것과 같은 시작·재개 순서를 따른다. 스코프 본문에서 만든 손자도 스코프 Job이 완료하기 전에 끝나야 한다. `SCOPE`도 형제 사이에 고유한 자식 이름을 쓴다.

[4.5] `CONTEXT <tag|trace>`는 현재 작업 문맥의 해당 값을 출력한다. 루트에서 넘기지 않은 값은 `-`다. 자식이 덮어쓰지 않은 키는 부모의 값을 그대로 읽는다. 어느 작업의 덮어쓰기도 부모나 형제의 문맥을 바꾸지 않는다.

[4.6] 자식의 `DONE` 뒤 대기 중인 `JOIN`, `AWAIT`, `SCOPE` continuation을 등록 순서로 준비 큐 끝에 넣는다. 부모가 본문 끝에서 자식 완료만 기다리고 있었다면 마지막 자식의 `DONE` 다음에 부모의 `DONE`을 낸다. 1단계 [4.4]의 부모 완료 순서는 그대로다.

## 5. 오류 규칙

[5.1] 1단계 [5.1]~[5.3]을 따른다. 선택 인자의 순서·키·값이 틀리거나 `SCOPE`가 `ASYNC` 정의를 참조하면 `FORMAT`이다. 없는 자식을 `STATE`, `START`, `JOIN`에 적으면 `REFERENCE`다. `SCOPE`에서 자식 이름이 겹치면 `DUPLICATE`다.

[5.2] 지연 시작 자식이 부모 본문 끝까지 시작 명령을 만나지 않으면 해당 `SPAWN` 줄의 `REFERENCE`다. `JOIN`과 `AWAIT`가 시작 요청을 겸한다. `SCOPE`도 정의 참조 순환 검사에 포함한다. 오류를 찾는 줄 번호와 우선순위는 1단계 [5.3]을 따른다.

## 6. 예시

[6.1] 지연 시작 자식은 `START` 전에는 `NEW`다. 자식에게 덮어쓴 `tag`는 부모의 `tag`를 바꾸지 않는다.

```text
> TASK worker LAUNCH
> CONTEXT tag
> LOG work
> END
> TASK parent LAUNCH
> SPAWN worker w LAZY tag=child
> STATE w
> START w
> CONTEXT tag
> JOIN w
> END
> ROOT parent r tag=root
> RUN
0 r START
0 r STATE w NEW
0 r CONTEXT tag root
0 r.w START
0 r.w CONTEXT tag child
0 r.w LOG work
0 r.w DONE
0 r DONE
```

[6.2] 자식 본문이 끝나도 손자가 남아 있으면 자식 Job은 `COMPLETING`이다.

```text
> TASK leaf LAUNCH
> DELAY 2
> END
> TASK branch LAUNCH
> SPAWN leaf l
> END
> TASK parent LAUNCH
> SPAWN branch b
> DELAY 0
> STATE b
> JOIN b
> END
> ROOT parent r
> RUN
0 r START
0 r.b START
0 r STATE b COMPLETING
0 r.b.l START
2 r.b.l DONE
2 r.b DONE
2 r DONE
```

## 7. 검사 방식

[7.1] 1단계 입력 방식과 출력 비교 방식을 따른다. 1단계 테스트를 먼저 다시 실행한다. 고정 테스트는 지연 시작의 상태 전이, `JOIN`의 즉시 반환과 중단, 스코프의 손자 대기, 두 문맥 키의 상속과 독립적인 덮어쓰기, 잘못된 지연 시작을 확인한다.

[7.2] 대규모 입력은 약 10,000개 작업 인스턴스와 약 30,000개 본문 명령을 포함한다. 한 테스트 제한 시간은 15초이고 모범 풀이 목표는 3초 이하다. Job 완료를 확인할 때마다 모든 작업을 훑지 않아야 한다.
