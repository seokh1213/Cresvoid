# 읽을 때 모으기

## 1. 개요

[1.1] 1단계 프로그램에 READ 모드를 추가한다. WRITE 모드의 명령과 출력은 그대로 유지한다. READ 모드에서는 글쓰기 때 팔로워 피드에 복사하지 않고 피드를 요청할 때 작성자별 글을 모은다. 두 모드는 같은 관계와 글 이력에 대해 같은 글목록을 내지만 비용이 다르다.

## 2. 배경 개념

[2.1] 읽기 시 팬아웃(fanout on read)은 독자가 피드를 요청할 때 팔로우하는 작성자들의 글을 모으는 방식이다. 발행 시 팔로워별 복사를 하지 않아도 되지만 같은 독자가 피드를 반복 요청하면 그때마다 글을 모으는 비용을 낸다. 쓰기 빈도, 읽기 빈도, 팔로워 수에 따라 두 방식의 비용 차이가 달라진다.

[2.2] 작성자별 최신순과 여러 작성자를 합친 피드의 최신순은 구분해야 한다. 작성자마다 글 수와 시각 분포가 다르며 한 작성자의 글이 최종 피드 대부분을 차지할 수도 있다. 후보를 결합하는 방법은 직접 정한다.

[2.3] 후보 글 수와 최종 반환 글 수는 다르다. 여러 작성자의 후보 중 일부는 다른 작성자의 더 최신 글에 밀려나므로 반환하지 않아도 읽기비용에는 포함된다. 여기서의 비용은 방식 간 비교를 위한 정해진 단위이며 실행 시간이나 실제 CPU 명령 수를 측정하는 지표가 아니다.

## 3. 입출력 규칙

[3.1] 첫 줄에 `MODE READ <L>`을 추가로 허용한다. L의 범위와 나머지 입력 형식은 1단계와 같다. 한 실행에는 첫 줄 하나와 모드 하나만 있으며 실행 중 모드를 전환하지 않는다. WRITE와 READ의 상태를 공유하거나 파일에 저장하지 않는다.

## 4. 명령 규칙

[4.1] READ 모드의 FOLLOW는 1단계와 같은 관계를 만든다. 팔로우 직후의 FEED에는 그 작성자의 과거 글도 포함한다. 중복 팔로우, 자기 글 제외, 정렬과 길이 한도는 그대로 적용한다.

[4.2] READ 모드에서 성공한 POST는 원본에 글을 저장하고 `POSTED 0`을 출력한다. 팔로워별 피드에 글 ID를 넣는 비용이 없다는 뜻이며 원본 저장 비용이 0이라는 뜻은 아니다.

[4.3] READ 모드의 FEED는 현재 팔로우하는 작성자마다 최신 글을 최대 L개씩 후보로 삼고 후보 전체에서 최신 L개를 반환한다. 읽기비용은 작성자별 후보 수의 합이다. 출력 형식은 `FEED <읽기비용> <글목록>`으로 유지한다. 글목록은 같은 명령 이력을 WRITE 모드로 실행했을 때와 같아야 한다.

[4.4] 작성자 a의 원본 글 수를 n(a)라고 하면 READ 읽기비용은 현재 팔로우하는 모든 a에 대한 min(L, n(a))의 합이다. 결과를 더 일찍 결정할 수 있어 실제로 후보를 덜 방문한 구현도 이 값을 출력한다. 글이 없는 작성자나 팔로우하지 않는 작성자는 비용을 더하지 않는다. 읽기비용도 매 FEED별 값이며 누계가 아니다.

## 5. 오류 규칙

[5.1] READ 모드에도 1단계의 업무 오류와 상태 불변 규칙을 적용한다. 잘못된 구문은 여전히 검사하지 않는다. WRITE 모드의 기존 입력이 READ 모드의 비용 규칙을 따르게 바꾸지 않는다.

## 6. 예시

[6.1] 독자 1은 작성자 2의 후보 2개와 작성자 3의 후보 1개를 모은다. 그래서 첫 읽기비용은 3이지만 반환 글은 2개다. 같은 시각에는 ID 40이 30보다 먼저다. 마지막에는 과거 시각의 글 50이 작성자 3의 두 번째 후보가 되어 읽기비용이 늘어난다.

```text
입력
MODE READ 2
POST 10 2 50
POST 20 2 100
POST 30 2 100
POST 40 3 100
FOLLOW 1 2
FOLLOW 1 3
FEED 1
FOLLOW 1 3
POST 50 3 10
FEED 1
FEED 2

출력
POSTED 0
POSTED 0
POSTED 0
POSTED 0
FOLLOWED
FOLLOWED
FEED 3 40,30
UNCHANGED
POSTED 0
FEED 4 40,30
FEED 0 NONE
```

[6.2] 위 입력의 첫 줄만 `MODE WRITE 2`로 바꾸면 두 FEED 1의 출력은 모두 `FEED 2 40,30`이고 마지막 POST는 `POSTED 1`이다. 나머지 출력은 같다. 후보 중 최종 결과에서 탈락한 글도 READ 비용에는 포함된다는 차이다.

## 7. 검사 방식

[7.1] 1단계의 표준 입력 전달, 출력 비교, 종료 코드, 30초 제한과 64MiB 출력 상한을 유지한다. READ 모드 검사를 추가하며 WRITE 모드의 이전 검사도 모두 통과해야 한다.

[7.2] 사용자·글·관계·명령·FEED 개수의 상한은 1단계와 같다. READ 모드에서는 POST의 쓰기비용이 항상 0이므로 WRITE 모드에 정한 쓰기비용 합 상한으로 발행량을 제한하지 않는다. 새 FOLLOW마다 min(L, 해당 작성자의 글 수)를 합산한 값은 최대 2,000,000이고, 모든 FEED의 READ 읽기비용 합은 최대 5,000,000이다.

[7.3] 대규모 READ 검사는 최대 100,000개의 글을 가진 작성자, 그 작성자를 팔로우하는 최대 40,000명의 사용자와 최대 50,000회의 FEED를 포함하며 7.2의 합계 상한을 지킨다. 원본 이력은 길지만 작성자별 후보는 L개 이하인 경우를 검사한다. 매 읽기마다 원본 전체를 모아 정렬하는 구현과 후보 수에 맞춰 처리하는 구현을 구분하는 규모다. 작성자 1,000명의 글이 계속 추가되는 동안 반복해서 피드를 요청하는 경우도 포함한다. 반복 읽기, 글 없는 작성자, 후보 수와 반환 수의 차이도 검사한다.
