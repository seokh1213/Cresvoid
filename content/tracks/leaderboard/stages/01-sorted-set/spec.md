# 점수 갱신과 순위

## 1. 개요

[1.1] 게임의 실시간 순위표를 만든다. 사용자의 점수를 더하거나 새 값으로 설정하고 명령이 끝난 직후의 순위를 조회한다. 점수가 같은 사용자에게도 서로 다른 순위를 부여하며 현재 점수에 먼저 도달한 사용자가 앞선다.

[1.2] 이 단계는 하나의 메모리 내 순위표를 다룬다. 외부 Redis 서버, 파일 저장, 동시 요청 처리는 필요하지 않다. Kotlin 표준 라이브러리와 JDK 21만 사용한다. 목표 풀이 시간은 약 2시간이다.

## 2. 배경 개념

[2.1] 정렬 집합은 사용자처럼 중복되지 않는 식별자에 점수를 붙이고 점수에 따른 순서를 유지하는 집합이다. 점수가 갱신되면 같은 사용자 한 명의 위치가 달라진다. 새 점수를 별도의 사용자처럼 추가하는 것은 아니다. 사용자가 n명일 때 어떤 사용자의 순위는 그 사용자보다 앞선 사용자 수에 1을 더한 값이다.

[2.2] 이 순위표의 순서는 점수 내림차순, 현재 점수에 도달한 순서 오름차순이다. 동점자가 셋이라도 순위는 1위, 2위, 3위처럼 이어진다. 공동 순위나 건너뛰는 순위는 쓰지 않는다. 도달 순서는 벽시계 시각이 아니라 입력 명령의 처리 순서로 판단한다.

[2.3] 같은 점수로 돌아오는 일과 그 점수에 계속 머무르는 일은 다르다. 100점에서 80점으로 내려갔다가 100점으로 돌아온 사용자는 이번에 100점에 도달한 것이다. 반면 100점인 사용자에게 다시 100점을 설정하는 명령은 새 도달로 보지 않는다. 과거에 처음 기록한 100점의 시각을 영구히 우선하는 규칙은 아니다.

[2.4] 실제 Redis 정렬 집합은 같은 점수의 멤버를 멤버 문자열의 사전식 순서로 정렬한다. 따라서 Redis의 기본 동점 규칙과 이 과제의 규칙은 다르다. 공식 문서의 [정렬 집합 설명](https://redis.io/docs/latest/develop/data-types/sorted-sets/)과 [ZRANK 설명](https://redis.io/docs/latest/commands/zrank/)은 배경 자료다. 이 과제의 점수 방향, 1부터 시작하는 순위, 동점 규칙은 아래 계약을 따른다.

## 3. 입출력 규칙

[3.1] UTF-8 표준 입력을 EOF까지 한 줄씩 처리한다. 첫 줄에 명령 수를 쓰지 않는다. 줄 앞뒤의 ASCII 공백과 탭은 무시하고 토큰은 하나 이상의 ASCII 공백이나 탭으로 구분한다. 공백과 탭만 있는 줄은 무시한다. 명령 이름은 대문자이며 대소문자를 구분한다.

[3.2] 정수 토큰은 `0` 또는 맨 앞이 0이 아닌 십진 숫자열이며, 음수는 그 숫자열 앞에 `-` 하나를 붙인 꼴이다. `+1`, `01`, `-0`, 소수, 지수 표기는 허용하지 않는다. 사용자 ID는 1 이상 2,147,483,647 이하의 정수다. 점수와 ADD의 증감량은 각각 -1,000,000,000,000 이상 1,000,000,000,000 이하의 정수다.

[3.3] 프로세스를 시작하면 등록된 사용자가 없다. 사용자는 ADD나 SET으로만 등록된다. 아직 등록되지 않은 사용자는 점수 0인 사용자와 구별한다. 점수가 0이거나 음수인 사용자도 등록된 사용자이며 순위에 포함한다.

[3.4] 성공한 ADD와 SET은 아무것도 출력하지 않는다. RANK는 한 줄을 출력한다. 등록된 사용자의 출력은 `순위 점수`이며 두 값 사이에 공백 하나를 둔다. 등록되지 않은 사용자의 출력은 `(none)`이다. 출력 정수는 3.2의 표기를 따르고, 설명 문구나 프롬프트를 표준 출력에 쓰지 않는다.

## 4. 명령 규칙

[4.1] `ADD <사용자> <증감량>`은 등록된 사용자의 기존 점수에 증감량을 더한다. 등록되지 않은 사용자는 기존 점수를 0으로 보고 등록한다. 따라서 처음 받은 `ADD 7 0`은 사용자 7을 점수 0으로 등록한다. 점수가 허용 범위를 벗어나는 덧셈은 실패한다.

[4.2] `SET <사용자> <점수>`는 기존 점수와 관계없이 점수를 지정한 값으로 바꾸며, 등록되지 않은 사용자도 등록한다. ADD의 증감량과 SET의 점수에는 음수가 올 수 있다. 점수가 내려가도 등록 상태를 유지한다.

[4.3] 새 사용자를 등록하거나 기존 사용자의 점수를 실제로 바꾼 성공 명령은 그 사용자의 현재 점수 도달 순서를 새로 정한다. 같은 점수로 바뀐 다른 사용자들보다 뒤의 도달 순서를 받는다. 점수가 바뀌지 않은 ADD와 SET은 기존 도달 순서를 그대로 유지한다. 사용자 ID의 크기는 동점 순서에 영향을 주지 않는다.

[4.4] `RANK <사용자>`는 현재 순서를 기준으로 1부터 시작하는 순위와 점수를 출력한다. 조회는 사용자 등록, 점수, 도달 순서를 바꾸지 않는다.

## 5. 오류 규칙

[5.1] 알 수 없는 명령, 토큰 수가 맞지 않는 명령, 잘못된 정수 표기, 인자의 범위 위반, ADD 결과의 점수 범위 위반은 해당 줄에 대해 `ERR` 한 줄을 출력한다. 정수 토큰이 64비트 정수로도 표현되지 않으면 범위 위반이다. 빈 줄은 오류가 아니다.

[5.2] 실패한 명령은 사용자 등록, 점수, 도달 순서를 전혀 바꾸지 않는다. 오류 뒤의 다음 줄도 계속 처리하고 EOF에서 정상 종료한다. 잘못된 사용자 ID를 조회하는 것은 오류이며, 범위 안에 있지만 등록되지 않은 ID를 조회하는 것은 `(none)`이다.

## 6. 예시

[6.1] 다음 예시는 사용자 ID와 관계없는 동점 순서, 같은 점수 설정, 점수 하락 후 복귀를 보여 준다. 코드 블록의 입력과 출력 구분 표시는 실제 입출력에 포함하지 않는다.

```text
입력
SET 20 100
SET 3 100
RANK 20
RANK 3
SET 20 100
ADD 3 0
RANK 20
ADD 20 -20
RANK 20
ADD 20 20
RANK 20
RANK 3
RANK 99

출력
1 100
2 100
1 100
2 80
2 100
1 100
(none)
```

[6.2] 다음 예시에서 점수 범위를 벗어나는 ADD는 기존 점수를 보존하며, 0점 사용자도 순위를 가진다.

```text
입력
ADD 7 0
SET 2 -5
RANK 7
SET 9 1000000000000
ADD 9 1
RANK 9
ADD 4 01
RANK 4
RANK 2

출력
1 0
ERR
1 1000000000000
ERR
(none)
3 -5
```

## 7. 검사 방식

[7.1] 검사기는 테스트마다 새 프로세스를 실행하고 입력을 표준 입력으로 보낸 뒤 EOF로 닫는다. 초기 상태를 파일이나 다른 테스트에서 가져오지 않는다. 종료 코드는 0이어야 한다. 표준 출력은 기대 출력과 줄 단위로 비교한다. 각 줄 끝의 공백·탭·CR과 출력 끝의 빈 줄만 제거하며, 줄 안의 공백과 줄 순서는 그대로 비교한다. 표준 출력은 64MB 이하여야 한다.

[7.2] 일반 테스트의 실행 제한은 테스트당 30초이고 대규모 테스트는 테스트당 120초다. 빌드 시간은 제외하고, JVM 시작부터 EOF 이후 종료까지의 실행 시간을 잰다. 대규모 입력은 등록 사용자 최대 2,000,000명, 비어 있지 않은 입력 줄 최대 2,200,000개, RANK 최대 100,000개다. 입력 크기는 64MB 이하이며 이 수치들은 생성되는 입력의 상한이지 초과 입력에 대해 ERR을 요구하는 명령 규칙은 아니다.

[7.3] 대규모 테스트에는 많은 사용자를 등록한 뒤 점수 변경과 순위 조회를 반복하는 입력이 포함된다. 조회마다 모든 사용자를 정렬하거나 세는 구현은 이 규모를 처리하기 어렵다. 특정 자료구조나 공개 클래스 이름은 요구하지 않으며, 갱신과 조회가 섞인 입력에서도 제한 시간 안에 정확히 동작해야 한다.
