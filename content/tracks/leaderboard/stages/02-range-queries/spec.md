# 상위 N, 주변 순위, 기간별 순위표

## 1. 개요

[1.1] 1단계의 순위표에 상위 사용자와 내 주변 사용자를 조회하는 기능을 더한다. 별도 이름을 가진 순위표를 만들고 기간 경계나 명시적 초기화에 따라 참가 기록을 비운다. 목표 풀이 시간은 약 2시간이다.

[1.2] 1단계의 ADD, SET, RANK와 입출력·점수·동점·오류 규칙은 그대로 유지한다. 기존 순위표의 이름은 `all`이며, 프로세스 시작부터 존재하고 자동으로 만료되지 않는다. 기존 세 명령은 항상 all에만 적용한다. 새 명령의 성공은 명시된 조회 외에는 출력하지 않는다.

## 2. 배경 개념

[2.1] 상위 N 조회는 정렬된 순서의 처음 일부를 반환한다. 주변 조회는 특정 사용자의 현재 순위를 중심으로 앞뒤의 일부를 반환한다. 주변에 동점자가 있더라도 점수 구간으로 넓히지 않고 도달 순서까지 적용한 개별 순위를 기준으로 자른다. 반환되는 순위는 전체 순위표에서의 순위다.

[2.2] 기간별 순위표에는 고정 길이의 구간이 연속해서 놓인다. 길이가 p초이면 기간은 `[0,p)`, `[p,2p)`처럼 시작을 포함하고 끝을 제외한다. 점수는 현재 기간에 속하며 기간이 바뀌면 이전 참가 기록을 이어받지 않는다. 이 과제는 과거 기간을 조회하거나 이동 창으로 점수를 합산하지 않는다.

[2.3] 시각은 입력으로 움직이는 가상 시계다. 명령 처리에 실제 시간이 얼마나 걸렸는지는 기간과 관계없다. 여러 명령의 가상 시각이 같아도 도달 순서는 입력 순서로 구분한다. 고정 기간의 원점은 각 순위표를 만든 시각이 아니라 가상 시각 0이다.

## 3. 입출력 규칙

[3.1] 새 명령은 `CREATE <순위표> <기간초>`, `TICK <시각>`, `BADD <순위표> <사용자> <증감량>`, `BSET <순위표> <사용자> <점수>`, `BRANK <순위표> <사용자>`, `TOP <개수>`, `AROUND <사용자> <반경>`, `BTOP <순위표> <개수>`, `BAROUND <순위표> <사용자> <반경>`, `RESET <순위표>`다. 꺾쇠로 표시한 인자는 각각 토큰 하나다.

[3.2] 순위표 이름은 소문자 영문자로 시작하고 뒤에 소문자 영문자, 숫자, 밑줄이 올 수 있으며 총 길이는 1~16자다. all도 이 이름 규칙을 따른다. 기간초와 시각은 각각 0 이상 1,000,000,000,000 이하의 정수다. 개수는 0 이상 1,000 이하이고 반경은 0 이상 500 이하의 정수다. 모든 숫자는 1단계의 정수 표기 규칙을 따른다.

[3.3] BRANK의 출력은 RANK와 같은 `순위 점수` 또는 `(none)`이다. TOP, AROUND, BTOP, BAROUND는 각각 한 줄을 출력한다. 반환할 사용자가 없으면 `(none)`을 출력한다. 있으면 전체 순위 오름차순으로 `순위:사용자:점수` 항목을 공백 하나로 잇는다. 콜론 앞뒤에는 공백을 쓰지 않는다.

## 4. 명령 규칙

[4.1] `CREATE <순위표> <기간초>`는 비어 있는 순위표를 만든다. 같은 이름이 이미 있으면 실패한다. 기간초가 0이면 자동 만료가 없고, 양수 p이면 현재 가상 시각 t가 속한 기간 `[floor(t/p)×p, (floor(t/p)+1)×p)`의 순위표로 시작한다. 프로세스 시작 시 가상 시각은 0이다.

[4.2] `TICK <시각>`은 가상 시각을 지정한 절대값으로 옮긴다. 현재 시각과 같은 값도 허용하며 과거로 옮기면 실패한다. 시각이 바뀌면 각 기간 순위표에서 이전 시각의 기간 번호와 새 시각의 기간 번호를 비교한다. 번호가 다르면 그 순위표의 모든 사용자를 제거한다. 기간을 여러 개 건너뛰어도 새 기간은 비어 있다. 기간초 0인 순위표와 all은 TICK으로 초기화하지 않는다.

[4.3] `BADD <순위표> <사용자> <증감량>`과 `BSET <순위표> <사용자> <점수>`는 지정한 순위표에서 각각 ADD와 SET의 동작을 한다. `BRANK <순위표> <사용자>`는 그 순위표에서 RANK의 동작을 한다. all을 지정해도 된다. 같은 사용자 ID가 여러 순위표에 있어도 점수, 등록 여부, 도달 순서는 순위표마다 독립적이다. all의 점수 변경을 다른 순위표로 복사하지 않는다.

[4.4] `TOP <개수>`는 all의 상위 개수 명을 반환한다. `BTOP <순위표> <개수>`는 지정한 순위표에서 같은 조회를 한다. 개수가 사용자 수보다 크면 있는 사용자만 반환한다. 개수가 0이면 순위표가 비어 있지 않아도 `(none)`이다.

[4.5] `AROUND <사용자> <반경>`은 all에서 사용자의 순위를 r이라고 할 때 `[max(1,r-반경), min(사용자수,r+반경)]`의 사용자를 양 끝을 포함해 반환한다. `BAROUND <순위표> <사용자> <반경>`은 지정한 순위표에서 같은 조회를 한다. 반경 0이면 사용자 자신만 반환한다. 중심 사용자가 등록되지 않았으면 다른 사용자가 있어도 `(none)`이다. 양 끝에서 잘린 수만큼 반대편을 더 채우지 않는다.

[4.6] `RESET <순위표>`는 지정한 순위표의 모든 사용자와 도달 순서를 제거한다. 이름과 기간초, 가상 시각은 유지하며 기간 경계의 원점을 옮기지 않는다. 비어 있는 순위표를 초기화해도 성공한다. all도 초기화할 수 있다. 초기화되거나 기간이 바뀐 뒤의 첫 ADD는 기존 점수를 0으로 보고 새로 등록한다. 다시 등록된 사용자는 그때의 명령 순서에 따라 새 도달 순서를 받는다.

[4.7] 조회 명령은 점수와 도달 순서를 바꾸지 않는다. 같은 기간 안의 TICK, 같은 시각의 TICK도 도달 순서를 바꾸지 않는다. 이 단계에서 순위표를 삭제하거나 기존 순위표의 기간초를 변경하는 명령은 없다.

## 5. 오류 규칙

[5.1] 1단계의 오류 조건에 더하여 잘못된 순위표 이름, 중복 CREATE, 존재하지 않는 순위표를 대상으로 하는 명령, 인자 범위 위반, 과거 시각을 지정한 TICK은 `ERR` 한 줄을 출력한다. CREATE all은 중복 생성 오류다. 존재하지 않는 순위표의 BTOP 개수가 0이어도 오류다.

[5.2] 실패한 명령은 모든 순위표와 가상 시각을 그대로 유지한다. 실패한 BADD나 BSET은 새 사용자를 남기지 않는다. TICK이 실패하면 기간 만료도 일어나지 않는다. 이후 입력은 계속 처리한다.

## 6. 예시

[6.1] 다음 예시는 순위 범위를 양 끝에서 자르는 방식과 all을 초기화하는 동작을 보여 준다.

```text
입력
SET 8 90
SET 2 90
SET 6 120
SET 4 -5
TOP 3
AROUND 8 1
AROUND 6 2
AROUND 2 0
TOP 0
RESET all
RANK 8

출력
1:6:120 2:8:90 3:2:90
1:6:120 2:8:90 3:2:90
1:6:120 2:8:90 3:2:90
3:2:90
(none)
(none)
```

[6.2] 다음 예시는 시각 7에 만든 10초 순위표가 시각 10에서 비워지는 동작을 보여 준다. 시각 9의 RESET은 다음 경계를 19로 미루지 않는다. all의 사용자 20은 다른 순위표의 초기화와 관계없이 남는다.

```text
입력
SET 20 500
TICK 7
CREATE daily 10
BSET daily 20 8
BSET daily 3 8
BTOP daily 5
TICK 9
RESET daily
BADD daily 3 2
BADD daily 20 2
BAROUND daily 20 1
TICK 10
BRANK daily 3
RANK 20
BADD daily 20 0
TICK 9
BRANK daily 20
TICK 30
BTOP daily 1
BTOP missing 0

출력
1:20:8 2:3:8
1:3:2 2:20:2
(none)
1 500
ERR
1 0
(none)
ERR
```

## 7. 검사 방식

[7.1] 1단계의 표준 입력 방식, 새 프로세스의 초기 상태, 종료 코드, 줄 단위 출력 비교 규칙을 그대로 적용한다. 이전 단계의 테스트도 회귀 검사로 실행한다. 시계는 TICK으로만 움직이며 검사기의 실제 시각은 사용하지 않는다.

[7.2] 일반 테스트의 실행 제한은 테스트당 30초이고 대규모 테스트는 테스트당 120초다. 빌드 시간은 제외한다. 대규모 입력은 all을 포함해 순위표 최대 32개, 모든 순위표를 합한 동시 등록 항목 최대 2,000,000개, 비어 있지 않은 입력 줄 최대 2,300,000개, 순위·범위 조회 합계 최대 100,000개다. 같은 ID가 두 순위표에 등록되면 두 항목으로 센다. 누적 반환 항목 수는 최대 500,000개이고 입력과 출력은 각각 64MB 이하다. 이 규모는 검사 입력의 상한이며 순위표 개수 초과 같은 별도 ERR 규칙을 요구하지 않는다.

[7.3] 대규모 테스트는 큰 순위표에서 갱신과 짧은 범위 조회를 반복한다. 범위의 시작 순위가 순위표 뒤쪽에 있는 주변 조회도 포함한다. 매번 전체 사용자를 정렬하거나 처음부터 순위를 세는 구현은 제한 시간을 넘길 수 있다. 기간 경계를 건너는 초기화와 명시적 초기화도 확인하되, 특정한 내부 초기화 방법은 요구하지 않는다.
