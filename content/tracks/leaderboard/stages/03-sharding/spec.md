# 샤딩과 전체 순위 비용

## 1. 개요

[1.1] 각 순위표의 사용자를 여러 샤드에 나누고, 점수 구간 분할과 사용자 ID 해시 분할에서 전체 순위를 계산한다. 두 배치를 함께 유지하여 같은 사용자 집합을 서로 다른 관점에서 조회한다. 전체 순위뿐 아니라 샤드별로 앞선 사용자 수와 논리적 조회 횟수를 출력해 비용 차이를 확인한다. 목표 풀이 시간은 2~3시간이다.

[1.2] 앞 단계의 모든 명령과 출력은 유지한다. 새 명령은 기존 순위표를 대상으로 하는 배치 설정과 샤드 조회이며 새 점수표를 만들지는 않는다. 외부 서버나 네트워크 연결 없이 한 프로세스 안에서 실행한다. 실제 지연 시간이나 CPU 명령 수는 출력하지 않는다.

## 2. 배경 개념

[2.1] 샤딩은 하나의 사용자 집합을 여러 부분으로 나누는 것이다. 샤드 안의 순서는 앞 단계와 같은 점수 내림차순, 현재 점수 도달 순서 오름차순이다. 전체 순위를 얻으려면 대상 사용자보다 앞선 사용자가 각 샤드에 몇 명인지 알아야 한다. 이 수들을 합하고 1을 더하면 전체 순위가 된다. 샤드 안의 순위와 전체 순위는 다를 수 있다.

[2.2] 점수 구간 분할은 낮은 점수부터 높은 점수까지 연속된 구간을 서로 다른 샤드에 배정한다. 같은 점수의 사용자는 같은 샤드에 모인다. 대상 샤드보다 높은 구간의 사용자는 모두 대상 사용자보다 앞서고, 낮은 구간의 사용자는 모두 뒤선다. 특정 점수대에 사용자가 몰리면 샤드별 인원이 크게 달라질 수 있다.

[2.3] 해시 분할은 사용자 ID로 샤드를 고른다. 점수가 바뀌어도 사용자의 샤드는 바뀌지 않지만 어떤 샤드에도 높은 점수와 낮은 점수가 함께 있을 수 있다. 샤드별 인원만으로는 각 샤드에서 대상보다 앞선 사용자 수를 알 수 없다. 대상과 같은 점수가 다른 샤드에 있어도 원래의 도달 순서를 적용해야 한다.

[2.4] 이 과제의 비용은 정해진 조회 모델에 따른 논리적 샤드 호출 수다. 조정자는 사용자 ID로 현재 점수와 도달 순서를 찾을 수 있고, 샤드별 인원과 구간 경계를 이미 알고 있다고 가정한다. 이 정보 조회와 정수 합산은 샤드 호출에 포함하지 않는다. 점수 구간 방식은 대상 샤드에 한 번 묻고 높은 구간의 인원은 조정자의 정보로 더한다. 해시 방식은 모든 샤드에 대상보다 앞선 사용자 수를 한 번씩 묻는다. 이 모델은 네트워크 지연이나 실제 서비스의 보편적인 비용을 나타내는 수치가 아니다.

## 3. 입출력 규칙

[3.1] 새 명령은 `DISTRIBUTE <순위표> <샤드수> <경계1> ... <경계k-1>`, `DRANK <순위표> <방식> <사용자>`, `DCOUNTS <순위표> <방식>`이다. 방식 토큰은 `RANGE` 또는 `HASH`이며 대소문자를 구분한다. 순위표 이름, 사용자 ID, 정수 표기는 앞 단계 규칙을 따른다.

[3.2] 샤드수 k는 1 이상 32 이하의 정수다. DISTRIBUTE에는 경계가 정확히 k-1개 있어야 하며, k가 1이면 경계 토큰이 없다. 각 경계는 점수와 같은 허용 범위의 정수이고 앞 경계보다 엄격히 커야 한다. 샤드 번호는 0부터 k-1까지다.

[3.3] 성공한 DISTRIBUTE는 출력하지 않는다. DCOUNTS는 샤드 번호 오름차순으로 각 샤드의 인원을 쉼표 하나로 이어 한 줄로 출력한다. 빈 샤드는 0으로 표시하고 쉼표 앞뒤에는 공백을 쓰지 않는다. 비어 있는 순위표도 k개의 0을 출력한다.

[3.4] 등록된 사용자의 DRANK 출력은 `전체순위 점수 호출수 기여량목록`이다. 필드 사이에는 공백 하나를 쓴다. 기여량목록은 샤드 번호 오름차순으로 대상 사용자보다 앞선 사용자 수를 쉼표로 이은 것이다. 대상 자신은 어느 기여량에도 포함하지 않는다. 등록되지 않은 사용자는 `(none)` 한 줄만 출력하며 호출수나 기여량은 출력하지 않는다.

## 4. 명령 규칙

[4.1] 프로세스 시작 시 어떤 순위표에도 샤드 배치 설정이 없다. `DISTRIBUTE <순위표> <샤드수> <경계1> ... <경계k-1>`은 존재하는 순위표의 현재 사용자들을 RANGE와 HASH 두 방식으로 각각 배치한다. 한 사용자는 각 방식에서 정확히 한 샤드에 속한다. 한 번의 명령으로 두 방식의 샤드수를 같은 k로 설정한다. 이미 설정되어 있으면 두 배치를 모두 새 설정으로 교체한다.

[4.2] RANGE의 샤드 0은 경계1보다 작은 점수, 중간 샤드 i는 경계i 이상 경계i+1 미만인 점수, 마지막 샤드 k-1은 경계k-1 이상인 점수를 맡는다. 즉 점수가 경계와 같으면 그 경계의 높은 쪽 샤드에 속한다. k가 1이면 모든 점수가 샤드 0에 속한다. 점수가 내려가거나 올라가 구간을 벗어나면 새 점수의 샤드로 이동한다.

[4.3] HASH에서 사용자 u의 샤드는 u를 k로 나눈 나머지다. 사용자 ID가 양수이므로 결과는 0 이상 k-1 이하다. 별도의 문자열 해시나 난수는 사용하지 않는다. 경계 토큰은 HASH 배치에 영향을 주지 않는다.

[4.4] `DRANK <순위표> <방식> <사용자>`는 해당 배치에서 전체 순위와 각 샤드의 기여량을 구한다. 기여량은 점수가 더 높은 사용자 수에, 점수가 같고 현재 점수 도달 순서가 더 앞선 사용자 수를 더한 값이다. 전체순위는 모든 기여량의 합에 1을 더한 값이며 BRANK와 같아야 한다. all에 대해서는 RANK와도 같아야 한다.

[4.5] 등록된 사용자의 DRANK 호출수는 RANGE이면 1, HASH이면 k다. HASH의 빈 샤드도 한 번 호출한 것으로 센다. RANGE 기여량목록에서 대상보다 높은 구간은 해당 샤드의 전체 인원, 낮은 구간은 0, 대상 구간은 그 샤드 안에서 앞선 인원이다. HASH 기여량목록에서는 각 샤드에 있는 사용자를 전체 순서와 비교한다. 호출수는 이 계약의 모델로 산출하며, 반복 조회라고 줄이거나 재배치 비용을 더하지 않는다.

[4.6] `DCOUNTS <순위표> <방식>`은 현재 배치의 인원을 출력한다. 이후의 ADD, SET, BADD, BSET은 원래 순위표와 이미 설정된 두 배치에 함께 반영한다. 실패한 갱신은 어느 쪽에도 반영하지 않는다. 점수가 그대로인 갱신과 배치 재설정은 도달 순서를 바꾸지 않는다.

[4.7] RESET과 기간 경계는 원래 순위표와 두 배치의 사용자를 함께 비운다. 순위표 이름, 기간초뿐 아니라 샤드수와 경계 설정도 유지한다. 초기화 뒤 DISTRIBUTE를 다시 실행하지 않아도 DCOUNTS와 DRANK를 사용할 수 있고, 새 사용자는 기존 설정에 따라 배치된다. 배치 설정과 조회는 가상 시각이나 기간 경계를 바꾸지 않는다.

## 5. 오류 규칙

[5.1] 앞 단계의 오류 조건에 더하여 잘못된 방식, 샤드수 범위 위반, 경계 개수·범위·오름차순 위반, 배치 설정이 없는 순위표의 DRANK와 DCOUNTS는 `ERR` 한 줄을 출력한다. 배치가 없으면 대상 사용자가 등록되지 않았어도 DRANK는 오류다. 순위표 자체가 없을 때도 오류다.

[5.2] DISTRIBUTE가 실패하면 이전 설정과 두 배치를 모두 유지한다. 실패한 다른 명령도 원래 순위표, 두 배치, 도달 순서, 가상 시각을 바꾸지 않는다. k가 1일 때 경계를 하나라도 주면 토큰 수 오류다.

## 6. 예시

[6.1] 다음 예시는 경계 100이 높은 구간에 포함되고, 다른 해시 샤드의 동점자도 도달 순서로 비교되는 경우다. 마지막 두 조회는 점수가 내려가 샤드가 이동한 뒤의 결과다.

```text
입력
SET 8 100
SET 2 100
SET 6 120
SET 4 -5
SET 5 0
DISTRIBUTE all 3 0 100
DCOUNTS all RANGE
DCOUNTS all HASH
DRANK all RANGE 2
DRANK all HASH 2
DRANK all RANGE 5
DRANK all HASH 5
ADD 8 -101
DCOUNTS all RANGE
DRANK all RANGE 2
DRANK all HASH 8

출력
1,1,3
1,1,3
3 100 1 0,0,2
3 100 3 1,0,1
4 0 1 0,0,3
4 0 3 1,0,2
2,1,2
2 100 1 0,0,1
4 -1 3 1,0,2
```

[6.2] 다음 예시는 잘못된 재설정의 원자성과 기간 경계 뒤에도 남는 배치 설정을 보여 준다. 빈 해시 샤드도 호출수에 포함한다.

```text
입력
CREATE sprint 10
BSET sprint 7 10
DRANK sprint RANGE 7
DISTRIBUTE sprint 2 10
DISTRIBUTE sprint 3 10 10
DRANK sprint HASH 7
TICK 10
DCOUNTS sprint RANGE
DRANK sprint HASH 7
BADD sprint 8 0
DCOUNTS sprint HASH
DRANK sprint HASH 8
DISTRIBUTE sprint 1
DRANK sprint RANGE 8

출력
ERR
ERR
1 10 2 0,0
0,0
(none)
1,0
1 0 2 0,0
1 0 1 0
```

## 7. 검사 방식

[7.1] 앞 단계의 표준 입력 방식, 새 프로세스 초기 상태, 종료 코드와 줄 단위 출력 비교 규칙을 그대로 적용한다. 앞 단계 테스트도 회귀 검사로 실행한다. 검사기는 DRANK의 전체 순위뿐 아니라 호출수와 샤드별 기여량, DCOUNTS의 배치 인원을 비교한다. 실제 네트워크 호출이나 시간 측정값을 출력할 필요는 없다.

[7.2] 일반 테스트의 실행 제한은 테스트당 30초이고 대규모 테스트는 테스트당 120초다. 빌드 시간은 제외한다. 대규모 입력은 순위표 최대 32개, 모든 원본 순위표를 합한 동시 등록 항목 최대 2,000,000개, 비어 있지 않은 입력 줄 최대 2,400,000개, 앞 단계 조회와 DRANK·DCOUNTS를 합한 조회 최대 100,000개다. 두 배치의 사본은 원본 항목 수에 중복해서 세지 않는다. 범위 조회의 누적 반환 항목 수는 최대 500,000개이며 입력과 출력은 각각 64MB 이하다.

[7.3] 한 테스트에서 성공한 모든 DISTRIBUTE에 대해 그 명령 직전 대상 순위표의 사용자 수를 합한 값은 최대 4,000,000이다. 실패한 DISTRIBUTE는 이 합계에서 제외한다. 빈 순위표에서 설정하고 이후 사용자를 추가하는 입력도 포함한다. 이 제한과 7.2의 수치는 검사 입력의 상한이며 초과 입력용 오류 처리를 요구하지 않는다.

[7.4] 대규모 테스트에는 샤드 간 점수 이동, 여러 샤드에 걸친 동점, 한 구간에 사용자가 몰린 배치, 갱신과 DRANK의 반복이 포함된다. 샤드의 앞선 사용자 수를 얻기 위해 매번 그 샤드 전체를 정렬하거나 세는 구현은 제한 시간을 넘길 수 있다. 내부 자료구조나 클래스 이름은 요구하지 않지만 두 방식의 결과와 비용 모델을 모두 만족해야 한다.
