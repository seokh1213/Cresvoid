# 선호 목록과 복제본 보충

## 1. 개요

[1.1] 2단계 프로그램에 서로 다른 물리 노드로 복제본을 배정하는 기능을 더한다. 새 명령은 REPLICAS와 FAIL이다. 이전 단계의 명령과 출력은 유지하며 같은 링과 등록 키 집합을 사용한다. 각 실행은 빈 상태에서 시작한다.

[1.2] REPLICAS는 키의 선호 목록을 조회한다. FAIL은 물리 노드를 제거하면서 제거 직후 목표 복제본 수보다 적어진 키, 살아남은 복제본의 노드, 새 배치 대상과 보충 후에도 남는 부족 수를 출력한다. FAIL은 제거한 노드를 별도 장애 목록에 보관하지 않으며 그 식별자는 나중에 ADD나 VADD로 다시 등록할 수 있다.

## 2. 배경 개념

[2.1] 키를 노드 하나에만 두면 그 노드가 사라졌을 때 다른 노드에 복사본이 남지 않는다. 복제는 같은 키를 여러 물리 노드에 두는 것이다. 여기서 목표 복제본 수 N은 첫 소유 노드의 복제본까지 포함하는 총개수다. 첫 소유 노드에 더해 N개를 고르는 뜻이 아니다.

[2.2] 선호 목록은 키 위치부터 링을 시계 방향으로 따라가며 고른 물리 노드의 순서다. 한 물리 노드에 가상 노드가 여러 개 있으므로 연속한 토큰 N개를 고르는 것만으로는 서로 다른 N개 노드를 얻는다고 보장할 수 없다. 이미 고른 물리 노드의 다른 토큰은 복제본 수를 늘리지 않는다.

[2.3] 노드를 제거하면 제거 직전의 복제본 중 일부가 사라진다. 남은 복제본 수는 제거 직후의 값으로, 새 배치를 마친 뒤의 복제본 수와 다르다. 새 노드를 보충할 수 있더라도 잠시 부족해진 키는 보고 대상이다. 남아 있는 물리 노드가 N개보다 적으면 보충 후에도 부족할 수 있다.

[2.4] 선호 목록에서 물리 노드 중복을 제외하는 배경은 [DeCandia 외, Dynamo, SOSP 2007, 4.3절](https://cdn.amazon.science/ac/1d/eb50c4064c538c8ac440ce6a1d91/dynamo-amazons-highly-available-key-value-store.pdf)에 있다. 실제 Dynamo의 선호 목록은 추가 장애 후보도 담는다. 이 과제의 목록에는 아래 규칙에 따른 최대 N개의 노드만 담으며 정족수, 임시 위탁 복제, 값의 버전 충돌은 다루지 않는다.

## 3. 입출력 규칙

[3.1] 이 문서는 이전 단계에 추가되는 규칙만 정의한다. 표준 입력의 줄 처리, H, 식별자와 토큰의 정렬, 빈 링, 나머지 배정은 이전 단계와 같다. N은 1~8의 정수이고 용량 인자와 같은 ASCII 숫자 표기를 쓴다. 선행 0은 허용하며 부호·소수점·지수 표기와 범위 밖의 값은 허용하지 않는다.

[3.2] 현재 링에서 키의 선호 목록 `P(키, N)`은 1단계의 링 소유 토큰부터 시작하여 2단계의 토큰 정렬 순서대로 시계 방향으로 진행하며 만든다. 물리 노드가 목록에 없을 때만 그 식별자를 뒤에 넣는다. 서로 다른 N개 노드를 얻거나 모든 토큰을 한 바퀴 확인하면 끝낸다. 마지막 토큰 다음은 첫 토큰이며 시작 토큰을 두 번 처리하지 않는다.

[3.3] 선호 목록의 길이는 `min(N, 현재 물리 노드 수)`다. 첫 원소는 링 소유 노드와 같고 나머지 원소도 선택된 순서 그대로다. 노드 식별자 사전순으로 다시 정렬하지 않는다. 같은 위치의 다른 물리 노드도 토큰 동점 순서대로 서로 다른 후보가 된다. 노드가 없으면 목록은 빈 목록이다.

[3.4] 출력의 노드 목록은 쉼표로 이어 붙인 식별자이며 쉼표 앞뒤에는 공백을 넣지 않는다. 빈 목록은 `-` 하나로 쓴다. LIVE, COPY와 REPLICAS에 쓰는 목록 모두 이 형식을 따른다. 부족 수는 항상 0 이상의 정수다.

[3.5] N은 그 명령에만 적용하는 비교 조건이다. 이전 REPLICAS나 FAIL의 N을 저장하거나 다음 명령에 물려주지 않는다. 각 명령 시작 시 현재 링의 P(키, N)에 복제본이 배정되어 있다고 가정하고 그 명령의 결과를 계산한다. 따라서 N이 다른 두 조회를 순서대로 실행해도 별도의 복제 설정 변경은 일어나지 않는다.

[3.6] 이 과제는 값이나 복제 전송 상태를 저장하지 않는 배치 모형이다. COPY는 새로 배치할 노드를 나타내며 실제 전송 가능성이나 데이터 보존을 보장하는 표시가 아니다. LIVE가 비어 있어도 COPY 대상을 계산한다. 키 목록은 별도로 유지하므로 노드가 모두 사라져도 키가 삭제되지는 않는다.

## 4. 명령 규칙

[4.1] `REPLICAS <키> <N>`은 등록된 키에 대해 `REPLICAS 키 목록 MISSING d` 한 줄을 출력한다. 목록은 현재의 P(키, N)이고 d는 N에서 그 목록의 길이를 뺀 값이다. 노드가 없어도 등록된 키라면 성공한다. 링이나 키 집합은 바꾸지 않는다.

[4.2] `FAIL <노드> <N>`은 있는 물리 노드의 모든 토큰을 제거한다. 먼저 제거 직전의 링에서 모든 등록 키의 P(키, N)을 정한다. 각 키의 이 목록을 B라고 한다. B에서 제거할 노드만 빼고 나머지 순서를 유지한 목록이 S다. S는 제거 직후 살아남은 복제본을 뜻한다.

[4.3] FAIL의 보고 대상은 S의 길이가 N보다 작은 모든 등록 키다. 제거 전부터 물리 노드가 부족했던 키도 제외하지 않는다. 반대로 제거한 노드가 B에 없고 S의 길이가 N이면 그 키는 보고하지 않는다. 이 판정은 새 복제본을 보충하기 전에 하므로 보충 후 부족 수가 0이 된 키도 보고한다.

[4.4] 노드를 제거한 뒤의 링에서 같은 N으로 구한 P(키, N)을 Q라고 한다. 새 배치 대상 C는 Q에서 S에 이미 들어 있는 노드를 제외한 목록이며 Q의 순서를 유지한다. 보충 후 부족 수 d는 `N - S의 길이 - C의 길이`다. 노드 제거만 일어난 이 명령에서는 S의 모든 노드가 Q에도 들어 있으므로 S와 C를 합한 노드 집합은 Q와 같다. LIVE는 S이고 COPY는 C다. S를 Q의 순서로 다시 정렬하지 않는다.

[4.5] FAIL 성공 응답의 첫 줄은 `FAILED 노드 REPAIRS r`이다. r은 4.3의 보고 대상 키 수다. 이어서 대상 키 사전순으로 r개의 `REPAIR 키 LIVE 목록 COPY 목록 MISSING d` 줄을 출력한다. 대상이 없으면 첫 줄만 출력한다. 이전 단계 REMOVE의 MOVED 헤더나 MOVE 줄은 이 응답에 덧붙이지 않는다.

[4.6] FAIL의 출력은 제거 직후의 S와 보충 대상으로 정한 C를 담는다. 다음 명령은 노드가 제거되고 배치가 끝난 링을 기준으로 실행하며 다시 옛 B나 S를 쓰지 않는다. N이 같으면 바로 뒤의 REPLICAS 목록은 Q가 된다. 이 명령은 노드 하나를 제거하기만 하므로 S 뒤에 C를 이어 붙인 목록도 Q와 같다.

[4.7] 마지막 노드를 FAIL로 제거하면 모든 등록 키가 보고 대상이다. LIVE와 COPY는 모두 `-`이고 d는 N이다. 키가 하나도 없으면 어떤 노드를 FAIL로 제거하든 `REPAIRS 0`이다. 두 경우 모두 노드 제거 자체는 성공한다.

[4.8] 기존 REMOVE는 계속 노드 제거에 따른 1차 소유 노드의 MOVE와 나머지 이동 수만 출력하고 복제본 보고를 덧붙이지 않는다. ADD·VADD·WEIGHT·REMOVE·FAIL이 끝난 뒤의 모든 조회는 현재 링을 기준으로 한다. 기존 LOAD는 1차 소유 노드별 키 수만 세며 복제본을 키수에 더하지 않는다.

## 5. 오류 규칙

[5.1] 새 명령의 인자 수나 식별자·N의 형식 또는 범위가 잘못되면 `ERROR INPUT`을 출력한다. 형식과 범위는 키나 노드의 존재 여부보다 먼저 검사한다. 오류가 난 FAIL은 노드를 제거하지 않는다.

[5.2] 형식이 올바른 REPLICAS의 키가 등록되지 않았으면 `ERROR KEY_MISSING`, FAIL의 노드가 없으면 `ERROR NODE_MISSING`을 출력한다. 오류 시 상태를 바꾸지 않고 성공 응답은 출력하지 않는다. 이전 단계의 오류 규칙도 그대로 유지한다.

## 6. 예시

[6.1] 첫 예시에서 a의 용량은 1, b의 용량은 2, c의 용량은 1이다. alpha의 H는 8235다. 그 위치 뒤에는 a의 토큰 여러 개가 먼저 나오지만 복제본 두 개는 a와 b다. gamma의 H는 43370이고 그 뒤 첫 토큰은 c의 인덱스 9 위치 44078, 그다음 다른 물리 노드의 첫 토큰은 b의 인덱스 11 위치 44408이다.

입력:

```text
VADD a 1
VADD b 2
VADD c 1
PUT alpha
PUT gamma
PUT b
REPLICAS alpha 2
REPLICAS gamma 2
FAIL b 2
REPLICAS alpha 2
REPLICAS gamma 3
FAIL a 3
FAIL c 2
REPLICAS b 2
OWNER b
```

출력:

```text
MOVED 0 MOD 0
MOVED 0 MOD 0
MOVED 0 MOD 0
KEY alpha a MOD a
KEY gamma c MOD c
KEY b b MOD b
REPLICAS alpha a,b MISSING 0
REPLICAS gamma c,b MISSING 0
FAILED b REPAIRS 3
REPAIR alpha LIVE a COPY c MISSING 0
REPAIR b LIVE a COPY c MISSING 0
REPAIR gamma LIVE c COPY a MISSING 0
REPLICAS alpha a,c MISSING 0
REPLICAS gamma c,a MISSING 1
FAILED a REPAIRS 3
REPAIR alpha LIVE c COPY - MISSING 2
REPAIR b LIVE c COPY - MISSING 2
REPAIR gamma LIVE c COPY - MISSING 2
FAILED c REPAIRS 3
REPAIR alpha LIVE - COPY - MISSING 2
REPAIR b LIVE - COPY - MISSING 2
REPAIR gamma LIVE - COPY - MISSING 2
REPLICAS b - MISSING 2
KEY b - MOD -
```

[6.2] 두 번째 예시는 N이 1일 때 제거된 노드에만 복제본이 있던 키의 배치 계획이다. LIVE가 비어도 새 위치를 COPY에 출력한다. 첫 FAIL의 N이 잘못되었으므로 그때 노드는 제거되지 않는다.

입력:

```text
ADD a
ADD b
PUT b
FAIL a 0
REPLICAS absent 2
FAIL b 1
REPLICAS b 1
FAIL b 1
LOAD
```

출력:

```text
MOVED 0 MOD 0
MOVED 0 MOD 0
KEY b b MOD b
ERROR INPUT
ERROR KEY_MISSING
FAILED b REPAIRS 1
REPAIR b LIVE - COPY a MISSING 0
REPLICAS b a MISSING 0
ERROR NODE_MISSING
LOAD 1 1
NODE a 1
RATIO 1.000000
```

## 7. 검사 방식

[7.1] 표준 입력의 명령을 EOF까지 처리하고 표준 출력을 비교한다. 1·2단계 테스트도 누적 실행한다. 출력 줄 끝의 공백·탭·CR과 끝의 빈 줄을 제거한 뒤 줄 수와 각 줄의 문자를 그대로 비교한다. REPAIR의 키 순서와 각 노드 목록의 순서도 비교 대상이다. 테스트마다 새 프로세스를 실행하며 빌드 시간을 제외한 실행 제한 시간은 각각 30초다.

[7.2] 한 테스트의 입력은 최대 4096줄, 현재 물리 노드는 최대 64개, 등록 키는 최대 512개다. 물리 노드당 토큰은 최대 128개이고 전체 토큰은 최대 8192개다. 성공한 ADD·REMOVE·VADD·WEIGHT·FAIL을 합쳐 구성 변경은 최대 256개이며 조회는 여기에 포함하지 않는다. N은 최대 8이다.

[7.3] 성능 차이를 강제하는 별도의 대규모 테스트는 두지 않으며 마지막 조합 테스트도 7.2의 한도 안에서 실행한다. 노드 추가·제거·용량 변경·키 등록과 복제 조회를 섞고 매번 전체 키를 재배정하는 계산으로 선호 목록과 보충 대상을 대조한다. 같은 물리 노드의 가상 노드 건너뛰기, 동점 토큰, 시작 위치로의 감김, 보충 직전과 직후의 부족 수 구분, N 변경, 마지막 노드 제거와 기존 명령의 회귀 테스트를 확인한다.
