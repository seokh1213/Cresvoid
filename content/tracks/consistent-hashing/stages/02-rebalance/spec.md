# 가상 노드와 용량 비례 배정

## 1. 개요

[1.1] 1단계 프로그램에 가상 노드로 물리 노드의 용량을 표현하는 기능을 더한다. 새 명령은 VADD, WEIGHT, LOAD다. 이전 단계의 명령과 출력 형식은 유지한다. 각 실행은 여전히 빈 노드 집합과 빈 키 집합에서 시작한다.

[1.2] ADD는 계속 토큰 하나인 노드를 만든다. VADD는 용량에 비례하는 여러 토큰을 가진 노드를 만들고, WEIGHT는 이미 있는 노드의 토큰 수를 바꾼다. 두 종류의 노드는 같은 물리 노드 집합과 같은 링을 공유한다. 별도의 링이나 별도의 키 집합을 만들지 않는다.

## 2. 배경 개념

[2.1] 노드 하나를 링의 한 점으로만 나타내면 우연히 긴 구간을 맡는 노드가 생길 수 있다. 가상 노드는 물리 노드 하나를 링의 여러 지점으로 나타낸 것이다. 여러 구간의 키가 한 물리 노드로 모이므로 물리 노드의 키 수는 그 노드가 가진 모든 토큰의 배정을 합한 값이다.

[2.2] 용량이 큰 물리 노드에 토큰을 더 많이 주면 그 노드가 더 많은 키를 맡도록 유도할 수 있다. 다만 유한한 토큰과 키의 분포에서 실제 키 수가 용량에 정확히 비례하지는 않는다. 가상 노드를 늘린 모든 입력에서 쏠림이 반드시 줄어드는 것도 아니다.

[2.3] 이 단계는 물리 노드별 키 수의 최댓값을 평균으로 나눈 비율을 관찰한다. 키가 특정 노드에 몰릴수록 비율은 커진다. 용량이 서로 다르면 큰 노드의 키 수가 더 큰 것이 의도된 결과일 수 있으므로, 이 비율을 용량 대비 이용률로 해석해서는 안 된다.

[2.4] 가상 노드와 용량에 따른 토큰 수의 배경은 [DeCandia 외, Dynamo, SOSP 2007, 4.2절](https://cdn.amazon.science/ac/1d/eb50c4064c538c8ac440ce6a1d91/dynamo-amazons-highly-available-key-value-store.pdf)에 있다. 토큰 수의 배수와 이름 생성 규칙은 아래에서 별도로 정한다.

## 3. 입출력 규칙

[3.1] 이 문서는 1단계에 추가되는 규칙만 정의한다. 입력 줄 처리, 식별자 문법, H, 소유 노드 판정, 나머지 배정, 오류 시 상태 보존과 출력 비교는 1단계 규칙을 따른다. 이후 문단의 토큰 수는 물리 노드 수와 구별한다.

[3.2] 용량 c는 1~8의 정수다. VADD 또는 WEIGHT로 정하는 토큰 수는 정확히 `16 × c`개다. 토큰 인덱스 i는 0부터 `16 × c - 1`까지다. 인덱스 0의 위치는 `H(노드 식별자)`이고, i가 1 이상이면 `H(노드 식별자 + "#" + i의 10진수 표기)`다. 인덱스 표기에 선행 0을 붙이지 않는다. #는 생성한 토큰 이름의 구분자이며 사용자 식별자에는 들어가지 않는다.

[3.3] 링의 모든 토큰은 위치 오름차순, 물리 노드 식별자 사전순, 토큰 인덱스의 정수 오름차순으로 정렬한다. 같은 위치에 같은 물리 노드의 토큰이 여럿 있어도 모두 유지한다. 키는 1단계와 같이 위치가 H(키) 이상인 첫 토큰을 고른다. 없으면 첫 토큰으로 감긴다. 소유 노드와 MOVE의 이전·새 노드는 물리 노드 식별자로 쓴다.

[3.4] 나머지 배정은 가상 노드 수나 용량을 사용하지 않는다. 현재의 물리 노드 식별자를 사전순으로 정렬하고 H(키)를 물리 노드 수로 나눈 나머지를 인덱스로 쓴다. 토큰 구성만 바꾼 WEIGHT는 나머지 배정을 바꾸지 않는다.

[3.5] 용량 인자는 ASCII 숫자 하나 이상으로만 이루어진다. 선행 0을 허용하므로 01과 1의 뜻은 같다. 부호, 소수점, 지수 표기와 1~8 범위 밖의 값은 허용하지 않는다. 출력에서는 수치에 선행 0을 쓰지 않는다.

## 4. 명령 규칙

[4.1] `VADD <노드> <용량>`은 없는 물리 노드를 3.2의 토큰들과 함께 추가한다. ADD와 VADD의 이름 공간은 같으므로 ADD로 만든 노드 이름으로 VADD할 수 없다. 성공 응답은 1단계 ADD와 같은 `MOVED r MOD m` 및 키 사전순의 `MOVE 키 이전노드 새노드` 줄이다. 변경 직전에 등록된 키를 대상으로 물리 소유 노드의 변화를 센다.

[4.2] `WEIGHT <노드> <용량>`은 있는 물리 노드의 토큰 집합을 3.2의 집합으로 교체한다. 다른 물리 노드의 토큰은 그대로 둔다. 토큰 하나인 ADD 노드에도 적용할 수 있으며 그때 용량 1은 토큰 16개를 뜻한다. 인덱스가 계속 존재하는 토큰의 이름과 위치는 유지된다. 토큰 집합이 이미 같으면 아무것도 바뀌지 않는다.

[4.3] WEIGHT의 성공 응답도 `MOVED r MOD m`과 이어지는 MOVE 줄이다. 물리 노드 집합이 같으므로 m은 항상 0이다. 키의 담당 토큰만 바뀌고 물리 소유 노드가 같으면 r에 포함하지 않는다. 같은 용량을 반복 지정한 경우에는 `MOVED 0 MOD 0` 한 줄을 출력한다.

[4.4] ADD는 여전히 인덱스 0인 토큰 하나만 만든다. 앞서 다른 노드에 적용한 WEIGHT나 VADD의 영향을 받아 토큰 수가 늘어나지 않는다. REMOVE는 지정한 물리 노드의 모든 토큰을 함께 제거한다. 이후 같은 식별자를 ADD하면 토큰 하나로 시작하며 VADD하면 그 명령에 지정한 용량으로 시작한다. OWNER와 PUT은 그 시점의 공통 링과 물리 노드 집합에서 정한 배정을 출력한다.

[4.5] `LOAD`는 첫 줄에 `LOAD n k`를 출력한다. n은 현재 물리 노드 수이고 k는 등록된 서로 다른 키 수다. 이어서 물리 노드 식별자 사전순으로 n개의 `NODE 노드 키수` 줄을 출력한다. 키수는 현재 그 물리 노드에 링 배정된 키 개수이며 0개인 노드도 출력한다. 마지막 줄에는 `RATIO 비율`을 출력한다. 상태는 바꾸지 않는다.

[4.6] n과 k가 모두 양수일 때 평균은 정확한 유리수 `k / n`이고 비율은 `키수의 최댓값 × n / k`다. 중간에 평균을 반올림하거나 정수로 버리지 않는다. 비율만 소수점 아래 6자리로 반올림하여 항상 6자리를 출력한다. 정확히 절반이면 큰 쪽으로 반올림한다. 소수점은 마침표이며 지수 표기는 쓰지 않는다. n 또는 k가 0이면 비율은 `0.000000`이다.

[4.7] LOAD의 k는 소유 노드가 없어도 등록된 키를 포함한다. 따라서 빈 링에 키가 있으면 `LOAD 0 k` 다음에 NODE 줄 없이 `RATIO 0.000000`을 출력한다. 노드는 있고 키가 없으면 모든 NODE 키수는 0이고 비율도 `0.000000`이다.

## 5. 오류 규칙

[5.1] VADD 또는 WEIGHT의 인자 수, 식별자나 용량 표기가 잘못되면 `ERROR INPUT`을 출력한다. LOAD에 인자를 붙여도 ERROR INPUT이다. 모든 형식·범위 검사는 노드의 존재 여부보다 우선한다.

[5.2] 형식이 올바른 VADD의 노드가 이미 있으면 `ERROR NODE_EXISTS`, WEIGHT의 노드가 없으면 `ERROR NODE_MISSING`을 출력한다. 오류 시 토큰, 키, 배정을 모두 보존하고 성공 응답은 출력하지 않는다. 기존 명령의 오류 규칙은 그대로 유지한다.

## 6. 예시

[6.1] 첫 예시는 기존 ADD 노드의 토큰 수를 늘리고 물리 노드별 키 수를 확인한다. `H(gamma)=43370`, `H(alpha)=8235`다. a의 토큰 16개 중 gamma 이상인 첫 위치는 a의 인덱스 0 위치 60556이다. b를 용량 2로 바꾸면 44408에 놓인 b의 인덱스 11 토큰이 gamma를 맡는다. 마지막에 추가한 c의 인덱스 9 위치는 44078이다.

입력:

```text
ADD a
ADD b
PUT gamma
PUT b
PUT alpha
WEIGHT a 1
WEIGHT b 2
LOAD
WEIGHT b 2
REMOVE b
LOAD
VADD c 1
LOAD
```

출력:

```text
MOVED 0 MOD 0
MOVED 0 MOD 0
KEY gamma a MOD a
KEY b b MOD b
KEY alpha a MOD b
MOVED 0 MOD 0
MOVED 1 MOD 0
MOVE gamma a b
LOAD 2 3
NODE a 1
NODE b 2
RATIO 1.333333
MOVED 0 MOD 0
MOVED 2 MOD 2
MOVE b b a
MOVE gamma b a
LOAD 1 3
NODE a 3
RATIO 1.000000
MOVED 1 MOD 2
MOVE gamma a c
LOAD 2 3
NODE a 2
NODE c 1
RATIO 1.333333
```

[6.2] 두 번째 예시는 빈 링의 LOAD, 용량 오류, 이름 공간 공유와 같은 용량 반복 지정을 보여 준다. 잘못된 명령은 그다음 명령의 상태에 영향을 주지 않는다.

입력:

```text
PUT apple
LOAD
VADD a 0
WEIGHT absent 2
VADD a 1
VADD a 2
WEIGHT a 01
LOAD
```

출력:

```text
KEY apple - MOD -
LOAD 0 1
RATIO 0.000000
ERROR INPUT
ERROR NODE_MISSING
MOVED 1 MOD 1
MOVE apple - a
ERROR NODE_EXISTS
MOVED 0 MOD 0
LOAD 1 1
NODE a 1
RATIO 1.000000
```

## 7. 검사 방식

[7.1] 표준 입력의 명령을 EOF까지 처리하고 표준 출력을 비교한다. 1단계의 모든 테스트도 누적 실행한다. 출력 비교는 1단계와 같으며 특히 RATIO의 소수점 아래 6자리를 문자열로 비교한다. 테스트마다 새 프로세스를 실행하고 빌드 시간을 제외한 실행 제한 시간은 각각 30초다.

[7.2] 1단계의 최대 4096줄, 물리 노드 64개, 등록 키 512개와 성공한 구성 변경 256개의 한도를 그대로 쓴다. 성공한 ADD·REMOVE·VADD·WEIGHT가 구성 변경 횟수에 포함되며 같은 용량의 WEIGHT도 성공한 명령 한 건으로 센다. 한 물리 노드의 토큰은 최대 128개이고 전체 토큰은 최대 8192개다.

[7.3] 성능 차이를 강제하는 별도의 대규모 테스트는 두지 않으며 마지막 조합 테스트도 7.2의 한도 안에서 실행한다. 노드 추가·제거, 용량 변경과 키 등록을 섞고 모든 키를 다시 배정한 결과와 이동 목록·LOAD를 비교한다. 토큰 충돌, 0개 배정 노드, 같은 물리 노드 안의 담당 토큰 변화, 나머지 배정이 용량과 무관하다는 점을 함께 확인한다. 최종 비율의 상한이나 가상 노드 사용 전후의 개선 여부는 합격 조건으로 삼지 않는다.
