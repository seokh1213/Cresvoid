# 해시 링과 옮겨지는 키

## 1. 개요

[1.1] 키를 여러 저장 노드에 배정하는 명령 처리기를 만든다. 노드가 추가되거나 제거되면 기존 키의 소유 노드가 어떻게 달라지는지 출력한다. 같은 키와 같은 노드 집합에 나머지 연산으로 배정한 결과도 함께 계산하여 두 방식의 이동량을 비교한다.

[1.2] 이 프로그램은 한 프로세스 안에서 노드 식별자, 키 식별자, 배정 관계만 다룬다. 실제 서버, 네트워크 통신, 값의 저장·전송은 구현하지 않는다. 프로그램을 새로 실행할 때마다 노드 집합과 등록된 키 집합은 모두 비어 있다.

## 2. 배경 개념

[2.1] 해시는 식별자를 정수 공간의 한 위치로 대응시킨다. 서로 다른 식별자가 같은 위치에 놓이는 충돌도 가능하다. 일관 해싱은 키와 노드를 같은 공간에 놓고 노드 집합이 바뀔 때 배정 변화가 국소적으로 일어나도록 하는 방식이다. 여기서 일관성은 읽기·쓰기의 순서 보장을 뜻하지 않는다.

[2.2] 정수 공간의 끝을 처음과 이으면 링이 된다. 키에서 시계 방향으로 진행해 처음 만나는 노드가 그 키를 맡는다. 이 방향은 정수가 커지는 방향이며 끝에 도달하면 0으로 돌아온다. 새 노드가 들어오면 그 노드가 차지한 구간의 키만 새 노드로 이동하고 노드가 빠지면 그 노드가 맡던 키만 다음 노드로 이동한다. 배정 결과가 이 성질을 만족하면 내부 갱신 방법은 자유다.

[2.3] 노드를 0부터 번호 매기고 `해시값 mod 노드 수`로 배정하면 노드 수가 바뀔 때 나눗셈의 기준도 바뀐다. 따라서 새 노드가 맡게 되는 키 외의 키도 다른 노드로 갈 수 있다. 특정 입력에서 링의 이동량이 반드시 더 작다는 보장은 없으므로 두 결과를 각각 계산해야 한다.

[2.4] 일관 해싱의 배경은 [Karger 외, Consistent Hashing and Random Trees, STOC 1997](https://people.csail.mit.edu/karger/Papers/web.pdf)에 있다. 이 과제의 시계 방향 링은 [DeCandia 외, Dynamo, SOSP 2007, 4.2절](https://cdn.amazon.science/ac/1d/eb50c4064c538c8ac440ce6a1d91/dynamo-amazons-highly-available-key-value-store.pdf)을 따른다. 아래의 해시 공간 크기, 동점 규칙과 명령 형식은 이 과제에서 정한 계약이다.

## 3. 입출력 규칙

[3.1] 표준 입력을 EOF까지 한 줄씩 읽는다. 명령 개수나 단계 번호를 나타내는 첫 줄은 없다. 줄의 앞뒤에 있는 ASCII 공백과 탭을 무시하고 인자 사이는 하나 이상의 ASCII 공백 또는 탭으로 구분한다. 빈 줄은 무시한다. 줄 끝은 LF 또는 CRLF이며 명령과 식별자는 대소문자를 구분한다.

[3.2] 노드 식별자와 키 식별자는 모두 정규식 `[a-z][a-z0-9_-]{0,23}`에 맞는 문자열이다. 두 집합은 별개이므로 같은 문자열을 노드와 키로 동시에 쓸 수 있다. 사전순은 ASCII 문자 코드 순이며, 접두사가 같으면 짧은 문자열이 먼저다. 출력의 `-`는 소유 노드가 없음을 뜻하는 예약 표기다.

[3.3] 식별자 문자열의 UTF-8 바이트에 FNV-1a 64비트를 적용한다. 초기값은 14695981039346656037이고 소수 상수는 1099511628211이다. 각 바이트를 0~255의 정수로 해석하여 누적값과 XOR한 다음 상수를 곱하고 매번 2의 64제곱으로 나눈 나머지를 취한다. 접두사, 줄바꿈, 구분 공백은 해시 입력에 넣지 않는다. [Go 표준 라이브러리의 FNV 구현](https://go.dev/src/hash/fnv/fnv.go)에서 상수와 연산 순서를 확인할 수 있다.

[3.4] 이 과제의 해시 함수 `H(s)`는 3.3의 최종 64비트 값을 65536으로 나눈 나머지다. 링의 위치는 0~65535이며 링 배정과 나머지 배정 모두 이 H를 쓴다. 축소한 공간은 충돌을 재현하기 위한 과제 규칙이다. 64비트 값의 부호를 바꾸거나 절댓값을 취해서는 안 된다.

[3.5] 각 노드는 자기 식별자의 H 위치에 토큰 하나를 갖는다. 토큰이란 링 위의 배정 지점이다. 토큰은 위치 오름차순, 같은 위치에서는 노드 식별자 사전순으로 정렬한다. 충돌한 토큰을 합치거나 덮어쓰지 않는다.

[3.6] 링 배정은 위치가 `H(키)` 이상인 토큰 중 정렬 순서가 가장 앞선 토큰의 노드다. 그런 토큰이 없으면 링에서 정렬 순서가 가장 앞선 토큰의 노드다. 키와 토큰의 위치가 같으면 그 토큰을 포함하고 같은 위치에 여러 토큰이 있으면 그중 먼저 정렬된 토큰을 고른다. 노드가 하나면 모든 키가 그 노드에 배정된다. 노드가 없으면 모든 키의 소유 노드는 `-`다.

[3.7] 시계 방향으로 이웃한 서로 다른 두 토큰 위치를 p와 t라고 할 때 t 위치에서 처음 정렬되는 토큰은 구간 `(p, t]`를 맡는다. 앞 경계는 제외하고 뒤 경계는 포함한다. p가 t보다 크면 끝에서 처음으로 감기는 구간이고 같은 t에 뒤따르는 동점 토큰은 1차 소유 구간이 없다. 실제 배정의 최종 기준은 3.6이다.

[3.8] 나머지 배정은 현재 물리 노드 식별자를 사전순으로 정렬한 목록에서 인덱스 `H(키) mod 노드 수`에 있는 노드다. 인덱스는 0부터 시작한다. 추가·제거할 때마다 그 시점의 노드 집합으로 목록을 정하며 삽입 순서나 과거 인덱스를 유지하지 않는다. 노드가 없으면 이 배정도 `-`다.

[3.9] 성공 응답과 오류 응답은 모두 표준 출력에 쓴다. 한 응답이 여러 줄이면 그 줄들을 연속으로 쓴다. 줄 사이에 빈 줄이나 안내 문구를 넣지 않는다. 정수는 선행 0이 없는 10진수로 쓰고 출력 필드 사이는 ASCII 공백 한 칸으로 구분한다. 처리할 오류가 있어도 다음 줄을 계속 읽고 EOF에서 종료 코드 0으로 끝낸다.

## 4. 명령 규칙

[4.1] `HASH <식별자>`는 `HASH h` 한 줄을 출력한다. h는 H의 결과다. 노드나 키의 등록 여부와 관계없이 사용할 수 있고 상태는 바꾸지 않는다.

[4.2] `PUT <키>`는 키를 등록하고 현재 링 배정과 나머지 배정을 `KEY 키 소유노드 MOD 나머지노드` 한 줄로 출력한다. 이미 등록된 키라면 중복 등록하지 않고 같은 형식으로 현재 배정을 출력한다. 노드가 없어도 등록에 성공한다. 등록된 키는 노드를 모두 제거해도 남으며 이 단계에는 키를 지우는 명령이 없다.

[4.3] `OWNER <키>`는 이미 등록된 키의 현재 배정을 `KEY 키 소유노드 MOD 나머지노드` 한 줄로 출력한다. 상태는 바꾸지 않는다. 등록되지 않은 키를 암묵적으로 등록하지 않는다.

[4.4] `ADD <노드>`는 없는 노드를 토큰 하나와 함께 추가한다. `REMOVE <노드>`는 있는 노드와 그 토큰을 제거한다. 두 명령 모두 변경 직전 등록되어 있던 모든 키에 대해 직전 배정과 직후 배정을 비교한다. 링 배정에서 소유 노드 문자열이 달라진 키 수를 r, 나머지 배정에서 소유 노드 문자열이 달라진 키 수를 m이라고 한다. `-`와 실제 노드 사이의 변화도 이동 한 건으로 센다.

[4.5] ADD와 REMOVE의 성공 응답은 첫 줄 `MOVED r MOD m`과, 이어지는 r개의 `MOVE 키 이전노드 새노드` 줄이다. MOVE 줄은 키 사전순이다. 나머지 배정에서만 옮겨진 키의 목록은 출력하지 않는다. r이 0이면 첫 줄만 출력한다. 토큰 위치가 달라져도 물리 소유 노드가 같으면 링 이동으로 세지 않는다.

[4.6] 첫 노드를 추가하면 그 전에 등록한 키 전부가 `-`에서 새 노드로 이동한다. 마지막 노드를 제거하면 키 전부가 그 노드에서 `-`로 이동한다. REMOVE 뒤에 같은 식별자를 다시 ADD하면 그 시점의 키와 노드 집합에서 배정을 정한다. 과거 배정은 되살리지 않는다.

## 5. 오류 규칙

[5.1] 정의되지 않은 명령, 인자 수 불일치, 식별자 형식 위반은 `ERROR INPUT` 한 줄을 출력한다. 명령 형식과 모든 인자의 유효성을 먼저 확인하므로 기존 노드 이름 뒤에 불필요한 인자가 붙어 있어도 중복 노드 오류보다 ERROR INPUT이 우선한다.

[5.2] 형식이 올바른 ADD의 노드가 이미 있으면 `ERROR NODE_EXISTS`, REMOVE의 노드가 없으면 `ERROR NODE_MISSING`, OWNER의 키가 등록되지 않았으면 `ERROR KEY_MISSING`을 각각 한 줄로 출력한다. 오류가 난 명령은 상태를 전혀 바꾸지 않고 MOVED나 KEY 같은 성공 응답도 출력하지 않는다.

## 6. 예시

[6.1] 첫 예시는 빈 링에서 키를 등록한 뒤 두 노드를 추가하고 제거한다. `H(a)=60556`, `H(b)=61861`, `H(apple)=64959`다. apple은 링 끝에서 처음으로 감겨 a에 배정된다. 두 노드일 때 나머지 배정은 `64959 mod 2 = 1`이므로 b다.

입력:

```text
PUT apple
ADD b
PUT a
PUT b
ADD a
OWNER apple
REMOVE b
REMOVE a
OWNER apple
```

출력:

```text
KEY apple - MOD -
MOVED 1 MOD 1
MOVE apple - b
KEY a b MOD b
KEY b b MOD b
MOVED 2 MOD 1
MOVE a b a
MOVE apple b a
KEY apple a MOD b
MOVED 1 MOD 2
MOVE b b a
MOVED 3 MOD 3
MOVE a a -
MOVE apple a -
MOVE b a -
KEY apple - MOD -
```

[6.2] 두 번째 예시는 토큰 충돌과 키가 토큰 위치에 정확히 놓인 경우를 함께 다룬다. 두 노드는 같은 20069에 놓이지만 node1120이 먼저 정렬된다. 나머지 배정에서는 `20069 mod 2 = 1`이므로 node309가 선택된다.

입력:

```text
HASH node309
HASH node1120
ADD node309
ADD node1120
PUT node1120
REMOVE node1120
OWNER absent
```

출력:

```text
HASH 20069
HASH 20069
MOVED 0 MOD 0
MOVED 0 MOD 0
KEY node1120 node1120 MOD node309
MOVED 1 MOD 0
MOVE node1120 node1120 node309
ERROR KEY_MISSING
```

## 7. 검사 방식

[7.1] Kotlin 표준 라이브러리와 JDK 21만 사용한다. 검사기는 프로그램을 한 번 빌드한 뒤 테스트마다 새 프로세스를 실행하고 명령들을 줄바꿈으로 이어 마지막 줄에도 줄바꿈을 붙여 표준 입력에 쓴 뒤 닫는다. 검사 대상은 표준 출력이며 공개 API의 이름이나 내부 자료구조는 지정하지 않는다.

[7.2] 각 출력 줄 끝의 공백·탭·CR과 출력 끝의 빈 줄을 제거한 뒤 기대 출력과 줄 수 및 각 줄의 문자를 비교한다. 줄 내부의 공백, 대소문자, MOVE 순서는 그대로 비교한다. 각 테스트의 실행 제한 시간은 빌드 시간을 제외하고 30초이며, 0이 아닌 종료 코드나 64MB를 넘는 표준 출력은 실패다.

[7.3] 한 테스트는 빈 줄을 포함하여 최대 4096줄이다. 어느 시점에나 물리 노드는 최대 64개, 서로 다른 등록 키는 최대 512개이며, 성공한 노드 구성 변경 명령은 전체에서 최대 256개다. 오류 명령과 조회·PUT은 구성 변경 횟수에 포함하지 않는다. 검사는 이 상한을 넘는 상태를 만들지 않는다. 이후 단계에서 추가되는 구성 변경 명령도 같은 256개 한도를 공유한다.

[7.4] 성능 차이를 강제하는 별도의 대규모 테스트는 두지 않는다. 마지막 조합 테스트도 7.3의 상한 안에서 실행한다. 매 변경마다 모든 키를 다시 배정하는 구현도 허용한다. 검사는 추가·제거·키 등록을 섞은 입력에서 전체 재배정으로 구한 이동 목록과 비교하며, 감김, 경계의 포함 여부, 충돌 동점, 빈 링과 오류 후 상태 보존을 확인한다.
