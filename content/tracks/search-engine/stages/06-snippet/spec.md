# 6단계: 검색 결과 발췌

## 1. 개요

[1.1] 6단계는 SNIPPET 명령을 더한다. SNIPPET 은 문서 하나의 원문에서 서로 다른 검색어를 가장 많이 담은 짧은 구간을 골라 검색어에 표시를 붙여 보여 준다.

[1.2] 1~5단계의 입출력 규칙, 토큰화 규칙, ADD·DEL·STATS·QUERY·SEARCH·FUZZY·SUGGEST 는 그대로다. 이 문서는 새로 생기는 규칙만 설명한다.

| 명령 | 하는 일 | 정상 출력 |
|---|---|---|
| `SNIPPET <id> <낱말> …` | 문서 원문에서 서로 다른 검색어를 가장 많이 담은 구간을 골라 검색어에 표시를 붙여 출력한다 | 한 줄 |

## 2. 배경 개념

[2.1] 검색 결과 화면은 문서마다 검색어가 나온 부분을 짧게 잘라 보여 주고 그 안의 검색어를 굵게 표시한다. 이 조각을 발췌라 한다. Elasticsearch 의 하이라이트 기능은 기본 설정에서 100자 안팎의 조각을 5개까지 고르고 검색어를 `<em>` 과 `</em>` 으로 감싼다. 이 트랙은 조각을 하나만 고르고 검색어를 `[` 와 `]` 로 감싼다.

[2.2] 색인은 원문을 그대로 두지 않는다. 토큰은 소문자로 바뀌고 구분자는 사라진다. 그래서 발췌를 만들려면 원문을 따로 보관하고 토큰마다 원문의 몇 번째 글자부터 몇 번째 글자까지를 차지하는지도 알아야 한다. Lucene 은 색인할 때 토큰마다 이 범위를 시작 오프셋과 끝 오프셋으로 저장할 수 있고 하이라이터가 이 값을 쓴다. Lucene 의 끝 오프셋은 토큰의 마지막 글자 다음 글자의 번호다. 아래는 `Kotlin은 JVM, 언어다` 의 토큰과 각 토큰의 첫 글자·마지막 글자 번호다. 글자 번호는 0 부터 센다.

```
Kotlin은 JVM, 언어다

kotlin   0~5
은       6
jvm      8~10
언어다   13~15
```

[2.3] 토큰의 위치(3단계 2.2)와 글자 번호는 다르다. 위치는 몇 번째 토큰인지를 나타내고 글자 번호는 원문의 몇 번째 글자인지를 나타낸다. 2.2 의 예에서 jvm 은 위치가 2 이고 글자 번호 8~10 을 차지한다.

[2.4] 서로 다른 검색어를 가장 많이 담은 구간을 찾으려면 검색어 토큰이 어디에 나오는지 알아야 한다. 3단계의 위치 색인은 토큰마다 문서 안 위치의 목록을 정렬해 둔다. 검색어 토큰마다 정렬된 위치 목록이 하나씩 있으면 이들을 합쳐 위치 순으로 정렬된 열 하나로 만들 수 있다. 정렬된 목록 여럿을 이렇게 합치는 일을 병합이라 한다. 목록마다 아직 꺼내지 않은 맨 앞 원소를 보고 그 가운데 가장 작은 원소를 꺼내는 일을 되풀이하면 된다.

[2.5] 두 포인터 창은 정렬된 열 위에서 창의 왼쪽 끝과 오른쪽 끝을 가리키는 두 포인터를 둘 다 앞으로만 움직이며 조건에 맞는 창을 찾는 방법이다. 오른쪽 끝을 하나씩 늘리다가 창이 조건을 어기면 조건을 다시 지킬 때까지 왼쪽 끝을 당긴다. 두 포인터가 뒤로 가지 않으므로 원소가 m 개인 열에서 포인터를 옮기는 횟수는 모두 합쳐 2m 을 넘지 않는다.

[2.6] 병합한 열에는 검색어 토큰의 위치만 들어 있으므로 이 방법에 드는 시간은 문서 길이가 아니라 검색어 토큰이 문서에 나온 횟수에 비례한다. 긴 문서에서 드문 검색어를 찾을 때는 문서의 토큰 대부분을 보지 않는다.

## 3. 입출력 규칙

[3.1] 1단계의 입출력 규칙을 그대로 따른다. 출력은 4단계 3.2 대로 UTF-8 로 쓴다.

## 4. 명령 규칙

### 형식

[4.1] `SNIPPET <id> <낱말> …` 은 id 문서의 원문에서 구간 하나를 골라 그 구간의 원문을 검색어 표시와 함께 한 줄에 출력한다.

[4.2] 인자는 1단계 3.6 대로 나눈다. 첫째 인자는 id 이고 1단계 4.8 의 형식을 따른다.

[4.3] 둘째 인자부터 하나하나가 낱말이다. 낱말이 하나도 없어도 된다.

[4.4] 낱말마다 1단계 4.1~4.6 의 규칙으로 토큰화한다. 모든 낱말에서 나온 토큰의 집합을 검색어 집합 Q 라 한다. 같은 토큰이 여러 번 나와도 Q 에는 한 번만 들어간다. 토큰이 0개인 낱말은 Q 에 아무것도 더하지 않는다.

[4.5] SNIPPET 의 낱말에서는 괄호, 큰따옴표, AND·OR·NOT, `NEAR/`, `+`, `-` 에 특별한 뜻이 없다. 이들도 다른 문자와 똑같이 토큰화 규칙을 따른다. `"new york"` 은 낱말 `"new` 와 `york"` 이고 Q 는 {new, york} 이다.

### 원문과 원문 범위

[4.6] 문서의 원문은 그 문서를 마지막으로 추가하거나 대체한 ADD 의 본문이다. 본문은 1단계 4.9 대로 id 뒤의 공백을 모두 건너뛴 다음부터 줄 끝까지이고 대소문자와 구분자를 그대로 담는다. 1단계 3.5 대로 줄 끝의 공백은 본문에 들어가지 않는다.

[4.7] 같은 id 로 다시 ADD 하면 원문도 새 본문으로 바뀐다. DEL 로 지운 문서는 원문도 함께 사라진다.

[4.8] 토큰은 본문에서 같은 부류 글자가 최대로 이어진 구간 하나에서 나온다(1단계 4.4). 이 구간을 토큰의 원문 범위라 한다. 원문 범위의 글자는 소문자로 바꾸기 전의 글자다. `Kotlin은` 에서 토큰 kotlin 의 원문 범위는 `Kotlin` 이고 토큰 `은` 의 원문 범위는 `은` 이다.

### 구간

[4.9] 위치 i 에 있는 문서의 토큰을 t[i] 라 하자. 위치는 3단계 4.10 대로 첫 토큰이 0 이다. 구간은 a ≤ b 인 두 위치 a 와 b 에 대해 위치 a 부터 b 까지 이어진 위치들이다. 구간의 토큰 수는 b − a + 1 이다.

[4.10] 후보 구간은 t[a] 와 t[b] 가 모두 Q 에 속하고 토큰 수가 10 이하인 구간이다. a 와 b 가 같은 구간도 후보다.

[4.11] 후보 구간마다 구간 안에 나오는 서로 다른 Q 토큰의 수를 센다. 이 수를 구간의 검색어 종류 수라 한다.

[4.12] 후보 구간 가운데 검색어 종류 수가 가장 큰 구간을 고른다. 그런 구간이 여럿이면 그 가운데 토큰 수가 가장 적은 구간을 고르고 그래도 여럿이면 a 가 가장 작은 구간을 고른다.

[4.13] 후보 구간이 없으면 `(none)` 을 출력한다. Q 가 비어 있거나 Q 의 토큰이 문서에 하나도 없을 때다. 토큰이 0개인 문서도 여기에 해당한다.

### 출력

[4.14] 고른 구간이 위치 a 부터 b 까지면 t[a] 원문 범위의 첫 글자부터 t[b] 원문 범위의 마지막 글자까지 원문을 그대로 옮겨 출력한다.

[4.15] 옮기는 동안 구간 안의 토큰 가운데 Q 에 속하는 토큰마다 원문 범위의 첫 글자 바로 앞에 `[` 를, 마지막 글자 바로 뒤에 `]` 를 넣는다. 같은 검색어 토큰이 구간 안에 여러 번 나오면 모두 감싼다. Q 에 속하지 않는 토큰과 구분자는 그대로 둔다.

[4.16] 표시는 토큰 단위로 붙는다. 원문에서 공백 없이 이어진 문자열이 토큰 여럿으로 나뉘면 그 가운데 Q 에 속하는 토큰에만 표시가 붙는다. 원문이 `Kotlin은 JVM` 인 문서에서 Q 가 {kotlin, jvm} 이면 `[Kotlin]은 [JVM]` 을 출력하고 Q 가 {kotlin, 은} 이면 `[Kotlin][은]` 을 출력한다. Q 가 {kotlin} 이면 고른 구간에는 토큰 kotlin 하나만 있다. `은` 은 구간 밖에 있으므로 출력은 `[Kotlin]` 이다.

[4.17] 원문에 이미 있는 `[` 와 `]` 는 다른 글자와 똑같이 그대로 옮긴다. 출력만 보고는 원문의 대괄호와 표시를 구별하지 못할 수도 있다.

[4.18] 본문에는 LF 가 들어 있지 않으므로 출력은 언제나 한 줄이다. 탭, CR, 한글 자모, 라틴 확장 문자, 이모지처럼 본문에 들어 있는 구분자도 구간 안에 있으면 그대로 옮긴다. 공백이 여러 개 이어져 있으면 그 수 그대로 옮긴다.

[4.19] SNIPPET 은 색인과 원문을 바꾸지 않는다.

## 5. 오류 규칙

[5.1] 1단계의 명령어 목록에 SNIPPET 이 더해진다. 명령어가 SNIPPET 인 줄은 1단계 5.2 가 출력을 정하지 않은 입력이고 그 출력은 이 문서가 정한다. SNIPPET 은 `ERR UNKNOWN_COMMAND` 를 내지 않는다. 명령어는 대소문자를 구분하므로 `snippet` 은 여전히 모르는 명령어다.

[5.2] SNIPPET 에 인자가 없거나 첫째 인자가 1단계 4.8 의 id 형식에 맞지 않으면 `ERR BAD_ARGUMENT` 를 출력한다. `SNIPPET`, `SNIPPET 07 data`, `SNIPPET data` 가 여기에 해당한다.

[5.3] 첫째 인자가 id 형식에 맞지만 그 id 의 문서가 없으면 `ERR NOT_FOUND` 를 출력한다. SNIPPET 은 id 형식을 먼저 확인하고 그다음에 문서가 있는지 확인한다.

[5.4] id 의 문서가 있으면 SNIPPET 은 오류를 내지 않는다. 낱말이 없거나 토큰이 0개인 낱말만 있으면 `(none)` 을 출력한다.

## 6. 예시

[6.1] 예시의 표기는 1단계와 같다. 예시 블록 하나는 프로그램을 한 번 실행한 기록이다.

[6.2] 기본 동작이다. `Kotlin은 JVM` 과 `JVM 언어다. Kotlin` 은 둘 다 검색어 두 종류를 담고 토큰 수가 3 이라서 앞 구간을 고른다. 원문의 대소문자는 그대로 나온다.

```
> ADD 1 Kotlin은 JVM 언어다. Kotlin과 Java는 모두 JVM에서 돈다.
> SNIPPET 1 kotlin jvm
[Kotlin]은 [JVM]
> SNIPPET 1 KOTLIN은
[Kotlin][은]
> SNIPPET 1 java python
[Java]
> SNIPPET 1 python
(none)
> SNIPPET 1
(none)
```

[6.3] 짧은 구간과 같은 검색어의 반복이다. red 와 apple 을 모두 담은 구간 가운데 토큰 수가 가장 적은 구간은 뒤쪽의 `red  apple` 이다. 원문에 공백이 둘 있으면 둘 그대로 나온다. 마지막 SNIPPET 의 구간 안에는 apple 이 두 번 나오고 둘 다 표시된다.

```
> ADD 2 Red wine, green APPLE and red  apple pie
> SNIPPET 2 apple red
[red]  [apple]
> SNIPPET 2 apple
[APPLE]
> SNIPPET 2 wine apple pie
[wine], green [APPLE] and red  [apple] [pie]
```

[6.4] 구간 상한이다. a 부터 j 까지는 토큰이 10개라 후보 구간이지만 a 부터 k 까지는 11개라 후보가 아니다. 그래서 `SNIPPET 3 k a` 는 토큰 하나짜리 구간 가운데 앞 구간을 고른다. 낱말의 순서는 결과에 영향을 주지 않는다.

```
> ADD 3 a b c d e f g h i j k
> SNIPPET 3 a j
[a] b c d e f g h i [j]
> SNIPPET 3 k a
[a]
```

[6.5] 원문에 있던 대괄호, 대체, 삭제다. 첫 SNIPPET 의 출력에서 `[draft]` 뒤의 `]` 는 원문에 있던 글자다. `Kotlin_2.0` 에서 밑줄과 마침표는 구분자라서 kotlin, 2, 0 이 각각 토큰이다.

```
> ADD 4 [draft] Kotlin_2.0 출시
> SNIPPET 4 draft 2
[draft]] Kotlin_[2]
> SNIPPET 4 kotlin 0
[Kotlin]_2.[0]
> ADD 4 Java 21
> SNIPPET 4 kotlin
(none)
> SNIPPET 4 java 21
[Java] [21]
> DEL 4
> SNIPPET 4 java
ERR NOT_FOUND
```

[6.6] 오류다.

```
> ADD 5 hello world
> SNIPPET
ERR BAD_ARGUMENT
> SNIPPET 05 hello
ERR BAD_ARGUMENT
> SNIPPET hello
ERR BAD_ARGUMENT
> SNIPPET 6 hello
ERR NOT_FOUND
> SNIPPET 5 !!! ㅋㅋ
(none)
> SNIPPET 5 "WORLD"
[world]
> snippet 5 hello
ERR UNKNOWN_COMMAND
```

## 7. 검사 방식

[7.1] 입력 방식, 종료 코드 검사, 표준 출력 비교, 일반 테스트 제한 시간 10초, 입력 한계는 1단계와 같다.

[7.2] 6단계 테스트도 출력을 글자 그대로 비교한다. 원문의 대소문자, 공백 수, 구분자, 표시 위치 가운데 하나라도 다르면 실패다.

[7.3] 대규모 테스트는 문서 1,000개와 SNIPPET 500,000개로 이뤄진다. 문서는 대부분 한 줄 상한(1단계 7.7)에 가까운 긴 문서이고 SNIPPET 사이에 문서를 대체하는 ADD 와 DEL 이 섞인다. SNIPPET 의 검색어는 대부분 대상 문서에 드물게 나오거나 아예 나오지 않는 토큰이다. 제한 시간은 15초다. SNIPPET 마다 문서 원문을 처음부터 다시 토큰화하는 풀이는 이 제한 시간을 넘기도록 규모를 정했다.

[7.4] 6단계를 검사할 때 1~5단계 테스트도 다시 실행한다. 앞 단계 검사 입력에는 명령어가 SNIPPET 인 줄이 없으므로 6단계 규칙과 부딪히지 않는다.
