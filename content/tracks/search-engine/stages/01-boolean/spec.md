# 1단계: 색인과 불리언 검색

## 1. 개요

[1.1] 이 트랙에서는 표준 입력으로 명령을 받아 문서를 색인하고 검색하는 프로그램을 만든다. 1단계에서는 문서를 토큰으로 나눠 역색인을 만들고 AND·OR·NOT 과 괄호로 이뤄진 불리언 질의에 답한다.

[1.2] 1단계의 명령은 아래 네 가지다.

| 명령 | 하는 일 | 정상 출력 |
|---|---|---|
| `ADD <id> <본문>` | 문서를 추가하거나 같은 id 의 문서를 대체한다 | 없음 |
| `DEL <id>` | 문서를 지운다 | 없음 |
| `STATS` | 문서 수와 서로 다른 토큰 수를 출력한다 | 한 줄 |
| `QUERY <식>` | 불리언 식에 맞는 문서의 id 를 출력한다 | 한 줄 |

[1.3] 2단계는 BM25 점수로 순위를 매기는 SEARCH 를 더하고 3단계는 QUERY 에 구문 검색과 근접 검색을 더한다. 4~6단계는 FUZZY, SUGGEST, SNIPPET 명령을 하나씩 더한다. 이 문서의 입출력 규칙과 토큰화 규칙은 6단계까지 그대로 쓴다. 뒤 단계는 이 문서가 정한 출력을 바꾸지 않는다. 이 문서는 뒤 단계에서 뜻이 생기는 입력의 출력을 정하지 않는다. 그런 입력은 4.33 과 5.2 에 적는다.

## 2. 배경 개념

[2.1] 검색 엔진은 문서를 글자 그대로 비교하지 않고 먼저 토큰으로 나눈다. 무엇을 같은 낱말로 볼지는 토큰화 규칙이 정한다. 이 트랙은 영문 대소문자를 구별하지 않고 영문·숫자 구간과 한글 구간을 따로 끊는다. 한국어 검색 엔진은 보통 형태소 분석기로 조사를 떼어 내지만 이 트랙은 그러지 않으므로 `Kotlin은` 은 `kotlin` 과 `은` 두 토큰이 된다.

[2.2] 문서마다 들어 있는 토큰을 적어 둔 표를 정방향 색인이라 한다. 질의가 올 때마다 정방향 색인을 처음부터 훑으면 문서 수에 비례하는 시간이 든다.

[2.3] 역색인은 방향을 뒤집어 토큰마다 그 토큰을 포함한 문서의 목록을 붙여 둔다. 이 목록을 포스팅 목록이라 한다. 책 뒤의 찾아보기가 낱말마다 쪽 번호를 적어 둔 것과 같은 구조다. 아래는 문서 세 개로 만든 역색인이다.

```
문서 2:  kotlin-flow와 coroutines
문서 9:  Java streams
문서 10: Kotlin coroutines guide

coroutines → 2, 10
flow       → 2
guide      → 10
java       → 9
kotlin     → 2, 10
streams    → 9
와         → 2
```

[2.4] 불리언 검색은 질의를 집합 연산으로 바꿔 계산한다. AND 는 교집합, OR 는 합집합이다. 2.3 의 색인에서 `kotlin AND coroutines` 는 {2, 10} ∩ {2, 10} = {2, 10} 이고 `kotlin OR java` 는 {2, 10} ∪ {9} = {2, 9, 10} 이다. 역색인이 있으면 질의에 나온 토큰의 포스팅 목록만 읽으면 된다.

[2.5] NOT 은 포스팅 목록 하나로 계산할 수 없다. `NOT java` 의 결과는 java 를 포함하지 않는 모든 문서이므로 전체 문서 집합이 기준이 된다. 2.3 의 예에서 `NOT java` 는 {2, 9, 10} − {9} = {2, 10} 이다. Lucene 의 질의 파서처럼 NOT 만으로 된 질의에 빈 결과를 내는 엔진도 있지만 이 트랙의 NOT 은 전체 문서를 기준으로 계산한다.

[2.6] 문서를 대체하거나 지우면 색인도 함께 바뀌어야 한다. 문서를 지우려면 그 문서가 들어 있는 모든 포스팅 목록에서 그 문서를 제거해야 한다. 대체는 이전 내용을 지운 뒤 새 내용을 넣는 일과 같다. Lucene 은 지운 문서에 표시만 해 두었다가 나중에 정리하지만 이 트랙은 다음 명령부터 바로 반영해야 한다.

[2.7] 질의 식은 연산자의 우선순위로 해석한다. 곱셈이 덧셈보다 먼저 묶이듯 이 트랙의 AND 는 OR 보다 먼저 묶인다. `a OR b AND c` 는 `a OR (b AND c)` 다. 괄호로 묶으면 순서를 바꿀 수 있다.

[2.8] 나란히 쓴 검색어를 AND 로 해석할지 OR 로 해석할지는 시스템마다 다르다. Lucene 의 기본 질의 파서는 OR 로 해석하지만 이 트랙은 나란히 놓인 피연산자를 AND 로 묶는다.

## 3. 입출력 규칙

[3.1] 프로그램은 표준 입력에서 명령을 한 줄씩 읽어 입력이 끝날 때까지 처리하고 결과를 표준 출력에 쓴다.

[3.2] 입력이 끝나면 종료 코드 0 으로 끝난다.

[3.3] 입력은 UTF-8 이다. 줄은 LF(U+000A) 로 나눈다. 마지막 줄 뒤에 LF 가 없어도 그 줄을 처리한다.

[3.4] 이 문서에서 공백은 U+0020 한 글자만 가리킨다. 탭(U+0009)과 CR(U+000D)은 공백이 아니다.

[3.5] 줄 앞뒤의 공백은 무시한다. 빈 줄과 공백만 있는 줄은 건너뛰고 아무것도 출력하지 않는다.

[3.6] 명령어는 줄 맨 앞부터 첫 공백 바로 앞까지다. 공백이 없으면 줄 전체가 명령어다. 명령어 뒤의 나머지에서 공백이 아닌 문자가 최대로 이어진 구간 하나하나가 인자다. 공백이 여럿 이어져도 빈 인자는 생기지 않는다. `DEL` 과 `7` 사이에 공백이 둘 있는 줄은 인자가 `7` 하나다.

[3.7] 명령어는 대소문자를 구분한다. `add` 와 `Add` 는 ADD 가 아니다.

[3.8] 출력하는 줄은 모두 LF 로 끝낸다.

[3.9] 프로그램은 문서가 하나도 없는 상태에서 시작한다. 이전 실행의 상태를 이어받지 않는다.

[3.10] 이 문서의 정규식은 문자열 전체에 적용한다. `^` 는 문자열의 처음, `$` 는 문자열의 끝이다.

## 4. 명령 규칙

### 토큰화

[4.1] 토큰화는 문자열을 토큰의 목록으로 바꾸는 일이다. 문서 본문과 QUERY 의 검색어 낱말은 같은 규칙으로 토큰화한다.

[4.2] ASCII 영문자와 숫자(A–Z, a–z, 0–9)는 L 부류다. 한글 음절(U+AC00–U+D7A3)은 H 부류다.

[4.3] L 부류도 H 부류도 아닌 문자는 모두 구분자다. 한글 자모(ㄱ, ㅏ 등), 라틴 확장 문자(é 등), 전각 문자(Ａ, １ 등), 밑줄(_), 작은따옴표('), 큰따옴표(")도 구분자다.

[4.4] 토큰은 같은 부류 문자가 최대로 이어진 구간이다. 구분자에서 끊기고 부류가 바뀌는 곳에서도 끊긴다. `abc가나` 는 `abc` 와 `가나` 두 토큰이고 `a1b2` 는 토큰 하나다.

[4.5] 토큰 안의 ASCII 대문자는 소문자로 바꾼다.

[4.6] 토큰 목록은 본문에 나온 순서를 따르고 중복을 그대로 둔다. 문서 길이(dl)는 중복을 포함한 토큰 개수다.

### ADD

[4.7] `ADD <id> <본문>` 은 문서를 추가한다. 성공하면 아무것도 출력하지 않는다.

[4.8] id 는 `^[1-9][0-9]{0,8}$` 에 맞는 10진 정수다. 1 이상 999,999,999 이하이고 0 으로 시작하지 않는다.

[4.9] 본문은 id 뒤의 공백을 모두 건너뛴 다음부터 줄 끝까지다. id 뒤에 아무것도 없으면 본문은 빈 문자열이다.

[4.10] 토큰이 0개인 문서도 문서다. 문서 수에 들어가고 NOT 이 기준으로 삼는 전체 문서에도 들어간다.

[4.11] 같은 id 의 문서가 이미 있으면 새 본문으로 완전히 대체한다. 이전 본문의 토큰은 그 문서에 남지 않는다. 문서 수는 늘지 않는다.

### DEL

[4.12] `DEL <id>` 는 그 id 의 문서를 지운다. 성공하면 아무것도 출력하지 않는다. 지운 문서는 같은 id 로 다시 ADD 하기 전까지 어떤 결과에도 나오지 않는다.

### STATS

[4.13] `STATS` 는 `<문서 수> <서로 다른 토큰 수>` 를 한 줄로 출력한다. 두 수는 공백 하나로 나눈다.

[4.14] 서로 다른 토큰 수는 현재 문서 가운데 하나 이상에 나타나는 토큰의 종류 수다. 대체나 삭제로 어느 문서에도 남지 않은 토큰은 세지 않는다.

### QUERY

[4.15] `QUERY <식>` 은 불리언 식에 맞는 문서를 찾는다. 식은 QUERY 뒤의 공백을 모두 건너뛴 다음부터 줄 끝까지다.

[4.16] 식은 왼쪽부터 어휘로 나눈다. 괄호 `(` 와 `)` 는 앞뒤에 다른 문자가 붙어 있어도 한 글자짜리 독립 어휘다. 공백도 괄호도 아닌 문자가 최대로 이어진 구간은 낱말이다. 공백은 어휘를 나눌 뿐 어휘가 아니다. `NOT(a)` 는 `NOT`, `(`, `a`, `)` 네 어휘다.

[4.17] 정확히 `AND`, `OR`, `NOT` 인 낱말은 연산자다. 연산자는 대소문자를 구분하므로 `and` 나 `Not` 은 연산자가 아니다.

[4.18] 연산자가 아닌 낱말은 검색어 낱말이다. 검색어 낱말은 4.1~4.6 의 규칙으로 토큰화한다.

[4.19] 토큰이 0개인 검색어 낱말은 파싱 전에 지운다. 지운 낱말은 처음부터 없던 것으로 다룬다.

[4.20] 토큰이 1개인 검색어 낱말은 그 토큰을 포함한 문서에 맞는 항이다.

[4.21] 토큰이 2개 이상인 검색어 낱말은 그 토큰을 모두 포함한 문서에 맞는 항 하나다. 이 항은 토큰을 AND 로 이어 괄호로 묶은 식과 같다. 토큰의 순서와 위치는 따지지 않는다. `e-mail` 은 `(e AND mail)` 과 같고 `NOT e-mail` 은 `NOT (e AND mail)` 이다.

[4.22] 0토큰 낱말을 지운 어휘의 열은 아래 문법의 or_expr 하나와 정확히 맞아야 한다. 대문자 AND, OR, NOT 은 연산자 어휘, `'('` 와 `')'` 는 괄호 어휘, 항은 4.20 과 4.21 의 항이다. 따옴표 없는 괄호는 묶음, `*` 는 0번 이상 되풀이, `[ ]` 는 생략할 수 있음을 뜻한다.

```
or_expr  := and_expr ( OR and_expr )*
and_expr := not_expr ( [ AND ] not_expr )*
not_expr := NOT not_expr | primary
primary  := '(' or_expr ')' | 항
```

[4.23] 4.22 의 문법에서 피연산자는 항, 괄호로 감싼 식, NOT 뒤에 피연산자를 붙인 것 가운데 하나다. 식은 피연산자 하나이거나 피연산자 여럿을 AND 나 OR 로 이은 것이다. AND 는 생략할 수 있다. AND 와 OR 의 양쪽에는 피연산자가 있어야 한다. 괄호 안은 비어 있으면 안 된다.

[4.24] 문법대로 읽고 나서 어휘가 남으면 문법에 맞지 않는 식이다. `a)` 는 `a` 를 읽은 뒤 `)` 가 남으므로 문법에 맞지 않는다.

[4.25] 우선순위는 NOT 이 가장 강하고 AND, OR 순으로 약하다. `a OR b AND c` 는 `a OR (b AND c)` 다.

[4.26] 나란히 놓인 두 피연산자는 AND 로 묶는다. 생략한 AND 와 적은 AND 는 우선순위가 같다. `a b OR c` 는 `(a AND b) OR c` 이고 `a NOT b` 는 `a AND (NOT b)` 다.

[4.27] 같은 우선순위끼리는 왼쪽부터 묶는다. `a OR b OR c` 는 `(a OR b) OR c` 다.

[4.28] NOT 은 바로 뒤의 피연산자 하나에만 적용된다. `NOT a b` 는 `(NOT a) AND b` 이고 `NOT NOT a` 는 `a` 와 같다.

[4.29] 항의 결과는 그 항에 맞는 문서의 집합이다. `x AND y` 의 결과는 두 결과의 교집합이고 `x OR y` 의 결과는 합집합이다.

[4.30] `NOT x` 의 결과는 현재 모든 문서의 집합에서 x 의 결과를 뺀 집합이다. 토큰이 0개인 문서도 현재 모든 문서에 들어간다.

[4.31] QUERY 는 식의 결과에 든 문서의 id 를 수 크기의 오름차순으로 정렬해 공백 하나씩 띄워 한 줄에 출력한다. 9 는 10 보다 앞에 온다.

[4.32] 식의 결과가 빈 집합이면 `(none)` 을 출력한다.

[4.33] QUERY 의 식에 큰따옴표가 하나라도 있거나 `NEAR/` 로 시작하는 낱말이 있으면 이 문서는 그 QUERY 의 출력을 정하지 않는다. 둘 다 3단계에서 새 뜻이 생기기 때문이다. ADD 의 본문은 이 규칙과 상관없이 4.1~4.6 대로 토큰화한다.

## 5. 오류 규칙

[5.1] 오류가 나면 오류 줄 하나만 출력한다. 오류를 낸 명령은 상태를 바꾸지 않는다. 프로그램은 다음 줄을 이어서 처리한다.

[5.2] 명령어가 ADD, DEL, STATS, QUERY, SEARCH 가운데 어느 것과도 정확히 같지 않으면 `ERR UNKNOWN_COMMAND` 를 출력한다. `QUERY(a)` 는 명령어가 `QUERY(a)` 이므로 모르는 명령어다. SEARCH 는 2단계에서 명령이 되므로 이 문서는 명령어가 SEARCH 인 줄의 출력을 정하지 않는다. 다만 FUZZY, SUGGEST, SNIPPET 은 4~6단계에서 명령이 되므로 이 문서는 명령어가 이 셋 가운데 하나인 줄의 출력도 정하지 않는다.

[5.3] ADD 에 인자가 없거나 첫 인자가 4.8 의 id 형식에 맞지 않으면 `ERR BAD_ARGUMENT` 를 출력한다. `ADD 0 x`, `ADD 01 x`, `ADD 1234567890 x`, `ADD 1,2 x` 가 여기에 해당한다.

[5.4] DEL 의 인자가 정확히 1개가 아니거나 그 인자가 id 형식에 맞지 않으면 `ERR BAD_ARGUMENT` 를 출력한다. `DEL 7 8` 은 문서 7 이 있어도 오류이고 아무것도 지우지 않는다.

[5.5] DEL 의 인자가 정확히 1개이고 id 형식에 맞지만 그 id 의 문서가 없으면 `ERR NOT_FOUND` 를 출력한다. DEL 은 인자 수와 id 형식을 먼저 확인하고 그다음에 문서가 있는지 확인한다. `DEL 99 8` 은 문서 99 와 8 이 없어도 `ERR BAD_ARGUMENT` 다.

[5.6] STATS 에 인자가 하나라도 있으면 `ERR BAD_ARGUMENT` 를 출력한다.

[5.7] QUERY 의 식이 비어 있으면 `ERR SYNTAX` 를 출력한다. 0토큰 낱말을 지운 뒤 어휘가 하나도 남지 않을 때도 빈 식이다.

[5.8] 0토큰 낱말을 지운 식이 4.22~4.24 를 만족하지 않으면 `ERR SYNTAX` 를 출력한다. `a AND !!!` 는 `a AND` 가 되어 오류이고 `a !!!` 는 `a` 와 같아 오류가 아니다. `()`, `(a`, `a OR OR b`, `NOT` 도 오류다.

## 6. 예시

[6.1] 예시 블록 하나는 프로그램을 한 번 실행한 기록이다. `> ` 로 시작하는 줄은 입력이고 나머지 줄은 바로 위 입력의 출력이다. 실제 입력에는 `> ` 가 없다.

[6.2] 기본 동작이다. id 는 수 크기 순으로 나온다. `KOTLIN` 은 연산자가 아닌 검색어 낱말이라 `kotlin` 으로 바뀐다. `flow와` 는 토큰 `flow` 와 `와` 로 나뉘므로 둘을 모두 포함한 문서 2 만 맞는다.

```
> ADD 10 Kotlin coroutines guide
> ADD 2 kotlin-flow와 coroutines
> ADD 9 Java streams
> QUERY kotlin
2 10
> QUERY KOTLIN AND coroutines
2 10
> QUERY kotlin java
(none)
> QUERY kotlin OR java
2 9 10
> QUERY flow와
2
> STATS
3 7
```

[6.3] 토큰화의 세부다. `Kotlin_1.9는 JVM용!` 의 토큰은 `kotlin`, `1`, `9`, `는`, `jvm`, `용` 여섯 개다. 자모만으로 된 `ㅋㅋ` 는 0토큰 낱말이라 지워진다. `é` 는 구분자라 `Café` 의 토큰은 `caf` 다.

```
> ADD 1 Kotlin_1.9는 JVM용!
> STATS
1 6
> QUERY 9는
1
> QUERY ㅋㅋ kotlin
1
> ADD 2 Café Latte
> QUERY caf
2
> STATS
2 8
```

[6.4] 우선순위와 NOT 이다.

```
> ADD 1 red apple
> ADD 2 green apple
> ADD 3 red cherry
> ADD 4 green grape
> QUERY red OR green apple
1 2 3
> QUERY (red OR green) apple
1 2
> QUERY apple NOT red
2
> QUERY NOT apple OR red
1 3 4
> QUERY NOT NOT red
1 3
```

[6.5] 여러 토큰 낱말, 0토큰 낱말, 빈 문서다. `new-york` 은 순서와 상관없이 두 토큰을 모두 포함한 문서에 맞는다. 문서 4 는 토큰이 없지만 NOT 의 결과에 들어간다. 소문자 `not` 은 검색어 낱말이다.

```
> ADD 1 new york pizza
> ADD 2 york is not new
> ADD 3 new delhi
> ADD 4
> QUERY new-york
1 2
> QUERY NOT new-york
3 4
> QUERY not
2
> QUERY pizza !!!
1
> QUERY pizza AND !!!
ERR SYNTAX
> QUERY NOT
ERR SYNTAX
> STATS
4 6
```

[6.6] 대체, 삭제, 오류다.

```
> ADD 7 alpha beta
> ADD 7 gamma
> QUERY alpha
(none)
> STATS
1 1
> DEL 7 8
ERR BAD_ARGUMENT
> DEL 7
> DEL 7
ERR NOT_FOUND
> DEL 07
ERR BAD_ARGUMENT
> STATS
0 0
> add 1 x
ERR UNKNOWN_COMMAND
> QUERY(gamma)
ERR UNKNOWN_COMMAND
> STATS now
ERR BAD_ARGUMENT
```

## 7. 검사 방식

[7.1] 엔진은 테스트마다 풀이의 `run.sh` 를 새 프로세스로 실행한다. 작업 디렉터리는 풀이 디렉터리다.

[7.2] 테스트의 입력 줄을 LF 로 잇고 마지막 줄 뒤에도 LF 를 붙여 표준 입력에 쓴 뒤 표준 입력을 닫는다.

[7.3] 프로세스가 0 이 아닌 종료 코드로 끝나면 실패다.

[7.4] 표준 출력만 기대 출력과 비교하고 표준 오류는 비교하지 않는다. 각 줄 끝의 공백, 탭, CR 을 지우고 끝에 붙은 빈 줄을 지운 뒤 줄 수와 각 줄의 내용이 정확히 같아야 한다.

[7.5] 일반 테스트의 제한 시간은 10초다. 제한 시간을 넘기면 엔진이 프로세스를 끝내고 실패로 판정한다.

[7.6] 대규모 테스트는 문서 20,000개(문서당 평균 30토큰 안팎)와 QUERY 20,000개로 이뤄진다. 제한 시간은 15초다. 색인 없이 QUERY 마다 모든 문서를 훑는 풀이는 이 제한 시간을 넘기도록 규모를 정했다.

[7.7] 검사 입력의 한 줄은 UTF-8 로 10,000바이트 이하다. QUERY 식의 어휘는 0토큰 낱말까지 세어 100개 이하다.

[7.8] 1단계와 2단계 검사 입력의 QUERY 에는 큰따옴표가 하나도 나오지 않고 `NEAR/` 로 시작하는 낱말도 나오지 않는다. 4.33 이 출력을 정하지 않은 입력이기 때문이다.

[7.9] 1단계 검사 입력에는 명령어가 SEARCH 인 줄이 나오지 않는다. 1~3단계 검사 입력에는 명령어가 FUZZY, SUGGEST, SNIPPET 가운데 하나인 줄이 나오지 않는다. 5.2 가 출력을 정하지 않은 입력이기 때문이다.

[7.10] 2~6단계를 검사할 때도 1단계 테스트를 다시 실행한다.

[7.11] 3.3 의 마지막 문장과 3.8 은 엔진이 검사하지 않는다. 엔진은 입력의 마지막 줄 뒤에도 LF 를 붙이고(7.2) 출력 줄 끝의 CR 과 끝에 붙은 빈 줄을 지운 뒤 비교하기(7.4) 때문이다. 두 규칙은 표준 입출력 프로그램의 관례라서 적어 둔다.
