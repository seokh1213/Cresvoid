# 02. 시장가·IOC·FOK와 정정

## 1. 개요

[1.1] 01단계 엔진에 `MARKET`, `IOC`, `FOK`, `AMEND`를 더한다. 기존 명령의 입력과 출력은 그대로 유지한다. 새 주문 유형마다 잔량의 처리와 접수 여부를 구분하고, 정정 전후의 시간 우선을 다룬다. 목표 풀이 시간은 2~3시간이다.

## 2. 배경 개념

[2.1] 시장가 주문은 가격 상한이나 하한을 지정하지 않고 현재 상대 호가에서 체결을 시도한다. 원하는 수량만큼 상대 주문이 없을 수도 있다. 이 과제에서는 시장가 잔량을 대기시키지 않고 취소한다. 체결 가격은 여전히 각 maker의 가격이므로 한 시장가 주문이 여러 가격에서 체결될 수 있다.

[2.2] IOC(Immediate Or Cancel)는 지금 체결할 수 있는 만큼만 체결하고 나머지를 취소하는 조건이다. FOK(Fill Or Kill)는 지금 전량 체결할 수 있을 때만 체결하고, 그렇지 않으면 전량을 취소하는 조건이다. 여기서는 둘 다 지정가를 가지며 그 가격 안에서만 상대 주문을 찾는다. FOK의 전량은 한 maker의 수량이 아니라 조건을 만족하는 여러 maker의 잔량 합으로 판단한다.

[2.3] FOK의 원자성은 전량 체결과 전량 취소 중 하나만 결과로 나타난다는 뜻이다. 전량 체결 불가능한 FOK는 체결 행을 출력하지 않고 상대 주문의 잔량·도착 순번과 체결 시계도 바꾸지 않는다. 다만 이 과제에서는 정상 접수한 뒤 전량 취소한 주문이므로 ID 사용 이력과 도착 시계에는 남는다.

[2.4] 정정에서 기존 주문보다 수량을 늘리거나 가격을 바꾸면 다른 대기 주문이 기다린 조건에 영향을 준다. 이 과제에서는 그런 정정에 새 도착 순번을 준다. 같은 가격에서 잔량만 줄이는 정정은 기존 순번을 보존한다. 정정 수량은 최초 주문의 총수량이 아니라 정정 직후 체결을 시작하기 전의 새 잔량이다.

## 3. 입출력 규칙

[3.1] 줄 처리, 토큰 문법, ID·방향·가격 범위, 출력 형식은 01단계를 따른다. `MARKET`, `IOC`, `FOK`는 새 주문이므로 ID를 공유하는 사용 이력 검사 대상이다. 정상 접수하면 체결 여부와 관계없이 도착 시계를 한 번 늘리고 ID를 사용 집합에 넣는다. 이 세 명령의 수량도 1~1,000,000,000이다.

[3.2] 새 주문은 각 체결의 `TRADE` 행을 먼저 출력한 뒤 `ORDER <id> <restingQty> <cancelledQty>`를 출력한다. 새 주문 수량은 체결 수량 합, `restingQty`, `cancelledQty`의 합이다. 취소된 잔량은 호가창에 남지 않고 별도의 `CANCEL` 행도 만들지 않는다. 체결 순번은 실제 체결이 있을 때만 증가한다.

## 4. 명령 규칙

[4.1] `MARKET <id> <owner> <side> <qty>`는 가격 조건 없이 상대 주문을 가격-시간 우선으로 체결한다. 모든 체결 가격과 체결 순번은 01단계를 따른다. 상대 주문이 없거나 부족하면 남은 전량을 취소한다. 출력의 `restingQty`는 항상 0이고 `cancelledQty`는 체결되지 않은 수량이다.

[4.2] `IOC <id> <owner> <side> <price> <qty>`는 같은 인자의 `LIMIT`와 같은 상대 주문을 같은 순서·가격으로 체결하되, 더 체결할 수 없으면 남은 전량을 취소한다. `restingQty`는 항상 0이다. 지정가 밖의 유동성이 있어도 그 가격에서는 체결하지 않는다.

[4.3] `FOK <id> <owner> <side> <price> <qty>`는 지정가 이내의 상대 잔량 합이 `qty` 이상이면 전량을 체결하고 `ORDER <id> 0 0`을 출력한다. 체결 상대의 선택, 체결 가격과 여러 `TRADE` 행의 순서는 같은 인자의 `LIMIT`와 같다. 합이 부족하면 체결 없이 `ORDER <id> 0 <qty>`만 출력한다. 양쪽 모두 ID를 사용하고 도착 시계를 늘린 정상 접수다. 실패한 FOK도 같은 ID로 다시 주문할 수 없다. 같은 소유자의 상대 주문 수량도 전량 체결 가능 수량에 포함한다.

[4.4] `AMEND <id> <newPrice> <newRemainingQty>`는 현재 대기 중인 주문을 정정한다. 소유자, 방향, ID는 바꾸지 않는다. 새 가격은 1~1,000,000,000이고 새 잔량은 0~1,000,000,000이다. 이전 체결량을 새 잔량에서 빼지 않는다. 예를 들어 최초 10에서 4가 체결되어 6이 남은 주문을 8로 정정하면 앞으로 체결할 수량은 8이다.

[4.5] 새 잔량이 0이면 가격 변경 여부와 관계없이 현재 잔량 전부를 취소한다. 새 잔량이 양수이고 가격이 같으며 새 잔량이 현재 잔량 이하이면 잔량만 바꾸고 도착 순번을 유지한다. 같은 값으로 정정하는 경우도 성공이다. 이 두 경우에는 새 도착 순번을 발급하지 않고 체결도 일어나지 않는다.

[4.6] 새 잔량이 양수이고 가격이 달라지거나 잔량이 증가하면 기존 대기 위치를 없애고 도착 시계를 1 늘려 새 도착 순번을 준다. 새 가격과 새 잔량으로 지정가 taker처럼 즉시 체결을 시도하고 남은 잔량을 대기시킨다. 같은 가격의 기존 주문들보다 뒤에 놓이며, 정정 직후 전량 체결되어도 도착 시계는 증가한다. 사용 ID 집합에는 새 ID를 추가하지 않는다.

[4.7] 성공한 정정은 체결 행들을 먼저 출력하고 마지막에 `AMEND <id> <restingQty> <cancelledQty>`를 출력한다. 여기서 `restingQty`는 정정과 체결이 끝난 뒤의 대기 잔량이고 `cancelledQty`는 `max(정정 전 잔량 - newRemainingQty, 0)`이다. 증가분은 취소 수량에 포함하지 않는다. 정정에 따른 체결 수량 합과 `restingQty`의 합은 `newRemainingQty`다. 새 잔량이 0인 경우도 이 식을 따르며 현재 잔량 전부가 취소 수량이다.

## 5. 오류 규칙

[5.1] 01단계의 오류 우선순위를 새 명령에도 적용한다. 인자 수·정수 문법이 잘못되면 `ERR FORMAT`, ID·방향·가격·수량 범위가 잘못되면 `ERR VALUE`, 형식과 값이 올바른 새 주문의 ID가 사용되었으면 `ERR DUPLICATE`다. 시장가·IOC·FOK의 수량 0은 `ERR VALUE`다. 정상 형식의 FOK가 잔량 부족으로 취소되는 것은 오류가 아니다.

[5.2] 형식과 값이 올바른 `AMEND`에서 현재 대기 주문이 없으면 `ERR NOT_FOUND`다. 전량 체결되거나 취소된 주문도 정정할 수 없다. 오류는 호가창, 사용 ID 집합, 도착 시계, 체결 시계를 바꾸지 않는다. 특히 실패한 정정이 기존 주문의 시간 우선을 잃게 해서는 안 된다.

## 6. 예시

[6.1] 다음 예시의 첫 정정은 수량 감소이므로 S1의 우선순위가 유지된다. FOK는 합계 7이 부족해 취소된다. S2의 수량 증가 후에는 S3이 먼저 체결된다. 마지막 0 정정은 남은 3을 취소한다.

입력:
```text
LIMIT S1 u SELL 100 5
LIMIT S2 v SELL 100 4
AMEND S1 100 3
FOK B1 w BUY 100 8
IOC B2 w BUY 100 4
LIMIT S3 u SELL 100 2
AMEND S2 100 5
MARKET B3 u BUY 4
BOOK
AMEND S2 99 0
BOOK
LIMIT B1 w BUY 100 1
```

출력:
```text
ORDER S1 5 0
ORDER S2 4 0
AMEND S1 3 2
ORDER B1 0 8
TRADE 1 B2 S1 100 3
TRADE 2 B2 S2 100 1
ORDER B2 0 0
ORDER S3 2 0
AMEND S2 5 0
TRADE 3 B3 S3 100 2
TRADE 4 B3 S2 100 2
ORDER B3 0 0
BOOK B - S 100:3
AMEND S2 0 3
BOOK B - S -
ERR DUPLICATE
```

[6.2] 다음 예시에서는 FOK가 여러 매수 주문을 전량 소진한다. 가격 변경으로 새 taker가 된 D는 maker E의 가격으로 체결하며 시장가 주문의 잔량은 취소한다.

입력:
```text
LIMIT A p BUY 100 2
LIMIT B q BUY 99 3
FOK C r SELL 99 5
LIMIT A p BUY 101 1
LIMIT D r SELL 105 3
LIMIT E p BUY 100 2
AMEND D 100 4
IOC F r SELL 101 2
MARKET G r SELL 2
BOOK
```

출력:
```text
ORDER A 2 0
ORDER B 3 0
TRADE 1 A C 100 2
TRADE 2 B C 99 3
ORDER C 0 0
ERR DUPLICATE
ORDER D 3 0
ORDER E 2 0
TRADE 3 E D 100 2
AMEND D 2 0
ORDER F 0 2
ORDER G 0 2
BOOK B - S 100:2
```

## 7. 검사 방식

[7.1] 입력 방식, 출력 비교, JDK·라이브러리 범위와 테스트별 60초 제한은 01단계와 같다. 01단계 테스트도 누적 실행한다. 새 단계의 고정·무작위 검사는 전량 체결 가능한 FOK와 불가능한 FOK, 잔량 취소, 부분 체결 후 정정, 우선순위 보존·상실, 가격 변경 직후 체결, 오류 뒤 상태 보존을 조합한다. 수량 보존에서는 실제 체결량과 취소량을 구분한다.

[7.2] 대규모 검사는 재사용하지 않은 ID의 새 주문 총 1,000,000건을 처리한다. 최대 500,000개의 서로 다른 가격과 같은 가격에 몰린 대기 주문을 포함한다. `CANCEL`·`AMEND`는 합쳐 최대 200,000건 추가한다. 실제 체결은 최대 500,000건이다. 전량 체결 불가능한 각 FOK를 처리하기 직전, 그 지정가 안의 상대 대기 주문 수는 최대 256개다. 이 입력 조건은 작은 검사에도 적용하며 실패 FOK의 반복 검사에 별도 범위 집계 기능까지 요구하지 않기 위해 둔다. 대규모 입력·기대 출력은 각각 64MiB 이하다. 제한 시간은 테스트별 60초이며 체결마다 호가 전체를 훑는 방식은 피해야 하는 규모다.
