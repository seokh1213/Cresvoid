# 01. 지정가 호가창과 체결

## 1. 개요

[1.1] 단일 종목의 주문 매칭 엔진을 만든다. 지정가 주문을 도착 순서대로 처리하고 가격-시간 우선으로 체결한 뒤, 취소와 가격별 잔량 조회를 제공한다. 목표 풀이 시간은 Kotlin 백엔드 경력 개발자 기준 2~3시간이다.

[1.2] 이 단계의 명령은 `LIMIT`, `CANCEL`, `BOOK`이다. 계좌 잔고, 수수료, 거래 시간, 네트워크, 동시 요청은 다루지 않는다. 소유자 식별자는 주문에 붙는 정보이며 같은 소유자의 매수·매도도 다른 주문과 똑같이 체결한다. 거래 규칙은 이 스펙에서 정한 계약을 따른다.

## 2. 배경 개념

[2.1] 지정가 매수는 정한 가격 이하에서 사겠다는 주문이고, 지정가 매도는 정한 가격 이상에서 팔겠다는 주문이다. 아직 체결되지 않고 기다리는 주문들의 집합을 호가창이라 한다. 매수 가격 중 가장 높은 가격과 매도 가격 중 가장 낮은 가격이 각각 최우선 호가다. 가격은 정수 단위이고 소수점 계산은 없다.

[2.2] 새로 들어와 상대 주문을 체결하는 주문을 taker, 호가창에서 기다리다가 체결되는 주문을 maker라 한다. 가격 우선은 매수 taker에게 가장 싼 매도를, 매도 taker에게 가장 비싼 매수를 먼저 배정한다는 뜻이다. 가격이 같으면 먼저 도착한 maker를 먼저 배정한다. 소유자나 주문 ID의 사전순은 도착 순서를 대신하지 않는다.

[2.3] 체결은 양쪽 주문에서 같은 수량을 줄이는 사건이다. 두 주문의 남은 수량이 다르면 작은 쪽만 모두 소진되고 다른 쪽에는 잔량이 남는다. 이를 부분 체결이라 한다. 호가 단계는 가격이 같은 대기 주문을 모은 것이며 단계별 잔량은 그 주문들의 현재 잔량 합이다.

[2.4] 도착 순번과 체결 순번은 서로 다른 시계다. 도착 순번은 주문 사이의 시간 우선을 나타내고, 체결 순번은 실제 발생한 체결의 출력 순서를 나타낸다. 취소는 체결이 아니므로 체결 순번을 늘리지 않는다. 이후 단계에서는 두 시계까지 복원해야 같은 후속 동작을 얻는다.

## 3. 입출력 규칙

[3.1] 표준 입력을 EOF까지 한 줄씩 읽고 줄마다 명령 하나를 처리한다. 명령 수를 먼저 주지 않는다. 줄 앞뒤의 공백·탭을 무시하고 연속 공백·탭은 토큰 하나의 구분자로 취급한다. 빈 줄은 무시한다. 명령과 토큰은 대소문자를 구분한다. 모든 테스트는 UTF-8이며 명령 토큰은 ASCII다.

[3.2] 주문 ID와 소유자 ID는 각각 `[A-Za-z][A-Za-z0-9_]{0,11}`에 맞는 문자열이다. 두 ID의 이름 공간은 별개다. 방향은 `BUY` 또는 `SELL`이다. 정수 토큰의 문법은 `-?[0-9]+`이며 앞자리 0과 `-0`도 허용한다. 문법에 맞는 정수라도 signed 64비트 범위를 벗어나거나 해당 필드의 허용 범위를 벗어나면 값 오류다. 가격과 새 주문 수량의 허용 범위는 각각 1~1,000,000,000이다.

[3.3] 새 프로세스는 빈 호가창, 빈 사용 ID 집합, 값이 0인 도착 시계와 체결 시계로 시작한다. 새 주문을 정상 접수할 때마다 도착 시계를 1 늘려 그 주문의 도착 순번으로 삼는다. 즉시 전량 체결되어 호가창에 남지 않는 주문도 도착 시계를 늘린다. 성공한 새 주문 ID는 사용 ID 집합에 영구히 남으며 전량 체결하거나 취소해도 재사용하지 못한다. 오류가 난 새 주문 ID는 사용한 것으로 보지 않는다.

[3.4] 출력 토큰은 공백 하나로 구분하고 각 출력 행 뒤에 줄바꿈을 붙인다. 수량·가격·순번은 앞자리 0과 부호가 없는 십진수로 출력한다. 명령 하나의 출력을 모두 끝낸 뒤 다음 명령을 처리한다. EOF 자체의 출력은 없다. 진단 메시지나 입력 안내를 표준 출력에 쓰지 않는다.

## 4. 명령 규칙

[4.1] `LIMIT <id> <owner> <side> <price> <qty>`는 지정가 주문을 접수한다. 매수 taker는 매도 maker의 가격이 자기 지정가 이하일 때만, 매도 taker는 매수 maker의 가격이 자기 지정가 이상일 때만 체결한다. 가능한 maker 중 가격-시간 우선으로 하나씩 선택한다. 체결 수량은 그 순간의 maker와 taker 잔량 중 작은 값이며 체결 가격은 maker의 지정가다.

[4.2] 체결 한 건마다 체결 시계를 1 늘리고 `TRADE <tradeNo> <buyId> <sellId> <price> <qty>`를 한 줄 출력한다. 매수·매도 ID의 위치는 taker의 방향과 관계없이 고정이다. 같은 명령에서 여러 maker를 소진하면 실제 체결 순서대로 여러 줄을 출력하며 같은 가격의 체결도 합치지 않는다. 잔량이 0이 된 maker는 즉시 호가창에서 제거하고, 일부만 체결된 maker는 원래 도착 순번을 유지한다.

[4.3] 더 체결할 수 없거나 taker의 잔량이 0이 되면 체결을 끝낸다. 양의 잔량은 자기 지정가와 도착 순번으로 호가창에 남긴다. 마지막으로 `ORDER <id> <restingQty> <cancelledQty>`를 출력한다. `restingQty`는 이 새 주문이 호가창에 남긴 수량이고 이 단계의 `cancelledQty`는 항상 0이다. 따라서 새 주문 수량은 해당 명령의 체결 수량 합과 `restingQty`의 합이다.

[4.4] `CANCEL <id>`는 현재 호가창에 있는 주문의 잔량 전부를 제거하고 `CANCEL <id> <removedQty>`를 출력한다. 부분 체결되었다면 최초 수량이 아니라 현재 잔량을 제거한다. 사용 이력이 있어도 현재 대기하지 않는 ID와 한 번도 접수하지 않은 ID는 모두 없는 주문이다. 다른 주문의 도착 순번은 바뀌지 않는다.

[4.5] `BOOK`은 한 줄 `BOOK B <bids> S <asks>`를 출력한다. 각 측은 `가격:합산잔량` 항목을 쉼표로 잇는다. 매수는 가격 내림차순, 매도는 가격 오름차순이다. 해당 측이 비었으면 `-`를 쓴다. 잔량 0인 주문과 가격 단계는 출력하지 않는다. 예를 들어 매수 가격 100에 2와 3이 남으면 `100:5`다. 조회는 상태와 두 시계를 바꾸지 않는다.

[4.6] 호가 합산 잔량과 시계는 signed 64비트 정수 범위에서 계산한다. 개별 주문 수량의 상한이 합산 잔량의 상한은 아니다. 모든 체결은 매수 감소량, 매도 감소량, 출력 체결 수량이 같아야 한다. 취소 수량을 체결 수량에 더하지 않는다.

## 5. 오류 규칙

[5.1] 알 수 없는 명령, 인자 수 불일치, 정수 토큰 문법 위반은 `ERR FORMAT`이다. 인자 수와 정수 문법을 먼저 확인하고, 그다음 모든 필드의 값 범위를 확인한다. ID 형식, 방향, 정수 범위 또는 가격·수량 범위 위반은 `ERR VALUE`다. 수량 0 주문도 `ERR VALUE`이며 빈 주문으로 접수하지 않는다.

[5.2] 형식과 모든 값이 올바른 새 주문에서 이미 사용한 주문 ID이면 `ERR DUPLICATE`다. 형식과 값이 올바른 `CANCEL`에서 현재 대기 주문이 없으면 `ERR NOT_FOUND`다. 따라서 중복 ID와 수량 0이 함께 있으면 `ERR VALUE`가 먼저다. 오류는 한 줄만 출력하며 호가창, 사용 ID 집합, 도착 시계, 체결 시계를 전혀 바꾸지 않는다. 오류 뒤에도 다음 줄을 계속 처리한다.

## 6. 예시

[6.1] 다음 예시는 가격이 먼저이고 같은 가격에서는 도착 순서가 먼저임을 보인다. 매수 B1은 더 비싼 S1보다 S2·S3을 먼저 소진하고, 남은 1을 S1에서 체결한다. 두 코드 블록은 각각 전체 입력과 전체 출력이다.

입력:
```text
LIMIT S1 kim SELL 101 5
LIMIT S2 lee SELL 100 3
LIMIT S3 park SELL 100 4
LIMIT B1 cho BUY 102 8
BOOK
CANCEL S1
BOOK
```

출력:
```text
ORDER S1 5 0
ORDER S2 3 0
ORDER S3 4 0
TRADE 1 B1 S2 100 3
TRADE 2 B1 S3 100 4
TRADE 3 B1 S1 101 1
ORDER B1 0 0
BOOK B - S 101:4
CANCEL S1 4
BOOK B - S -
```

[6.2] 다음 예시에서는 같은 소유자의 주문끼리 체결한다. 잘못된 수량은 ID를 사용하지 않지만, 접수 후 취소한 ID는 재사용하지 못한다.

입력:
```text
LIMIT A same BUY 100 0
LIMIT A same BUY 100 4
LIMIT B same SELL 99 1
BOOK
CANCEL A
LIMIT A same BUY 100 1
CANCEL B
```

출력:
```text
ERR VALUE
ORDER A 4 0
TRADE 1 A B 100 1
ORDER B 0 0
BOOK B 100:3 S -
CANCEL A 3
ERR DUPLICATE
ERR NOT_FOUND
```

## 7. 검사 방식

[7.1] JDK 21과 Kotlin 표준 라이브러리만 사용한다. 제공된 `build.sh`로 빌드한 프로그램에 전체 입력을 표준 입력으로 주고 EOF를 보낸다. 테스트마다 새 프로세스를 쓴다. 빌드 시간을 제외한 테스트별 실행 제한은 60초다. 출력은 각 행 끝의 공백·탭·CR과 전체 출력 끝의 빈 행을 제거한 뒤 행 수와 각 행을 글자 그대로 비교한다. 종료 코드가 0이 아니거나 표준 출력이 64MiB를 넘으면 실패다.

[7.2] 고정 검사와 작은 무작위 혼합 검사는 가격·시간 우선, 부분 체결, 양방향 체결 가격, 취소, 합산 잔량, ID 재사용, 오류 후 상태, 자기 주문 간 체결을 함께 확인한다. 생성 입력에서는 각 체결 수량 합이 양쪽 주문의 감소량과 같은지도 교차 검증한다. 공개 클래스나 자료구조의 형태를 강제하지 않으며 표준 입출력으로 검사한다.

[7.3] 대규모 검사는 새 주문 1,000,000건이다. 서로 다른 가격 1~500,000에 매도 수량 1을 먼저 접수한다. 이어서 각 주문이 정확히 한 maker를 체결하도록 지정가 1,000,000,000인 매수 수량 1을 500,000건 접수한다. 마지막 `BOOK`도 검사한다. 전체 입력과 기대 출력은 각각 64MiB 이하다. 체결할 때마다 남아 있는 호가 전체를 훑는 방식이 제한 시간을 넘는 규모를 의도한다. 실행 제한은 일반 검사와 같은 60초다.
