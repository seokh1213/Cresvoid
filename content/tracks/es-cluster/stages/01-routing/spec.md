# 1단계: 라우팅과 샤드별 점수

## 1. 개요

[1.1] 이 트랙에서는 주 샤드 여러 개로 나뉜 Elasticsearch 색인에서 조정 노드가 하는 일을 흉내 내는 프로그램을 만든다. 프로그램 하나가 모든 샤드와 조정 노드의 역할을 함께 맡는다. 프로그램은 표준 입력으로 명령을 받아 색인을 바꾸고 조회 명령에 답한다. 1단계에서는 라우팅 값으로 문서가 놓일 샤드를 정하고 샤드마다 따로 매긴 BM25 점수로 검색 결과를 합친다.

[1.2] 1단계의 명령은 아래 다섯 가지다.

| 명령 | 하는 일 | 정상 출력 |
|---|---|---|
| `CREATE <주 샤드 수>` | 빈 색인을 만든다 | 없음 |
| `PUT <id> <라우팅 값> <브랜드> <가격> <제목>` | 문서를 색인한다 | 없음 |
| `DEL <id> <라우팅 값>` | 문서를 지운다 | 없음 |
| `STATS` | 샤드마다 문서 수와 토큰 수를 보여 준다 | 주 샤드 수만큼의 줄 |
| `SEARCH <매개변수> …` | 검색어에 맞는 문서를 점수 순으로 보여 준다 | 1줄 이상 |

[1.3] 2단계는 브랜드마다 문서 수를 세는 TERMS 명령을 더한다. 3단계는 SEARCH 에 정렬, 건너뛸 결과 수, search_after, PIT 매개변수를 보태고 PIT 를 여닫는 명령을 더한다. 이 문서의 입출력 규칙과 명령 규칙은 3단계까지 그대로 쓴다. 뒤 단계는 이 문서가 정한 출력을 바꾸지 않는다. 이 문서는 뒤 단계에서 뜻이 생기는 입력의 출력을 정하지 않는다. 그런 입력은 4.20 과 5.2 에 적는다.

[1.4] 문서에는 브랜드와 가격이 있다. 1단계는 둘을 저장만 하고 출력에 쓰지 않는다. 브랜드는 2단계의 집계에서, 가격은 3단계의 정렬에서 쓴다.

## 2. 배경 개념

[2.1] Elasticsearch 의 색인은 주 샤드 여러 개로 나뉜다. 주 샤드 하나는 그 자체로 완결된 Lucene 색인이고 자기에게 온 문서만 담는다. 주 샤드 수는 색인을 만들 때 정하며(index.number_of_shards) 기본값은 1 이다. 실제 클러스터는 주 샤드마다 복제본을 두지만 이 트랙은 복제본을 다루지 않는다.

[2.2] 문서가 놓일 샤드는 라우팅 값으로 정한다. Elasticsearch 는 라우팅 값을 Murmur3 로 해시하고 그 해시를 주 샤드 수로 나눈 나머지를 샤드 번호로 쓴다. 라우팅 값을 따로 주지 않으면 문서의 id 가 라우팅 값이 된다. 한 판매자의 상품처럼 함께 찾는 문서에 같은 라우팅 값을 주면 그 문서들은 한 샤드에 모인다. 주 샤드 수가 바뀌면 같은 라우팅 값이 다른 샤드를 가리키므로 주 샤드 수는 나중에 쉽게 바꿀 수 없다. 이 트랙은 손으로 계산할 수 있는 단순한 해시 함수를 쓴다(4.7).

[2.3] 샤드는 다른 샤드에 어떤 문서가 있는지 모른다. 색인 요청은 라우팅 값이 가리키는 샤드 하나에만 가고 그 샤드는 자기 안에서만 같은 id 의 문서를 찾는다. 그래서 같은 id 를 다른 샤드를 가리키는 라우팅 값으로 다시 색인하면 처음 문서는 원래 샤드에 그대로 남고 새 샤드에 같은 id 의 문서가 하나 더 생긴다. Elastic 문서도 라우팅 값을 빠뜨리면 문서 하나가 여러 샤드에 색인될 수 있다고 경고한다. 지우기도 라우팅 값이 가리키는 샤드 안에서만 문서를 찾는다.

[2.4] 검색 요청을 받은 노드를 조정 노드라 한다. 조정 노드는 질의를 모든 샤드에 보낸다. 샤드는 자기 문서 가운데 질의에 맞는 문서를 찾아 점수를 매기고 점수가 높은 결과를 요청받은 수만큼 조정 노드에 보낸다. 조정 노드는 샤드들이 보낸 결과를 합쳐 다시 정렬한 뒤 최종 결과를 고른다. Elasticsearch 는 이 방식을 query_then_fetch 라 부른다. 샤드가 먼저 문서 번호와 점수만 보내고 조정 노드가 최종 결과에 든 문서의 내용을 나중에 따로 가져오기 때문에 붙은 이름이다. 샤드마다 상위 k 개만 보내도 최종 상위 k 개는 정확하다. 전체에서 상위 k 개에 드는 결과는 자기 샤드 안에서도 상위 k 개에 들기 때문이다.

[2.5] BM25 는 Lucene 과 Elasticsearch 의 기본 점수 함수이고 질의 토큰이 문서에 나온 횟수, 그 토큰이 드문 정도, 문서의 길이를 한 식에 담는다. 토큰이 문서에 나온 횟수 tf 는 `tf × (k1 + 1) / (tf + k1 × L)` 로 점수에 들어간다. 이 문서는 이 값을 tf 부분이라 부른다. tf 부분은 tf 가 늘수록 커지지만 k1 + 1 을 넘지 않는다. 길이 보정 값 `L = 1 − b + b × dl / avgdl` 은 문서 길이 dl 이 평균 길이 avgdl 보다 길수록 커져 점수를 낮춘다. 드문 토큰에 무게를 주는 `idf = ln(1 + (N − df + 0.5) / (df + 0.5))` 는 문서 수 N 가운데 그 토큰을 포함한 문서 수 df 가 작을수록 크다. 식 전체는 4.27 과 4.28 에 있다. 실제 Lucene 의 계산은 세부가 조금 달라 이 트랙의 점수는 Elasticsearch 가 내는 점수와 같지 않다.

[2.6] N, df, avgdl 은 문서 모음 전체에서 구하는 통계다. query_then_fetch 에서 샤드는 다른 샤드의 통계를 모르므로 자기 샤드의 통계로 점수를 매긴다. 내용이 똑같은 문서라도 놓인 샤드가 다르면 점수가 다를 수 있다. 어떤 토큰이 한 샤드에 몰려 있으면 그 샤드에서는 흔한 토큰이라 idf 가 낮고 그 토큰이 드문 샤드에서는 idf 가 높다. 문서가 많고 샤드에 고르게 퍼져 있으면 샤드마다 통계가 비슷해져 차이가 작다. 문서가 적거나 라우팅 값이 한쪽으로 몰리면 차이가 커진다.

[2.7] 아래는 주 샤드가 2개인 색인에서 trail 의 idf 를 구한 예다. 문서 다섯 개의 길이가 모두 2 라서 두 샤드와 색인 전체의 avgdl 도 모두 2 다. trail 이 한 번 나오는 문서는 tf 부분이 1 이므로 점수가 idf 와 같다. 문서 1, 2, 4 는 제목이 같지만 문서 4 만 점수가 높다.

```
샤드 0: 문서 1 trail shoes, 문서 2 trail shoes, 문서 3 running shoes
샤드 1: 문서 4 trail shoes, 문서 5 rain coat

샤드 0 의 통계  N 3  df 2  idf = ln(1 + 1.5 / 2.5) = ln 1.6 ≈ 0.470004
샤드 1 의 통계  N 2  df 1  idf = ln(1 + 1.5 / 1.5) = ln 2   ≈ 0.693147
전역 통계       N 5  df 3  idf = ln(1 + 2.5 / 3.5)          ≈ 0.538997
```

[2.8] 샤드별 통계 때문에 생기는 차이를 없애는 방식이 dfs_query_then_fetch 다. 조정 노드는 질의를 보내기 전에 모든 샤드와 한 번 더 주고받으며 질의 토큰의 문서 빈도와 샤드의 문서 수, 토큰 수를 모으고 그 합으로 만든 전역 통계를 질의와 함께 보낸다. 샤드는 자기 통계 대신 전역 통계로 점수를 매긴다. 주고받는 횟수가 한 번 늘지만 같은 내용의 문서는 어느 샤드에 있든 같은 점수를 받는다. Elasticsearch 는 검색 요청의 search_type 으로 두 방식 가운데 하나를 고르고 기본값은 query_then_fetch 다. Elastic 문서는 query_then_fetch 가 대개 빠르지만 덜 정확하고 dfs_query_then_fetch 는 대개 느리지만 더 정확하다고 설명한다.

[2.9] Lucene 은 샤드 안의 문서에 색인된 순서대로 내부 문서 번호를 붙인다. 점수가 같으면 샤드 안에서는 내부 번호가 작은 문서가 앞서고 조정 노드가 합칠 때는 샤드 번호가 작은 결과가 앞선다. Lucene 은 문서를 대체할 때 옛 문서를 지우고 새 문서를 더하므로 대체된 문서는 새 내부 번호를 받는다. Lucene 의 내부 번호는 세그먼트를 병합할 때 다시 매겨질 수 있지만 이 트랙에는 병합이 없다. 이 트랙도 같은 방식으로 동점을 푼다(4.14, 4.32).

[2.10] 실제 Elasticsearch 에서는 색인과 삭제가 refresh 를 거친 뒤에야 검색에 반영된다. 지운 문서와 대체된 옛 문서는 바로 없어지지 않고 삭제 표시가 붙은 채 남는다. 이런 문서는 병합으로 걸러질 때까지 점수에 쓰는 통계에 그대로 들어가므로 문서를 지워도 idf 가 바로 바뀌지 않는다. 이 트랙에는 refresh 와 삭제 표시가 없어서 PUT 과 DEL 이 다음 명령부터 결과와 N, df, avgdl 에 바로 반영된다(4.31).

## 3. 입출력 규칙

[3.1] 프로그램은 표준 입력에서 명령을 한 줄씩 읽어 입력이 끝날 때까지 처리하고 결과를 표준 출력에 쓴다.

[3.2] 입력이 끝나면 종료 코드 0 으로 끝난다.

[3.3] 입력은 UTF-8 이다. 줄은 LF(U+000A)로 나눈다. 마지막 줄 뒤에 LF 가 없어도 그 줄을 처리한다.

[3.4] 이 문서에서 공백은 U+0020 한 글자만 가리킨다. 탭(U+0009)과 CR(U+000D)은 공백이 아니다.

[3.5] 줄 앞뒤의 공백은 무시한다. 빈 줄과 공백만 있는 줄은 건너뛰고 아무것도 출력하지 않는다.

[3.6] 명령어는 줄 맨 앞부터 첫 공백 바로 앞까지다. 공백이 없으면 줄 전체가 명령어다. 명령어 뒤의 나머지에서 공백이 아닌 문자가 최대로 이어진 구간 하나하나가 인자다. 공백이 여럿 이어져도 빈 인자는 생기지 않는다.

[3.7] 명령어는 대소문자를 구분한다. `put` 과 `Put` 은 PUT 이 아니다.

[3.8] 출력하는 줄은 모두 LF 로 끝낸다.

[3.9] 프로그램은 색인이 없는 상태에서 시작한다. 이전 실행의 상태를 이어받지 않는다.

[3.10] 이 문서의 정규식은 문자열 전체에 적용한다. `^` 는 문자열의 처음, `$` 는 문자열의 끝이다.

[3.11] 점수는 double 로 계산하고 소수점 아래 넷째 자리까지 쓴다. 소수점 아래 넷째 자리까지로 나타낼 수 있는 수 가운데 계산한 double 값에 가장 가까운 수를 쓴다. 가장 가까운 수가 둘이면 큰 쪽을 쓴다. 소수 부분은 언제나 네 자리이고 소수점은 마침표(.)다. 1 보다 작은 점수는 정수 부분에 0 을 쓴다. 지수 표기는 쓰지 않는다. `0.4700`, `1.3863`, `1.0000` 처럼 쓴다.

[3.12] 이 문서에서 반올림한 점수는 3.11 의 방법으로 넷째 자리까지 나타낸 수다. 점수를 비교하거나 정렬할 때는 반올림한 점수를 쓴다.

[3.13] 정수 인자의 범위는 수의 크기로 따진다. 자릿수가 많아 64비트 정수에 담기지 않는 수도 범위를 넘는 수이므로 형식에 맞지 않는다.

## 4. 명령 규칙

### 토큰화

[4.1] 토큰은 ASCII 영문자와 숫자(A–Z, a–z, 0–9)가 최대로 이어진 구간이다. 그 밖의 문자는 모두 구분자다. 한글, 밑줄(_), 하이픈(-), 쉼표(,), 더하기(+)도 구분자다. 토큰 안의 대문자는 소문자로 바꾼다. `Trail-Running_2024` 의 토큰은 `trail`, `running`, `2024` 다.

[4.2] 문서의 제목과 SEARCH 의 검색어는 같은 규칙으로 토큰화한다. 제목의 토큰은 나온 순서와 중복을 그대로 둔다. 문서 길이 dl 은 중복을 포함한 제목 토큰의 개수다.

### CREATE

[4.3] `CREATE <주 샤드 수>` 는 주 샤드가 그 수만큼 있는 빈 색인을 만든다. 성공하면 아무것도 출력하지 않는다.

[4.4] 주 샤드 수는 `^[1-9][0-9]?$` 에 맞고 64 이하인 10진 정수다. 이 문서는 주 샤드 수를 P 라 쓴다. 샤드 번호는 0 부터 P − 1 까지다.

[4.5] 프로그램이 다루는 색인은 하나뿐이다. 한 번 만든 색인은 없앨 수 없다.

### 라우팅

[4.6] 라우팅 값 인자는 `-` 이거나 `^[a-z0-9]{1,32}$` 에 맞는 문자열이다. 인자가 `-` 이면 같은 명령의 id 인자를 그대로 라우팅 값으로 쓴다. id 가 `17` 이면 라우팅 값은 문자열 `17` 이다.

[4.7] 라우팅 값의 해시 h 는 다음처럼 구한다. 처음에 h 는 0 이다. 라우팅 값의 글자를 앞에서부터 하나씩 읽을 때마다 h × 31 에 그 글자의 ASCII 코드를 더하고 그 값을 4294967296(2^32)으로 나눈 나머지를 새 h 로 삼는다. 마지막 글자까지 읽은 뒤의 h 가 해시다. h 는 언제나 0 이상 4294967295 이하다.

[4.8] 라우팅 값이 가리키는 샤드는 h 를 P 로 나눈 나머지를 번호로 가진 샤드다. store1 의 h 는 3402900336 이므로 P 가 3 이면 샤드 0 이고 P 가 5 이면 샤드 1 이다. seller1 은 일곱째 글자 1 을 읽을 때 3388952447 × 31 + 49 = 105057525906 이 되고 이 수를 4294967296 으로 나눈 나머지인 1978310802 가 해시다.

### PUT

[4.9] `PUT <id> <라우팅 값> <브랜드> <가격> <제목>` 은 문서 하나를 색인한다. 성공하면 아무것도 출력하지 않는다.

[4.10] id 는 `^[1-9][0-9]{0,8}$` 에 맞는 10진 정수다. 브랜드는 `^[a-z0-9]{1,32}$` 에 맞는 문자열이다. 가격은 `^(0|[1-9][0-9]{0,8})$` 에 맞는 10진 정수다.

[4.11] 제목은 가격 인자 바로 뒤의 공백을 모두 건너뛴 다음부터 줄 끝까지다. 가격 뒤에 아무것도 없으면 제목은 빈 문자열이다. 제목에는 어떤 글자가 와도 오류가 아니다.

[4.12] 문서는 라우팅 값이 가리키는 샤드 하나에만 들어간다. 그 샤드에 같은 id 의 문서가 있으면 새 문서로 완전히 대체한다. 없으면 그 샤드에 문서를 더한다.

[4.13] PUT 은 다른 샤드에 있는 같은 id 의 문서를 바꾸지 않는다. 그래서 같은 id 의 문서가 여러 샤드에 하나씩 있을 수 있다. 이 문서들은 서로 다른 문서다.

[4.14] 샤드마다 내부 번호 카운터가 있고 색인을 만들 때 카운터는 0 이다. PUT 이 성공하면 문서가 들어간 샤드의 카운터 값을 그 문서의 내부 번호로 매기고 그 샤드의 카운터를 1 올린다. 대체한 문서도 새 내부 번호를 받는다. 지운 문서의 내부 번호는 다시 쓰지 않는다.

[4.15] 토큰이 0개인 제목의 문서도 문서다. 문서 수에 들어가고 dl 은 0 이다.

### DEL

[4.16] `DEL <id> <라우팅 값>` 은 라우팅 값이 가리키는 샤드에서 그 id 의 문서를 지운다. 성공하면 아무것도 출력하지 않는다. 다른 샤드에 있는 같은 id 의 문서는 남는다. 문서를 색인할 때와 다른 라우팅 값이라도 같은 샤드를 가리키면 그 문서를 지운다.

### STATS

[4.17] `STATS` 는 샤드 번호 오름차순으로 샤드마다 한 줄씩 `shard <샤드 번호> docs <문서 수> tokens <토큰 수>` 를 출력한다. 토큰 수는 그 샤드에 있는 문서들의 dl 을 더한 값이다.

### SEARCH 매개변수

[4.18] SEARCH 의 인자 하나하나는 `<이름>=<값>` 모양의 매개변수다. 인자에서 첫 `=` 앞이 이름이고 뒤가 값이다. 값은 비어 있어도 되고 `=` 를 더 담고 있어도 된다. 매개변수의 순서는 결과를 바꾸지 않는다.

[4.19] 1단계의 매개변수 이름은 q, size, search_type 세 가지다. 한 SEARCH 에 같은 이름을 두 번 쓸 수 없다.

[4.20] 색인이 있을 때 SEARCH 의 인자 가운데 이름이 from, sort, search_after, pit 인 매개변수가 하나라도 있으면 이 문서는 그 SEARCH 의 출력을 정하지 않는다. 넷 모두 3단계에서 뜻이 생기기 때문이다. 색인이 없으면 이런 SEARCH 도 5.3 대로 `ERR NO_INDEX` 를 출력한다.

[4.21] q 는 검색어다. q 의 값을 4.1 대로 토큰화해 나온 서로 다른 토큰의 집합을 Q 라 한다. 같은 토큰이 여러 번 나와도 Q 에는 한 번만 들어간다. 인자에는 공백을 넣을 수 없으므로 낱말 여러 개는 `q=trail,shoes` 나 `q=trail+shoes` 처럼 구분자로 잇는다.

[4.22] size 는 출력할 결과의 최대 개수다. 값은 `^(0|[1-9][0-9]*)$` 에 맞고 10000 이하인 10진 정수다. size 가 없으면 10 이다.

[4.23] search_type 의 값은 `query_then_fetch` 나 `dfs_query_then_fetch` 다. search_type 이 없으면 `query_then_fetch` 다.

### 결과

[4.24] q 가 없으면 색인의 모든 문서가 결과다. q 가 있으면 Q 의 토큰을 제목에 하나 이상 포함한 문서가 결과다. q 가 있는데 Q 가 비어 있으면 결과가 없다. `q=` 와 `q=!!!` 가 여기에 해당한다.

[4.25] 같은 id 의 문서가 여러 샤드에 있으면 조건에 맞는 문서마다 따로 결과가 된다.

### 점수

[4.26] q 가 없으면 모든 결과의 점수는 1 이다. search_type 은 이 점수를 바꾸지 않는다.

[4.27] q 가 있으면 결과 d 의 점수는 Q 의 토큰 t 마다 `idf(t) × tf × (k1 + 1) / (tf + k1 × (1 − b + b × dl / avgdl))` 를 구해 모두 더한 값이다. k1 은 1.2, b 는 0.75 다. tf 는 d 의 제목에 t 가 나온 횟수이고 dl 은 d 의 문서 길이다. tf 가 0 인 토큰은 0 을 더한다. 토큰마다 구한 값은 Q 의 토큰이 q 에 처음 나온 순서대로 더한다. 이 식과 4.28 의 식은 적힌 그대로 괄호 안부터 계산하고 우선순위가 같은 연산은 왼쪽부터 계산한다.

[4.28] `idf(t) = ln(1 + (N − df + 0.5) / (df + 0.5))` 다. ln 은 자연로그다.

[4.29] search_type 이 query_then_fetch 이면 N, df, avgdl 은 d 가 있는 샤드의 값이다. N 은 그 샤드의 문서 수, df 는 그 샤드에서 제목에 t 를 포함한 문서 수, avgdl 은 그 샤드의 토큰 수를 N 으로 나눈 값이다.

[4.30] search_type 이 dfs_query_then_fetch 이면 N, df, avgdl 은 색인 전체의 값이다. N 은 모든 샤드의 문서 수를 더한 값, df 는 샤드마다 제목에 t 를 포함한 문서 수를 모두 더한 값, avgdl 은 모든 샤드의 토큰 수를 더해 N 으로 나눈 값이다.

[4.31] N, df, avgdl 은 SEARCH 를 실행할 때 색인에 있는 문서로 구한다. PUT 과 DEL 은 다음 명령부터 바로 반영된다. 토큰이 0개인 문서도 N 에 들어간다. q 가 있는 SEARCH 에 결과가 하나라도 있으면 쓰이는 avgdl 은 언제나 0 보다 크다.

### 정렬과 출력

[4.32] 결과는 반올림한 점수의 내림차순으로 정렬한다. 반올림한 점수가 같으면 샤드 번호가 작은 결과가 앞서고 샤드 번호도 같으면 내부 번호가 작은 결과가 앞선다. 반올림하기 전의 점수가 달라도 반올림한 점수가 같으면 이 규칙으로 순서를 정한다.

[4.33] SEARCH 는 먼저 `hits <결과 수> merged <합친 결과 수>` 한 줄을 출력한다. 결과 수는 4.24 와 4.25 로 정한 결과 전체의 개수다. 합친 결과 수는 샤드마다 그 샤드에 있는 결과의 수와 size 가운데 작은 값을 구해 모두 더한 값이다. 샤드들이 조정 노드에 보내는 결과의 수가 이 값이다.

[4.34] 이어서 정렬한 결과를 앞에서부터 size 개까지 한 줄에 하나씩 `<id> <샤드 번호> <점수>` 형식으로 출력한다. 점수는 3.11 의 형식으로 쓴다. 결과가 size 개보다 적으면 결과를 모두 출력한다. 결과가 없거나 size 가 0 이면 첫 줄만 출력한다.

## 5. 오류 규칙

[5.1] 오류가 나면 오류 줄 하나만 출력한다. 오류를 낸 명령은 상태를 바꾸지 않는다. 프로그램은 다음 줄을 이어서 처리한다.

[5.2] 명령어가 CREATE, PUT, DEL, STATS, SEARCH 가운데 어느 것과도 정확히 같지 않으면 `ERR UNKNOWN_COMMAND` 를 출력한다. 다만 TERMS 는 2단계에서, OPEN_PIT 과 CLOSE_PIT 은 3단계에서 명령이 되므로 이 문서는 명령어가 이 셋 가운데 하나인 줄의 출력을 정하지 않는다.

[5.3] 명령어가 올바르면 색인이 있는지를 인자보다 먼저 확인한다. 색인이 없을 때 PUT, DEL, STATS, SEARCH 는 인자와 상관없이 `ERR NO_INDEX` 를 출력한다. 색인이 있을 때 CREATE 는 인자와 상관없이 `ERR INDEX_EXISTS` 를 출력한다.

[5.4] 색인이 없을 때 CREATE 의 인자가 정확히 1개가 아니거나 그 인자가 4.4 의 형식에 맞지 않으면 `ERR BAD_ARGUMENT` 를 출력한다. `CREATE 0`, `CREATE 03`, `CREATE 65` 가 여기에 해당한다.

[5.5] PUT 의 인자가 4개보다 적거나 id, 라우팅 값, 브랜드, 가격 가운데 하나라도 4.6 과 4.10 의 형식에 맞지 않으면 `ERR BAD_ARGUMENT` 를 출력한다. `PUT 1 Store1 acme 100 x`, `PUT 1 a Acme 100 x`, `PUT 1 a acme 0100 x`, `PUT 1 a acme` 가 여기에 해당한다.

[5.6] DEL 의 인자가 정확히 2개가 아니거나 id 와 라우팅 값 가운데 하나라도 형식에 맞지 않으면 `ERR BAD_ARGUMENT` 를 출력한다. 인자가 올바르지만 라우팅 값이 가리키는 샤드에 그 id 의 문서가 없으면 `ERR NOT_FOUND` 를 출력한다. 다른 샤드에 같은 id 의 문서가 있어도 `ERR NOT_FOUND` 다.

[5.7] STATS 에 인자가 하나라도 있으면 `ERR BAD_ARGUMENT` 를 출력한다.

[5.8] 4.20 에 해당하지 않는 SEARCH 는 인자를 다음처럼 확인한다. 인자에 `=` 가 없거나 인자가 `=` 로 시작하면 `ERR BAD_ARGUMENT` 다. 매개변수 이름이 q, size, search_type 가운데 하나가 아니거나 같은 이름이 두 번 이상 나와도 `ERR BAD_ARGUMENT` 다. size 의 값이 4.22 에 맞지 않거나 search_type 의 값이 4.23 에 맞지 않아도 `ERR BAD_ARGUMENT` 다. `SEARCH trail`, `SEARCH Q=trail`, `SEARCH q=a q=b`, `SEARCH size=01`, `SEARCH size=10001`, `SEARCH search_type=dfs` 가 여기에 해당한다.

[5.9] q 의 값은 형식을 따지지 않는다. 색인이 있을 때 4.20 에 해당하지 않고 인자가 올바른 SEARCH 는 오류를 내지 않는다. 결과가 없으면 `hits 0 merged 0` 한 줄을 출력한다.

## 7. 검사 방식

[7.1] 엔진은 테스트마다 풀이의 `run.sh` 를 새 프로세스로 실행한다. 작업 디렉터리는 풀이 디렉터리다.

[7.2] 엔진은 테스트의 입력 줄을 LF 로 잇고 마지막 줄 뒤에도 LF 를 붙여 표준 입력에 쓴 뒤 표준 입력을 닫는다.

[7.3] 프로세스가 0 이 아닌 종료 코드로 끝나면 실패다.

[7.4] 표준 출력만 기대 출력과 비교하고 표준 오류는 비교하지 않는다. 각 줄 끝의 공백, 탭, CR 을 지우고 끝에 붙은 빈 줄을 지운 뒤 줄 수와 각 줄의 내용이 정확히 같아야 한다. 점수도 글자 그대로 비교하므로 3.11 의 형식을 하나라도 어기면 실패다.

[7.5] 기대 출력의 점수는 64비트 부동소수점(IEEE 754 double)으로 계산한다.

[7.6] 일반 테스트의 제한 시간은 10초다. 제한 시간을 넘기면 엔진이 프로세스를 끝내고 실패로 판정한다.

[7.7] 대규모 테스트는 주 샤드 5개 색인에 PUT 100,000개, DEL 5,000개, SEARCH 40,000개를 섞어 넣는다. 제목은 토큰 4~12개이고 SEARCH 의 q 는 토큰 1~3개다. SEARCH 하나의 결과는 많아야 500개이고 size 는 10 이하다. 제한 시간은 15초다. 결과를 찾거나 문서 빈도를 세려고 SEARCH 마다 색인의 문서를 모두 훑는 풀이는 문서의 토큰을 정수 배열에 모아 두고 훑더라도 이 제한 시간을 넘기도록 규모를 정했다.

[7.8] 검사 입력의 한 줄은 UTF-8 로 2,000바이트 이하다.

[7.9] 1단계 검사 입력에는 4.20 과 5.2 가 출력을 정하지 않은 줄이 나오지 않는다.

[7.10] 2단계와 3단계를 검사할 때도 1단계 테스트를 다시 실행한다.

[7.11] 3.3 의 마지막 문장과 3.8 은 엔진이 검사하지 않는다. 엔진은 입력의 마지막 줄 뒤에도 LF 를 붙이고(7.2) 출력 줄 끝의 CR 과 끝에 붙은 빈 줄을 지운 뒤 비교하기(7.4) 때문이다. 두 규칙은 표준 입출력 프로그램의 관례라서 적어 둔다.
