# 오프셋 커밋 시점과 중복 처리

[1] 읽을 파일과 순서는 `OrderEffects.kt` → `MemoryBroker.kt` → `OrderConsumer.kt` → `Main.kt`이다. 파일은 모두 `code/src/main/kotlin/`에 있다. 목표 풀이 시간은 25분이다.

[2] 쇼핑 카탈로그의 주문 후속 처리를 맡는 소비자다. 주문 이벤트를 읽어 판매 가능 재고를 예약하고 회원에게 포인트를 적립한다. 재고 저장소, 기존 포인트 API, 브로커를 메모리 안에서 재현한다. 기존 포인트 API는 멱등 요청 키를 지원하지 않는다. 두 저장소와 브로커는 소비자 프로세스 밖에 있다고 가정한다. 입력 명령으로 소비자의 장애와 파티션 재할당을 일으킨다.

[3] 표준 입력의 명령을 한 줄씩 EOF까지 읽는다. 공백으로 필드를 구분하며 식별자에는 공백을 쓰지 않는다. 파티션은 0과 1이다. `STOCK <sku> <수량>`은 초기 재고를 설정한다. `EVENT <파티션> <이벤트ID> <sku> <회원ID> <수량> <포인트>`는 해당 파티션의 로그 끝에 주문 하나를 추가한다. 수량은 양수, 포인트는 0 이상의 정수다. 같은 이벤트ID를 다시 넣을 때는 주문 내용도 같다고 가정한다.

[4] `START BEFORE` 또는 `START AFTER`는 지정한 커밋 정책으로 새 소비자를 시작한다. 처음 시작하거나 소비자가 실패 또는 중단된 뒤에 사용한다. `POLL <최대 개수>`는 소비자에게 묶음 하나를 처리하게 한다. 최대 개수는 양수다. 묶음 구성 순서와 커밋 정책의 구체적인 동작은 코드에서 읽는다.

[5] `FAIL <이벤트ID> BEFORE|STOCK|POINTS`는 해당 이벤트의 지정 처리 지점에서 한 번 예외가 발생하도록 예약한다. BEFORE는 재고 예약 전, STOCK은 재고 예약 후, POINTS는 포인트 호출 후의 지점이다. 같은 이벤트에 다시 예약하면 이전 예약을 바꾼다. `CRASH`는 소비자를 강제 중단한다. 그 뒤에는 START로 새 소비자를 시작한다. 문항은 모든 주문에 재고가 충분하고 예약한 장애 외의 오류는 없다고 가정한다.

[6] `REBALANCE <파티션 목록>`은 현재 소비자의 할당을 전부 회수하는 콜백을 호출하고 목록의 파티션을 재할당한다. 목록은 `0`, `1`, `0,1` 중 하나다. 실패한 소비자에도 사용할 수 있으며 강제 중단한 소비자에는 사용하지 않는다. 이 명령은 소비자 객체를 새로 만들지 않는다. 실제 Kafka의 타이머, 네트워크, 그룹 경쟁은 모델링하지 않는다.

[7] `REPORT <sku> <회원ID>`는 `stock=<재고> points=<누적 포인트> offsets=0:<값>,1:<값> state=<상태>` 한 줄을 출력한다. offsets는 브로커에 저장된 다음 읽기 위치이며 초기값은 모두 0이다. 상태는 STARTED, OK, EMPTY, STOPPED, ASSIGNED, CRASHED 또는 `FAILED:<이벤트ID>:<처리 지점>`이다.

[8] `PROGRESS`는 소비자 내부의 진단 값을 `position=<위치> ready=<위치> revoked=<위치> seen=<ID 목록>` 한 줄로 출력한다. position은 가져온 위치, ready는 처리 루프가 기록한 위치, revoked는 마지막 회수 콜백에서 남긴 위치다. 위치는 파티션 번호 순서의 `번호:값` 목록이고, seen은 이벤트ID의 사전순 목록이다. 빈 목록은 `-`다. REPORT와 PROGRESS만 출력하며 나머지 명령은 출력하지 않는다. 문항마다 프로그램을 새로 실행하며 모든 상태는 비어 있다.

[9] 참고 자료는 [Kafka 4.1 Consumer Configs](https://kafka.apache.org/41/configuration/consumer-configs/)와 [Message Delivery Semantics](https://kafka.apache.org/41/design/design/#message-delivery-semantics)다. 이 코드는 Kafka 클라이언트를 호출하지 않는다. 문항은 참고 자료의 기본값을 외우는 대신 이 프로그램에 작성된 정책과 상태를 기준으로 푼다.
