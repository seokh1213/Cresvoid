# 겹겹이 감싼 상품 조회 클라이언트

[1] `Catalog.kt` → `Decorators.kt` → `CatalogSession.kt` → `Main.kt` 순서로 읽는다. 파일은 모두 `code/src/main/kotlin/`에 있다. 목표 풀이 시간은 25분이다.

[2] 쇼핑 카탈로그 서비스에서 외부 상품 저장소에 접속하는 클라이언트를 검토한다. 상품에는 SKU와 개정 번호가 있다. 캐시, 실패 재시도, 호출 기록을 같은 인터페이스 뒤에 조립한다. 이 프로그램은 실제 저장소 대신 응답을 예약할 수 있는 가짜 저장소를 사용한다. 네트워크 요청과 대기는 없다.

[3] 명령을 표준 입력에서 한 줄씩 EOF까지 읽는다. 빈 줄은 무시한다. 명령과 인자는 공백으로 구분하고 대소문자를 구별한다. SKU는 영문 대문자로 된 식별자다. 모든 문항은 올바른 명령만 주며 `OPEN`으로 시작한다. 문항마다 새 프로세스로 실행한다.

[4] `OPEN FRONT 2` 또는 `OPEN INNER 2`는 새 세션을 연다. `FRONT`와 `INNER`는 `CatalogSession.kt`의 조립 방식을 고르고 마지막 인자는 최대 시도 횟수다. 최대 시도 횟수는 1~5다. `OPEN`은 예약 응답, 캐시, 카운터, 조회 결과를 모두 초기화한다.

[5] `PLAN A FAIL,MISS,3`은 SKU A의 저장소 응답을 순서대로 예약한다. `FAIL`은 `CatalogUnavailable`, `MISS`는 `null`, 양의 정수는 해당 개정 번호의 상품을 뜻한다. 같은 SKU의 기존 예약은 새 목록으로 교체한다. 저장소의 `get` 호출 하나가 응답 하나를 소비한다. 예약이 없거나 소진됐으면 `null`을 반환한다. `PLAN`은 캐시나 카운터를 초기화하지 않는다.

[6] `GET A`는 단건 조회를, `MANY A,B,A`는 주어진 순서의 묶음 조회를 요청한다. 중복 SKU도 허용한다. 조회 결과는 세션에 순서대로 모으고 즉시 출력하지 않는다. 상품은 `A@3`, 없는 상품은 `null`, 세션까지 전파된 저장소 예외는 `error`로 기록한다. 묶음이 성공하면 `[A@3,null]` 형식으로 기록하며, 예외가 전파되면 묶음 전체를 `error` 하나로 기록한다.

[7] `REPORT`만 한 줄을 출력한다. 형식은 `results=<결과> | log=<단건>/<묶음> cache=<reads>/<loads> retry=<attempts> source=<reads>`다. 결과는 세미콜론으로 잇고 아직 조회가 없으면 `-`다. 카운터 이름은 각 클래스의 프로퍼티와 대응한다. 출력은 누적 상태를 보여 주며 세션을 바꾸지 않는다.

[8] 실행 결과와 카운터는 코드의 호출 경로를 따라 판단한다. 문항의 입력과 비교용 입력은 각각 새 세션에서 실행한다. 코드를 바꾸는 문항은 없으며, 명시한 명령 외의 호출도 없다.
