# 재조회해도 유지되는 추천 다양성

[1] 읽는 순서는 `RequestSeed.kt`, `CandidatePool.kt`, `Recommendation.kt`, `Main.kt`다. 파일은 모두 `code/src/main/kotlin/`에 있다. 목표 풀이 시간은 30분이다.

[2] 쇼핑 카탈로그에서 검색한 후보를 추천 칸에 배치하는 모듈이다. 후보의 정수 점수는 이미 계산되어 있다. 요청은 세션 ID, 페이지 번호, 노출 개수, 품질 비율을 가진다. 같은 세션·페이지·후보 ID와 점수 집합·노출 개수·품질 비율로 재조회하면 같은 ID 순서를 반환해야 한다. 페이지 번호는 추첨 문맥이며 후보 목록의 페이지 오프셋이 아니다. 서로 다른 페이지 사이의 중복 노출을 막는 기능은 없다.

[3] 표준 입력을 EOF까지 한 줄씩 읽는다. 명령과 인자는 공백으로 구분하며 빈 줄은 무시한다. `POOL 이름 ID:점수 ...`는 후보 묶음을 저장하거나 교체한다. 후보를 생략하면 빈 묶음이다. 한 묶음 안의 ID는 고유하다. 점수는 0 이상 1,000,000 이하의 정수다. 묶음 이름·결과 이름·후보 ID는 영문자로 시작하고 이후 영문자, 숫자, 밑줄, 하이픈을 쓴다. 대소문자를 구분한다.

[4] `PICK 결과이름 묶음이름 세션ID 페이지 개수 품질비율`은 저장된 묶음으로 추천을 계산해 결과 이름에 저장한다. 같은 결과 이름을 다시 쓰면 교체한다. 세션 ID는 영문자, 숫자, 밑줄, 하이픈으로 된 1~32자 문자열이다. 페이지는 0~99, 개수는 0~100, 품질 비율은 0~100의 정수다. 품질 정책은 최고 점수의 지정 비율 이상인 후보만 노출하는 것이다. 후보 선정과 추첨 순서는 코드에 정의되어 있다.

[5] `SHOW 결과이름 ...`은 지정한 결과들을 인자 순서로 한 줄에 출력한다. 한 결과의 ID는 쉼표로 잇고 결과 사이는 ` | `로 잇는다. ID가 없는 결과는 `(none)`으로 표시한다. `POOL`과 `PICK`은 정상 처리되면 출력하지 않는다. 잘못된 명령, 범위를 벗어난 값, 중복 후보 ID, 없는 묶음이나 결과 참조는 해당 줄에 `ERROR`를 출력한다. 문항 입력은 모두 유효하다. 문항마다 새 프로세스의 빈 저장소에서 시작한다.

[6] 난수 API는 `java.util.Random(seed)`와 `nextInt(bound)`다. `nextInt(bound)`는 0 이상 bound 미만의 인덱스를 반환한다. 시드 구성, 생성기의 수명, bound로 쓰는 목록의 길이와 호출 시점은 코드에서 확인한다.

[7] 난수 구현의 내부 비트를 계산할 필요는 없다. 실제 인덱스가 필요한 문항은 특정 시드와 호출 순서에 대한 반환값을 함께 제시한다. 반환값 표는 명시한 생성기 하나에서 왼쪽부터 연속 호출한 값이다. 새 생성기를 만들면 표의 처음부터 읽는다. Java SE 21은 같은 시드와 같은 메서드 호출 순서에 대해 같은 난수열을 보장한다. 이는 추천 결과를 재현하기 위한 성질이다. 세션 인증이나 토큰 생성은 이 모듈의 용도가 아니다. 출처는 [Java SE 21 Random](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/Random.html)이다.
