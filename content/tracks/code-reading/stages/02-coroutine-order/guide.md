# 코루틴 실행 순서와 디스패처

읽을 파일은 `code/src/main/kotlin/` 의 다섯 파일이다. 아래 순서로 읽는다.

1. `Main.kt`: 명령을 한 줄씩 읽어 가짜 하위 서비스와 연결 풀을 설정하고 상품 상세를 조회한 뒤 결과를 출력한다.
2. `ProductPageService.kt`: 가격, 재고, 리뷰 평점을 하위 서비스에서 동시에 받아 상품 상세 화면 데이터를 만든다.
3. `Downstream.kt`: 지연과 실패를 넣을 수 있는 가짜 하위 서비스, 하위 서비스 호출을 연결 풀과 span 으로 감싸는 게이트웨이, 상품 데이터를 정의한다.
4. `Tracer.kt`: 호출마다 시작 시각, 끝 시각, 결과를 span 으로 기록하고 요청 ID 로 골라낸다.
5. `ViewTracker.kt`: 상품 상세를 보여 준 뒤 조회수와 최근 본 상품 기록을 백그라운드에서 보낸다.

## 맥락

[1] 쇼핑몰 상품 상세 화면에 필요한 데이터를 모으는 집계 서비스다. 가격은 가격 서비스(price)에, 재고 수량은 재고 서비스(stock)에, 리뷰 평점은 리뷰 서비스(review)에 있다. 집계 서비스는 세 서비스를 동시에 호출해 결과를 합친다. 가격을 받지 못하면 화면을 띄우지 않는다. 재고와 평점은 받지 못하면 비워 둔 채 화면을 띄운다.

[2] 재고 서비스가 가끔 느려져서 재고를 기다리는 시간에 한도를 둔다. 가격, 재고, 평점을 모으는 시간 전체에도 한도를 둔다. 리뷰 서비스는 평점 목록을 돌려주고 평균은 집계 서비스가 계산한다. 리뷰가 많은 상품은 평점 목록이 아주 길다.

[3] 화면을 띄운 뒤에는 조회수 서비스(counter)와 최근 본 상품 서비스(recent)에 조회 기록을 보낸다. 화면 응답이 늦어지지 않도록 조회 기록은 백그라운드에서 보낸다. 기록이 실패해도 화면은 영향을 받지 않는다. 최근 본 상품 서비스가 가끔 느려져서 이 서비스로 보내는 기록에는 시간 한도를 둔다. 조회수 기록은 인기 상품 순위를 매기는 데 쓰여서 시간이 걸려도 끝까지 보낸다.

[4] 모든 하위 서비스 호출은 게이트웨이 하나를 거친다. 게이트웨이의 연결 풀은 동시에 열 수 있는 연결 수가 정해져 있다. 게이트웨이는 호출마다 span 을 하나 남긴다.

[5] 이 프로그램은 하위 서비스를 가짜로 바꿔 집계 동작만 떼어 낸 것이다. 가짜 하위 서비스는 정해진 지연만큼 기다린 뒤 응답하거나 실패한다. 응답 내용은 `PRODUCT` 명령으로 등록한 상품 데이터에서 나온다.

[6] 프로그램 전체가 kotlinx-coroutines-test 의 `runTest` 안에서 실행된다. 시각은 가상 시각이고 단위는 밀리초다. 프로그램이 시작할 때 시각은 0 이다. 출력은 입력만으로 정해지고 실제로 걸린 시간과는 상관없다.

## 명령

[7] 프로그램은 표준 입력을 끝까지 한 줄씩 읽고 줄마다 명령 하나를 처리한다. 명령 이름과 인자는 공백으로 나눈다. 시간 인자의 단위는 밀리초다.

[7.1] `PRODUCT <상품ID> <가격> <재고> <평점>...` 은 상품 데이터를 등록한다. 평점은 1~5 정수이고 개수 제한이 없다.

[7.2] `SLOW <서비스> <지연>` 은 그 서비스가 응답하기까지 걸리는 시간을 정한다. 서비스 이름은 `price`, `stock`, `review`, `counter`, `recent` 가운데 하나다.

[7.3] `FAIL <서비스> <사유>` 는 그 서비스가 지연만큼 기다린 뒤 사유를 담아 실패하게 한다. 한 번 정하면 그 서비스로 가는 호출이 모두 실패한다.

[7.4] `POOL <연결 수>` 는 게이트웨이 연결 풀의 크기를 바꾼다.

[7.5] `VIEW <상품ID>` 는 고객 한 명이 상품 상세를 연 것처럼 화면 데이터를 조회한다. 조회마다 `view-1`, `view-2` 처럼 차례로 요청 ID 를 붙인다. VIEW 는 그 조회가 시작한 백그라운드 기록이 모두 끝난 뒤에 다음 명령으로 넘어간다.

[7.6] 명령으로 정하지 않은 지연과 연결 풀 크기는 코드에 적힌 기본값을 따른다.

## 출력

[8] `PAGE` 는 마지막 VIEW 의 결과를 한 줄로 출력한다. 화면을 띄웠으면 `<상품ID> price=<가격> stock=<재고> rating=<평균>(<평점 수>) <걸린 시간>ms` 꼴이다. 받지 못한 재고나 평점은 `?` 로 쓰고 평균은 소수 첫째 자리까지 쓴다. 화면을 띄우지 못했으면 `<상품ID> failed <사유> <걸린 시간>ms` 꼴이다. 걸린 시간은 VIEW 가 조회를 시작한 시각부터 화면 데이터를 돌려받은 시각까지다.

[8.1] `TRACE` 는 마지막 VIEW 의 요청 ID 로 기록된 span 을 기록 순서 그대로 공백으로 이어 한 줄로 출력한다. 끝 시각으로 다시 정렬하지 않으므로 끝 시각이 같은 span 은 먼저 기록된 것이 앞에 온다. span 하나는 `<이름>:<시작 시각>-<끝 시각>:<결과>` 꼴이고 결과는 `ok`, `error`, `cancelled` 가운데 하나다. 시각은 프로그램이 시작한 때부터 잰 가상 시각이다.

[8.2] VIEW 가 한 번도 없었으면 PAGE 와 TRACE 는 `NO VIEW` 를 출력한다. 처리할 수 없는 명령에는 `ERROR` 로 시작하는 한 줄을 출력한다.

[8.3] PRODUCT, SLOW, FAIL, POOL, VIEW 명령은 스스로 아무것도 출력하지 않는다. 다만 VIEW 가 시작한 백그라운드 기록 코드는 표준 출력에 줄을 쓸 수 있다.

## 문항이 가정하는 상황

[9] 문항의 입력은 모두 형식에 맞는 명령이다. 실행 결과를 묻는 문항의 답은 출력 한 줄을 글자 그대로 쓴다.

[9.1] 코드를 바꾼다고 한 문항은 그 문항에서만 바꾼 코드로 실행한다고 본다. 나머지 문항은 원래 코드를 기준으로 한다.

[9.2] 코드 위치의 줄 번호는 `cresvoid read` 가 보여 주는 줄 번호와 같다.
