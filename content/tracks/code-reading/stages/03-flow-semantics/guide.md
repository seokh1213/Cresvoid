# StateFlow 와 SharedFlow 의 의미

읽을 파일은 `code/src/main/kotlin/` 의 다섯 파일이다. 아래 순서로 읽는다.

1. `Main.kt`: 명령을 한 줄씩 읽어 상품, 화면, 알림 채널, 공급사 가격표를 다루고 결과를 출력한다.
2. `PriceStore.kt`: 상품마다 현재 판매가를 들고 있다가 판매가가 바뀌면 화면과 알림 처리기에 알린다.
3. `ProductScreen.kt`: 상품 상세 화면을 연 고객에게 현재 판매가를 보낸다.
4. `PriceAlertHandler.kt`: 가격 변경에서 가격 인하를 골라 알림 채널로 보낸다. 가짜 알림 채널도 이 파일에 있다.
5. `SupplierSync.kt`: 공급사 API 에서 가격표를 받아 저장소에 반영한다. 가짜 공급사 API 도 이 파일에 있다.

## 맥락

[1] 쇼핑몰의 가격 저장소다. 상품의 판매가는 MD 가 직접 바꾸거나 공급사 가격표를 동기화할 때 바뀐다. 판매가는 1원 이상 정가 이하여야 한다. 저장소는 판매가가 바뀌면 두 곳에 알린다. 상품 상세 화면에는 현재 판매가를, 알림 처리기에는 가격 변경을 알린다.

[2] 화면은 고객 브라우저로 판매가를 보낸다. 브라우저 부담을 줄이려고 갱신이 너무 잦지 않게 한다.

[3] 알림 처리기는 판매가가 내려간 변경을 골라 고객에게 가격 인하 알림을 보낸다. 알림 채널은 앱 푸시, 카카오 알림톡처럼 여러 개이고 채널마다 알림 처리기가 하나씩 실행된다. 알림 한 건을 보내는 데 걸리는 시간은 채널마다 다르다. 운영자는 프로그램이 실행되는 동안 채널을 활성화할 수 있다.

[4] 공급사 동기화는 공급사 API 에서 가격표를 한 줄씩 받아 차례로 저장소에 반영한다. 동기화는 공급사 API 의 응답을 입출력용 디스패처에서 읽는다. 이 예제는 실제 `Dispatchers.IO` 대신 같은 가상 시계를 쓰는 테스트 디스패처를 입출력용으로 주입한다. 공급사 API 는 가끔 응답 도중에 연결이 끊긴다. 저장소에 반영할 때는 화면 갱신과 알림이 한꺼번에 몰리지 않도록 속도를 조절한다.

[5] 이 프로그램은 저장소와 그 주변 동작만 떼어 낸 것이다. 화면이 고객 브라우저로 판매가를 보내는 부분, 알림 채널, 공급사 API 는 가짜다. 화면은 판매가를 브라우저로 보내는 대신 기록에 남기고 가짜 알림 채널은 보낸 알림을 기록한다. 가짜 공급사 API 는 가격표 한 줄을 보내는 데 정해진 시간이 걸린다.

[6] 프로그램 전체가 kotlinx-coroutines-test 의 `runTest` 안에서 실행된다. 시각은 가상 시각이고 단위는 밀리초다. 프로그램이 시작할 때 시각은 0 이다. 출력은 입력만으로 정해지고 실제로 걸린 시간과는 상관없다.

## 명령

[7] 프로그램은 표준 입력을 끝까지 한 줄씩 읽고 줄마다 명령 하나를 처리한다. 명령 이름과 인자는 공백으로 나눈다. 가격은 원 단위 정수이고 시간 인자의 단위는 밀리초다.

[7.1] `PRODUCT <상품ID> <정가>` 는 상품을 등록한다. 판매가는 정가에서 시작한다.

[7.2] `PRICE <상품ID> <판매가>` 는 MD 가 판매가를 바꾼 것을 처리한다.

[7.3] `OPEN <화면ID> <상품ID>` 는 고객 한 명이 그 상품의 상세 화면을 연 것을 처리한다.

[7.4] `ALERT <채널> <발송 시간>` 은 알림 채널을 활성화한다. 발송 시간은 그 채널로 알림 한 건을 보내는 데 걸리는 시간이다.

[7.5] `SUPPLY <공급사ID> <상품ID>:<판매가>...` 는 그 공급사 API 가 돌려줄 가격표를 정한다. 공백으로 나뉜 인자 하나가 가격표의 한 줄이다. 형식이 틀린 줄도 넣을 수 있다.

[7.6] `DROP <공급사ID> <줄 수>` 는 그 공급사로 가는 다음 요청에서 공급사 API 가 그 줄 수만큼 보낸 뒤 연결이 끊기게 한다.

[7.7] `SYNC <공급사ID>` 는 그 공급사의 가격표를 동기화한다. 동기화가 끝나야 다음 명령으로 넘어간다.

[7.8] `WAIT <시간>` 은 그 시간이 지난 뒤에 다음 명령을 처리한다.

## 출력

[8] `SCREEN <화면ID>` 는 그 화면이 남긴 기록을 순서대로 `<화면ID> <판매가>@<시각> ...` 꼴의 한 줄로 출력한다. 기록 하나는 화면이 고객에게 판매가를 한 번 보낸 것이고 시각은 보낸 시각이다.

[8.1] `SENT <채널>` 은 그 채널이 보낸 알림을 보낸 순서대로 `<채널> <상품ID>:<판매가>@<시각> ...` 꼴의 한 줄로 출력한다. 판매가는 내린 뒤의 판매가이고 시각은 발송을 마친 시각이다. 보낸 알림이 없으면 `<채널> none` 을 출력한다.

[8.2] `SYNC` 는 동기화를 마치면 `<공급사ID> requests=<요청 수> changed=<바뀐 수> unchanged=<그대로인 수> <걸린 시간>ms` 꼴의 보고 한 줄을 출력한다. 요청 수는 공급사 API 에 가격표를 요청한 횟수다. 바뀐 수는 반영해서 판매가가 바뀐 횟수이고 그대로인 수는 반영했지만 판매가가 이미 같아서 바뀌지 않은 횟수다. 보고에 동기화가 멈춘 사유가 들어 있으면 끝에 ` stopped: <사유>` 를 붙인다.

[8.3] 처리할 수 없는 명령에는 `ERROR` 로 시작하는 한 줄을 출력한다. 그 밖에는 SCREEN, SENT, SYNC 만 출력한다.

## 문항이 가정하는 상황

[9] 문항의 입력에는 프로그램이 모르는 명령이나 인자가 빠진 명령이 없다. PRODUCT, PRICE, ALERT, DROP, WAIT 의 숫자 인자는 모두 정수다. 실행 결과를 묻는 문항의 답은 출력 한 줄을 글자 그대로 쓴다.

[9.1] 코드를 바꾼다고 한 문항은 그 문항에서만 바꾼 코드로 실행한다고 본다. 나머지 문항은 원래 코드를 기준으로 한다.

[9.2] 코드 위치의 줄 번호는 `cresvoid read` 가 보여 주는 줄 번호와 같다.
