# 주문 상태 객체와 구독자 알림

[1] 읽을 파일과 순서는 `OrderState.kt` → `Order.kt` → `Observers.kt` → `Main.kt`다. 모두 `code/src/main/kotlin/`에 있다. 목표 풀이 시간은 25분이다.

[2] 쇼핑 카탈로그에서 선택한 상품의 주문을 처리하는 서비스다. 결제 승인, 출고 요청, 취소 요청을 주문에 전달하고 구독자가 남긴 알림 기록을 조회한다. 실제 결제사와 배송사 호출은 하지 않는다. `dispatch`는 출고 연동, `receipt`는 접수 알림, `ledger`는 주문 이력 기록을 맡는다. 각 구독자의 호출 횟수와 순서는 코드를 읽어 판단한다.

[3] 표준 입력에서 한 줄에 명령 하나를 받아 EOF까지 실행한다. 토큰은 공백으로 구분한다. 주문 ID와 참조값은 공백이 없는 문자열이고 대소문자를 구분한다. 빈 줄은 건너뛴다. 문항의 명령은 아래 형식을 지키며, 이미 만든 주문 ID와 정의된 구독자 이름만 사용한다. 문항마다 프로그램을 새로 시작한다.

[4] `CREATE <주문 ID> <IGNORE|REJECT>`는 주문과 그 주문의 구독자 인스턴스를 만든다. 구독자 이름은 `ledger`, `dispatch`, `receipt`다. `SUB <주문 ID> <구독자 이름>`은 구독을 등록하고, `UNSUB <주문 ID> <구독자 이름>`은 구독을 해제한다. 생성 직후의 구독 목록과 중복 등록의 효과는 조립 코드와 주문 코드에서 확인한다.

[5] `DO <주문 ID> <PAY|SHIP|CANCEL> <참조값>`은 전이를 요청한다. 참조값은 각각 결제 승인 번호, 배송 조회 번호, 취소 접수 번호다. 허용되는 전이는 상태 객체에서 확인한다. `IGNORE`와 `REJECT`는 허용되지 않은 전이를 다루는 정책이며, 명령 처리기가 그 결과를 기록한다. 각 요청이 상태와 참조값에 미치는 영향은 코드로 판단한다.

[6] `TRACE`는 지금까지 쌓인 기록 전체를 한 줄로 출력한다. 기록 사이는 ` | `로 구분하며 기록이 없으면 `(empty)`를 출력한다. 알림 기록의 형식은 `<구독자>:<주문>#<변경 버전>:<변경 전 상태>><변경 후 상태>@<기록 시점의 주문 상태>`다. 요청 결과 기록은 `<ignored|rejected>:<주문>:<요청>@<주문 상태>`다. `TRACE`는 기록을 지우지 않는다.

[7] `STATUS <주문 ID>`는 `<주문>:<현재 상태>#<버전>:pay=<결제 참조>:ship=<배송 참조>:cancel=<취소 참조>:sub=<구독자 목록>`을 한 줄로 출력한다. 참조값이 없거나 구독자가 없으면 해당 자리에 `-`를 쓴다. 구독자 이름 사이는 쉼표로 구분한다. `TRACE`와 `STATUS` 이외의 명령은 직접 출력하지 않는다.

[8] 실행은 단일 스레드에서 진행한다. 외부 시스템, 실제 시각, 난수는 사용하지 않는다. 문항이 코드 변경이나 별도 호출 코드를 제시하면 그 조건만 적용하고 나머지 코드는 그대로 둔다. 출처는 GoF의 State·Observer 패턴이며, 이 단계의 서비스와 문항은 학습용으로 새로 구성했다.
