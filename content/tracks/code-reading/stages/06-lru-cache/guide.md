# 상품 상세 로컬 캐시

[1] 읽을 파일은 `CacheModel.kt` → `ProductCache.kt` → `Main.kt` 순서다. 모두 `code/src/main/kotlin/` 아래에 있다. 목표 풀이 시간은 25분이다.

[2] 상품 상세 API 앞에 둔 프로세스 안 캐시다. 상품 ID마다 상세 데이터의 리비전과 만료 시각을 보관한다. 운영자가 상품 변경을 반영하거나 인기 상품을 미리 채울 수 있고, 진단 명령으로 캐시 상태를 확인할 수 있다. 모든 명령은 단일 스레드에서 입력 순서대로 처리한다. 저장소 조회나 백그라운드 작업은 없다.

[3] 첫 줄은 `CACHE capacity`다. `capacity`는 양의 Int 범위 정수다. 처음에는 캐시가 비어 있고 시각과 모든 통계는 0이다. 이후 한 줄에 명령 하나를 주고 EOF까지 처리한다. 빈 줄은 건너뛴다. 상품 ID와 리비전은 영문자·숫자·밑줄·하이픈으로 이루어진 공백 없는 문자열이다. 문항에는 올바른 입력만 주며 시각 계산은 Long 범위를 넘지 않는다.

[4] `PUT id revision ttl`은 상품 상세를 등록하거나 갱신한다. `WARM id revision ttl`은 미리 채울 후보를 전달한다. `ttl`은 양의 Long 범위 정수이고 단위는 초다. 두 명령이 기존 항목을 처리하는 방식은 코드에서 확인한다. 명령 자체는 출력하지 않는다.

[5] `GET id`는 상세 조회 요청이다. 조회 결과를 마지막 응답으로 보관하고 적중 또는 실패 횟수를 센다. 실패해도 원본 저장소에서 데이터를 가져오지는 않는다. `PROBE id`는 저장 여부를, `REVISION id`는 저장된 리비전을 진단해 마지막 응답으로 보관한다. 진단은 GET의 적중·실패 횟수에 포함하지 않는다. 만료와 접근 순서에 관한 처리는 코드에서 확인한다.

[6] `INVALIDATE id`는 해당 상품을 무효화하고 `SWEEP`은 만료 항목을 정리한다. `ADVANCE seconds`는 가짜 시계를 음이 아닌 Long 범위 정수만큼 전진시킨다. 실제 시각은 사용하지 않는다. 이 명령들은 출력하지 않으며 마지막 응답도 바꾸지 않는다.

[7] `REPORT`만 한 줄을 출력한다. 형식은 `time=시각 hits=적중수 misses=실패수 evictions=퇴출수 last=마지막응답 order=[항목,...]`다. 퇴출수는 용량 정책이 제거한 횟수다. 각 항목은 `id@revision:만료시각`이고, `order`는 맵의 순회 순서다. 비어 있으면 `[]`다. 마지막 응답은 처음에 `NONE`이고, 이후 `HIT:id@revision`, `MISS:id`, `PRESENT:id`, `ABSENT:id`, `REVISION:id@revision` 중 하나다. 저장되지 않은 상품의 리비전 표시는 `-`다.

[8] 문항마다 새 프로세스를 시작한다. 원본 코드가 정상 종료하는 경우, 입력에 REPORT가 하나 있으면 출력도 한 줄이다. 문항에서 명시한 코드 변경은 해당 문항에서만 가정한다. 실행 환경은 Kotlin/JVM과 JDK 21이며 코드와 문항은 스레드 간 동시 실행을 가정하지 않는다.
