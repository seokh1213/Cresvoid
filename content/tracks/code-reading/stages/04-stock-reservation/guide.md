# 재고 예약과 만료

[1] 읽는 순서는 `Main.kt` → `Reservation.kt` → `ReservationService.kt` → `ReservationReports.kt`다. 파일은 모두 `code/src/main/kotlin/`에 있다. 목표 풀이 시간은 25분이다.

[2] 쇼핑 카탈로그에서 주문을 만들기 전에 상품 재고를 예약하는 서비스다. 입고, 예약, 주문 확정, 취소와 만료 처리를 한 프로세스에서 수행한다. 상품별 재고 조회, 확정일별 집계, 최근 예약 조회와 만료 알림 전달도 이 서비스의 업무다.

[3] 표준 입력에서 명령을 한 줄씩 EOF까지 읽는다. 명령과 인자는 공백으로 구분하며 빈 줄은 무시한다. 각 문항은 새 프로세스에서 시작한다. 처음에는 재고와 예약이 없고 시각은 `2026-01-01T00:00:00Z`다. 실제 시계나 다른 프로세스의 영향을 받지 않는다.

[4] `AT <시각>`으로 서비스 시각을 옮긴다. 시각은 `2026-01-01T15:00:00Z` 같은 ISO-8601 Instant 형식이다. 입력 시각은 현재 시각보다 이르지 않다. 입력에 `AT`가 없으면 명령을 처리해도 시각이 흐르지 않는다.

[5] `ADD <상품> <수량>`은 입고, `HOLD <예약 ID> <상품> <수량> <유효 초>`는 예약 요청이다. 상품과 예약 ID는 공백 없는 영문·숫자 문자열이다. 수량과 유효 초는 양수이며 문항에는 수치 범위를 넘는 연산이 없다. `HOLD`에 쓰는 예약 ID는 한 입력 안에서 중복되지 않는다.

[6] `CONFIRM <예약 ID>`는 주문 확정 요청이고 `CANCEL <예약 ID>`는 취소 요청이다. `COMPACT <상품>`은 상품별 추적 목록을 정리하는 유지보수 명령이다. 예약 승인 여부, 각 상태에서 요청을 처리하는 방식, 만료 판정과 정리 범위는 코드에서 확인한다.

[7] `STOCK <상품>`은 `<상품> available=<가용 수량> held=<예약 중 수량> tracked=<추적 목록 크기>`를 한 줄로 출력한다. `tracked`는 상품별 추적 목록에 남아 있는 예약 객체 수다. 재고 수량과 목록 크기를 구분해서 읽는다.

[8] `DAILY <날짜>`는 확정일별 집계를 `<상품>:<예약 건수>/<수량 합계>` 형식으로 출력한다. 날짜 인자는 `2026-01-02` 같은 ISO 날짜다. `LATEST`는 상품별 최근 예약을 `<상품>:<예약 ID>/<상태>` 형식으로 출력한다. 두 명령 모두 상품 이름순으로 정렬하고 항목 사이에 쉼표만 넣는다. 결과가 비어 있으면 `(none)`을 출력한다. 날짜 변환과 최근 예약의 선택 기준은 코드에서 확인한다.

[9] `EXPIRED`는 아직 전달하지 않은 만료 알림의 예약 ID를 쉼표로 이어 한 줄로 출력한다. 전달할 알림이 없으면 `(none)`을 출력한다. 알림의 선택, 전달 순서와 전달 뒤 보관 방식은 코드를 따른다. `STOCK`, `DAILY`, `LATEST`, `EXPIRED`만 출력하고 나머지 명령은 출력하지 않는다.

[10] 문항에 별도 변경안이 없으면 제공된 코드를 그대로 실행한다고 가정한다. 변경 영향을 묻는 문항은 명시한 코드만 바꾼다. Kotlin 2.4.21과 JDK 21을 사용하며 우선순위 큐 내부를 관찰하기 위한 출력은 추가하지 않는다.
