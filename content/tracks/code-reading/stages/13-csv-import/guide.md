# 상품 일괄 등록

읽을 파일과 순서: `Main.kt` → `CsvReader.kt` → `ImportHeader.kt` → `ProductImporter.kt` → `ImportOutput.kt`. 파일은 모두 `code/src/main/kotlin/`에 있다.

[1] 판매자가 올린 CSV를 상품 등록 요청으로 바꾸는 처리기다. CSV를 해석하고 머리글에 따라 열을 연결한 뒤 상품별 검증 결과를 낸다. 이 단계는 저장소에 쓰기 직전의 처리만 다룬다. 목표 풀이 시간은 30분이다.

[2] 표준 입력에서 `IMPORT n` 명령을 EOF까지 읽는다. 명령 다음의 물리적인 줄 n개가 CSV 본문 하나다. 큰따옴표 안에서 이어지는 줄도 각각 센다. 명령 줄은 본문 줄 수에 넣지 않는다. CSV 본문에는 LF 또는 CRLF를 쓰며, 마지막 줄은 줄 끝 문자 없이 EOF로 끝날 수도 있다. 명령마다 독립된 등록 요청을 처리한다.

[3] CSV의 첫 레코드는 머리글이다. 취급하는 열은 `sku`, `name`, `price`, `stock`이며 앞의 세 열은 필수다. 열 순서는 바꿀 수 있다. 머리글 뒤의 레코드가 상품 행이다. 쉼표, 큰따옴표, 줄바꿈이 들어 있는 필드를 읽을 때에는 파서가 문자를 소비하는 위치도 추적해야 한다. CSV 문법과 머리글의 오류는 요청 전체의 오류이며, 상품 검증 오류는 해당 상품의 실패로 출력한다.

[4] 정상적으로 해석한 요청은 `OK=성공수[성공목록] ERR=실패수[실패목록]` 한 줄로 출력한다. 성공 항목은 `시작줄:"SKU":"상품명":가격:재고`, 실패 항목은 `시작줄:실패이유`이며 각각 세미콜론으로 잇는다. 시작줄은 CSV 본문의 첫 줄을 1로 센 물리적인 줄 번호다. 각 목록은 본문에서 만난 순서를 따른다. 빈 목록은 `[]`로 쓴다.

[5] 출력의 문자열은 큰따옴표로 감싼다. 문자열 안의 역슬래시, 큰따옴표, LF, CR, 탭은 각각 `\\`, `\"`, `\n`, `\r`, `\t`로 표시한다. 따라서 상품명이 여러 줄이어도 출력은 한 줄이다. 요청 전체의 오류는 `ERROR 이유`로 출력한다. 문항에서는 출력 문자열의 실제 문자와 이 표시를 구별해야 한다.

[6] 문항 입력에 보이지 않는 문자가 쓰이면 해당 문항에서 위치를 밝힌다. BOM은 U+FEFF, NBSP는 U+00A0, CR은 U+000D, LF는 U+000A다. `\uFEFF` 같은 표기는 코드값을 설명하는 기호이며, 입력에서 그 여섯 글자를 해석하는 명령은 없다. 별도 설명이 없는 입력 줄의 끝은 LF다. 인코딩 표를 외울 필요는 없다.

[7] 문항마다 새 프로세스로 시작하며 코드 변경을 가정하는 문항에서만 지정한 변경을 적용한다. 코드를 실행하기 전에 각 입력의 레코드 경계, 열 개수, 검증 순서, 출력 문자열을 끝까지 예측하는 과제다.
