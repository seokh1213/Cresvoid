# 3단계: 순위 결합과 검색 결과의 다양성

## 1. 개요

[1.1] 2단계 위에 RRF·MMR·GROUP 명령을 더한다. 각각 두 검색 목록 결합, 중복 내용 억제, 같은 문서의 청크 묶기를 맡는다. 앞 단계의 검색 출력은 그대로다. 목표 작업 시간은 2시간 안팎이다.

## 2. 배경 개념

[2.1] BM25와 코사인은 점수의 단위와 분포가 달라 그대로 더하기 어렵다. Reciprocal Rank Fusion(RRF)은 점수 대신 각 목록에서의 순위를 사용한다. 두 목록에 모두 높은 순위로 나타나는 청크는 두 목록에서 점수를 얻는다. 목록을 미리 자르면 잘린 청크에는 그 목록의 순위가 없으므로 기여도 없다.

[2.2] [Cormack·Clarke·Büttcher의 SIGIR 2009 논문](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf)은 순위 r에 `1/(c+r)`을 부여해 합하는 RRF를 제시한다. 원문의 상수 k는 여기서 결과 개수 k와 구분하려고 c로 부르며 기본값은 60이다. c가 커지면 상위 몇 순위 사이의 기여 차이가 완만해진다.

[2.3] Maximum Marginal Relevance(MMR)는 관련도와 이미 고른 결과와의 중복을 함께 본다. 매번 아직 고르지 않은 후보 가운데 관련도 보상에서 중복 벌점을 뺀 값이 가장 큰 것을 고른다. 첫 번째 결과와 두 번째 결과의 선택 기준이 달라질 수 있으므로 최종 목록은 한 번의 점수 정렬과 다르다.

[2.4] 중복 억제와 문서 묶기는 다른 동작이다. 서로 다른 문서라도 내용이 비슷할 수 있고, 같은 문서 안에도 서로 다른 내용의 청크가 있을 수 있다. 이 단계의 MMR는 벡터로 유사함을 판단하며 GROUP은 문서 id만으로 묶는다. 두 기능을 자동으로 연달아 적용하지 않는다.

## 3. 입출력 규칙

[3.1] 필드 구분, 숫자 문법, 차원 검사와 청크 기본 순서는 앞 단계를 따른다. k와 depth는 각각 1~1,000이며 서로 대소 관계를 제한하지 않는다. c 필드는 `-`이면 60, 아니면 0~1,000 정수다. lambda는 2단계의 실수 문법을 따르되 0 이상 1 이하이다. RRF·MMR·GROUP의 모든 출력 점수는 여섯 자리 반올림이다.

[3.2] RRF와 MMR의 결과 행은 `청크id<TAB>점수`다. GROUP의 결과 행은 `문서id<TAB>점수<TAB>청크id목록`이며 청크id목록은 쉼표로만 구분한다. 빈 결과는 모두 `(none)`이다. 검색용 텍스트를 함께 출력하지 않는다.

## 4. 명령 규칙

[4.1] `RRF<TAB>k<TAB>depth<TAB>c<TAB>text<TAB>vector`는 BM25 상위 depth개와 VECTOR 상위 depth개를 결합하고 상위 k개 청크를 출력한다. 각 목록은 2단계 규칙으로 점수를 반올림해 정렬한 목록이다. BM25의 text는 빈 필드도 허용하고 VECTOR의 vector는 반드시 주어진다.

[4.2] 잘린 두 목록의 합집합만 결합 후보다. 각 목록의 순위는 정렬된 위치 그대로 1부터 하나씩 증가한다. 한 청크의 RRF 점수는 그 청크가 BM25 목록에 있으면 `1.0/(c+BM25순위)`, VECTOR 목록에 있으면 `1.0/(c+VECTOR순위)`를 더한 값이다. 목록에 없으면 그 목록의 기여는 0이다. 끝 순위나 depth+1을 대신 넣지 않는다. 0.0부터 BM25 기여, VECTOR 기여 순으로 더한다.

[4.3] RRF 점수를 여섯 자리로 반올림하고 내림차순으로 정렬한다. 동점은 청크 기본 순서다. 이 정렬을 결합 목록이라고 부른다. RRF는 결합 목록 앞 k개와 반올림한 RRF 점수를 출력한다. 두 원래 목록의 점수 자체를 더하거나, 결합한 뒤 원래 순위를 다시 매기지 않는다.

[4.4] `MMR<TAB>k<TAB>depth<TAB>c<TAB>lambda<TAB>text<TAB>vector`는 같은 결합 후보와 반올림한 RRF 점수를 구한 뒤 최대 k개를 차례로 고른다. 후보 x의 관련도 rel(x)는 반올림한 RRF 점수를 후보 중 가장 큰 반올림한 RRF 점수로 나눈 값이다. 후보가 없으면 빈 결과다. rel은 이 나눗셈 후에 별도로 반올림하지 않는다.

[4.5] 이미 선택한 집합을 S라 할 때 후보 x의 중복도 red(x,S)는 `max(0, sim(x,s): s∈S)`다. S가 비어 있으면 0이다. sim은 두 청크 벡터의 2단계 코사인을 여섯 자리로 반올림한 값이다. 두 청크 중 하나라도 벡터가 없으면 sim은 0이고, 0벡터도 2단계 정의대로 sim이 0이다. 음수 유사도는 다양성 보너스를 만들지 않는다.

[4.6] 선택 점수는 `lambda*rel(x)-(1.0-lambda)*red(x,S)`다. 매 선택 시점마다 남은 후보들의 선택 점수를 여섯 자리로 반올림하여 가장 큰 후보를 고른다. 동점은 RRF 순서가 아니라 청크 기본 순서다. 고른 후보를 S에 넣고 다음 선택을 계속한다. 점수가 0이나 음수여도 후보가 남으면 고른다. 같은 청크를 두 번 고르지 않는다.

[4.7] MMR는 선택 순서대로 청크 id와 그 청크를 고르던 시점의 반올림한 선택 점수를 출력한다. 고른 뒤 다시 정렬하거나 이전 선택 점수를 갱신하지 않는다. lambda=1이면 관련도만 보고, lambda=0이면 첫 선택의 모든 후보가 0점이므로 청크 기본 순서의 첫 후보를 고른다.

[4.8] `GROUP<TAB>k<TAB>depth<TAB>c<TAB>text<TAB>vector`는 4.3의 전체 결합 목록을 문서 id로 묶는다. 각 문서의 점수는 그 문서에 속한 후보들의 반올림한 RRF 점수 중 최댓값이다. 청크가 많다는 이유만으로 점수를 합하지 않는다. 문서는 이 점수 내림차순, 동점이면 문서 id 오름차순으로 정렬한 뒤 k개까지 출력한다.

[4.9] 각 GROUP 행의 청크id목록은 해당 문서의 결합 후보를 결합 목록에서 나타난 순서로 전부 나열한다. 결합 전에 잘린 청크는 넣지 않으며 청크 기본 순서로 다시 정렬하지 않는다. k는 문서 수를 제한할 뿐 문서별 청크 수를 제한하지 않는다. GROUP은 MMR를 수행하지 않는다.

## 5. 오류 규칙

[5.1] 새 세 명령은 먼저 필드 수와 모든 필드의 문법·범위를 검사하여 틀리면 `ERR BAD_ARGUMENT`를 출력한다. 그 뒤 청크 미생성이면 `ERR NOT_BUILT`, 마지막으로 설정된 임베딩 차원과 질의 벡터 차원이 다르면 `ERR DIMENSION`이다. 오류 시 상태를 바꾸지 않는다. 후보가 없거나 BM25 목록이 비어 있어도 차원 검사는 한다.

## 6. 예시

[6.1] 세 청크의 BM25 토큰 수와 빈도는 같다. VECTOR도 처음 두 청크가 1점으로 동점이어서 두 목록 모두 1:0,1:1,2:0 순이다. c=0이면 RRF는 2,1,2/3이다. 기본 c=60이면 각각 2/61,2/62,2/63이다.

```text
> CONFIG	4	0	CHAR	NONE
OK
> DOC	1		red red
OK
> DOC	2		red
OK
> BUILD
OK	3
> VEC	1:0	1,0
OK
> VEC	1:1	1,0
OK
> VEC	2:0	0,1
OK
> RRF	3	3	0	red	1,0
1:0	2.000000
1:1	1.000000
2:0	0.666667
> RRF	3	3	-	red	1,0
1:0	0.032787
1:1	0.032258
2:0	0.031746
> MMR	3	3	0	0.5	red	1,0
1:0	0.500000
2:0	0.166667
1:1	-0.250000
> GROUP	2	3	0	red	1,0
1	2.000000	1:0,1:1
2	0.666667	2:0
> RRF	3	1	0	red	0,1
1:0	1.000000
2:0	1.000000
```

[6.2] 위 MMR 예시에서는 처음에 1:0을 고른다. 다음 선택에서 1:1의 점수는 `0.5*(1/2)-0.5*1=-0.25`, 2:0의 점수는 `0.5*(0.666667/2)-0.5*0=0.16666675`이므로 2:0을 먼저 고른다. 마지막 RRF는 각 목록의 첫 후보만 기여하며, 어느 목록에 없는 청크는 그 목록에서 기여를 받지 않는다.

## 7. 검사 방식

[7.1] 표준 입력, 종료 코드와 글자 그대로의 출력 비교는 1단계와 같다. 일반 테스트는 10초, 대규모 테스트는 빌드 시간을 제외하고 40초다. MMR는 선택 순서와 선택 시점 점수까지 비교한다.

[7.2] 대규모 테스트는 청크 최대 50,000개와 차원 최대 32를 사용한다. RRF·MMR·GROUP 합계 최대 30회이며, 이 중 MMR는 최대 10회, 각 MMR의 depth는 최대 100, k는 최대 50이다. 다른 명령의 depth·k는 3.1의 전체 범위를 검사한다. 일반 테스트는 모든 유효한 depth·k 조합을 사용할 수 있다. 모든 청크를 정확히 검색해도 되는 규모이며 근사 최근접 이웃 탐색은 필요하지 않다. 나머지 자원 상한은 2단계를 따른다.

[7.3] 누락 순위의 0 기여, 반올림 동점과 연속 순위, c=0과 기본값, 빈 낱말 목록, 미적재·0·반대 방향 벡터, lambda 양 끝값, 음수 선택 점수, 문서 묶기의 순서와 구성원을 확인한다. 앞 단계 테스트도 누적 실행한다.
