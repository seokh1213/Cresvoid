# 2단계: 청크 단위 낱말 검색과 벡터 검색

## 1. 개요

[1.1] 1단계 위에 청크 임베딩 적재, BM25 검색과 코사인 유사도 검색을 더한다. 기존 명령의 입력과 출력은 그대로다. 새 명령은 VEC·BM25·VECTOR다. 목표 작업 시간은 2시간 안팎이다.

## 2. 배경 개념

[2.1] BM25는 낱말이 청크에 몇 번 나오는지, 전체 청크에서 얼마나 드문지, 청크가 평균보다 얼마나 긴지를 함께 보는 관련도 점수다. 같은 낱말이 반복되면 점수는 늘지만 증가 폭은 줄어든다. 희귀한 낱말은 더 큰 기여를 하고 긴 청크는 길이 보정을 받는다. 이 단계의 BM25 식과 상수는 프로젝트 search-engine 트랙의 02-ranking과 같다. 검색 단위와 질의 문법은 아래에서 따로 정한다.

[2.2] 임베딩은 텍스트를 여러 실수로 된 벡터로 표현한 것이다. 이 과제에서는 이미 계산된 벡터를 입력받는다. 코사인 유사도는 두 벡터의 내적을 각각의 길이로 나눈 값으로, 크기보다 방향이 얼마나 같은지를 나타낸다. 반대 방향은 음수일 수 있다. 길이가 0인 벡터에는 이 식을 그대로 적용할 수 없어 별도 규칙이 필요하다.

[2.3] 낱말 검색은 정확한 용어에 강하다. 벡터 검색은 주어진 임베딩의 관계를 반영한다. 두 점수의 수치 범위는 다르므로 같은 숫자라고 같은 관련도를 뜻하지 않는다. 이 단계에서는 각각의 결과를 독립적으로 출력한다.

## 3. 입출력 규칙

[3.1] 탭 필드, 정수 형식, 청크 기본 순서와 오류 후 계속 처리하는 규칙은 1단계를 따른다. 검색 결과의 행은 `청크id<TAB>점수`다. 최대 k행을 출력하고 후보가 없으면 `(none)`이다. k는 1~1,000이다.

[3.2] 입력 실수는 `-?(0|[1-9][0-9]*)(\.[0-9]{1,6})?` 형식이며 소수 부분은 최대 여섯 자리다. 절댓값은 1,000 이하이고 Double로 변환했을 때 유한해야 한다. 지수·플러스 부호·공백·NaN·Infinity는 허용하지 않는다. 벡터 필드는 이 실수를 쉼표 하나로 나눈 1~32개 성분이며 빈 성분은 없다. `-0`, `0.0`도 허용한다.

[3.3] 모든 수치 계산은 IEEE 754 Double로 한다. 이후 문서에서 p자리 반올림은 `u=floor(x*10^p+0.5)`로 정수 단위를 정하는 것이다. 출력은 u를 10^p로 나눈 고정 소수점이며 소수 부분을 정확히 p자리 쓴다. 단위 u가 0이면 음수 기호를 붙이지 않는다. 동점 판정도 이 정수 단위를 비교한다. 지수 표기와 로케일별 쉼표는 쓰지 않는다. BM25는 p=4, 코사인은 p=6이다.

[3.4] 결과는 반올림한 점수 내림차순, 동점이면 청크 기본 순서로 정렬한다. 반올림 전 점수가 달라도 반올림 결과가 같으면 동점이다. 정렬한 다음 k개를 취한다. 이후 단계가 이 검색 목록의 순위를 사용하면 이 순서의 1,2,3,…을 쓰며 공동 순위나 건너뛴 순위는 없다.

## 4. 명령 규칙

[4.1] `VEC<TAB>chunkId<TAB>vector`는 생성된 청크 하나의 벡터를 추가하거나 대체하고 `OK`를 출력한다. chunkId의 문서 id는 1단계 범위, 순번은 0 이상 1,000,000,000 이하이며 둘 다 정수 형식을 지킨다. 없는 청크를 자동으로 만들지 않는다.

[4.2] BUILD 뒤 첫 성공한 VEC가 현재 임베딩 차원을 정한다. 이후 VEC와 VECTOR 질의 벡터는 이 차원과 같아야 한다. 아직 성공한 VEC가 없으면 질의 벡터의 차원은 1~32 중 어느 것이든 허용하되 그 질의가 차원을 설정하지는 않는다. VEC를 대체할 때도 차원은 바뀌지 않는다. 모든 성분이 0인 벡터도 적재할 수 있다.

[4.3] 성공한 DOC·DEL·CONFIG는 청크와 함께 모든 벡터와 차원을 폐기한다. BUILD도 호출할 때마다 벡터와 차원을 폐기한다. 청크 id가 이전 BUILD와 같아도 벡터는 재적재해야 한다. 기존 명령의 응답은 바뀌지 않는다.

[4.4] `BM25<TAB>k<TAB>text`는 질의 텍스트로 청크를 검색한다. text는 빈 필드를 허용한다. 검색용 텍스트 전체를 토큰화하므로 TITLE 접두도 빈도와 길이에 포함된다. ASCII 영문자·숫자를 L 부류, 한글 음절 U+AC00~U+D7A3을 H 부류로 정한다. 같은 부류 문자가 최대로 이어진 구간이 토큰이며 부류가 바뀌어도 끊는다. 그 밖의 문자는 구분자다. ASCII 대문자는 소문자로 바꾼다. `Ab12가나_é`는 `ab12`, `가나` 두 토큰이다.

[4.5] 질의 토큰은 중복을 없앤 집합으로 사용한다. `+`, `-`, 괄호에는 질의 연산자 뜻이 없다. 질의 토큰을 하나 이상 포함하는 모든 청크가 후보이며, 토큰 없는 질의는 빈 결과다. 벡터 적재 여부는 BM25 후보에 영향을 주지 않는다.

[4.6] 전체 생성 청크 수를 N, 토큰 t를 포함한 청크 수를 df(t), 후보 d에 t가 나오는 횟수를 tf(t,d), d의 전체 토큰 수를 dl(d)라 한다. avgdl은 모든 청크의 토큰 수 합을 N으로 나눈 값이다. 토큰 없는 청크도 N에 들어가며 df와 avgdl은 후보가 아닌 전체 생성 청크에서 구한다. 제목이 같은 여러 청크와 겹친 본문도 각각 센다.

[4.7] `idf(t)=ln(1+(N-df(t)+0.5)/(df(t)+0.5))`이며 ln은 자연로그다. 후보의 점수는 각 질의 토큰에 대해 `idf(t)*tf(t,d)*2.2/(tf(t,d)+1.2*(1-0.75+0.75*dl(d)/avgdl))`을 더한 값이다. tf가 0인 토큰의 몫은 0이다. 질의 토큰은 Kotlin String의 자연 순서 오름차순으로 처리하고 0.0에서 왼쪽부터 차례로 더한다. 후보가 없으면 avgdl이나 점수의 나눗셈을 수행할 필요 없이 빈 결과다.

[4.8] `VECTOR<TAB>k<TAB>vector`는 적재된 벡터가 있는 청크만 검색한다. 0점과 음수 점수도 후보에 남기며 k가 후보 수보다 크면 모두 출력한다. 벡터가 없는 청크와 0벡터가 있는 청크는 다르다.

[4.9] 코사인은 `dot(a,b)/(sqrt(dot(a,a))*sqrt(dot(b,b)))`다. 내적은 성분 번호 오름차순으로 곱을 구해 0.0부터 차례로 더한다. 각 벡터 길이는 해당 자기 내적의 제곱근이다. 어느 한쪽이 0벡터면 유사도는 0.0이다. 그 밖에는 계산한 값을 [-1,1] 범위로 자른 뒤 여섯 자리로 반올림한다. 이 코사인 정의는 뒤 단계의 청크 사이 유사도에도 사용한다.

## 5. 오류 규칙

[5.1] VEC·BM25·VECTOR는 필드 수와 각 필드 형식·범위를 먼저 검사하고 위반 시 `ERR BAD_ARGUMENT`를 출력한다. 이 검사에는 VEC의 chunkId 문법과 벡터 성분 형식이 포함된다. BM25의 text에는 토큰이 없어도 오류가 아니다.

[5.2] 형식이 맞으면 세 명령 모두 청크 생성 여부를 검사하고 미생성이면 `ERR NOT_BUILT`다. 그 뒤 VEC는 청크 존재를 검사해 없으면 `ERR NOT_FOUND`다. 마지막으로 VEC와 VECTOR는 설정된 차원과 다르면 `ERR DIMENSION`이다. 빈 후보에서도 질의의 차원 검사는 생략하지 않는다. 오류 한 줄만 내며 실패한 VEC는 차원을 설정하거나 기존 벡터를 바꾸지 않는다.

## 6. 예시

[6.1] 청크 네 개의 토큰 길이는 2,1,1,0이며 avgdl은 1이다. red의 df는 2여서 idf는 ln(2)다. 문서 2의 점수는 ln(2), 문서 1의 점수는 `ln(2)*2.2/3.1`이다. 코사인 0인 두 청크는 청크 기본 순서로 정렬한다.

```text
OK
> DOC	1		red blue
OK
> DOC	2		red
OK
> DOC	3		green
OK
> DOC	4		!!!
OK
> BUILD
OK	4
> BM25	10	RED red
2:0	0.6931
1:0	0.4919
> VEC	1:0	1,0
OK
> VEC	2:0	0,1
OK
> VEC	3:0	-1,0
OK
> VEC	4:0	0,0
OK
> VECTOR	10	1,0
1:0	1.000000
2:0	0.000000
4:0	0.000000
3:0	-1.000000
> VECTOR	2	0,0

```

[6.2] 차원이 다른 벡터로 대체하려다 실패하면 기존 벡터가 남는다. BUILD 뒤에는 차원도 미설정 상태로 돌아간다.

```text

(none)
> VEC	1:8	1

```

## 7. 검사 방식

[7.1] 표준 입력 방식, 종료 코드와 행 단위 출력 비교는 1단계와 같다. 점수 문자열도 정확히 비교하며 허용 오차 비교를 하지 않는다. 일반 테스트는 빌드 시간을 제외하고 10초, 대규모 테스트는 30초다.

[7.2] 대규모 테스트는 청크 최대 50,000개, 차원 최대 32, BM25·VECTOR 질의 합계 최대 100개다. 문서·텍스트·출력 상한은 1단계를 따른다. 임베딩 적재 등을 포함한 전체 명령은 최대 100,000줄이다. 모든 청크와의 정확한 코사인 계산을 허용하는 규모이며 근사 검색이나 거리 계산 생략을 요구하지 않는다.

[7.3] 검사에는 제목과 겹침이 통계에 주는 영향, 토큰 없는 청크, 중복 질의 토큰, 반올림 동점, 음수 코사인, 0벡터, 미적재 벡터, 차원과 상태 초기화가 포함된다. 앞 단계 테스트도 누적 실행한다.
