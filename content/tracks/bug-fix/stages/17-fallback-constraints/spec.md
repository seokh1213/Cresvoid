# 카탈로그 페이지 배치 이상

## 결과 배치 서비스

[1] 쇼핑 카탈로그의 검색 결과에는 일반 후보열과 추천 후보열이 들어온다. 배치 서비스는 두 후보열을 섞어 한 페이지를 만든다. 최적화기가 실패하면 탐욕 배치로 응답한다. 이 과제는 외부 검색 엔진이나 최적화 라이브러리를 쓰지 않는 로컬 모형이다.

[2] 프로그램은 표준 입력에서 명령을 한 줄씩 EOF까지 읽고 명령마다 결과 한 줄을 표준 출력에 쓴다. 빈 줄은 무시한다. 요청 사이에 상태를 공유하지 않는다. 필드는 하나 이상의 공백 문자로 구분하며 앞뒤 공백은 무시한다.

## 명령과 검증

[3] 명령은 `PLACE <상태> <칸수> <추천상한> <일반후보열> <추천후보열>`이다. 상태는 `OK` 또는 `FAIL`이다. `OK`이면 최적화 경로를 실행한다. `FAIL`이면 최적화 결과 없이 대체 경로를 실행한다. 실제 실행 시간이나 난수로 경로를 바꾸지 않는다.

[4] 칸수는 1 이상 8 이하이고 추천상한은 0 이상 칸수 이하이다. 각 후보열은 쉼표로 이은 `상품ID:점수` 항목이며 빈 후보열은 `-`로 쓴다. 한 후보열은 최대 8항목이다. 점수는 0 이상 1000000 이하의 정수이며 입력 순서는 점수순이라는 보장이 없다. 숫자는 ASCII 숫자만으로 표기한다. 앞의 0은 허용한다.

[5] 상품ID는 `[a-z][a-z0-9-]{0,15}`에 맞아야 한다. 같은 요청의 두 후보열 전체에서 상품ID가 겹치면 안 된다. 명령 이름, 필드 수, 상태, 숫자 범위, 후보 표기, 상품ID 중 하나라도 규칙을 어기면 `ERROR`를 출력한다. 잘못된 줄이 있어도 다음 줄을 처리한다. 후보가 부족한 요청 자체는 입력 오류가 아니다.

## 두 경로가 지킬 필수 규칙

[6] 성공한 배치는 정확히 칸수만큼의 상품을 담고 같은 상품을 두 번 담지 않는다. 일반 후보와 추천 후보는 각각 입력 순서를 지킨다. 각 후보열에서는 앞부분만 사용한다. 예를 들어 일반 후보열의 세 번째 상품을 쓰려면 첫 번째와 두 번째 상품도 그 앞에 써야 한다. 추천 상품 수는 추천상한 이하여야 한다. 추천상한은 목표 수량이 아니므로 추천이 적거나 없어도 된다.

[7] 필수 규칙을 만족하는 배치가 없으면 두 경로 모두 `IMPOSSIBLE`을 출력한다. 덜 채운 페이지나 제약을 어긴 페이지를 성공으로 반환하지 않는다. 일반 후보 수와 추천 후보 수의 합이 충분해도 추천상한 때문에 배치가 불가능할 수 있다.

## 점수와 경로별 선택

[8] 배치 점수는 각 상품 점수에 자리 가중치를 곱해 더한 값이다. 칸수가 K이면 앞에서부터 가중치는 K, K−1, …, 1이다. 출력은 `<경로> <상품ID목록> <배치점수>`이다. 상품ID목록은 배치 순서대로 쉼표로 잇고 점수는 십진 정수로 쓴다. 경로는 최적화 경로의 `OPTIMAL` 또는 대체 경로의 `FALLBACK`이다.

[9] 최적화 경로는 필수 규칙을 지키는 모든 배치 중 배치 점수가 가장 큰 것을 고른다. 동점이면 상품의 출처를 일반 `O`, 추천 `R`로 나타낸 문자열이 사전순으로 가장 앞선 배치를 고른다. `O`가 `R`보다 앞선다. 후보열 안의 순서와 앞부분 사용 규칙 때문에 출처 문자열이 같으면 상품 목록도 같다.

[10] 대체 경로는 앞자리부터 채운다. 매 자리에서 각 후보열의 아직 쓰지 않은 첫 항목을 비교한다. 추천상한에 도달한 경우에는 추천 후보를 비교 대상에서 제외한다. 비교 대상 중 상품 점수가 큰 항목을 고르고 동점이면 일반 후보를 고른다. 한쪽만 남으면 그쪽을 고른다. 고른 후보열에서만 다음 항목으로 넘어간다. 칸을 다 채우기 전에 비교 대상이 없어지면 `IMPOSSIBLE`이다. 대체 경로는 이 선택 순서를 따르며 최적 점수를 보장하지 않는다.

[11] 목적값과 필수 제약을 구분하는 배경은 [Google OR-Tools의 배정 문제 예제](https://developers.google.com/optimization/assignment/assignment_example)에 있다. 두 후보열, 앞부분 사용, 추천 노출 정책과 대체 경로의 선택 순서는 이 과제의 제품 규칙이다. 채점은 입출력 동작을 확인하며 수정 코드의 구조나 자료구조를 제한하지 않는다.

## 버그 신고

[12] 카탈로그 페이지 미리보기를 점검하다가 일부 페이지의 상품 목록과 배치 점수가 예상과 다른 응답을 발견했다. 아래는 서로 다른 카테고리의 요청을 모은 재현 자료다. 세 번째와 여섯 번째 응답이 예상과 달랐고 나머지 응답은 예상과 같았다. 같은 입력으로 다시 실행해도 결과는 같았다.

[13] 재현 입력은 다음과 같다.

```text
PLACE OK 2 1 mug:9,plate:4 -
PLACE FAIL 2 2 tea:60,cup:30 spoon:50
PLACE FAIL 4 1 boot:70,sock:40,lace:25,belt:15 bag:90,cap:35,glove:30
PLACE OK 3 1 bowl:80,pan:10 tray:55
PLACE FAIL 2 0 book:45,pen:20 -
PLACE FAIL 4 1 lamp:40,desk:30,rug:20 vase:95,clock:85,frame:75
```

[14] 기대한 출력은 다음과 같다. 각 요청의 배치 규칙에 따라 페이지를 채운 결과다.

```text
OPTIMAL mug,plate 22
FALLBACK tea,spoon 170
FALLBACK bag,boot,sock,lace 675
OPTIMAL bowl,tray,pan 360
FALLBACK book,pen 110
FALLBACK vase,lamp,desk,rug 580
```

[15] 실제 출력은 다음과 같다. 세 번째와 여섯 번째 응답은 페이지를 채웠지만 상품 목록과 배치 점수가 기대한 결과와 달랐다.

```text
OPTIMAL mug,plate 22
FALLBACK tea,spoon 170
FALLBACK bag,boot,sock,cap 685
OPTIMAL bowl,tray,pan 360
FALLBACK book,pen 110
FALLBACK vase,clock,frame,lamp 825
```
