# 추천 점수 정렬

[1] 쇼핑 카탈로그의 카테고리별 추천 목록을 제공한다. 상품별 카탈로그 점수와 재고를 관리하고 카테고리별 정책에 따라 점수와 재고 신호를 합산해 기준을 만족하는 상품을 추천한다. 재고 신호는 충분한 수량을 확보한 상품을 우선 노출하는 데 쓴다. 이 단계의 상품과 입력은 학습용 가상 자료다.

## 입력과 출력

[2] 프로그램은 표준 입력에서 명령을 한 줄씩 EOF까지 읽는다. 명령의 토큰은 하나 이상의 공백으로 구분하고 빈 줄은 무시한다. 각 명령은 결과 한 줄을 표준 출력에 쓴다. 실행을 시작하면 카탈로그는 비어 있다.

[3] 상품 ID와 카테고리는 영문 소문자로 시작하고 영문 소문자·숫자·하이픈으로 이루어진 1~32자 문자열이다. 점수는 부호와 지수 표기가 없는 십진수이며 Double로 읽었을 때 0 이상 1 이하인 유한한 값이다. 재고는 0~1000000의 정수이고 조회 개수는 1~10000의 정수다. 입력은 이 범위와 아래 명령 형식을 지킨다. 전체 상품 수는 10000개 이하이며 같은 상품 ID를 여러 번 등록할 수 있다.

## 카탈로그 명령

[4] `PUT <id> <category> <score> <stock>`은 상품을 등록하고 `OK`를 출력한다. 같은 ID가 있으면 카테고리·점수·재고를 모두 새 값으로 교체한다. 다른 상품은 바꾸지 않는다.

[5] `SCORE <id> <score>`는 해당 상품의 점수만 바꾸고 `STOCK <id> <stock>`은 재고만 바꾼다. 상품이 있으면 `OK`, 없으면 `MISSING`을 출력한다. 없는 상품을 새로 만들지는 않는다.

[6] `REMOVE <id>`는 해당 상품을 삭제한다. 삭제했으면 `OK`, 상품이 없었으면 `MISSING`을 출력한다. 삭제한 ID는 다시 등록할 수 있다.

[7] `GET <id>`는 저장된 상품을 `<id> <category> <score> <stock>` 형식으로 출력한다. 재고가 0이어도 조회한다. 점수는 저장된 Double의 `toString()` 결과로 출력한다. 상품이 없으면 `MISSING`을 출력한다.

## 추천 조회

[8] `SHOW <category> <limit>`은 해당 카테고리에서 재고가 1 이상인 상품을 고른다. 각 상품의 추천 점수를 계산하고 최저 점수 이상인 상품만 추천 순서로 정렬한 뒤 앞에서부터 최대 limit개를 출력한다. 다른 카테고리의 상품과 품절 상품은 추천에서 제외한다.

[8.1] `POLICY <category> <score_weight> <stock_target> <minimum_score>`는 해당 카테고리의 점수 가중치·목표 재고·최저 점수를 교체하고 `OK`를 출력한다. 점수 가중치와 최저 점수는 [3]의 점수와 같은 범위와 표기 규칙을 따른다. 목표 재고는 1~1000000의 정수다. 정책이 없는 카테고리의 기본값은 차례로 `1.0`, `1`, `0.0`이다. 상품이 없는 카테고리에도 정책을 설정할 수 있다. 다른 카테고리의 정책과 저장된 상품 값은 바꾸지 않는다. 설정한 정책은 상품을 모두 삭제해도 유지된다.

[8.2] 재고 신호는 재고와 목표 재고 중 작은 값을 Double로 변환한 뒤 목표 재고로 나눈 값이다. 추천 점수는 `카탈로그 점수 * 점수 가중치`와 `재고 신호 * (1.0 - 점수 가중치)`를 각각 Double로 계산한 뒤 더한 값이다. 중간값과 결과는 따로 반올림하지 않는다. GET은 추천 점수가 아닌 저장된 카탈로그 점수를 출력한다. SHOW는 조회 시점의 정책·점수·재고를 사용한다.

[9] 추천 순서는 계산된 Double 추천 점수의 내림차순이며 점수가 같은 상품끼리는 ID의 사전순 오름차순이다. 점수 차이의 크기에 관계없이 이 순서를 적용한다. 상품을 등록한 순서는 추천 순서에 영향을 주지 않는다.

[10] SHOW 결과는 상품 ID를 공백 하나로 이어 출력한다. 대상 상품이 없으면 `EMPTY`를 출력한다. SHOW는 카탈로그를 변경하지 않는다. 같은 상태에서 반복 조회하면 같은 결과가 나와야 한다. 유효한 입력은 상품 수와 조회 개수에 관계없이 정상적으로 처리해야 한다.

## 버그 신고

[11] 운영 확인 중 다음 증상을 발견했다. “홈에 재고를 반영하는 정책을 설정했는데 쟁반이 머그보다 뒤에 나온다. 상품 조회에는 내가 등록한 점수가 그대로 보이고, 식료품 추천도 나온다. 아래 입력을 새로 실행한 프로그램에 넣어 확인했다.”

```text
POLICY home 0.5 10 0.5
PUT mug home 0.91 4
PUT tray home 0.81 6
PUT plate home 0.35 0
PUT tea pantry 0.7 8
GET tray
SHOW pantry 3
SHOW home 5
```

[12] 신고자가 기대한 출력은 다음과 같다. 실제로는 마지막 줄만 `mug tray`로 나왔다.

```text
OK
OK
OK
OK
OK
tray home 0.81 6
tea
tray mug
```
