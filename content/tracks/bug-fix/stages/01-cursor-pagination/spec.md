# 커서 페이지네이션

## 1. 제품 맥락

[1.1] 이 프로그램은 쇼핑 카탈로그 서비스에서 카테고리별 상품 목록을 돌려주는 API 를 흉내 낸 명령 처리기다. 사용자가 카테고리 화면을 아래로 내리면 앱이 다음 페이지를 요청한다. 서버는 요청을 받을 때마다 상품을 한 페이지씩 보낸다.

[1.2] 목록에는 많이 팔린 상품이 먼저 나온다. 판매량이 같은 상품끼리는 상품 ID 가 작은 상품이 먼저 나온다.

[1.3] 서버는 다음 페이지의 시작 위치를 순번(오프셋)으로 정하지 않는다. 앞 페이지의 마지막 상품을 기준으로 삼아 그 상품 뒤에 오는 상품부터 읽는다. 이렇게 이어 읽는 방식을 키셋 페이지 넘기기라 한다. 오프셋으로 이어 읽으면 앞 페이지를 보낸 뒤 그 페이지의 마지막 상품보다 앞에 오는 상품이 새로 등록될 때 앞 페이지에서 본 상품이 밀려 다음 페이지에 다시 나온다.

[1.4] 서버는 페이지를 보낼 때 그 페이지의 마지막 상품으로 만든 커서를 함께 보낸다. 앱은 커서를 보관했다가 다음 페이지를 요청할 때 서버에 돌려준다. 이 프로그램에서는 세션 하나가 앱 하나 역할을 하며 커서를 보관한다. 커서는 출력에 나오지 않는다.

## 2. 입출력 규칙

[2.1] 프로그램은 표준 입력에서 명령을 한 줄씩 읽어 입력이 끝날 때까지 처리하고 결과를 표준 출력에 쓴다. 입력이 끝나면 종료 코드 0 으로 끝난다.

[2.2] 입력은 UTF-8 이고 줄은 LF(U+000A) 로 나눈다. 마지막 줄 뒤에 LF 가 없어도 그 줄을 처리한다.

[2.3] 이 문서에서 공백은 U+0020 한 글자만 가리킨다. 낱말은 공백이 아닌 문자가 최대로 이어진 구간이다. 줄의 첫 낱말이 명령어이고 나머지 낱말이 차례로 인자다. 공백이 여럿 이어져도 빈 인자는 생기지 않는다.

[2.4] 낱말이 하나도 없는 줄은 건너뛰고 아무것도 출력하지 않는다.

[2.5] 명령어는 대소문자를 구분한다. `next` 는 NEXT 가 아니다.

[2.6] 출력하는 줄은 모두 LF 로 끝낸다.

[2.7] 프로그램은 상품도 세션도 없는 상태에서 시작한다.

[2.8] 이 문서의 정규식은 낱말 전체에 적용한다. `^` 는 낱말의 처음, `$` 는 낱말의 끝이다.

## 3. 상품과 목록 순서

[3.1] 상품마다 상품 ID, 카테고리, 판매량이 있다. 상품 ID 는 `^[1-9][0-9]{0,8}$` 에 맞는 10진 정수다. 판매량은 `^(0|[1-9][0-9]{0,8})$` 에 맞는 10진 정수다. 카테고리는 낱말 하나이고 글자 그대로 비교한다.

[3.2] 상품 ID 는 카테고리와 상관없이 상품마다 다르다. 한 번 등록한 상품은 바뀌거나 지워지지 않는다.

[3.3] 두 상품의 순서는 이렇게 정한다. 판매량이 큰 상품이 앞에 온다. 판매량이 같으면 상품 ID 가 작은 상품이 앞에 온다. 상품 ID 는 수의 크기로 비교하므로 9 가 10 보다 작다. 상품 A 가 상품 B 보다 앞에 오면 B 는 A 보다 뒤에 온다고 한다.

[3.4] 카테고리 목록은 한 카테고리의 상품을 3.3 의 순서대로 늘어놓은 것이다. 상품 ID 는 겹치지 않으므로 목록의 순서는 하나로 정해진다.

## 4. 명령 규칙

### ADD

[4.1] `ADD <상품 ID> <카테고리> <판매량>` 은 상품을 등록한다. 성공하면 아무것도 출력하지 않는다.

### LIST

[4.2] `LIST <세션> <카테고리> <페이지 크기>` 는 세션을 열고 그 카테고리 목록의 첫 페이지를 출력한다. 세션 이름은 낱말 하나다. 페이지 크기는 `^[1-9][0-9]*$` 에 맞고 100 이하인 정수다.

[4.3] 첫 페이지에는 카테고리 목록의 맨 앞부터 페이지 크기만큼의 상품을 담는다. 목록의 상품이 페이지 크기보다 적으면 있는 상품을 모두 담는다.

[4.4] 세션은 LIST 에서 정한 카테고리와 페이지 크기를 끝까지 유지한다. 같은 이름의 세션이 이미 있으면 기존 세션을 버리고 새로 연다.

### NEXT

[4.5] `NEXT <세션>` 은 그 세션의 다음 페이지를 출력한다.

[4.6] 그 세션에서 마지막으로 출력한 페이지의 마지막 상품을 기준 상품이라 한다. 다음 페이지에는 NEXT 를 실행하는 시점의 카테고리 목록에서 기준 상품보다 뒤에 오는 상품을 앞에서부터 페이지 크기만큼 담는다.

[4.7] 앞 페이지를 출력한 뒤에 등록된 상품도 기준 상품보다 뒤에 오면 다음 페이지에 담길 수 있다. 기준 상품보다 앞에 오는 상품은 언제 등록됐든 그 세션의 남은 페이지에 담기지 않는다.

[4.8] 4.6 과 4.7 에 따라 한 세션에서 같은 상품은 두 번 나오지 않는다. LIST 로 세션을 연 뒤 `END` 가 나올 때까지 NEXT 를 실행하면 LIST 시점에 그 카테고리에 있던 상품이 모두 한 번씩 나온다.

### 페이지 출력

[4.9] 페이지는 한 줄로 출력한다. 담은 상품의 상품 ID 를 목록 순서대로 공백 하나씩 띄워 쓰고 그 뒤에 공백 하나와 표지 하나를 쓴다. 담은 상품이 없으면 표지만 쓴다.

[4.10] 페이지를 출력하는 시점에 카테고리 목록에서 그 페이지의 마지막 상품보다 뒤에 오는 상품이 하나라도 있으면 표지는 `MORE` 이고 없으면 `END` 다. 담은 상품이 없는 페이지의 표지는 `END` 다.

[4.11] 표지가 `END` 인 페이지를 출력하면 그 세션은 끝난다. 끝난 세션은 NEXT 로 이어 읽을 수 없다. 세션이 끝난 뒤에 그 카테고리에 상품이 등록돼도 마찬가지다.

## 5. 오류 규칙

[5.1] 오류가 나면 오류 줄 하나만 출력한다. 오류를 낸 명령은 상품과 세션을 바꾸지 않는다. 프로그램은 다음 줄을 이어서 처리한다.

[5.2] 명령어가 ADD, LIST, NEXT 가운데 어느 것과도 같지 않으면 `ERR UNKNOWN_COMMAND` 를 출력한다.

[5.3] 인자 수가 맞지 않으면 `ERR BAD_ARGUMENT` 를 출력한다. ADD 와 LIST 는 인자가 3개이고 NEXT 는 1개다.

[5.4] ADD 의 상품 ID 나 판매량, LIST 의 페이지 크기가 3.1 과 4.2 의 형식에 맞지 않으면 `ERR BAD_ARGUMENT` 를 출력한다. `ADD 0 socks 1`, `ADD 7 socks -1`, `LIST web socks 0`, `LIST web socks 101` 이 여기에 해당한다.

[5.5] ADD 의 인자가 모두 형식에 맞지만 같은 상품 ID 가 이미 등록돼 있으면 `ERR DUPLICATE_PRODUCT` 를 출력한다. 카테고리나 판매량이 달라도 같다.

[5.6] NEXT 의 세션이 열린 적이 없으면 `ERR UNKNOWN_SESSION` 을 출력한다.

[5.7] 끝난 세션에 NEXT 를 실행하면 `ERR NO_NEXT_PAGE` 를 출력한다.

## 6. 예시

[6.1] 아래는 프로그램을 한 번 실행한 기록이다. `> ` 로 시작하는 줄은 입력이고 나머지 줄은 바로 위 입력의 출력이다. 실제 입력에는 `> ` 가 없다.

[6.2] 상품 1 과 3 은 판매량이 같아서 ID 가 작은 상품 1 이 앞에 온다. 첫 페이지를 출력한 뒤의 기준 상품은 상품 3 이다. 그 뒤에 등록한 상품 6 은 상품 3 보다 앞에 오므로 이 세션에 나오지 않는다. 상품 7 은 상품 3 보다 뒤에 오므로 다음 페이지에 담긴다. mugs 카테고리의 상품 5 는 tumblers 목록에 없다.

```
> ADD 1 tumblers 40
> ADD 2 tumblers 75
> ADD 3 tumblers 40
> ADD 4 tumblers 15
> ADD 5 mugs 75
> LIST web tumblers 3
2 1 3 MORE
> ADD 6 tumblers 90
> ADD 7 tumblers 15
> NEXT web
4 7 END
> NEXT web
ERR NO_NEXT_PAGE
```

## 7. 버그 신고

[7.1] 아래는 카테고리 화면을 맡은 앱 개발자가 보낸 신고다. 페이지를 끝까지 넘겨도 어떤 상품은 한 번도 나오지 않는다. 판매자가 자기 상품이 아동화 카테고리 목록에 없다고 문의해서 알게 됐다.

[7.2] 아래 입력으로 재현할 수 있다. 등록한 상품은 14개인데 `END` 가 나올 때까지 넘겨도 12개만 나온다. 문의가 들어온 상품 1212 도 나오지 않는다.

```
ADD 1201 kids-shoes 97
ADD 1202 kids-shoes 45
ADD 1203 kids-shoes 152
ADD 1204 kids-shoes 20
ADD 1205 kids-shoes 45
ADD 1206 kids-shoes 45
ADD 1207 kids-shoes 230
ADD 1208 kids-shoes 8
ADD 1209 kids-shoes 64
ADD 1210 kids-shoes 45
ADD 1211 kids-shoes 51
ADD 1212 kids-shoes 45
ADD 1213 kids-shoes 97
ADD 1214 kids-shoes 180
LIST app kids-shoes 5
NEXT app
NEXT app
```

[7.3] 기대한 출력이다.

```
1207 1214 1203 1201 1213 MORE
1209 1211 1202 1205 1206 MORE
1210 1212 1204 1208 END
```

[7.4] 실제 출력이다.

```
1207 1214 1203 1201 1213 MORE
1209 1211 1202 1205 1206 MORE
1204 1208 END
```

[7.5] 신상품만 모은 카테고리에서도 비슷한 일이 생긴다. 첫 페이지에 `MORE` 가 붙어서 다음 페이지를 요청했더니 상품이 하나도 없는 페이지가 `END` 와 함께 나왔다.

```
ADD 2101 new-arrivals 41
ADD 2102 new-arrivals 0
ADD 2103 new-arrivals 17
ADD 2104 new-arrivals 6
ADD 2105 new-arrivals 0
ADD 2106 new-arrivals 0
ADD 2107 new-arrivals 0
LIST app new-arrivals 4
NEXT app
```

[7.6] 기대한 출력이다.

```
2101 2103 2104 2102 MORE
2105 2106 2107 END
```

[7.7] 실제 출력이다.

```
2101 2103 2104 2102 MORE
END
```
