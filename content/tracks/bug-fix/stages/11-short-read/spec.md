# 저장되지 않는 이미지 구간

## 제품 맥락

[1] 쇼핑 카탈로그의 이미지 묶음을 전송받아 구간별 임시 파일로 보관하는 처리기다. 상위 계층이 계산한 시작 바이트 위치와 길이를 그대로 받는다. 이번 작업에서는 구간 전송의 성공·실패 판정과 저장 결과를 스펙에 맞게 고친다. 실제 네트워크 대신 응답 크기를 지정할 수 있는 가짜 전송원을 쓴다.

## 명령과 입출력

[2] 프로그램은 표준 입력에서 명령을 한 줄씩 EOF까지 읽고 명령마다 결과 한 줄을 표준 출력에 쓴다. 빈 줄은 무시한다. 토큰은 공백으로 구분한다. 식별자는 영문 소문자로 시작하는 영문 소문자·숫자·하이픈 1~32자다. 아래 형식을 만족하는 입력만 주어진다.

[3] `SOURCE <전송원> <바이트열> <응답 상한 목록>`은 전송원을 등록하고 `SOURCE <전송원> <바이트 수>`를 출력한다. 같은 이름을 다시 등록하면 원본과 응답 설정을 교체한다. 바이트열은 두 자리 16진수를 이어 쓴 문자열이며 대소문자를 모두 허용한다. `-`는 빈 바이트열이다. 원본은 최대 1,048,576바이트다. 응답 상한 목록은 1~1,048,576의 정수를 쉼표로 이은 것이다.

[4] `FETCH <구간> <전송원> <시작> <길이>`는 지정한 전송원의 시작 위치부터 길이만큼 전송받는다. 시작 위치는 원본 첫 바이트를 0으로 세며 원본 바이트 수 이하인 정수다. 길이는 0~1,048,576의 정수다. 각 FETCH는 해당 위치에서 시작하는 새 스트림을 열며 응답 상한 목록도 처음부터 사용한다. 시작 위치 계산과 스트림을 여는 코드는 제공되며 수정 대상이 아니다. 등록된 전송원만 참조한다.

[5] 가짜 스트림은 양수 길이로 읽을 때마다 요청 길이, 원본에 남은 바이트 수, 이번 응답 상한 중 가장 작은 수만큼 원본 순서대로 반환한다. 응답 상한은 호출마다 다음 값으로 넘어가고 목록을 다 쓰면 마지막 값을 계속 쓴다. 원본이 끝나면 EOF를 반환한다. 요청 길이가 0이면 아무것도 소비하지 않고 0을 반환한다. 양수 길이의 정상 응답에는 0이 없다. 응답 상한은 전송원 전체의 길이를 바꾸지 않는다.

## 저장 규칙

[6] 요청한 길이만큼 바이트를 모두 받으면 구간 파일을 저장하고 `STORED <구간> <길이>`를 출력한다. 파일 내용은 지정한 시작 위치부터 요청 길이까지의 원본 바이트와 같아야 한다. 원본의 마지막 바이트까지 정확히 받는 것도 성공이다. 길이가 0이면 원본 끝에서도 빈 파일을 저장하는 데 성공한다.

[7] 요청 길이를 채우기 전에 EOF를 만나면 `FAILED <구간> EOF`를 출력한다. 실패한 전송의 일부 바이트는 구간 파일로 공개하지 않는다. 같은 구간 이름으로 저장한 파일이 이미 있으면 성공한 FETCH만 그 파일을 교체한다. 실패하면 기존 파일을 유지한다. 다른 구간 파일에는 영향을 주지 않는다.

[8] `SHOW <구간>`은 저장된 파일을 읽어 `PART <구간> <바이트 수> <바이트열>`을 출력한다. 바이트열은 소문자 16진수로 출력하고 빈 파일은 `-`로 나타낸다. 저장한 파일이 없으면 `MISSING <구간>`을 출력한다. 저장 결과는 현재 프로세스 안에서만 유지하며 종료할 때 임시 파일을 정리한다.

## 버그 신고

[9] 이미지 묶음을 옮기는 점검 중 tile 구간이 저장되지 않았다. 같은 점검에서 thumb와 badge는 조회할 수 있었고 footer는 실패로 남았다. 아래는 실제 전송 대신 가짜 전송원으로 옮긴 재현 입력이다.

```text
SOURCE local 1020304050607080 64
SOURCE relay 1020304050607080 2,1,4
FETCH thumb local 1 3
SHOW thumb
FETCH tile relay 1 6
SHOW tile
FETCH badge relay 6 2
SHOW badge
FETCH footer local 7 3
SHOW footer
```

[10] 기대한 결과는 다음과 같다. tile도 저장되어 조회할 수 있어야 한다.

```text
SOURCE local 8
SOURCE relay 8
STORED thumb 3
PART thumb 3 203040
STORED tile 6
PART tile 6 203040506070
STORED badge 2
PART badge 2 7080
FAILED footer EOF
MISSING footer
```

[11] 실제 결과는 다음과 같다. tile을 보내는 명령이 EOF 실패로 끝났고 저장된 구간도 없었다.

```text
SOURCE local 8
SOURCE relay 8
STORED thumb 3
PART thumb 3 203040
FAILED tile EOF
MISSING tile
STORED badge 2
PART badge 2 7080
FAILED footer EOF
MISSING footer
```
