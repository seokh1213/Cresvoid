# 작업자별 내보내기 결과 불일치

[1] 쇼핑 카탈로그의 상품 내보내기 파일을 여러 작업자에게 나누어 보내는 처리기다. 상품 레코드는 한 줄에 하나씩 들어 있다. 처리기는 파일을 저장하고 지정한 레코드 수마다 구간을 만든다. 작업자는 받은 구간을 다시 읽는다. 이 단계의 입력은 학습용으로 만든 파일이다.

[2] 프로그램은 표준 입력에서 명령을 한 줄씩 EOF까지 읽고 결과를 표준 출력에 한 줄씩 쓴다. 명령은 `FILE`, `SIZE`, `SPLIT`, `READ`, `REPLAY`다. 명령과 인자는 공백 하나로 구분한다. 파일 ID는 영문 소문자·숫자·하이픈으로 이루어진 1~30자다. 파일을 조회하는 명령에는 이미 저장한 ID만 준다. 잘못된 명령의 처리는 이 단계의 범위 밖이다.

[3] `FILE <id> <내용>`은 내용을 UTF-8 파일로 저장한다. 같은 ID가 있으면 덮어쓴다. 내용은 ID 다음 구분 공백 하나를 제외한 나머지 전체이며 공백을 보존한다. 내용에서 `\n`은 LF, `\r`은 CR, `\\`는 역슬래시 하나를 나타낸다. 다른 이스케이프는 없다. 내용이 비어 있으면 `FILE <id>`로 입력한다. 출력은 `STORED <id> <파일 바이트 수>`다. 파일 내용은 유효한 유니코드 문자열이며 BOM은 없다. 제어 문자는 줄 끝을 이루는 LF와 CR만 있다. CR은 반드시 바로 뒤의 LF와 짝을 이룬다. 파일 하나의 크기는 1 MiB 이하이며 ID는 최대 50개다.

[4] 레코드의 끝은 LF 또는 CRLF다. 한 파일 안에서 두 줄 끝을 섞을 수 있다. 줄 끝은 레코드 내용에 포함하지 않는다. 마지막 레코드에 줄 끝이 없어도 레코드 하나로 읽는다. 파일 끝의 줄 끝 뒤에 빈 레코드를 덧붙이지 않는다. 빈 파일에는 레코드가 없고, LF 하나만 있는 파일에는 빈 레코드 하나가 있다. 레코드 내용의 공백과 역슬래시를 그대로 보존한다.

[5] `SIZE <id>`는 저장한 파일의 바이트 수를 십진수로 출력한다. 파일을 나누거나 읽어도 저장한 파일은 변하지 않는다.

[6] `SPLIT <id> <묶음 크기>`는 파일의 레코드를 처음부터 묶음 크기만큼 묶는다. 묶음 크기는 1~1000의 정수다. 마지막 묶음은 그보다 적을 수 있다. 각 묶음의 구간은 시작 포함·끝 제외 바이트 위치이며 해당 레코드의 줄 끝도 구간에 포함한다. 첫 구간의 시작은 0이고, 각 구간의 끝은 다음 구간의 시작과 같고, 마지막 구간의 끝은 파일의 바이트 수와 같다. 각 구간을 `시작:끝`으로 나타내고 공백 하나로 이어 출력한다. 빈 파일은 `(none)`을 출력한다.

[7] `READ <id> <시작> <끝>`은 실제 파일의 해당 바이트 구간만 읽어 레코드를 복원한다. 입력 위치는 0 이상 파일 바이트 수 이하이며 시작은 끝보다 크지 않다. 두 위치는 파일의 처음·끝 또는 레코드 사이의 경계다. 시작과 끝이 같으면 빈 목록이다. 결과는 레코드 내용을 원래 순서로 담은 JSON 문자열 배열이며 쉼표 앞뒤에 공백을 넣지 않는다. 문자열의 큰따옴표와 역슬래시는 각각 `\"`와 `\\`로 출력한다. 예를 들어 두 레코드가 `A1`과 `모자`라면 `["A1","모자"]`를 출력한다.

[8] `REPLAY <id> <묶음 크기>`는 `SPLIT`과 같은 구간을 만든 뒤 각 구간을 `READ`와 같은 방식으로 다시 읽는다. 구간별 레코드 목록을 파일 순서로 담은 JSON 배열을 출력한다. 예를 들어 두 구간의 목록이 `["A1","모자"]`와 `["B2"]`라면 `[["A1","모자"],["B2"]]`를 출력한다. 빈 파일은 `[]`를 출력한다. 구간별 결과를 순서대로 이어 붙이면 파일의 모든 레코드가 빠지거나 중복되지 않고 한 번씩 나와야 한다.

## 버그 신고

[9] 내보내기 검수 중에 작업자별 결과가 원본과 달라지는 파일을 발견했다. 전체 조회에서는 네 상품이 보이는데 작업자별 결과에서는 상품명이 나뉘어 나온다. 같은 실행에서 다른 파일을 조회한 결과도 함께 남긴다.

[10] 아래 입력으로 재현했다. `sample`은 `A1`, `모자`, `B2`, `C3`가 차례로 들어 있고 각 줄이 LF로 끝나는 작은 파일이다. `labels`는 CRLF로 구분한 두 레코드이며 마지막 줄 끝은 없다.

```text
FILE sample A1\n모자\nB2\nC3\n
SIZE sample
READ sample 0 16
FILE labels x\r\ny
REPLAY labels 1
SPLIT sample 2
REPLAY sample 2
READ sample 10 16
```

[11] 기대한 결과는 다음과 같다. 작업자별 결과를 합쳐도 원본의 상품명과 순서가 유지되어야 한다.

```text
STORED sample 16
16
["A1","모자","B2","C3"]
STORED labels 4
[["x"],["y"]]
0:10 10:16
[["A1","모자"],["B2","C3"]]
["B2","C3"]
```

[12] 현재 프로그램에서는 다음 결과가 나온다. 전체 조회와 마지막 조회는 그대로인데 작업자별 결과에 원본과 다른 상품명이 들어 있다.

```text
STORED sample 16
16
["A1","모자","B2","C3"]
STORED labels 4
[["x"],["y"]]
0:6 6:16
[["A1","모"],["자","B2","C3"]]
["B2","C3"]
```
