# 일일 사용 한도

## 서비스와 실행

[1] 쇼핑 카탈로그 서비스는 판매자가 상품 분석 기능을 호출할 때 사용자별 일일 한도에서 사용량을 차감한다. 사용자마다 일일 한도가 다르며 사용 취소로 잘못 차감한 양을 돌려줄 수 있다. 이 프로그램은 등록, 사용, 취소, 한도 조회 명령을 처리한다. 데이터는 프로세스 안에서만 유지한다.

[2] 표준 입력에서 명령을 한 줄씩 EOF까지 읽고 명령마다 결과 한 줄을 표준 출력에 쓴다. 빈 줄은 무시한다. 명령과 인자는 공백으로 구분한다. 안내 문구나 로그는 출력하지 않는다.

[3] 모든 명령의 두 번째 항목은 UTC 시각이다. 형식은 `2026-11-05T14:30:00Z`처럼 초 단위 ISO-8601 문자열이며 연도는 2000~2099다. 프로그램의 시계는 각 명령을 처리하기 전에 해당 시각으로 이동한다. 입력 시각은 전체 명령에 걸쳐 감소하지 않으며 같은 시각의 명령도 입력 순서대로 처리한다. 실제 시스템 시각은 쓰지 않는다. 업무 규칙으로 거절되는 명령도 시계를 이동시킨다.

[4] 하루는 한국 시각(UTC+09:00) 자정에 시작해 다음 자정 직전까지다. 자정과 정확히 같은 시각의 사용은 새날에 속한다. 하루의 사용량은 해당 한국 날짜에 성공한 사용 중 아직 취소하지 않은 사용량의 합이다. 남은 한도는 일일 한도에서 그 합을 뺀 값이다. 날짜가 바뀌면 새날의 사용량은 0이며, 며칠 동안 명령이 없어도 이 규칙을 적용한다. 사용자별 집계는 서로 독립적이다.

[5] 사용자 ID와 사용 ID는 영문 소문자로 시작하고 영문 소문자·숫자·하이픈으로 이루어진 1~30자 문자열이다. 한도와 사용량은 1~1,000,000,000의 정수다. 명령 이름, 인자 수, 시각과 ID 형식, 정수 범위는 모두 올바르게 들어온다. 입력 형식 오류 처리는 요구하지 않는다. 명령 수는 최대 20,000개다.

## 명령과 응답

[6] `REGISTER <시각> <사용자ID> <일일한도>`는 사용자를 등록한다. 성공하면 `REGISTERED <사용자ID> <일일한도>`를 출력한다. 이미 등록한 사용자라면 `ERROR USER_EXISTS`를 출력하며 기존 한도와 기록을 유지한다. 등록한 한도는 이후 바꾸지 않는다.

[7] `USE <시각> <사용자ID> <사용ID> <사용량>`은 그 사용자의 오늘 남은 한도를 차감한다. 남은 한도와 사용량이 같아도 성공한다. 성공하면 `USED <사용ID> <차감후남은한도>`를 출력한다. 한도를 넘으면 `ERROR LIMIT_EXCEEDED`를 출력하고 사용 기록을 남기지 않는다. 거절된 사용 ID로 나중에 다시 요청할 수 있다.

[8] 사용 ID는 사용자 안에서만 유일하다. 한 번 성공한 사용 ID는 날짜가 바뀌거나 그 사용을 취소해도 다시 쓸 수 없다. 같은 ID로 다시 사용하면 `ERROR DUPLICATE_USE`를 출력한다. 다른 사용자는 같은 사용 ID를 쓸 수 있다. `USE`는 사용자 존재, 사용 ID 중복, 한도 초과 순서로 검사하며 먼저 걸린 오류 하나만 출력한다.

[9] `CANCEL <시각> <사용자ID> <사용ID>`는 성공했던 사용 전체를 취소한다. 성공하면 `CANCELED <사용ID> <오늘남은한도>`를 출력한다. 같은 한국 날짜의 사용을 취소하면 오늘의 사용량에서 그 양을 뺀다. 이전 날짜의 사용도 취소할 수 있지만 오늘의 사용량과 남은 한도에는 영향을 주지 않는다. 취소 후에도 원래 사용 기록은 유지한다.

[10] `CANCEL`에서 해당 사용자의 기록이 없으면 `ERROR UNKNOWN_USE`, 이미 취소한 기록이면 `ERROR ALREADY_CANCELED`를 출력한다. `CANCEL`은 사용자 존재, 사용 기록 존재, 취소 여부 순서로 검사한다. 거절된 명령은 한도와 사용 기록을 바꾸지 않는다.

[11] `LIMIT <시각> <사용자ID>`는 `LIMIT <사용자ID> <오늘사용량> <오늘남은한도>`를 출력한다. `USE`, `CANCEL`, `LIMIT`에서 등록하지 않은 사용자라면 `ERROR UNKNOWN_USER`를 출력한다. 조회는 사용 기록을 만들거나 취소하지 않는다.

## 버그 신고

[12] 판매자 계정에서 분석 작업을 여러 번 실행하고 그중 하나를 취소한 뒤 내보내기 작업으로 남은 한도를 전부 썼다. 다음 날 첫 분석이 한도 초과로 거절됐다. 전날 작업을 취소하자 남은 한도가 늘었고 거절된 분석을 같은 사용 ID로 다시 요청하니 이번에는 성공했다. 아래 입력으로 재현했다.

```text
REGISTER 2026-11-05T08:00:00Z seller 100
USE 2026-11-05T08:05:00Z seller batch 40
USE 2026-11-05T10:20:00Z seller preview 25
CANCEL 2026-11-05T10:25:00Z seller preview
USE 2026-11-05T14:40:00Z seller export 60
LIMIT 2026-11-05T14:50:00Z seller
LIMIT 2026-11-05T15:10:00Z seller
USE 2026-11-05T15:11:00Z seller next 40
CANCEL 2026-11-05T15:12:00Z seller batch
LIMIT 2026-11-05T15:13:00Z seller
USE 2026-11-05T15:14:00Z seller next 40
LIMIT 2026-11-05T15:15:00Z seller
CANCEL 2026-11-05T15:16:00Z seller export
LIMIT 2026-11-05T15:17:00Z seller
USE 2026-11-05T15:18:00Z seller report 60
LIMIT 2026-11-05T15:19:00Z seller
```

[13] 첫날의 취소와 내보내기가 끝나면 남은 한도는 0이다. 다음 날 첫 조회에서는 100이 남아야 하고 `next`로 40을 쓰면 60이 남아야 한다. 전날의 `batch`와 `export`를 취소해도 오늘 잔액은 그대로여야 한다. 이미 성공한 `next`를 다시 요청하면 중복 오류가 나야 한다. 기대한 전체 출력은 다음과 같다.

```text
REGISTERED seller 100
USED batch 60
USED preview 35
CANCELED preview 60
USED export 0
LIMIT seller 100 0
LIMIT seller 0 100
USED next 60
CANCELED batch 60
LIMIT seller 40 60
ERROR DUPLICATE_USE
LIMIT seller 40 60
CANCELED export 60
LIMIT seller 40 60
USED report 0
LIMIT seller 100 0
```

[14] 실제로는 다음 날 첫 조회에서도 사용량이 100이고 `next`가 거절된다. `batch` 취소 뒤에는 잔액이 40으로 늘어나고 `next` 재요청이 성공하면 잔액이 다시 0이 된다. 이후 `export`를 취소하고 `report`를 실행하면 마지막 조회 결과는 기대와 같아진다. 현재 프로그램에서 확인한 전체 출력은 다음과 같다.

```text
REGISTERED seller 100
USED batch 60
USED preview 35
CANCELED preview 60
USED export 0
LIMIT seller 100 0
LIMIT seller 100 0
ERROR LIMIT_EXCEEDED
CANCELED batch 40
LIMIT seller 60 40
USED next 0
LIMIT seller 100 0
CANCELED export 60
LIMIT seller 40 60
USED report 0
LIMIT seller 100 0
```
