# 다시 실행하면 끼어드는 옛 편집

## 상품 설명 편집

[1] 카탈로그 운영자가 상품 설명을 고치는 편집기의 재현용 프로그램이다. 커서 위치에 문장을 쓰거나 커서 뒤의 글자를 지우고 편집을 되돌리거나 다시 실행한다. 검수 도구가 보낸 여러 수정안을 한 번에 반영할 수도 있다. 시작 코드를 읽고 아래 규칙과 다르게 동작하는 부분을 고친다. 편집기 전체를 다시 구현할 필요는 없다.

[2] 프로그램은 표준 입력에서 명령을 한 줄씩 EOF까지 읽는다. 처음에는 설명이 빈 문자열이고 커서는 0이다. 명령은 소문자이며 `cursor n`, `write 본문`, `erase n`, `apply n`, `back`, `again`, `view` 가운데 하나다. `write`만 있는 줄은 빈 본문을 뜻한다. `write ` 뒤의 나머지 문자열은 앞뒤 공백까지 본문에 포함한다. 따옴표나 이스케이프 처리는 하지 않는다.

[3] 위치와 개수는 유니코드 코드 포인트 단위다. 커서 0은 첫 글자 앞이고 커서가 설명 길이와 같으면 마지막 글자 뒤다. 입력의 숫자는 0 이상 1,000,000 이하의 정수이고 본문에는 탭·줄바꿈·제어 문자가 없다. 명령 문법이 잘못된 입력은 주어지지 않는다. 명령은 최대 2,000줄이고 설명 길이는 항상 10,000 코드 포인트 이하다.

## 명령과 출력

[4] `cursor n`은 커서를 절대 위치 n으로 옮긴다. n이 설명 길이보다 크면 `ERR position`을 출력하고 아무 상태도 바꾸지 않는다. 커서 이동은 편집이 아니며 되돌리기의 대상이 아니다.

[5] `write 본문`은 현재 커서 위치에 본문을 삽입하고 커서를 삽입한 본문 바로 뒤로 옮긴다. 빈 본문이면 아무 상태도 바꾸지 않는다. 공백만 있는 본문도 길이가 1 이상이면 편집이다.

[6] `erase n`은 현재 커서부터 오른쪽으로 n글자를 삭제한다. 삭제 뒤 커서는 삭제가 시작된 위치에 남는다. 커서 오른쪽에 남은 글자보다 n이 크면 `ERR range`를 출력하고 아무 상태도 바꾸지 않는다. n이 0이면 아무 상태도 바꾸지 않는다. 범위를 넘어가는 요청을 잘라서 처리하지 않는다.

[7] 실제로 글자를 삽입하거나 삭제한 명령 하나를 편집 하나로 기록한다. `back`은 아직 되돌리지 않은 가장 최근 편집 하나를 취소하고 커서를 그 편집 직전의 위치로 돌린다. 취소할 편집이 없으면 아무 상태도 바꾸지 않는다. 편집 뒤 커서를 따로 옮겼더라도 취소하는 위치와 내용은 그 편집의 기록을 따른다.

[8] `again`은 되돌린 편집 가운데 가장 나중에 되돌린 것 하나를 다시 실행한다. 현재 커서와 관계없이 원래 편집 위치에 원래 내용을 적용한다. 커서는 그 편집을 처음 실행했을 때의 결과 위치로 옮긴다. 다시 실행한 편집도 `back`으로 취소할 수 있다. 다시 실행할 편집이 없으면 아무 상태도 바꾸지 않는다.

[9] 되돌린 상태에서 새 편집을 하면 그전에 되돌린 편집은 모두 다시 실행할 수 없게 된다. 새 편집과 그때까지 되돌리지 않은 편집은 계속 되돌릴 수 있다. 커서 이동, 조회, 범위 오류, 빈 본문의 입력, 0글자 삭제는 새 편집으로 취급하지 않으므로 다시 실행할 수 있는 편집을 바꾸지 않는다.

[9.1] `apply n`은 바로 다음 n줄을 하나의 일괄 작업으로 읽는다. n은 0 이상 2,000 이하이며 뒤따르는 줄은 빠짐없이 주어진다. 이 n줄에는 `cursor`, `write`, `erase`만 들어간다. 작업이 실패해도 이 줄들을 일반 명령으로 다시 실행하지 않는다. 전체 입력 2,000줄 제한에는 `apply`와 뒤따르는 줄도 모두 포함한다. 각 명령은 앞 명령의 결과 상태에 이어서 실행한다. 작업이 성공하면 내부의 실제 삽입·삭제를 각각 편집 하나로 기록하고 `back`도 편집 하나씩 취소한다. 커서 이동만 있거나 실제 편집이 없는 작업은 편집 이력을 바꾸지 않는다. `apply 0`은 아무 상태도 바꾸지 않는다.

[9.2] 일괄 작업 중 위치나 삭제 범위가 잘못된 명령을 만나면 그 명령에 해당하는 오류 한 줄만 출력한다. 그 뒤의 내부 명령은 실행하지 않고, 설명·커서·되돌리기 이력·다시 실행 이력을 모두 `apply` 직전 상태로 돌린다. 앞서 성공한 내부 편집도 남기지 않는다. 운영자가 수정안을 따로 취소하지 않아도 일부만 반영된 설명이 남지 않게 하는 규칙이다. 작업 뒤의 일반 명령은 복구된 상태에서 계속 실행한다.

[10] `view`는 현재 상태를 `커서|설명` 형식으로 한 줄 출력한다. 빈 설명이면 구분자 뒤에 아무것도 붙이지 않는다. 설명에 있는 공백과 `|`도 그대로 출력한다. 오류가 없는 나머지 명령은 아무것도 출력하지 않는다. EOF에서 추가 출력은 하지 않는다.

## 버그 신고

[11] 봄 상품의 설명을 검수하는 상황을 재현한 신고다. 배송 안내를 되돌리거나 다시 실행하며 확인했다. 이어 검수 도구의 일괄 수정안을 반영하려 했으나 삭제 범위 오류로 거절됐다. 이후 계절 문구를 붙이고 상품명을 지웠다가 복구했다. 최종 문구는 '면 셔츠 / 선물 포장'으로 정했다. 마지막 확인 중 다시 실행을 누르자 배송 안내가 끼어들고 커서도 움직였다. 아래는 검수 과정의 입력이다. `view`는 검수 중 화면을 확인하려고 입력했다.

```text
write 면 셔츠
write  / 무료 배송
back
again
view
apply 3
cursor 0
write 임시
erase 99
cursor 0
write 봄 신상 
cursor 5
erase 4
view
back
cursor 0
view
back
back
write  / 선물 포장
cursor 0
view
again
view
```

[12] 기대한 출력은 아래 여섯 줄이다. 세 번째 줄의 '상'과 '/' 사이에는 공백 두 개가 있다. 실제 출력은 앞의 다섯 줄까지 같고 마지막 줄만 `12|면 셔츠 / 무료 배송 / 선물 포장`이다. 마지막 두 번의 조회에서는 커서와 설명이 모두 같아야 한다.

```text
12|면 셔츠 / 무료 배송
ERR range
5|봄 신상  / 무료 배송
0|봄 신상 면 셔츠 / 무료 배송
0|면 셔츠 / 선물 포장
0|면 셔츠 / 선물 포장
```
