# 포인트 적립 계산

## 결제와 정산

[1] 쇼핑 카탈로그 서비스는 결제가 들어올 때 회원 등급과 진행 중인 이벤트를 확인해 포인트를 적립한다. 운영자는 결제별 적립 내역과 결제일별 정산 합계를 조회한다. 이 프로그램은 한 번 실행하는 동안 설정과 적립 내역을 메모리에 보관한다.

[2] 프로그램은 표준 입력에서 명령을 한 줄씩 EOF까지 읽고 결과를 표준 출력에 한 줄씩 쓴다. 빈 줄은 무시한다. 토큰은 하나 이상의 공백이나 탭으로 구분한다. 명령과 등급의 대소문자를 구분하며 안내 문구나 종료 합계는 출력하지 않는다. 날짜는 명령에 명시하므로 실제 시각을 사용하지 않는다.

[3] 날짜는 2000년부터 2099년까지 실제로 존재하는 날짜이며 `yyyy-MM-dd` 형식이다. 결제 ID와 이벤트 ID는 영문 대소문자, 숫자, 밑줄, 하이픈으로 이루어진 1~40자 문자열이다. 결제 금액은 0~1,000,000,000,000 사이의 원 단위 정수다. 금액에는 숫자만 쓴다. 한 번 실행할 때 명령은 최대 10,000개다.

[4] 등급은 `BASIC`, `SILVER`, `GOLD`이며 초기 기본 적립률은 각각 1%, 3%, 5%다. 적립률 인자는 0~100 사이의 십진수 백분율이며 소수점 이하 두 자리까지 허용한다. 정수부에는 한 자리 이상의 숫자를 쓰며 부호와 지수 표기는 쓰지 않는다. 예를 들어 `0`, `1.5`, `29.00`을 허용하고 `1.234`, `.5`, `-1`은 허용하지 않는다.

## 명령과 계산 규칙

[5] `RATE <등급> <적립률>`은 해당 등급의 기본 적립률을 바꾸고 `OK`를 출력한다. 다른 등급은 바꾸지 않는다. 초기값으로 되돌리는 별도 명령은 없다.

[6] `EVENT <이벤트ID> <시작일> <종료일> <추가적립률>`은 이벤트를 등록하고 `OK`를 출력한다. 시작일과 종료일을 모두 포함하며 시작일은 종료일보다 늦을 수 없다. 같은 이벤트 ID를 다시 등록하면 그 이벤트의 기간과 추가 적립률을 모두 교체한다. 이벤트 ID가 다르면 기간이 겹쳐도 별개로 취급한다.

[7] `ACCRUE <결제ID> <결제일> <등급> <금액>`은 새 결제의 포인트를 적립한다. 명령을 처리하는 시점의 해당 등급 기본 적립률에 결제일을 포함하는 모든 이벤트의 추가 적립률을 더한다. 합산 적립률이 100%를 넘으면 100%를 적용한다. 명령 입력 순서와 결제일 순서는 달라도 된다.

[8] 결제별 적립 포인트는 결제 금액에 적용 적립률을 곱한 값에서 소수 부분을 버린 정수다. 예를 들어 3%를 적용한 199원 결제는 5포인트다. 성공하면 `ACCRUED <결제ID> <포인트>`를 출력한다. 결제 ID는 전체 실행에서 유일하다. 이미 적립한 결제 ID로 유효한 `ACCRUE` 명령이 들어오면 `ERROR duplicate`를 출력하고 기존 내역을 유지한다.

[9] 적립 내역에는 결제일, 등급, 결제 금액, 적용 적립률, 포인트를 확정해 저장한다. 나중에 `RATE`나 `EVENT`로 설정을 바꿔도 이미 적립한 내역은 다시 계산하지 않는다. 같은 날짜의 뒤늦은 결제는 변경한 설정을 적용한다.

[10] `RECEIPT <결제ID>`는 `RECEIPT <결제ID> <결제일> <등급> <금액> <적립률> <포인트>`를 출력한다. 적립률은 백분율 숫자만 소수점 이하 두 자리로 출력한다. 예를 들어 3%는 `3.00`이다. 결제 ID가 없으면 `NONE`을 출력한다. 조회는 내역을 바꾸지 않는다.

[11] `DAY <결제일>`은 `DAY <결제일> <결제건수> <결제금액합계> <포인트합계>`를 출력한다. 해당 날짜에 성공적으로 적립한 결제만 센다. 포인트합계는 결제별로 소수 부분을 버린 포인트를 모두 더한 값이며 금액 합계에 적립률을 적용해 다시 계산하지 않는다. 내역이 없으면 세 수를 모두 `0`으로 출력한다. 금액과 포인트 합계는 32비트 정수 범위를 넘을 수 있다.

[12] 알 수 없는 명령, 인자 개수 오류, 잘못된 ID·날짜·등급·금액·적립률, 이벤트 기간의 역전은 `ERROR invalid`를 출력한다. 잘못된 명령은 설정과 적립 내역을 바꾸지 않으며 다음 줄을 계속 처리한다. `ACCRUE`는 인자 형식과 범위를 먼저 검사한 뒤 결제 ID의 중복을 검사한다.

## 버그 신고

[13] 운영자가 행사 기간의 일별 정산을 대조하다가 포인트 합계가 맞지 않는 날을 발견했다. 해당 실행에서는 회원 등급별 적립률과 이벤트 기간을 바꾸면서 여러 날짜의 결제를 접수했다. 운영자는 당시 입력한 명령과 조회 결과를 첨부했다.

[14] 새로 실행한 프로그램에 다음 명령을 차례로 입력하면 증상이 재현된다.

```text
RATE GOLD 4
EVENT autumn 2026-11-01 2026-11-07 28
ACCRUE kiosk-a 2026-11-04 SILVER 875
EVENT weekend 2026-11-06 2026-11-07 6
ACCRUE pay-100 2026-11-05 BASIC 100
ACCRUE web-a 2026-11-06 GOLD 1250
RATE SILVER 4.50
ACCRUE shop-a 2026-11-04 SILVER 875
ACCRUE pay-101 2026-11-05 BASIC 101
EVENT weekend 2026-11-07 2026-11-08 2.50
ACCRUE web-b 2026-11-06 GOLD 1250
RECEIPT kiosk-a
RECEIPT pay-100
RECEIPT web-a
DAY 2026-11-04
DAY 2026-11-05
DAY 2026-11-06
```
