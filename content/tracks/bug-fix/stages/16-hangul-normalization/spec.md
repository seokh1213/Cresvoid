# 목록에는 있지만 검색되지 않는 상품

## 상품 카탈로그

[1] 판매자가 올린 상품명을 보관하고 상품명에 포함된 단어로 검색하는 로컬 명령 처리기다. 목록에는 판매자가 보낸 원문을 표시한다. 검색에서는 같은 글자의 유니코드 표현이 달라도 같은 단어로 취급한다. 이 단계의 데이터와 버그 신고는 학습용으로 구성한 가상 사례다.

[2] 표준 입력에서 UTF-8 명령을 한 줄씩 EOF까지 읽고 결과를 표준 출력에 쓴다. 명령과 필드는 `|`로 구분한다. 필드 앞뒤 공백을 자동으로 제거하지 않는다. 빈 줄도 명령 한 줄이다. 상품명과 검색어에는 `|`, 줄바꿈, 제어 문자가 들어오지 않는다. 입력은 올바른 유니코드 문자열이며 최대 2,000줄이다.

[3] 명령 이름과 필드 수는 정확히 맞아야 한다. 지원하지 않는 명령이나 필드 수가 틀린 명령은 `ERR command`를 출력한다. 형식이 맞으면 id, 텍스트 순서로 검증하고 처음 발견한 오류만 출력한다. 오류가 발생한 명령은 상태를 바꾸지 않으며 다음 줄을 계속 처리한다.

## 등록과 목록

[4] `PUT|id|상품명`은 상품을 등록하거나 같은 id의 기존 상품을 교체하고 `SAVED id`를 출력한다. id는 부호와 선행 0이 없는 십진 정수이며 1 이상 2,147,483,647 이하다. id가 잘못되면 `ERR id`를 출력한다. 상품명은 ASCII 공백(U+0020)을 제외한 문자를 하나 이상 포함해야 하며 그렇지 않으면 `ERR title`을 출력한다. 교체가 끝난 상품은 새 상품명으로만 검색된다.

[5] `REMOVE|id`는 등록된 상품을 지우고 `REMOVED id`를 출력한다. 없는 id면 `MISSING id`를 출력한다. id 형식은 [4]와 같으며 잘못되면 `ERR id`를 출력한다. 삭제한 상품은 목록과 모든 검색 결과에서 빠진다.

[6] `LIST`는 첫 줄에 `LIST 상품수`를 출력한 뒤 상품마다 `id|상품명`을 한 줄씩 출력한다. id의 숫자 오름차순으로 나열하며 상품명은 공백과 유니코드 표현을 포함해 등록된 원문 그대로 출력한다. 빈 목록은 `LIST 0` 한 줄이다.

## 검색 규칙

[7] 검색에서 비교하는 상품명과 검색어는 모두 NFC 정규화를 적용한 뒤 ASCII 대문자 `A`~`Z`만 소문자로 바꾼 문자열로 취급한다. 변환한 문자열을 U+0020으로 나누고 빈 조각을 버려 단어를 얻는다. 같은 단어가 여러 번 나와도 한 번 나온 것과 같다. 원문 상품명은 이 변환의 영향을 받지 않는다.

[8] NFC는 정준적으로 같은 문자의 표현을 합성형으로 맞추는 유니코드 정규화 형식이다. 예를 들어 `한`은 U+D55C 한 개로도, U+1112 U+1161 U+11AB 세 개로도 표현된다. 두 표현은 검색에서 같은 단어가 된다. 호환 자모 `ㅎㅏㄴ`(U+314E U+314F U+3134)은 별개의 문자열이다. NFC 적용 외에 전각 영문, 문장부호, 폭 없는 공백(U+200B)을 추가로 변환하거나 제거하지 않는다. U+0020 외의 문자는 단어 구분자로 취급하지 않는다.

[9] `SEARCH|검색어`는 검색어의 모든 단어를 포함하는 상품을 찾는다. 단어 전체가 같아야 하며 부분 문자열, 초성, 접두어로 찾지 않는다. 일치한 id를 숫자 오름차순으로 쉼표로 이어 `FOUND id,id`로 출력한다. 일치한 상품이 없으면 `FOUND -`를 출력한다. 검색어가 빈 문자열이거나 U+0020만 있으면 `ERR query`를 출력한다.

[10] 예를 들어 `PUT|8|Blue 한 컵` 뒤에 `SEARCH|컵 BLUE`를 실행하면 `FOUND 8`이 된다. `SEARCH|Blu`는 `FOUND -`가 된다. 등록과 삭제는 즉시 검색에 반영되며 별도의 새로 고침 명령이나 외부 저장소는 없다.

[11] 정규화의 개념은 [Unicode Standard Annex #15](https://unicode.org/reports/tr15/)와 [Java SE 21 Normalizer 문서](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/text/Normalizer.html)에서 확인할 수 있다. 대소문자, 공백, 단어 일치 정책은 이 카탈로그가 정한 규칙이다.

## 버그 신고

[12] 판매자 지원 담당자의 신고다. “오늘 받은 상품 세 건을 등록한 뒤 판매자가 보낸 수정 상품명으로 7번을 교체했다. 수정 전후에 같은 검색이 되는 것도 있고, 목록에는 보이는데 검색되지 않는 것도 있다. 판매가 끝난 상품을 지우고 다른 상품명도 바꾸며 확인한 명령을 순서대로 남겼다.”

[13] 재현 입력은 다음과 같다. 복사 과정에서 문자가 바뀌지 않도록 등록 자료의 코드 포인트를 함께 적는다. `Blue 한 컵`은 `U+0042 U+006C U+0075 U+0065 U+0020 U+D55C U+0020 U+CEF5`, `Red 한 접시`는 `U+0052 U+0065 U+0064 U+0020 U+1112 U+1161 U+11AB U+0020 U+C811 U+C2DC`, `Green 수저`는 `U+0047 U+0072 U+0065 U+0065 U+006E U+0020 U+C218 U+C800`이다.

```text
PUT|24|Blue 한 컵
PUT|7|Red 접시
PUT|31|Green 수저
SEARCH|red 접시
PUT|7|Red 한 접시
SEARCH|red 접시
SEARCH|red 한
SEARCH|컵 한
REMOVE|24
SEARCH|한
SEARCH|red
LIST
PUT|31|Green 한 수저
SEARCH|한
SEARCH|접시 한
SEARCH|수저 green
REMOVE|7
SEARCH|한
LIST
```
