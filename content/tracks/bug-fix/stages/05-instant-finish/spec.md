# 시작하자마자 끝나는 백그라운드 이벤트

## 카탈로그 이벤트

[1] 쇼핑 카탈로그의 기획전은 노출 기간 동안 상품 목록을 주기적으로 갱신한다. 이벤트 관리자는 진행 중인 이벤트를 보관하고 시작, 조회, 중단 요청을 처리한다. 기간이 끝난 이벤트는 관리자 목록에서 빠진다. 이 단계의 프로그램은 외부 서비스 호출 대신 갱신 횟수를 기록하는 재현용 실행기다.

[2] 프로그램은 표준 입력에서 명령을 한 줄씩 EOF까지 읽고 명령마다 결과 한 줄을 표준 출력에 쓴다. 빈 줄은 무시한다. 토큰은 공백으로 구분하며 대소문자를 구분한다. 이벤트 ID는 1~24자이며 영문 소문자·숫자·하이픈으로 이루어진다. 첫 글자는 영문 소문자다.

[3] 첫 번째 비어 있지 않은 줄은 `SCHEDULER QUEUED` 또는 `SCHEDULER INLINE`이다. 실행기는 `READY`를 출력한다. QUEUED는 이벤트 작업을 실행 큐에 넣는다. INLINE은 작업을 호출한 흐름에서 실행하다가 처음 대기하는 지점에서 제어를 돌려준다. 두 방식 모두 각 명령의 처리와 현재 시각에 실행 가능한 작업을 마친 뒤 다음 명령을 처리한다. 이벤트의 업무 결과는 실행 방식에 따라 달라지지 않는다. 스케줄러 설정은 처음에 한 번만 주어지며 형식은 항상 올바르다.

[4] 가상 시각은 0밀리초에서 시작하고 `ADVANCE`로만 움직인다. 실제 시계나 실행 속도는 결과에 영향을 주지 않는다. EOF에서는 남은 이벤트를 정리하고 출력 없이 종료한다. 모든 명령은 차례로 처리하며 이벤트 작업도 같은 실행 흐름에서 수행한다.

## 명령과 규칙

[5] `START <id> <기간> <간격>`은 현재 시각을 시작 시각으로 삼아 이벤트를 등록하고 `STARTED <id>`를 출력한다. 기간과 간격은 각각 1~1000000밀리초의 정수다. 종료 시각은 시작 시각에 기간을 더한 값이다. 시작이 성공한 이벤트는 종료 시각 전까지 목록에 남아 있어야 한다.

[6] 이벤트는 시작 시각에 한 번 갱신하고 이후 시작 시각에서 간격의 정수 배만큼 지난 시각마다 갱신한다. 종료 시각과 같거나 늦은 시각에는 갱신하지 않는다. 종료 시각에 도달하면 간격이 아직 남아 있더라도 목록에서 제거한다. 갱신 횟수는 이벤트마다 따로 센다.

[7] `STATUS <id>`는 진행 중인 이벤트의 `EVENT <id> <갱신 횟수> <시작 시각> <종료 시각>`을 출력한다. 목록에 없는 ID는 `ERROR NOT_FOUND <id>`를 출력한다. 조회로 시각이나 갱신 횟수가 바뀌지는 않는다.

[8] `LIST`는 진행 중인 ID를 사전순으로 정렬해 `EVENTS <id1> <id2> ...`로 출력한다. 진행 중인 이벤트가 없으면 `EVENTS -`를 출력한다.

[9] `ADVANCE <밀리초>`는 현재 시각을 지정한 만큼 앞으로 옮기고 그 시각까지 예정된 갱신과 종료 처리를 모두 마친 뒤 `TIME <현재 시각>`을 출력한다. 이동량은 0~1000000000의 정수다. 전체 입력에서 가상 시각은 1000000000밀리초를 넘지 않는다. 한 번에 이동하든 나누어 이동하든 같은 시각에서 조회한 결과는 같아야 한다.

[10] `STOP <id>`는 진행 중인 이벤트를 목록에서 제거하고 작업을 중단한 뒤 `STOPPED <id>`를 출력한다. 목록에 없는 ID는 `ERROR NOT_FOUND <id>`를 출력한다. 중단한 이벤트는 이후 갱신하지 않는다. 종료되거나 중단된 ID는 다시 사용할 수 있고 새 이벤트의 갱신 횟수와 시작 시각은 새로 계산한다.

[11] 진행 중인 ID에 대한 `START`는 `ERROR EXISTS <id>`를 출력하고 기존 이벤트를 그대로 둔다. 명령 이름, 토큰 수, ID 형식, 숫자 형식이나 범위가 틀리면 `ERROR INVALID`를 출력한다. 정수는 부호 없는 십진 숫자로 쓴다. 잘못된 명령은 이벤트나 시각을 바꾸지 않는다. `START`는 형식과 범위를 검사한 뒤 ID 중복을 검사한다.

## 버그 신고

[12] 카탈로그 운영 담당자의 신고를 가정한 내용이다. “기획전을 시작한 직후 상태를 물으면 이벤트가 없다고 나온다. 서비스에서는 간헐적으로 보였고 단독 테스트에서는 놓쳤다. 아래 입력으로 재현 실행기를 돌리면 같은 증상이 난다. 첫 줄을 `SCHEDULER QUEUED`로 바꾸면 정상으로 보인다.”

```text
SCHEDULER INLINE
START spring 100 25
STATUS spring
LIST
ADVANCE 25
STATUS spring
```

[13] 신고자가 기대한 결과다. “아직 종료 시각이 아니므로 시작 직후에도 목록에 있어야 한다. 25밀리초 뒤에는 두 번째 갱신까지 끝나 있어야 한다.”

```text
READY
STARTED spring
EVENT spring 1 0 100
EVENTS spring
TIME 25
EVENT spring 2 0 100
```

[14] 시작 코드에서 확인한 실제 결과다. “시작은 성공했다고 나오지만 조회와 목록에서는 이미 사라져 있다. 시간을 더 보내도 돌아오지 않는다.”

```text
READY
STARTED spring
ERROR NOT_FOUND spring
EVENTS -
TIME 25
ERROR NOT_FOUND spring
```
