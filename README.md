# Cresvoid

구현 감각과 긴 글을 정확히 읽는 힘을 되찾기 위한 로컬 훈련 도구다. 서버 없이 이 디렉터리 안에서 모든 기능이 동작한다.

Cresvoid는 crescent(초승달)와 void를 합친 이름이다.

컨텐츠와 엔진은 나뉘어 있다. 엔진(`engine/`)은 [content/FORMAT.md](content/FORMAT.md)에 적힌 형식만 읽는다. 그래서 형식을 지키는 트랙은 엔진을 고치지 않고 추가할 수 있다.

## 준비

필요한 도구는 다음과 같다.

| 도구 | 쓰는 곳 |
|---|---|
| JDK 21, kotlinc | 엔진과 Kotlin 프로젝트의 빌드와 실행, Kotlin 스크립트(`.main.kts`) 실행 |
| bash | 엔진이 풀이 프로그램을 새 프로세스 그룹에서 실행할 때 쓴다 |
| less | `cresvoid read` 의 문서 보기. `$PAGER` 로 바꿀 수 있다 |

엔진은 Gradle 로 빌드하는 Kotlin 프로그램이다. `engine/bin/cresvoid` 는 엔진 소스가 jar 보다 새로울 때만 `engine/gradlew jar` 로 다시 빌드한다. Gradle 은 래퍼가 처음 빌드할 때 내려받는다. `engine/bin` 을 PATH 에 추가한다.

```sh
echo 'export PATH="$HOME/personal/cresvoid/engine/bin:$PATH"' >> ~/.zshrc
```

시작 코드와 참조 풀이 같은 Kotlin 프로젝트에는 `.java-version`, `build.gradle.kts`, `settings.gradle.kts` 가 들어 있다. jenv 가 그 디렉터리에서 JDK 21 을 고르고 IntelliJ 로 열 수 있다. 테스트할 때는 `build.sh` 가 kotlinc 로 직접 빌드한다.

## 한 단계를 푸는 흐름

트랙 종류마다 단계에서 할 일이 다르다.

| 종류 | 이름 | 할 일 |
|---|---|---|
| build | 구현 | start, read, quiz, test |
| reading | 독해 | read, quiz |
| code | 코드 읽기 | read, quiz. read 가 코드를 줄 번호와 함께 보여 준다 |
| fix | 버그 수정 | start, read, test. 작업 공간은 단계마다 따로 만든다 |

build 트랙의 한 단계는 다음 순서로 푼다.

1. `cresvoid start <트랙>` 으로 작업 공간(`practice/<트랙>/`)을 만든다. 모든 단계가 이 작업 공간 하나를 쓴다.
2. `cresvoid read <트랙>` 으로 단계 문서를 읽는다. 첫 시도 풀이 시간은 이때부터 잰다.
3. `cresvoid quiz <트랙>` 으로 확인 문항을 푼다. 모든 문항이 닫혀야 다음으로 넘어간다. 문항은 맞히거나 세 번 틀려 정답이 공개되면 닫힌다.
4. 작업 공간에서 AI 없이 구현한다. AI 리뷰는 테스트를 통과한 뒤에만 받는다.
5. `cresvoid test <트랙>` 으로 테스트를 실행한다.
6. 참조 풀이는 `cresvoid solution <트랙>` 으로 본다. 테스트를 통과하지 않아도 볼 수 있다.
7. 통과하고 2주가 지나면 빈 작업 공간에서 같은 단계를 다시 구현한다. `cresvoid` 가 복습할 단계를 알려 준다.

fix 트랙은 문항 없이 그 단계 테스트만 통과하면 된다. 작업 공간은 단계마다 `practice/<트랙>/<단계 디렉터리>/` 에 만든다. `cresvoid solution` 은 시작 코드와 참조 풀이의 차이를 보여 준다.

`cresvoid` 를 인자 없이 실행하면 트랙마다 진행 상황과 다음에 실행할 명령을 보여 준다. 문항 칸의 `5/5` 는 첫 시도 점수다. `공개 1` 은 정답이 공개되어 닫힌 문항 수다.

### 첫 시도

- 첫 시도 점수와 걸린 시간은 한 번만 기록한다.
- 걸린 시간은 `cresvoid read` 로 문서를 연 시각부터 첫 제출까지다. 문서를 다시 열어도 마지막으로 읽은 지 한 시간이 지나지 않았으면 처음 연 시각을 유지한다.
- `cresvoid read` 없이 문항을 풀거나 마지막으로 읽은 지 한 시간이 지났으면 시간을 재지 않는다.
- 첫 시도를 Ctrl-C 나 Ctrl-D 로 도중에 그만두면 답한 문항만 채점하고 답하지 않은 문항은 틀린 것으로 기록한다. 답을 하나도 하지 않고 그만두면 그 시도는 저장하지 않는다. 두 번째 시도부터는 그만두면 아무것도 저장하지 않는다.

### 테스트 실패

테스트 입력과 기대 출력은 보여 주지 않는다. 실패하면 다음만 나온다.

- 실패한 테스트 이름과 실패 종류(제한 시간 초과, 비정상 종료, 출력 불일치 같은 판정 문구)
- 다시 읽을 문서 경로와 문단 번호, 핵심 문장
- 무작위 입력으로 실패했으면 같은 입력으로 다시 실행하는 `-seed` 명령
- 참조 풀이를 보는 `cresvoid solution <트랙> -stage N` 명령. N 은 실패한 테스트가 속한 단계다

내 프로그램의 표준 출력과 표준 오류도 보여 주지 않고 파일로 남기지 않는다. 확인이 필요하면 직접 만든 입력으로 작업 공간의 `run.sh` 를 실행한다. 같은 테스트를 여러 번 실패해도 보여 주는 내용은 같다. 실패는 진행 기록에 남지 않는다. 빌드가 실패하면 빌드 출력을 보여 준다.

### 문항 오답

정답을 바로 보여 주지 않는다. 같은 문항을 다시 틀릴 때마다 보여 주는 것이 하나씩 늘어난다.

| 오답 횟수 | 보여 주는 것 |
|---|---|
| 1 | 다시 읽을 문단 번호나 코드 위치 |
| 2 | 핵심 문장 |
| 3 | 정답과 해설. 문항은 공개됨으로 닫힌다 |

### 복습

처음 통과하고 2주가 지난 뒤 다른 작업 공간에서 다시 통과하면 복습으로 기록된다. 2주가 지나기 전의 통과는 복습으로 치지 않는다.

```sh
cresvoid start search-engine -dir practice/search-engine-review
cresvoid test search-engine -stage 1
```

`cresvoid start` 는 그 트랙의 작업 공간을 새 경로로 바꾼다. 원래 작업 공간으로 돌아가려면 `cresvoid start` 에 원래 경로를 `-dir` 로 준다. 경로에 `run.sh` 가 있으면 시작 코드를 복사하지 않고 그 작업 공간을 고르기만 한다.

## 명령

| 명령 | 하는 일 |
|---|---|
| `cresvoid` | 진행 상황과 다음 할 일 |
| `cresvoid start <트랙> [-stage N] [-lang 언어] [-dir 경로]` | 시작 코드를 복사해 풀이 작업 공간을 만든다. 기본 경로는 build 트랙이 `practice/<트랙>/`, fix 트랙이 `practice/<트랙>/<단계 디렉터리>/` 다. 이미 있는 작업 공간이면 고르기만 한다. `-stage` 는 fix 트랙에만 쓴다 |
| `cresvoid read <트랙> [-stage N]` | 단계 문서를 보여 준다 |
| `cresvoid quiz <트랙> [-stage N]` | 확인 문항을 푼다. 틀린 문항만 다시 묻는다 |
| `cresvoid test <트랙> [-stage N] [-dir 경로] [-seed S]` | 테스트를 실행한다. build 트랙은 1단계부터 대상 단계까지 실행하고 그 범위의 문항을 마쳐야 한다 |
| `cresvoid solution <트랙> [-stage N]` | 참조 풀이를 보여 준다. 통과하지 않은 단계도 볼 수 있다 |
| `cresvoid reset [트랙] [-stage N] [-yes]` | 진행 기록을 지운다. 지우기 전에 `practice/progress/backups/` 에 사본을 남기고 작업 공간은 지우지 않는다 |
| `cresvoid validate <트랙>` | 컨텐츠가 FORMAT.md 형식과 검증 항목을 지키는지 확인한다 |
| `cresvoid help` | 명령과 트랙 종류별 할 일을 보여 준다 |

`-stage` 에는 단계 번호나 단계 디렉터리 이름을 쓴다. 생략하면 아직 마치지 않은 첫 단계가 대상이다. 모든 단계를 마쳤으면 마지막 단계가 대상이다. 플래그는 `-stage` 와 `--stage` 둘 다 받는다.

## 컨텐츠 카탈로그

기르려는 역량과 앞으로 만들 단계는 [content/ideas/README.md](content/ideas/README.md) 에 있다. 역량은 읽기, 구현(구현·코드 읽기·버그 수정), 실무로 나뉜다. 실무는 부하 엣지 케이스, 프레임워크, 데이터베이스, 메시징, 검색, 시스템 설계, Spark, HDFS, 레이크하우스, OLAP, AI 에이전트, 분산 시스템, 관측성, JVM, 네트워크, 코루틴, 장애 보고서 도메인으로 나뉜다. 단계 하나는 카드 파일 한 장이고 전체 목록과 다음 후보는 [content/ideas/INDEX.md](content/ideas/INDEX.md) 에 있다. 새 단계는 카드를 골라 `content/skills/` 의 스킬로 만든다.

## 지킬 것

- 단계의 `hidden/` 은 열지 않는다. 숨은 테스트, 문항 정답, 참조 풀이가 들어 있다. 참조 풀이는 `cresvoid solution` 으로 본다.
- 구현하는 동안 AI 를 쓰지 않는다. 엔진은 이것을 막지 못한다.
- 문항을 찍지 않는다. 첫 시도 점수와 걸린 시간이 기록된다.

## 디렉터리

```
cresvoid/
├── AGENTS.md             에이전트(Claude Code, Codex 등)가 가장 먼저 읽는 안내. 규칙은 docs/agents.md 에 있다
├── content/              문제 원본. 풀어도 참조 풀이의 build/ 말고는 바뀌지 않는다
│   ├── FORMAT.md         컨텐츠 형식 계약
│   ├── tracks/           트랙 컨텐츠. 단계의 채점용 파일은 hidden/ 에 있다
│   ├── ideas/            역량 지도, 카드, 카드 색인(INDEX.md)과 색인 생성기
│   ├── skills/           컨텐츠를 만드는 스킬과 워크플로우
│   └── templates/        Kotlin 프로젝트 공통 파일의 원본(kotlin/)과 복사 스크립트(sync.main.kts)
├── engine/               엔진. Gradle Kotlin DSL 프로젝트이고 실행 코드는 표준 라이브러리와 JDK 만, 테스트는 Kotest 를 쓴다
│   ├── bin/cresvoid          엔진 실행 스크립트. 소스가 바뀌었으면 엔진을 빌드한 뒤 실행한다
│   └── e2e.main.kts      끝에서 끝까지 확인
├── practice/             로컬 풀이 작업 공간. cresvoid start 가 만들며 Git에 올리지 않는다

└── docs/                 에이전트 작업 규칙(agents.md), 작업 기록, 결정, 인수인계
```

## 컨텐츠 추가

1. [content/ideas/INDEX.md](content/ideas/INDEX.md) 의 "다음 후보" 에서 카드를 고른다.
2. `content/skills/cresvoid-content` 의 절차와 종류별 스킬로 [content/FORMAT.md](content/FORMAT.md) 형식의 `content/tracks/<트랙>/` 을 만든다.
3. `cresvoid validate <트랙>`, `kotlin content/templates/sync.main.kts --check`, `kotlin engine/e2e.main.kts` 로 확인한다.

build 트랙의 검증은 참조 풀이가 모든 테스트를 통과하는지, 시작 코드가 1단계에서 실패하는지, 앞 단계 참조 풀이가 다음 단계 테스트에서 실패하는지까지 실행으로 확인한다. fix 트랙은 시작 코드가 그 단계 테스트에서 실패하고 참조 풀이와의 차이가 몇 줄인지, code 트랙은 코드가 빌드되고 short 문항의 정답이 실행 결과와 같은지 확인한다.
